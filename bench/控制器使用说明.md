# 基准控制器使用说明

截至 2026-10-24，入口为本目录 `bench_controller.py`。它调用原版 Harbor，只负责串行实验、暂停与评分；产品任务仍由 PAO 执行。旧 `real-run-*` 保持原样，不能把新控制器套到旧目录后续跑。

## 准备新运行

真实模型运行及其费用另行授权。本次隔离验证目录仅作验收，不能用于正式运行。

1. 新建独立运行目录，复制准备代理、模型适配器及 `organized-post/`，使用待测源码包。不要复制旧启动、暂停、状态和结果文件。
2. 写 `run-config.json`：保持固定题目、模型、思考档、权限及官方评分；`n_attempts=1`、`retry.max_retries=0`、`n_concurrent_trials=1`。仅接受一个 `map_bench_pao_organized:OrganizedPAOAgent`。
3. `jobs_dir` 使用 Linux 中可访问的绝对路径，并放在该新运行目录内。配置里的其他宿主路径也须转换为 Linux 挂载路径；控制器不会静默改写冻结配置。
4. 显式设置 `environment.type=docker`、`environment.kwargs.keep_containers=true`。单独的 `delete=false` 不足以保留可供中断评分的容器；此调整须在冻结前记录。
5. 保存 `run-freeze.json`，格式为 `{"files":[{"path":"相对路径","sha256":"文件摘要"}]}`，覆盖配置、控制器、全部适配器、组织配置、源码包等输入。控制器强制检查配置、准备代理与模型适配器六个必要文件，其余输入按清单核对；源码及组织配置还由原适配器核对各自摘要。凭证通过环境传入，不写入冻结文件。
6. 使用已有 Linux Harbor 解释器执行 `bench_controller.py validate --run <新运行目录>`。此操作核验冻结内容、真实 `JobConfig` 与适配器参数，不调用模型。通过后才可执行 `run`。

`run` 先对全部题目执行 PreparationOnlyAgent。只有数量匹配、无异常且每题都有实际 `preparation-complete.txt`，才运行正式模型。正式阶段逐题建立原版 Harbor Job，保存派生配置、逐题汇总及官方原件；不会替换失败实验方式。

## 操作

以下命令都使用同一个新运行目录和同一份控制器；解释器使用已核实的 Linux Harbor 解释器绝对路径。

| 操作 | 参数 | 含义 |
|---|---|---|
| 配置检查 | `validate --run <目录>` | 不调用模型 |
| 启动 | `run --run <目录>` | 各题一次、串行、零自动重试 |
| 查看 | `status --run <目录>` | 展示最后落盘阶段；不是进程存活探测 |
| 立即暂停 | `pause --run <目录>` | 提交取消请求，等待 Harbor 收尾 |
| 本题后暂停 | `pause --after-current --run <目录>` | 本题自然结束，不启动后题；不能覆盖已有立即暂停 |
| 现有成果评分 | `score --run <目录> --score-spec <清单路径>` | 不调用模型，在新评分容器中执行原测试 |

收到暂停请求不等于已经停下。只有状态明确 `writers_stopped=true` 才确认本控制器完成收尾；真实 Harbor 返回后还会检查本 Job 是否残留活动容器。停止失败保留异常，不伪报暂停成功。宿主被强杀时落盘状态可能陈旧，必须核查进程与容器；不能靠手工把状态改成已停止来继续运行。

启动标记 `control-started.json` 独占创建且不自动删除。暂停、失败、崩溃后均拒绝重新运行原目录；需要恢复实验时另行决定并建立新运行，避免重复付费。

## 独立评分清单

`score-spec` 包含：

- `source_container`：保存当前成果的已停止容器。
- `task_dir`：原题素材目录，仅评分器访问，不交给做题 agent。
- `files`：`task.toml` 和 `tests/` 全部文件的相对路径及 SHA-256，必须与预先固定的素材完全对应。
- `artifacts`：明确的待测文件列表，例如 `[{"target":"/app/filter.py"}]`。只接受 `/app/` 下的明确文件；不猜测整个目录是否属于成果。

评分器在复制前后检查来源容器已停止，固定产物摘要，使用 `task.toml` 中带 digest 的原评分镜像。测试内容合并进入 `/tests/`，保留镜像原有素材，避免整目录挂载遮住它们。新结果写入 `current-score/`，已有结果不覆盖。

正常结束后的重评分标为 `completed_artifact_rescore`；暂停或错误后的成果评分标为 `interrupted_artifact_score`。数值 0 是有效分数；缺奖励文件、环境异常或非法数值记为 `scoring_invalid`，不能填 0。失败与官方日志原件保留。
