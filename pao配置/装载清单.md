# pao 装载清单（R10 留档正本）

建稿：2026-10-02（M1-04 两档路由和生态实挂）。本文是 R10「主控与 worker 各自加载的扩展/工具清单」的成文正本：清单＋隔离机制＋与代码接线的对应关系。装载面变化时同批订正本文。

## 0. 机制总览

- pao 全部定制以**内置扩展 `pao`** 注册进 pi 内核：`packages/coding-agent/src/extensions/index.ts:16`（`factory: paoExtension, replaceable: false`）。扩展源码总入口 `src/pao/index.ts`。
- 角色由环境变量 **`PAO_ROLE`** 决定：`worker` ＝ worker 会话；未设/其他值 ＝ 主控（保守侧：主控装载面是超集）。解析在 `src/pao/role.ts:18`。
- **worker 隔离是注册层跳过，不是藏提示词**：worker 会话不注册派发/全库管理/自动推进/后台管理/主控诊断类模块，间接入口（事件钩子，如巡检落卡 `afterInspect`）随模块一起消失。跳过清单 `src/pao/role.ts:34`（`WORKER_SKIPPED_MODULES`），门控执行 `src/pao/index.ts:167-187`。
- **worker 子进程由 WorkerRunner 强制注入角色**：`src/pao/worker/runner.ts:195`（`env: { ...process.env, [PAO_ROLE_ENV]: "worker", ...环境变量 }`）——即使主控进程忘了设，worker 也绝不会拿到主控装载面；显式 `环境变量` 可覆盖（测试逃生舱）。
- 工具白名单（`--tools`）是第二道独立防线，由主控派卡时给定（`runner.ts` buildArgs），管"模型看得见哪些工具"；`PAO_ROLE` 管"扩展注册了什么"。两层叠加。

## 2. worker 会话装载面（PAO_ROLE=worker）

- **注册的**：tiers（虚拟模型两档，worker 收 `--model` 档位名时可用）＋ 品牌指示器。仅此两件。
- **跳过的**（清单即 `WORKER_SKIPPED_MODULES`）：cards、collab、worker、dept、knowledge、fanout、healthcheck。理由逐条见 `src/pao/role.ts` 注释：worker 无 PAO 再派发入口（cards/collab/fanout）、不管后台（worker）、不注入注册表提示（dept）、不碰全库管理与自动推进（knowledge 的入库/巡检及落卡钩子）、不背主控诊断（healthcheck）。
- worker 的 `pao_受限补查`（G1-09 受限再查）待 M1-05 真实库接线时以最小白名单方式单独放行——届时订正本文。
- 兜底白名单：主控派卡经 `--tools` 只放行任务所需工具（`runner.ts` buildArgs）。

### worker 实际会话注意（用户级资源的边界）

WorkerRunner 以 `pao --mode json -p --no-session` 拉起子进程，pi 会照常读**用户级**配置（`~/.pi/agent/`）：

- `mcp.json`（codebase-memory）与 `packages`（rpiv-todo）对 worker 同样生效。MCP 工具在 worker 未列入 `--tools` 白名单时模型不可直接调，但服务器进程仍会连接（资源开销，非能力缺口）；rpiv-todo 的 `todo` 工具同理被白名单遮蔽。
- 这是用户级 pi 配置的既有行为，不由 `PAO_ROLE` 门控（pao 只管自家扩展的注册面）。若日后要求 worker 连 MCP 都不连，需在派发时加 `--no-...`/settings 覆盖，属 M2 加固项。
- 用户级 `~/.pi/agent/extensions/`（orca-*.ts，Orca 桌面状态件）与项目级 `.pi/extensions`（仓库内 tps 等 demo）也在装载面内；均无任务写入面。

## 4. 两档路由（M1-04 落定）

- 配置正本：`pao配置/档位.json`（快＝zai-coding-cn/glm-5.3-flash/low；主力＝zai-coding-cn/glm-5.3/high；provider 名 `pao`）。换物理模型只改此文件。
- 装载：`registerTiers` 把每档注册成 pi 虚拟模型（`src/pao/routing/index.ts:42`），协议层只见档位名。
- 档位语义：架构 §98（两档起步）＋ §105（主控/验收钉贵档，worker 默认便宜档；判断性活禁外派）。
- 失注册不静默：恢复会话时若分支记录的档位选择已不在配置中，pi 原生回退到最后作答的物理模型（docs/virtual-models.md），pao 守卫（`src/pao/routing/session-guard.ts:53`）在 session_start 发结构化警告指明失效档位与恢复动作。route 时物理模型缺失直接报错不回退（`routing/tiers.ts`）。
- 实证（2026-10-02，全仓 build 后）：`pao --list-models` 列出 `pao/快`、`pao/主力`；主控与 `PAO_ROLE=worker` 下均在。
