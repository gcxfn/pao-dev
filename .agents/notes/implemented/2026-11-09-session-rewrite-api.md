# 会话持久条目的受控重写 API

## 缺口

`SessionManager` 公开读接口只提供条目副本，历史没有公开写入口；`_rewriteFile`
是私有方法，调用方修改 `getEntries()` 返回对象也不会更新内部索引和 JSONL。
记忆彻底删除需要在取得会话控制权后，保留 entry ID、父链和工具调用配对，
只清理指定正文及受管派生正文。外部模块不能调用私有方法，也不能靠改副本绕过 API。

## 决定

新增 `SessionManager.rewriteEntries()`。调用方按 entry ID 提供同步重写函数；
Manager 在副本上执行函数，校验 ID、父链、时间戳和条目类型不变，构建新索引后
一次原子替换当前持久文件。未持久化、未知 ID、重复 ID、校验失败或写盘失败均抛错，
调用方不会得到部分成功的会话对象。

这是通用条目维护原语：不包含记忆、脱敏、归档或业务删除规则。记忆删除的选择范围、
共享来源、派生正文识别与状态机仍由 `pao/memory` 持有。

## 影响与升级验证

- `flush()` 保留，后台 ledger 行为不变。
- 现有 append/branch/compaction 路径不变；只有显式调用新入口才发生原地重写。
- 定向测试覆盖真实持久 JSONL：重开后正文已替换、其他条目保留、父链与
  `toolCallId` 不变；任一重写函数失败时文件和内存索引均不改变。
