# 验收命令 argv 解析依赖（2026-10-28）

## 决策

`@earendil-works/pi-coding-agent` 直接固定 `shell-quote@1.12.0`，只负责把验收卡里的
命令字符串切成 argv；安全检查、schema、沙箱、超时、取消和真实执行仍由
`verifier.ts` 与 `process.ts` 原有链路承担。执行继续使用无 shell 的
`execFile`，不展开变量、通配符或命令替换。

选择成熟库而不继续维护旧简化 lexer，是因为旧实现遇到引号结束就发布参数，既不能处理
嵌套引号，也让预检和执行使用两套不同的词法结果。`shell-quote` 有 TypeScript 类型，
支持单/双引号、反斜杠、空参数和相邻引号段；其宽松的未闭合引号、环境变量、operator、
comment 和 glob 结果由 `verifier.ts` 的薄校验拒绝。Windows 相对路径的反斜杠另做窄范围
保护，避免把路径分隔符当成 POSIX 转义，不重新实现 shell 解析器。

## 保守安全视图

命令字符串会先保留旧安检的保守词视图：去掉全部引号、按空白切词，再扫描删除词和
绝对路径。成熟解析后的最终 argv 还会再扫描一遍相同规则。两份结果只用于安全判断，
执行器只接收 `shell-quote` 解析并经校验的那一份 argv，因此没有第二个执行 parser。

这条旧视图不能省。例如 `node -e "rm "` 的成熟 argv 只有一个完整字符串参数，但旧视图
会在去引号后看到独立的 `rm` 词；`node -e " /!"` 同理会看到以 `/` 开头的词。两者都应
在执行前被拦截。

## 版本、许可与维护

- 版本：`1.12.0`，固定到 `packages/coding-agent/package.json`；安装命令为
  `npm install --workspace=@earendil-works/pi-coding-agent shell-quote@1.12.0 --save-exact --ignore-scripts --no-audit --no-fund`。
- 许可：MIT；包内 `LICENSE` 与 npm 元数据一致。
- 维护：npm 包由 `ljharb` 维护；截至 2026-10-28 使用当前发布版。
- 安全：1.9.0 修复 `GHSA-395f-4hp3-45gv` 的二次复杂度；1.11.0 继续修复反斜杠和
  ANSI-C 未闭合输入的性能问题。因此不选旧版或仅存在于其他工具沙箱的副本。
- 依据：[README](https://github.com/ljharb/shell-quote)、[源码](https://github.com/ljharb/shell-quote/blob/main/parse.js)、[MIT 许可](https://github.com/ljharb/shell-quote/blob/main/LICENSE)。

## 未采用的方案

- 继续在旧 lexer 上补引号特例：无法让预检和执行共享同一 argv，也会持续堆积命令形状
  分支。
- 引入完整 shell 解释器或临时脚本借壳：会重新引入 shell 语义和安全面，违反无 shell 边界。
- 使用偶然存在的根 `node_modules/shell-quote@1.10.0` 或 pnpm 沙箱副本：不是直接依赖，
  版本和发行路径不可审计。

本决策只覆盖命令字符串到 argv 的公共传输，不代表卡片业务验收、模型评分或答案正确性。
