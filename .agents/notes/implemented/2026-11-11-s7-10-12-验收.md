# S7-10 / S7-12 验收：真实 Electron 用量面板 + 发行物四段链

- 日期：2026-11-11
- 位置：`desktop/apps/desktop/tests/core/memory-usage-panels.spec.ts`、`desktop/apps/desktop/tests/production/packaged-s7-12.spec.ts`；截图与证据 `.pao/内置记忆与受控自进化-2026-11-08/S7/`

## 决定

- S7-10 用量面板验收走真实 Electron + PAO 内置扩展（`PAO_DISABLE_BUILTIN_EXTENSION="0"`）+ 隔离 PAO_HOME，档位.json 指向 `memory-s7-scripted` 脚本 provider——提炼真实走脚本模型并经 `appendUsage(kind=extract)` 记账进 `background-ledger/`，不 mock 聚合层。
- `agentDir` 必须放 `<PAO_HOME>/agent`：`readDesktopContextUsage` 扫 `<home>/agent/sessions/<cwd>/*.jsonl`，桌面会话文件由 `PAO_CODING_AGENT_DIR` 决定，两路不重合则快照面板永远为空。
- 扩展自动发现：`<agentDir>/extensions/*.ts` 由 `package-manager.ts::addAutoDiscoveredResources`（user scope）启用，settings.json **不写** `extensions` 字段（该字段是覆盖模式数组，写空数组=显式禁用）。project 级 `.pi/extensions` 需 projectTrusted，user 级不需要。
- 记忆模块启用开关是 `$PAO_HOME/pao配置/记忆供应商.json` 存在——缺文件 `registerMemory` 直接 return，整条记忆链（采集/提炼调度/维护调度/context-usage）都不挂。验收写 builtin 范本（`base_url` 指不通的 127.0.0.1:9 防真请求，`自动召回:false`）。
- 档位.json `model` 字段写**裸 modelId**（`tierNameToModel` 返回 `${provider}/${model}` 拼接，写 `provider/model` 会被拼成 `provider/provider/model`）。

## 桌面 lane 的 jiti/Babel 两个解析坑（实测）

1. 扩展源里**正则字面量含中文** → `ParseError: Unterminated regular expression`。改 `new RegExp("...")` 字符串构造。
2. 扩展源字符串里**真换行** → `Unterminated string constant`。spec 反引号模板里 `\n` 须写 `\\n`（写出文件为 `\n`）、`\\s` 须写 `\\\\s`（写出 `\\s` → 正则 `\s`）。

定位入口：`getDesktopState(page).runtimeByWorkspace` → `RuntimeSnapshot.extensions[].diagnostics` 含 `Failed to load extension: ParseError ...` 原文；stderr 不上抛、errors 不可见，这是最直接出口。

## streamSimple 触发 context-usage 快照的完整链

`pao-context-usage` 快照 = `context_with_system` 事件记 pending → `before_provider_request` 事件消费写 `pi.appendEntry("pao-context-usage", snapshot)`。两事件都是 Agent loop 钩子，而 `before_provider_request` 只在 provider 调 `options.onPayload` 时发射——真实 provider 发 HTTP 前 `await options?.onPayload?.(params, model)`。**脚本化 provider 必须同样调 `options.onPayload`** 否则 pending 快照永不落。

`streamSimple` 签名要求**同步返回** `AssistantMessageEventStream`：模式 = push start → `Promise.resolve(options.onPayload(payload, model)).then(finish, finish)` → finish 里 push delta+done。

`modelRuntime.streamSimple` 先 `normalizeContext(context)` 把 `Context.systemPrompt` 折成 messages[0]（system role leading message）——provider 收到的 `TranscriptContext` 无顶层 `systemPrompt`，提炼判定须读 `messages[0].role==="system"` 的 content，条目从 `role==="user"` 消息聚合。

## S7-12 发行物验收形

沿用 S4-17/S6-11 先例：`ELECTRON_RUN_AS_NODE=1` 起发行物 `PAO.exe` node 子进程，从 `app.asar` 内 `@pao/coding-agent/dist/pao/` 导入内核（不读开发仓 dist，不冒充发行验证）。五个 phase（setup→claim-b→recover→reuse→usage）串成一条链，每段结果带 `execPath===PAO.exe` 证明双宿主都是发行物运行时：

- 整理中退出→重启→继续：宿主 A claim 推进 `ckpt-1` 后进程结束（running 死持有者）；宿主 B 并行 claim 抢不到（如实 `undefined`，不重复消费）；B recoverJobs 重取 pending → claim 从 `ckpt-1` 续到 `ckpt-2` done。
- CLI/桌面并行：两个发行物进程不同 ownerProcess 同 home，只一个 owner。
- 成果复用 + 全程用量：registerArtifact 受管版本 resolve 回读 + recordArtifactUse 归因；后台账本 `openPersistentMemoryLedger` 写一笔 extract usage（含 requestId），`readMemoryUsage` 聚合出该 requestId 与 token/费用。完成判据「状态、版本、费用、来源链全部可追溯」逐项落实：job checkpoint+owner、artifact versionId+seq、usage requestId+jobId、artifact_use 归因行。

## 被否方案

- S7-12 用 Playwright 起发行物桌面端驱动 UI：本轮无 UI 断言（S7-10 已覆盖页面），发行物验收目标是内核链路在真包运行时；UI 发行验收已由 S6-11 覆盖。
- 脚本化 provider 省略 `options.onPayload` 调用：快照依赖该钩子，不调则 `pao-context-usage` 永远为空。
- settings.json `extensions: []` 显式列出扩展：空数组按显式禁用处理，自动发现才是正确启用路径。
