# 专用记忆账本持久化 API

## 上游能力缺口

`SessionManager` 当前没有公开的“无对话落盘”入口。新会话的首次写入由私有 `_persist` 控制，并且只有出现 user 或 assistant 消息时才创建 JSONL；仅含 setup/custom entry 的后台账本会停留在内存。

## 影响

记忆后台账本只记录 attempt、usage、result、failure 等 custom entry，不应为了触发落盘而写入虚构 user 消息。若继续依赖旧行为，账本会混入不存在的对话事件，或者无法在重启后读取。

## 当前实现

`SessionManager.flush()` 作为最小公开入口，显式把当前 header 和 entries 写入持久化会话文件，不改变普通聊天的惰性建文件规则。专用记忆账本在取得稳定 S2 `jobId` 后调用它，并以每个 job 独立目录归属事件。

## 升级验证

上游若提供公开的 no-conversation persist API，验证 custom-only 账本能够直接创建、再次打开并读回全部事件，同时普通聊天在只有 setup entry 时仍不创建文件；满足后以该 API 替换 `flush()` 调用。
