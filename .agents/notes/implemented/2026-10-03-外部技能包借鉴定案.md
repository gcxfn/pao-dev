## 采纳清单（全部原生化）

### 第一梯队（随工作流引擎 v2 实施）

1. **判定包**（来源：superpowers 评审封装＋matt code-review 双轴）：部长三态判定的输入由机械打包成自足单文件——卡面＋git diff（基线真值）＋回执路径＋部门标准轴判据；**双轴取证**（忠于卡面 vs 符合部门工程标准）分开引用；**判据自足**（包内带全部判据，部长不自行查证）；**工具已强制的跳过**（lint/类型能拦的不重复判）；**两轴不合并不重排、不选跨轴冠军**——change/reject 理由必须标明失败轴（如「对题但不过部门标准→change」）；判定理由必须挂 file:line；**报告限幅 400 词**；回执算宣称不算证据（diff 才是证据）。
2. **重试分级**（来源：superpowers 修复循环）：change 回边重做——前 2 次原档重试，之后**升一档模型**再试（「轮数比单价贵」），到上限走已定案的超限动作（停滞/放行）。
3. **两段式对齐协议**（来源：matt grilling 前沿轮询＋superpowers brainstorming，两源合并）：接活先**三路分级并宣告**（探针＝可行性答案不留代码／小改＝聊天短设计点头即干／工程＝建工作流走规格），拿不准走重路、**棘轮单向**（中途变复杂只升不降）；**探索期一次一问**（问题随答案演化）＋**收敛期整轮确认**（编号列完＋每题附建议答案＋只问不依赖未答的前沿＋事实自己查决策才问人）；**写回理解**（事实与假设分离，纠完才动工）；配方落盘前**自检**（占位符/矛盾/范围/歧义）＋用户过目。落点：新建工作流主控对话＋主控接活纪律＋部长判定需澄清时。
4. **注入位次纪律**（来源：superpowers bootstrap 的位置智慧；2026-10-03 用户抓出实锤缓存 bug）：静态信息进系统提示段（字节不变→前缀缓存稳定）；**每轮变化的信息走 context 事件注入轮次消息**（历史尾部、标记串防重复、压缩后才重注一次）。**实施挂钩＝独立小改：`pao-auto-recall` 从系统提示段迁到消息层**（现状 resident.ts 每轮按检索词变、打掉其后全部历史的前缀缓存）。消费式段（fanout-done/workflow-review）事件轮才变、低频可接受不动。

### 第二梯队（部门体系小件，独立排期）

5. **术语表**（来源：matt GLOSSARY/domain-modeling）：部门知识库骨架加固定「术语表」区——术语＋定义＋_Avoid_ 禁用同义词；跨部门关系记导览；部长维护纪律＝用户用词与词表冲突当场指出、决议当场落盘、懒创建。降 token 降歧义，与「共享读不共享写」同构。

### 第三梯队（写作规范，纯文档零代码）

6. **触发条件式描述**：技能/配方 description 只写「何时用」，绝不概括流程（防模型抄捷径跳正文）。
7. **机械/判断分流**：摩擦项机械的→自动化检查（测试/钩子）；判断的→配方/标准；「没有 guardrail 的仓库本身就是 finding」。
8. **技能写作规范三补**：写完按四维自检（调用/内部结构/行为引导/范围组合——Matt Pocock 框架）；体量纪律（正文 <5k token、>100 行参考拆文件）；流程分级指引（引用第一梯队第 3 条三路分级，什么时候不该用工作流）。

3. **完工前并主干不搬**——同项目单写者现状无并发冲突；worktree 预案（§25）启用时再评估。
4. **ledger 流水账不搬**——卡文件＋用量账.jsonl 已是账本。
5. **人工门脚本向导不搬**——Windows 适配成本，现有确认语义够用。
6. **诊断流水线暂缓**（deferred）：「自动复盘糟糕会话」七步蓝图已记（受理逼成可诊断陈述→定位会话文件＋枚举子代理转录→七维并行分诊〔技能触发时序/是否按计划/重复劳动/卡壳/质量证据/需求冲突/成本时间〕→固定模板报告〔每个发现必须带 path:line 引文，数字必须来自转录〕→脱敏导出）；PAO 素材全有（会话 JSONL＋worker 证据＋用量账），等真实摩擦攒够与 M2-08 收敛一起排期。
