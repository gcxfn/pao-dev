# 受限子调用（轻派通道）留档不实施

- 日期：2026-10-02（深夜）
- 状态：用户拍板「留档」——记入设计备选，不实施、不排期

## 是什么

主控会话内嵌套调一次快档模型干**无产物的小执行活**（读、总结、变换），只把最终结果拿回主控上下文——没有卡、没有 worker 子进程、没有状态机。来源参照：[多模型协作探索（二）](https://gaoxiaodiao.github.io/p/exploring-multi-model-collaboration-part-2/)（同为 pi 生态，Splash 扩展：拆掉主会话 read/write 工具、经一个元工具全权委派本地快模型；贵模型判断＋快模型执行，成本约 1/4）。

「受限」四限：能力受限（最小工具集或零工具）、权限受限（非 worker 角色、无建卡/回执/改状态、无递归）、生命周期受限（活完即散不落状态）、上下文受限（只有结果回主控，中间过程不进主控对话）。

## 为什么现在不做

1. **第二委派通道风险**：PAO 唯一委派通道是卡协议（凡外派必有真相）；开轻通道必须配硬规则「轻通道只干无产物临时执行辅助，凡交东西/动文件/跨会话必须走卡」，否则模型会把正经任务往轻通道塞，审计穿底——正是「不造第二套任务真相」要防的。
2. **当前瓶颈不在委派延迟**：M2 剩余缺口是深度（在线宿主/巡库驱动/mnemosyne/大活/对照），不是速度。
3. ZCode 的后台子代理、文章的 Splash 都证明该形态可行，不需要先行验证。

## 触发条件（何时重启讨论）

- M2-07 对照实测显示「主控亲自读文件」类小活的 token 占比成为可见成本项；
- 或 worker 派发延迟在交互任务里被用户真实抱怨；
- 重启时按上述硬规则起草设计，先审后做。

## 同文附带收获（已另行采纳）

- 「判断贵＋执行快」4 倍成本降幅实证 → M2-07 对照的预期基线参照。
- 「断代优势」安全判据：判断方须碾压执行方，快档换太强（与主力差距缩小）会削验收把关可靠性——档位选型看差距不看绝对分。
