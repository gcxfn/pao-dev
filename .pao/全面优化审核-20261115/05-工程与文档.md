## E01 保存三个仓的未提交成果

**问题。** 2026-11-15 核实：开发根有 730 项未提交改动（分支 `main`），内核仓 103 项（分支 `pao-main`），桌面仓 25 项（分支 `main`）。这些是此前多轮工作的成果，只存在于工作区。此时开始新任务，新旧改动混在一起，出问题无法退回，也看不清每个任务到底改了什么。

**目标。** 三个仓各形成一个或几个提交作为基线。不推送。

**实施步骤：**
1. 三个仓分别执行 `git status --porcelain`，把结果按目录归类，写成一份清单（每类一行：目录、文件数、是什么）。
2. 逐类判断并标注：
   - **应提交**：源码、测试、计划文档、任务书、验收留档。
   - **不应提交**：E03 表里的残留文件（等用户决定）、临时运行目录、含凭证的文件、E02 提到的被测试改写的截图（先用 `git checkout -- <路径>` 还原这 7 张图是**撤销改动**，属于需授权操作，列入清单由用户决定）。
   - **拿不准**：单列出来问用户。
3. 把清单和拟定的提交划分（每个提交包含哪些目录、提交说明）交给用户确认。
4. 用户确认后，用 `git add <具体路径>` 逐类添加（**不用** `git add -A` 或 `git add .`），逐个提交。提交说明用中文，沿用仓里已有的 `类型(范围): 说明` 写法。
5. 提交前对暂存内容搜索常见凭证特征（`api_key`、`token`、`secret`、`Authorization`、`.env`、`auth.json`），有命中逐条核对。

**禁止：** 不推送；不改写历史；不用 `--no-verify` 跳过提交检查；不提交 E03 表里的文件。

**验收：**
- 三个仓 `git status --porcelain` 只剩清单里标为“不应提交”和“等用户决定”的条目，逐条能对上。
- `git log -5 --stat` 显示的提交内容与确认过的划分一致。
- 反面场景：从每个仓的新提交里各抽三个文件，用 `git show HEAD:<路径>` 与工作区文件比较，内容相同（证明提交的就是当前成果）。

## E04 清理外层仓的垃圾对象

**问题。** 开发根的 `.git/objects/` 里有 27 个 `tmp_obj_*` 文件，共 396.66 MiB（`git count-objects -vH` 的 `garbage` 与 `size-garbage` 两行）。这是 git 写入过程被中断留下的半成品，不属于任何提交，只占空间，并且每次相关命令都会打印一串警告。

**需用户授权：** 清理的是 `.git` 内部文件，不经过回收站。

**实施步骤（授权后）：**
1. 确认没有 git 进程在运行（任务管理器或 `Get-Process git`），并确认 E01 已完成。
2. 记录清理前的 `git count-objects -vH` 全部输出。
3. 执行 `git fsck --full`，确认现有提交完好；有错误则停下回报，不继续。
4. 执行 `git prune --expire=now`。它只删除不被任何提交引用的对象和过期的临时文件。
5. 再次执行 `git count-objects -vH` 与 `git fsck --full`。

**禁止：** 不手工删除 `.git` 里的文件；不执行 `git gc --aggressive`；不对内核仓和桌面仓做同样操作（未发现垃圾对象）。

**验收：** `garbage: 0`；`git fsck --full` 无错误；`git log -3` 与清理前一致；`git status` 的条目数与清理前一致。
