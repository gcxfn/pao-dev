# 04 大文件拆分

核实日期：2026-11-15。先读[总览与通用规则](00-总览与通用规则.md)。

拆分的目的：单个文件几千行时，改一处要读很多无关代码，也容易多人同时改同一个文件。本分册只做**搬移**，不改任何行为。

界面组件与样式的拆分已写在[界面改版](03-界面改版.md)的 U14、U24，这里不重复。记忆与自进化目录（内核 `memory/`、`evolution/`、`desktop/memory.ts`）属于另一份任务书的在途范围，本批不拆。

## 0. 纯搬移规则（本分册与 U14、U24 共用）

1. **只搬不改。** 函数体、类型定义、注释原样剪切到新文件。不改名、不调整参数、不“顺手优化”、不重排函数内部顺序。唯一允许的改动是：补 `import`、补 `export`、原文件加重新导出。
2. **导出路径不变。** 原文件里被外部使用的名字，搬走后必须在原文件用 `export * from "./新文件"` 或具名重新导出继续提供。任何现有 `import` 语句都不需要修改；需要改调用方才能编译时，说明切分线选错了，停下回报。
3. **一次搬一块。** 每个任务按表里的顺序逐块搬，每搬完一块就跑一次类型检查，通过后再搬下一块。
4. **类的私有成员不跨文件。** 用 `#name` 或 `private` 声明的字段和方法不能从别的文件访问。任务表里标“不动”的部分就是因为这个原因，不要尝试把它们改成公开来搬走。
5. **搬移前先搜索被搬的名字。** 在三个仓里全文搜索每个要搬的导出名，确认引用方都经由原文件路径导入。测试文件直接导入的名字尤其要保留重新导出。
6. **内核仓的额外要求。** 相对导入必须带 `.ts` 后缀；`worker/` 与 `fanout/` 目录下的文件不得导入 `workflow/` 目录（包括只导入类型）。搬完跑 `npm run check:gates`。
7. **桌面仓的额外要求。** 搬完跑 `pnpm check:architecture`。新文件放在与原文件相同的目录层级，目录边界检查会自动覆盖。
8. **不改测试。** 纯搬移不应导致任何测试改动。测试失败说明搬的过程中改了行为。

**通用验收（每个 S 任务都适用）：**
- 所在仓的基础检查通过，任务列出的回归测试在搬移前后各跑一次、结果相同。
- 回报里给出：每个新文件的行数、原文件搬移后的行数、抽查的三个函数“搬移前后函数体逐字相同”的证据（例如把两段文本各存成临时文件后比较，或贴出 `git diff --color-moved=zebra` 里显示为“移动”的摘要）。
- 在三个仓里搜索原文件路径的 `import`：没有任何一条被修改。

## 内核第二批（S09—S14）共用的两条注意

1. **测试会替换被调用的函数。** 有的测试用“打桩”（把某个模块导出的函数临时换成假的）来模拟故障，例如替换 `cards/process.ts` 的 `runCardProcess`、`node:fs` 的 `readdirSync`。打桩只对“每次调用时按名字去取”的写法有效。所以新文件必须**照抄原文件的 `import` 写法**（原来是 `import { runCardProcess } from "./process.ts"` 就原样写），不得改成先存到一个变量里再用。
