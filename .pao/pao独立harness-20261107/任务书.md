## 0. 背景与目标

pao 是 pi 的 fork，但当前仍共用 pi 的运行身份：
- 用户配置目录 `~/.pi/agent/`（会话、认证、models.json、settings.json 全在这里）
- 项目级配置目录 `<项目>/.pi/`（项目 settings、skills、prompts、extensions、mcp.json）
- npm 包名 `@earendil-works/pi-*`、desktop 自有包 `@pi-gui/*`
- HTTP User-Agent `pi/{version}`
- CLI 同时暴露 `pi` 和 `pao` 两个命令

结果：pao 和上游 pi 看到同一批会话、同一份认证——"被识别为 pi"。

目标：把 pao 改成独立 harness，与 pi 完全分家。**不迁移旧数据**——`~/.pi` 原样保留给上游 pi 用，pao 从空的 `~/.pao` 重新开始。

## 1. 已批准决策

| 决策 | 结论 |
|---|---|
| 迁移旧 `~/.pi` 数据 | 不迁移，pao 从空目录起步 |
| pao 与 pi 互见会话 | 不能，完全隔离 |
| 内核包名前缀 | `@pao/*`，去掉 `pi-` |
| desktop 自有包前缀 | `@pao/*` 统一（与内核同 scope） |
| `pi` CLI 命令 | 移除，只留 `pao` |

## 7. 风险与注意

- **会话隔离即丢历史**：改完后用户第一次跑 pao 看不到任何旧会话、要重新登录、重新配 models.json——这是已批准的预期行为，报告里要提醒。
- **项目 `.pi/` → `.pao/`**：目标项目里若有 `.pi/settings.json`、`.pi/skills/` 等资源，pao 不再读取，需手动挪到 `.pao/`。pao-dev 根下无 `.pi` 目录（已核实），desktop 仓也干净。
- **lockfile 重建**：包名变了所有内部依赖的 lockfile 条目都要重新生成，不能手改 lockfile。
- **`piConfig` 字段名**：`package.json` 里的 `piConfig` 键名是 config.ts 读取的契约，键名本身不改（改 `configDir` 值即可）；改名属于 config.ts 代码变更，不在本批。
- **test fixture**：`.pi` 出现在测试 fixture 里多为语义化测试值，逐个看意图再改，不全局替换。
