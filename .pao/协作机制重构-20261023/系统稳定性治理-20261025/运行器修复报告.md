## 实际改动

### 准备入口

新增 `prepare_run.py`，只在明确独立的新目录中组装一次运行：

- 暂存目录按最终 `run` 路径写入配置中的 `configuration_root`、源码归档、离线件、模型元数据和 `jobs_dir`，不把 temporary 路径写入最终配置。
- 校验最终容器路径能映射到当前暂存文件，再完成 rename；rename 后再次使用 `bench_controller.validate` 校验最终目录。
- 逐项校验冻结原题集合与摘要、任务范围、配置来源摘要、模型元数据、冻结件摘要、一次串行执行和零自动重试。
- 当前适配器、组织配置、SDK 宿主、控制器与模型元数据一起复制并记录来源和最终摘要；没有动态 import `dispatch-r4`，也没有源码字符串替换。
- 选定外部模型与内部运行别名明确分开：外部 `openai/minimax-code/MiniMax-M3.1-Flash` 映射到已注册路由 `harbor-endpoint/minimax-code/MiniMax-M3.1-Flash`；原 `openai` provider 不被凭空注册。
- 部门配方追加的模型文字只作说明。实际主控、部长、工人模型来自同一个 `role-model-binding.json`，并通过 agent 配置、workflow 节点和 setup 契约核对。
- `main()` 使用已导入的 `json` 输出结果，消除 API 成功但 CLI 末尾 `NameError` 的入口缺陷。
- 来源清单可选提供 `extra_docker_compose_source` 与 `extra_docker_compose_sha256`；准备时校验并复制为 `network-override.yaml`，把最终容器路径写成单元素列表 `[.../network-override.yaml]`，匹配 Harbor `base.py` 对 `Sequence` 的逐项读取契约。来源摘要与配置路径同时进入 run-freeze 和来源记录。该字段可缺省，本入口不创建或修改 Docker 网络。

### 启动入口

新增 `launch_run.py`，复用现有控制器镜像、挂载、环境变量与 Docker 启动命令。启动前检查运行冻结、授权文件、模型、思考强度、一次执行、零重试和启动标记。已有 `control-started.json` 时在 Docker 调用前拒绝重放。凭证只从现有 `PAO_BENCH_API_KEY` 环境变量检查，不读取、记录或输出其值。

指定上一轮时，同时读取 `terminal-receipt.json` 和 `runtime-containers.json`，要求 `writers_stopped_observed=true`，再逐个查询上一轮记录容器，尚未停止则不启动。

启动命令保留两条独立挂载：宿主 `D:/AI/workspace` 固定挂到 `/mnt/d/AI/workspace`，供现有 Linux Python 使用；配置中的 `local_root` 挂到本轮 `container_root`，供最终运行目录、源码归档与离线件使用。不会再用 `pao-dev` 冒充包含解释器的宿主工作区。

本轮没有执行真实启动。

### 观察入口

新增 `watch_run.py`，按本轮控制器名、预检/正式试次 Compose 项目、子项目和 `pao-score-<runsha>` 发现容器：

- 控制器、评分和工作流容器分别记录角色；容器存活与业务状态分栏保存。
- 继续读取 `control-status.json` 与 `mechanism-progress.json` 的正本，不在观察器建立状态机或成功账本。
- 控制器退出但其他本轮容器仍可能写入时继续采样，不签发 `controller-exit.json`。
- 只有控制器停止、`control-status.json` 明确停写、本轮实际发现的全部容器停止时，才写终局回执。
- Docker 查询失败写 `watch-error.json`，保留异常类型、原文、traceback 后重新抛出；观察超时留可处理错误，不无限安静循环，也不自动清理、停止或强杀容器。
- 按 r12 和 r10 实际公开结果结构读取 `jobs/*task-*/*/result.json` 的 `verifier_result`、`exception_info` 和 `agent_result`。r10 的奖励字段位于 result 顶层的 `verifier_result.rewards.reward`；真实 `0.0` 保留，缺失保持 `null`。
- 终局回执写 `writers_stopped_observed=true`，与启动入口的上一轮停写核查字段前后衔接。
- 预检失败允许在没有正式 `result.json` 时结束采样：`control-status.json` 的 `failed`、原始错误与 `writers_stopped=false` 原样保留，观察回执另记实际停写、业务失败、预检异常、正式结果是否出现和评分是否运行。此时 `official_rewards=[]`、`scoring=not_run`，不填 0。控制器或任一已识别的本轮容器仍活着、容器身份重复或 Docker 查询失败时，不签发实际停写。

### 适配器

`setup.mjs` 增加真实路由与三角色契约：运行 provider 必须是 `harbor-endpoint`，运行别名必须是注册 provider 加内部 model id，外部选定模型必须携带相同 model id。主控、部长、工人档位及流水线节点都由同一个 binding 派生并在建组时校验。

`organized-post/manifest.json` 当前逐项摘要以实际来源为准。`kit.json`、`setup.mjs`、`activate-tools.mjs` 和 `probe-tools.mjs` 均与实际文件一致；`map_bench_pao_organized.py` 记录的是准备入口最终使用的 SDK 适配器 `63df7ca4...`，而不是 benchmark 根目录旧文件 `2f79277f...`。`created_at` 保留原值，它本身不证明清单陈旧。`benchmark-host-factories.mjs` 继续使用主控加入的公共 `processInvocation`，部长保留显式 30 分钟预算；该文件由主控维护，本代理未修改。
