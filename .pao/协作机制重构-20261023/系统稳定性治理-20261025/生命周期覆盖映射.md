## 证据等级

| 标记 | 含义 |
|---|---|
| 实际通过 | 当前记录中有明确退出码和断言结果；只对当时源码、测试与环境有效 |
| 实际失败 | 当前记录明确失败，不能计入通过 |
| 模拟通过 | 使用固定模型回应、注入错误或模拟 Docker 输出；证明程序衔接，不证明真实模型或真实环境 |
| 源码覆盖、结果未验 | 仓库有对应测试或实现，但本轮没有找到可核对的运行结果；不能写成已通过 |
| 未验 | 本轮没有对应真实运行证据，不能由相近测试、文件名或静态审查代替 |

这里“真实”只表示真实临时文件、Git、锁或子进程/RPC 边界，不表示真实模型。`workflow-*-real.test.ts`、`host-rpc-background-real.test.ts` 和 `*managed-real.test.ts` 中的模型回应均为固定替身；它们不能证明真实模型会选择正确工具。

## 覆盖缺口与现有验证限制

- 已有真实 RPC、文件锁、worker 子进程和 Docker 观察器证据，但没有真实在途桌面/CLI 关闭证据，计划 §5 的必要真实宿主验证尚未完成。
- 内核、SDK、退出协调测试覆盖失败不伪成功、其他会话继续处理、失败可重试等程序语义；不能替代真实 Electron/CLI 在途任务。
- r14 的观察器失败收尾是本轮真实证据，但模型、官方评分和费用未发生。r15 目前只证明凭证环境到达容器及预检中，不能记模型成功。
- 四部门测试使用固定模型回应，每场景单独运行；不能拼成一次真实模型全链通过。
- `parent-lifecycle.test.ts`、`worker-sdk-entry.test.ts` 的源码存在不等于本轮运行通过；没有结果时保持未验。
- 工作树原始字节与恢复边界有测试，但不能代替旧进程仍存活时的执行互斥和停写证据。
- 本文件没有运行任何测试；所有“通过”均引用已有记录，不能据此重新签发当前源码的最终验收。
