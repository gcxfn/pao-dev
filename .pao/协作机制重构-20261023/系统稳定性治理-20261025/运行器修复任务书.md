# 工作包 H：集中治理运行器任务书

记录时间：2026-10-25

## 目标

把每次真实运行都复制并修改 prepare/launch/watch 脚本的做法，收拢到 benchmark 开发目录中的三个共享入口。新入口只负责明确准备、受控启动和持续观察，复用 `bench_controller.py` 已有的冻结校验、Compose 项目命名、结果分类和评分语义。

本包解决四类问题：

1. 运行目录中的源码、适配器、SDK 宿主和离线件可能来自不同轮次，形成混合版本。
2. 模型配置、角色配置和适配器元数据可能指向不同模型。
3. 观察器把容器存活、业务推进和错误混在一起，或过早结束采样。
4. 控制器退出但子容器仍在运行时，可能被误报为已经停写和完整收尾。

本包不新增状态机、任务账本、通用调度框架或第二套成功判定。`control-status.json`、`mechanism-progress.json`、`run-freeze.json` 和原版评分结果继续分别作为各自事实的正本。

## 实施边界

### 准备

- 新入口接收一个尚不存在的新运行目录、运行配置和机器可读来源清单。
- 来源明确区分：
  - 历史冻结原题、官方测试和离线安装件；
  - 当前 PAO 开发源码；
  - 当前 benchmark 适配器；
  - 当前 SDK 宿主。
- 准备时逐项校验来源、摘要、任务范围、模型范围、思考强度、零自动重试和目录边界。
- 当前源码使用 Git 的 tracked 加未忽略 untracked 文件打包，并排除凭证、构建产物、缓存和无关数据目录。
- 模型元数据只从本包维护的可信配置中按完整选定模型名读取；适配器不再保留 DeepSeek 默认元数据。
- 准备阶段只做本地文件、配置和冻结校验，不调用 Docker、模型、服务或正式 `PAO_HOME`。
- 来源清单可选提供 `extra_docker_compose_source` 与 `extra_docker_compose_sha256`。准备时校验来源摘要，复制到本轮 `network-override.yaml`，以单元素路径列表写入 Harbor 现有的 `environment.kwargs.extra_docker_compose`，并纳入冻结和来源记录。Harbor `base.py` 按 `Sequence` 逐项迭代，单字符串会被当作字符序列，因此本入口只接受列表配置。该字段可缺省；本入口不创建 Docker 网络，也不修改原题、测试或全局配置。

### 启动

- 启动入口单独存在，先校验本轮冻结、已有授权文件、配置范围和单次启动标记。
- 指定上一轮时，必须同时读取其 `terminal-receipt.json` 和 `runtime-containers.json`，再通过 Docker 查询确认每个记录容器实际停止；只凭回执不通过。
- 已有 `control-started.json` 时拒绝再次启动，也不调用 Docker。
- 凭证只使用现有 `PAO_BENCH_API_KEY` 环境变量。启动入口不读取、记录或输出用户全局模型配置与凭证。
- 保留现有 Docker 控制器镜像、挂载、环境变量和控制器命令语义。本包不执行真实启动。

### 观察

- 按本轮控制器名、预检/正式/评分 Compose 项目和本轮评分容器名发现资源，不按模糊全局名称猜测。
- 容器状态与业务状态分别记录。容器存活不等于业务正在推进，业务静默也不直接判定失败。
- `control-status.json` 继续表示控制器状态；`mechanism-progress.json` 继续表示业务身份、阻塞和进展。
- Docker 查询或容器检查失败时写 `watch-error.json`，保留异常类型、原文和 traceback，并继续抛出原异常。
- 控制器退出后若预检、正式、评分或其他本轮容器仍可能写入，观察器继续采样，不写成功收尾。
- 正常完成时，只有控制器已退出、`control-status.json` 明确 `writers_stopped=true`，并且本轮实际发现的全部容器都已停止时，才写 `terminal-receipt.json` 和 `controller-exit.json`。
- 预检失败、正式模型没有启动且没有正式结果时，若控制器和全部已识别的本轮容器都已实际停止，可另记实际停写并写 `terminal-receipt.json` 和 `controller-exit.json` 让采样结束。`control-status.json` 的 `failed`、原始错误和 `writers_stopped=false` 原样保留；回执明确评分未运行，不得填 0。控制器或任一容器仍活、身份重复或 Docker 查询失败时不能签发。
- 观察有明确最大时长；到期仍不能确认时留下可处理错误，不无限安静循环，也不自动清理、停止或强杀容器。
- 缺失评分保持 `null`；真实数值 `0.0` 原样保留。

## 验收矩阵

| 场景 | 期望 |
|---|---|
| 当前适配器与历史冻结适配器内容不同 | 新运行明确选择当前来源，并记录当前摘要 |
| 选定 MiniMax、元数据为 DeepSeek 或其他模型 | 准备失败，不生成可启动运行 |
| 原题与官方测试准备前后 | 来源文件集合和摘要不变 |
| 多题、错误模型、非 high、重试、非独立目录 | 准备或启动前拒绝 |
| 预检容器使用独立 Compose 项目 | 观察器按本轮配置发现并记录 |
| 控制器退出但子容器仍活 | 继续采样，不写 `controller-exit.json`，不宣称停写 |
| Docker 查询失败 | `watch-error.json` 保留原异常并重新抛出 |
| 真实奖励 `0.0` 与缺失奖励 | 分别保留为 `0.0` 和 `null`，分类不混同 |
| 已存在 `control-started.json` | 启动入口拒绝重放，Docker 调用次数为零 |
| 预检失败、无正式结果，控制器与全部本轮容器已退出 | 原业务失败和 `writers_stopped=false` 保留；另记实际停写、评分未运行并结束采样 |
| 预检失败，但本轮子容器仍活 | 不写终局回执或 `controller-exit.json`，继续观察 |
| 可选网络覆写来源与摘要 | 校验并复制为 `network-override.yaml`，配置、冻结与来源记录使用同一最终路径；来源缺失时不写入 |
| 网络覆写摘要错误 | 准备失败，不发布可启动运行目录 |
| 无正式结果且模型启动状态未知 | 评分记为 `missing_or_not_run`，不断言评分或模型未运行 |

离线测试使用真实临时文件、Git 来源差异和模拟 Docker 文本输出；它证明程序接线和边界，不证明真实 Harbor、真实模型或真实供应商行为。
