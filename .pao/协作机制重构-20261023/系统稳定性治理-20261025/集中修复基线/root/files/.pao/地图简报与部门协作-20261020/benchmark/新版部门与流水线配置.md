# 新版部门与流水线配置

更新日期：2026-10-21。用户要求新版 PAO 在测试前建立部门和流水线；新版三题当时均未启动。本次只调整新版组，保留单代理、旧版组和既有结果，不增加题目或重试。

| 部门 | 职责与交付 | 执行边界 |
|---|---|---|
| 侦察 | 找到相关代码入口、路径、接口、验证入口和未知项，摘要写入真实流程实例 | 只读，不修改代码、不派工 |
| 规划 | 根据侦察摘要制定修改范围、实施步骤和验证方案 | 只读，不重复全仓调查 |
| 实施 | 根据计划提交工作卡，由工人修改代码、自测并交付 | 部长拆解与整合，实际编码由工人执行 |
| 审核 | 独立核对实际改动和运行证据，引用真实文件与行号提交判定 | 不修改实现、不把执行者总结当证据 |

流水线使用现有 v2 部门工作流，自动执行，依赖为“侦察 → 规划 → 实施 → 审核”。不设置人工确认门、自动回边或额外重试。当前 CLI 没有安装独立工作目录宿主，工人并发设为 1，因此本轮不能证明独立工作树并行收益。

每题在独立容器、隔离 PAO_HOME 内初始化相同组织。注册部门使用现有 `createDept` 接口，保存流水线使用现有 `saveRecipe` 接口。业务源码与源码 ZIP 摘要不变。主控、部长和工人继续使用同一 `group/deepseek` / high，不设 token 或费用上限，官方时限和验收器不变。组织配置不含题目解法、隐藏测试或前几次试验结果。

为让运行明确遵守部门分工，本轮增加通用调度指令：主控启动预置流水线、传递原始任务、处理阻塞和最终报告；不能绕过部门直接编码。组织扩展只通过现有接口启用角色已注册的工具，不为 worker 增加再派发权限。配置清单见 [manifest](organized-post/manifest.json)，具体配方见 [kit.json](organized-post/kit.json)，实际任务配置见 [organized-post-config.json](real-run-20261021/organized-post-config.json)。

Linux 实际建部、部门配置校验及流水线解析已通过；真实 SDK 的主控、部长、worker 工具装载也通过。部长装载检查使用模拟身份，不启动 RPC 或模型，不能替代真实部门协作。预检没有增加模型调用，证据见 [准备放行记录](real-run-20261021/organized-post-ready.json)。

正式题目将保留组织配置、工具启用记录、流程实例、部长会话、工作卡及工人回执。适配器在模型结束后核对流程实例确实存在；未实际启动流水线会明确报错。流程启动、流程完成和官方题目验收通过是三件事，须分别核查。

后台旧控制器在新版空配置入口被明确门禁阻止，旧版正在执行的题目继续。独立观察脚本在确认旧版两道接续题均终结后，自动启动已校验的新版三题；异常会保留现场，不自动重跑。当前进度与最终结果见 [九项对比自动汇总](real-run-20261021/九项对比自动汇总.md)。

新版现在额外增加部门配置、流程和明确调度指令，与旧版干净配置存在差异。比较反映“修复后 PAO 加组织流程”的整体表现，不能把差异全部归因于代码修复。全部角色费用仍未知；用量在覆盖未核实前仅报告已观察下界。
