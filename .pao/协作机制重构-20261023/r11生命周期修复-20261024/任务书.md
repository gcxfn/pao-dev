# r11 生命周期修复任务书

## 目标

修复 print 模式在后台工作收敛后、最终销毁前仍可受理新通知的竞态。最终关闭按以下顺序执行：

1. 先封闭新轮次和新的会触发轮次的消息。
2. 等待关闭门前已受理的轮次与 settled 后续动作收敛。
3. 再发送 `session_shutdown`。
4. 最后释放后台端口、使扩展上下文失效并销毁会话。

关闭门之前已受理的活动必须正常完成；关闭门之后晚到的事件必须拒绝，不能借旧扩展上下文继续执行。

主控复核后的返修边界：正常 print 先显式关闭并排空已受理工作；所有主动会话销毁必须保留原有取消语义，依次封闭接收、abort、等待收敛、shutdown。slash 输入必须在第一次异步等待前完成“是否真实扩展命令”的同步判定，避免未知命令和 skill 路由在关闭或销毁后继续执行；真实扩展命令仍按现有会话替换路径执行。

## 范围

- print 模式生命周期。
- `AgentSessionRuntime` 与会话的必要关闭接入。
- 现有 `background-work` 接口及 PAO 后台适配，仅在确有需要时调整。
- worker 通知面仅在确有需要时调整。
- 覆盖上述行为的定向、无模型真实事件测试。

不修改 intake、host、tools、workflow、minister、worker/index 与 `pao/index`，不操作 r11 冻结现场、历史容器、正式 `PAO_HOME` 或用户主目录。

## 基线

修改前九个相关文件已保存到 `baseline/`，路径与 SHA-256 位于 `baseline.sha256`。仓库已有大量其他未提交改动，本轮只保留这些文件相对基线的增量。

## 设计约束

- 复用现有生命周期接口，不建立通用生命周期框架。
- 不新增权限边界或违规终止机制。
- 不使用额外 sleep、轮询、吞通知或强制 `process.exit` 掩盖竞态。
- 保留身份、取消、后台通知、交互模式和 RPC 会话替换语义。
- 必须区分关闭前已受理的结果与销毁后晚到的事件。
- 不改变 SIGTERM、SIGHUP、交互 shutdown 和 RPC 会话替换对运行中模型的取消语义。

## 验证

只运行必要的定向测试和受影响文件的类型/格式检查。测试使用 faux provider 或纯事件夹具，不使用网络、付费模型、官方测试或全库检查。

本修复能确认并消除源码中的关闭窗口缺陷；r11 的真实退出因果仍需现场证据闭环，不能由本修复反推为已确认。
