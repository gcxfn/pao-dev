## 逐项复核

### R1 清单与快照一致（P1，I4）→ 已修

`createMemoryBackup` 改为：`VACUUM INTO` 生成快照后，用 `new DatabaseSync(snapshotPath,{readOnly:true})` 打开快照文件，**从中**读 `archive_segments`、`artifact_versions`（kind='managed'）、counts（backup.ts:218-247）。清单、成果、计数全部与快照同一时刻，不再回活动库分次拼。I4 并发登记场景下新段进快照即进 manifest 一并复制。复验：清单来源确实是 `snapshotDb` 而非 `store.db`。

### R2 共享保留来源索引不丢（P2，I1）→ 已修

`purgeExcludedContent` 来源清理段（backup.ts:578-585）：新增 `sourceStillLinked` 预检（`SELECT 1 FROM memory_source_links WHERE source_id=?`），仍有引用则 **continue 跳过**——行留、source_fts 也留。与 `deleteSource` 的 `NOT EXISTS remaining links` 守卫同口径。共享保留来源（仍被存活记忆引用）行在索引在，独占来源照常清。复验：判定顺序正确——先预检引用再决定是否删 fts+行，不再无条件先删 fts。

### R3 缺失副本解除旧 home 路径（P2，I2/I3）→ 已修

- `relocateArchiveSegments`（backup.ts:618-635）：空 `backupPath` 或备份文件缺失的段，跑 `clearPaths`（`original_path/compressed_path` 双置 NULL），不再 continue 跳过。readSourceEvents 如实 `source_missing`，不回读旧 home。
- `restoreManagedArtifacts`（backup.ts:653-684）：改为遍历**恢复库内全部** `kind='managed'` 版本（不只 manifest 登记项）。manifest 未登记（旧版 manifest 无 artifacts 字段）或副本缺失的，`location.dir` 重写到目标 home 预期位置；文件不存在时 `resolveArtifactVersion` 走 `existsSync` 返回 `available:false`。不留旧 home 绝对路径作隐式回读源。

### sha256 优化 → 已做

删 `sha256File` 与 `createHash` import；`BackupSegmentEntry.sha256`/`BackupArtifactFileEntry.sha256` 字段保留（manifest 公共形状不变）但不再计算不再填。去掉了无消费方的整文件重读。
