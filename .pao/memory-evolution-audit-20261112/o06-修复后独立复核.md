# 三轮复核（D7：running 期间登记丢失）

二轮通过后审核方补 D7 复现：同 scopeKey job running 时再次 enqueue，旧 handler 返回 done 后 `completeJob` 置终态，drain 尾部扫描时 `claimJob` 拒领 done，运行期间登记的新工作被吞。我亲自复跑确认 D7 单独失败、D1—D6 通过。

**修复 R5**（亲自实施，`maintenance.ts`）：

- 新增 `enqueueWhileRunning: Set<string>`——enqueue 命中 `status==='running'` 的同 scopeKey job 时登记标记；
- `runJob` done 分支：`enqueueWhileRunning.delete(scopeKey)` 命中 → 已存游标 + `releaseJob` 放回 pending（不 `completeJob`），drain 尾部续轮 `claimJob` 领到 pending 续跑；
- 每批 handler 调用前 `enqueueWhileRunning.delete(scopeKey)` 清上批残留标记，防误触发；
- unmount 清理该集合。

不改 `mergeMemories` 契约、不动 extract 幂等、不提前解除 running job 所有权——只在 handler 结束后判定归属。

# 四轮复核（D8：跨实例登记丢失）

三轮后审核方补 D8 复现：同 PAO_HOME 下 A 实例 running、B 实例 enqueue，内存 `enqueueWhileRunning` 只存在 B 内存，A 批末查自己的 Set 无标记→置 done，跨实例登记仍丢失。我亲自复跑确认 D8 单独失败、D1—D7 通过。

**根因**：续跑标志是单实例内存 Set，跨实例/跨进程登记不可见。审核要求「续跑状态归属共享维护作业」。

**修复 R5-D8**（亲自实施）：

1. **共享标志落库**（`store.ts` schema）：新表 `maintenance_pending_rerun(scope_key PRIMARY KEY, marked_at)`——CREATE IF NOT EXISTS 兼容老库。
2. **共享标志读写**（`extraction-jobs.ts`）：`markMaintenanceRerun`（INSERT OR REPLACE 幂等写标志）；`consumeMaintenanceRerun`（DELETE 原子消费，changes>0 命中，无双消费窗口）。
3. **enqueue**（`maintenance.ts`）：running 时改调 `markMaintenanceRerun` 落库（替换内存 Set），任何实例/进程写同一行。
4. **runJob done 分支**：`consumeMaintenanceRerun(scopeKey)` 命中 → `releaseJob` 放回 pending 续跑（不 `completeJob`）；每批 handler 前的内存清标记已随 Set 一并移除（共享标志一次性消费，天然只生效一次）。
5. **drainQueue 尾部**（`maintenance.ts`）：原 `pendingScopes.size===0 → return` 只看本实例内存，改为回到头部重扫——头部统一取「pendingScopes ∪ 库内 pending（`job_kind != 'extract'`）」并集，库内 releaseJob 放回的续跑项被下轮捞起，两者皆空才退出。

不改 `mergeMemories` 契约、不动 extract 幂等（标志表只被维护类读写、drain SQL 限 `job_kind != 'extract'`）、不提前解除 running 所有权。

# 五轮复核（D9：批末事务非原子）

四轮后审核方补 D9 复现真竞态：`consumeMaintenanceRerun`（删标志）与 `completeJob`（置 done）是**两个独立事务**——consume 返回 false 提交后、completeJob 前，B enqueue 写标志→completeJob 置 done→标志残留但 job 已 done 无人能消费，跨进程登记仍丢。登记端 `createJob`→`reopen`/`mark` 同样分两个事务。我亲自复跑确认 D9 单独失败、D1—D8 通过。

**根因**：「读状态→写动作」和「存游标→消费标志→置终态」分散在多事务，交错窗口丢工作。审核明确要求两处各收成单事务。

**修复 R5-D9**（亲自实施，`extraction-jobs.ts` 两个新原子函数 + `maintenance.ts` 接入）：

1. **`enqueueMaintenanceJob`**（登记端单事务）：同事务内「确保 job 行存在（scopeKey 幂等建/读）→ 读真实状态 → done/failed 复活 pending（限 `job_kind != 'extract'`）/ running 写共享标志 / pending 不动」。替换原 `createJob`+`reopenMaintenanceTerminalJob`/`markMaintenanceRerun` 三步。
2. **`finishMaintenanceBatch`**（批末端单事务）：同事务内「存本批游标（清 consecutive_failures）→ DELETE 消费共享标志 → 据命中写 pending（清 owner）或 done（保留 owner 归属审计）」。替换原 `advanceCursor`+`consumeMaintenanceRerun`+`completeJob`/`releaseJob` 三步。
3. **`maintenance.ts` 接入**：enqueue 改调 `enqueueMaintenanceJob`；runJob done 分支改调 `finishMaintenanceBatch`；未完成分支保留 `advanceCursor`+`releaseJob`（未完成不消费标志）。删除死代码 `reopenMaintenanceTerminalJob`/`markMaintenanceRerun`/`consumeMaintenanceRerun`。
4. **owner 字段修正**：初版把 done 也清 owner，回退了 S7-03「done 保留 owner_process/owner_token 供回读」断言——改为 pending 清 owner、done 保留。

不改 `mergeMemories` 契约、不动 extract 幂等（复活 SQL 限 `job_kind != 'extract'`）、不提前解除 running 所有权（标志只在批末单事务消费）。
