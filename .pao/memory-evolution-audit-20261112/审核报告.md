# 持久记忆与自进化审核报告

核实日期：2026-11-15。范围：O01—O15 对应需求、共享内核、CLI/worker/桌面装配及现有验收证据。代码基线见 [baseline.json](evidence/final-audit/baseline.json)，包含相关未提交实现。原 135 项任务的覆盖索引见[需求覆盖](需求覆盖.md)。

## 结论

**O 系列不能整体关闭。持久记忆的确认、纠正、召回和项目接续已有有效实现；成果跨任务实际执行已补证；自动技能进化与当前发行物仍未达到既定交付要求。**

当前必须处理的是行为验收、真实使用与回退、模型请求归属、附件生命周期以及发行包同步。把会话结束视为验收通过、把绑定视为使用、把包内 API 读库视为真实宿主恢复，会使完成状态高于实际能力。

确认/纠正、当前修订与范围筛选、接续完成及详情接线未发现新增独立缺陷。请求结算、来源归档、后台唤醒、维护重建、成果归因及自进化有本轮确认的整合缺口；其当前状态和后续修复只在[优化任务](优化任务.md)维护。历史组件测试结果仍有效，不能替代缺失的产品行为。

## 4. 已落实的优化与有效结果

- 旧备份清单未登记的受管成果计入缺失提示；备份套件 12/12 通过。
- 同段批读复用一次解析，三事件/三来源由 9 次 JSON.parse 降至 3 次，读盘仍为一次；来源套件 10/10、相关定向检查 2/2 通过，窗口及错误语义保持一致。
- 成果登记使用规范任务身份，避免不同项目同号卡共用登记键；登记与实际执行定向验证 8/8 通过，交卷继续按确切提交版本区分。
- 提炼调度测试的采集项目与被测记忆/job 身份对齐，保持原断言和等待时间；原套件 10/10 通过，原四项失败归属夹具。

Git 与受管目录两路都通过真实工具生成、登记固定版本，另一任务确切回读并执行 node，输入 11、实际输出为 {"input":11,"answer":80}、退出码 0，再提交结果文件和卡回执。执行前工作树已换成必抛错脚本，证明读取的是登记版本。详情见[宿主审核](evidence/final-audit/final-hosts-audit.md)。这支持离线工具边界的实际成果复用，不替代模型自主决策或 Electron 端到端行为。

既有 O15 模型调用证明了预置历史可被模型使用、真实模型能生成两轮 diff。技能文件文本变化、指向变化与实际任务行为改善分开验收，详见 [O15 证据边界](o15-验收报告.md)。

## 5. 验证与已知限制

本轮使用隔离 PAO_HOME，未访问正式运行现场，未新增付费请求，未运行全量测试或构建。新增修改仅限来源批读、备份缺失提示、成果登记身份及对应测试夹具；具体路径和检查结果见三个分报告。

进化五个探针命中了实际业务缺陷：它们断言缺陷存在，绿色表示复现成功。模型输出与命令退出码为注入值，冻结、物化、回执、评估、发布、激活和回退使用真实业务实现。记忆缺陷探针按正确行为断言，未修复项保持失败，不能合并成“全绿”统计。

实际发行包运行使用 Electron 37.10.3 / Node 22.21.1，加载包内 dist 并真实调用备份；它证明当前包确有运行故障，不否定 O07 新源码已有的 Electron 成功证据。发行包不得手工改生成文件，须经现有 vendor/构建/打包入口同步后定向复验。

尚未完成：修复后的真实 provider 技能行为验收、实际 worker 子进程清单验证、当前源码桌面忙中换版/退出重启、脱离开发仓发行测试及持续使用收益。FE5/FE6 为静态请求接线问题，未据此声称发生了实际收费或外发。成本以实际 token 用量为准；现有金额预算须按 AF05 接入 token 额度。未核验 magpie 单价不影响已记录 token 用量的已知性。

既有全量记录 3718/3828 通过、100 失败缺少完整逐项留档；不能认定为 100 个产品缺陷，也不能用于证明全量通过。已定位的 scheduler 四项夹具问题单独处理，其他失败仅保留证据边界，不以盲目重跑全目录代替归因。
