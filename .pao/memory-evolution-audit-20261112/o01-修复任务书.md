## 总原则

- **预算判据改绑每次实际请求的 requestId**。之前 attemptKey 用「来源 ID / 候选序位」做语义键——同一来源重试、no_change、解析失败都会复用同一条预留并被覆盖结算。复核修法明确：「每次实际模型调用使用独立 request/attempt 身份作为预算判据；来源批次、问题和候选序位保留为归属信息。复用已有 requestId，不改变预算账对同一笔请求的幂等语义。」
- 判据拼法沿用 `memory-job:{jobId}:{kind}:{attemptKey}`；调用方把 attemptKey 传成该次请求的 requestId。
- unlimited 直通不落预留——结算/释放只对实际存在的预留做（`budgetReserved` 标志），不对空气结算。
- 费用已知/未知用同一判断：`usage.totalTokens > 0 && usage.cost?.total !== undefined`；默认零对象（totalTokens=0）不能证明免费。
- 日累计检查必须和预留在同一账本临界区（F04）。

## 修改清单（8 项）

### 1. `pao/usage/budget-ledger.ts` — 预留时可选核对当日累计（F04 结构性改动）

现状 `reserveBudget` 在锁内只判断「同判据幂等 → 总预算剩余」。新增：

- `ReserveBudgetInput` 加可选 `当日上限?: number`。
- 在同判据幂等返回 `reused:true` 之后、`invalid_amount`/`insufficient` 检查之前，加一段：
  - `当日上限 !== undefined` 时，按 `input.现在.slice(0,10)` 聚合 file.reservations 内 `卡号` 以 `memory:` 开头的记录：settled 取 `已结算费用`、reserved/unknown 取 `预留额`、released 不计；
  - `当日已发生 + input.金额 > 当日上限` → 返回 `{ok:false, code:"daily_exceeded", reason:"记忆后台当日累计 $… + 本次 $… 超过每日上限 $…"}`。
- `reserveBudget` 返回 union 的失败 code 加 `"daily_exceeded"`。
- 这仍是账本锁内同一段 fn——不拆第二把锁、不新增平行账。

### 2. `pao/memory/budget.ts` — 日累计检查移进预留临界区
