## 2. O02-J01 / P1：已修复——确认升级允许证据类别升级

原问题：I02 修复后工具落库为 `model_inference/tentative`，但确认升级分派要求 `evidenceKind` 不变，真实用户确认（`user_statement`/`confirmed`）被当作 `semantic_conflict` 跳过——推断永远无法凭真实用户确认转正。

修法（见 [J01 修复任务书](o02-j01-修复任务书.md)）：`extract-commit.ts` 新增 `isEvidenceUpgrade(target, candidate)`，仅 `model_inference → user_statement|execution` 返回 true；三处入口（dispatchSameConclusion 内部 upgradeOnly、第 4 关来源级外层 upgraded、第 5 关同范围外层 upgradeOnly）统一改为 `(!delta.evidenceKindChanged || isEvidenceUpgrade(...))`。降级方向与其余互转仍走 semantic_conflict。

修复后实际落库复核：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| J1：普通对话明确纠正 | 工具改 rev2 tentative；用户确认候选被跳过 | 同一 ID rev3、confirmed/user_statement；来源 = 原 user + 纠正 user + toolcall 三条并集 |
| J2：先推断、后确认 | rev1 留 tentative；用户确认候选被跳过 | 同一 ID rev2、confirmed/user_statement；来源 = toolcall + 确认 user 并集 |
| I3：仅助手工具调用 | tentative/model_inference | 保持 tentative/model_inference（不自动确认） |
| I4：推断条件变化对已确认决定 | 不重议、rev 不变 | 保持 confirmed、rev1、不重议 |

`correctMemory` 的 `replacement.evidenceKind` 本已取候选值，升级分支放行后新修订自动获得 `user_statement` 身份，与真实确认来源一致，evidence 身份闭合不被破坏。
