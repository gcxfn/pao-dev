## J07（P2，C1）：刷新沿用本轮收紧预算

**缺口**：`session.ts:794` `filterVisibleMessages` 调 `budgetAutomaticRecallHits` 硬编码 `AUTO_RECALL_BODY_LIMIT`（2000）；`context` 钩子刷新召回消息时未用本轮 `autoRecallBudgetChars(ctx)` 收紧预算。实测本轮预算 287、实际输出 513。

**修复**：让本轮有效预算流入可见副本刷新。

- `filterVisibleMessages`/`budgetAutomaticRecallHits` 增加可选 `budgetChars` 参数（贯穿到计费）。
- 两处 `context` 钩子调用点把本轮预算传入：
  - `resident.ts:413` `pi.on("context")` —— 用 `autoRecallBudgetChars(ctx)` 计算并传入；
  - `tools.ts:1053` builtin freshness 的 context 调用 —— 同口径传入。
- 注意「另一个钩子不重新放宽」：若多个 context 钩子串行，都以同一本轮预算收紧，不在后续钩子回退到 2000。
- 装不下的可见项整项省略，依据留 `state.visibleHits`/`details` 不进可见文本；条件不截断。

**验收**：C1——本轮预算<2000、条件/来源修订后，context 返回的自动召回完整渲染 ≤ 本轮预算。

## J08（P2，C2）：首次消息头与降级说明纳入预算

**缺口**：`AUTO_RECALL_MESSAGE_OVERHEAD`（session.ts:60）按「当前可见 N 条」短头 103 码点计费，实际首次注入用 `renderRecallSection` 的「本轮按用户输入自动召回 N 条……」长头；`resident.ts` 语义降级说明（`found.degraded` 分支约 L342）在选完条目后追加、未预留成本。实测预算 331、实际输出 396。

**修复**：让首次注入按**实际返回模板**计费。

- `selectForContext`（或调用方传入开销）按 `renderRecallSection` 的真实首次头模板计 `AUTO_RECALL_MESSAGE_OVERHEAD`，不用「当前可见」短头——区分「首次注入头」与「刷新可见头」两种口径，首次用长头。
- 语义降级说明：resident.ts 在选定条目前预留降级说明所需码点（降级发生时 `found.degraded && degradeReason` 的那行 + 分隔），或把它计入消息固定开销；不能选完后无预留追加。
- 以最终 `response.content` 文本长度验证总成本不超本轮预算；保留降级状态真实说明（不删降级行，只是计费预留）。

**验收**：C2——刚好放入条目的预算边界、及语义降级正常路径，最终自动召回消息 ≤ 本轮预算。
