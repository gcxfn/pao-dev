## 5. 验证边界

- `isBranchScoped` 只识别 ASCII 分支名（`[A-Za-z0-9][\w./-]*`），中文分支名不触发剔除——程序性识别的既定取舍，不升级为全量自然语言解析。
- lane 排除子查询用 `JOIN sources` 替代任务书的双 `SELECT` 子查询，语义等价且少一层嵌套。
- `semanticCandidates` 的 `scopeRows`（search.ts:352-355）使用不含修订条件的 filter（`currentScopeFilter` 或 `historyScopeFilter` 不传 `historyRevisions`），因为该查询无 `v` 别名；修订身份由 `inScope`/`matchesHistoryRevisionSelection` 在内存核对——与 SQL 下推口径一致。
- 本轮复核使用确定性夹具与固定向量，不验证真实嵌入端点质量；未跑全量测试与构建。
- `memory-recall-inject.test.ts` 一处断言因 O02 的 correctMemory 来源并集（新修订保留旧出处）而更新为「旧来源行显示当前会话事件」，属断言口径修正非实现缺陷。

## 6. 任务书偏差（以源码为准，已核实无实质偏离）

- lane 排除子查询实现形态：`JOIN sources`（search.ts:141-149）替代任务书建议的双 `SELECT` 子查询，覆盖 `source_id` 与 `session_id+entry_id` 两种排除形式及 `memory_id` 列探测。
- `semanticCandidates` 的 `scopeRows` filter：为避免 `v.revision` 在无 `v` 别名查询中报错，改用不含修订条件的 `historyScopeFilter(scope, kind)`（不传 historyRevisions）；修订维度由 `matchesHistoryRevisionSelection` 内存核对，与 SQL 下推后的候选语义一致。
