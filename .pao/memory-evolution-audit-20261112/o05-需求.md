# O05 需求确认：来源原文词法索引、来源展开工具、完整上下文预算、事件段封存接入

核实日期：2026-11-14。对应[优化任务 O05](优化任务.md)，来源：召回 Q3/Q4/Q6（[召回与管理页审核](audit-search-ui.md)）与存储 F10（[存储与提炼审核](audit-storage-extraction.md)）。依赖 O02（修订提交与来源核对）、O03（调度与空闲边界）、O04（候选截取、准确 ID、分支语义、向量范围下推），均已复核关闭。

## 背景与业务缺口

### Q3（P1）：未提炼原文的历史检索没有实现

- 位置：[search.ts](../../PAO/packages/coding-agent/src/pao/memory/search.ts#L130)、[store.ts](../../PAO/packages/coding-agent/src/pao/memory/store.ts#L180)、archive.ts 来源段写入。
- 缺口：`history` 仅在 `memory_fts → memories → memory_revisions` 与结构化向量中查询；来源归档只有定位与回读，没有原文词法索引及其查询分支。
- 需求：S3-06 要求 history 模式包含归档事件段 FTS；原始事件段只索引可保存文本和 sourceId；命中后调 `readMemorySource` 展开，不预解压全部历史。删除同批清事件段索引。
- 影响：从未形成结构化记忆的旧讨论搜索不到，即使原文仍可按已知 sourceId 回读。

### Q4（P1）：模型缺少受支持的来源展开入口

- 位置：[tools.ts](../../PAO/packages/coding-agent/src/pao/memory/tools.ts#L704) 的工具注册；service.ts 的 readMemorySource；桌面 memory.ts 的 readDesktopMemorySource。
- 缺口：模型侧只有写入/召回/忘却/成果读取四个工具；`readMemorySource` 被桌面、提炼器、项目上下文内部调用，但没有供当前模型按 sourceId/准确修订分页展开原文的工具。
- 需求：S3-11 要求正文不足时提供展开工具；S3-06 要求命中后调 `readMemorySource` 展开。
- 影响：模型不能沿同一来源契约完成按需查证；召回错误提示本身也把原文查证交给宿主。

### Q6（P2）：固定 top3 和正文字符上限尚未兑现完整上下文预算

- 位置：resident.ts 固定三条；session.ts 固定正文 2000/800 码点；selectForContext 仅累计正文，不接收当前模型上下文余量；来源元信息与渲染头不在该预算内。
- 需求：S3-11 要求按当前上下文余量先放结论+完整条件+出处短标识；正文不足时整项省略并提供展开工具；来源展开有任务内预算与足够即止条件。
- 已有效行为：builtin 条目正文装不下时整条省略，避免截断否定条件；可见修订去重和压缩后重注入均存在。
- 影响：完整条件和来源标识可能被截断；候选条数与注入条数不分，装不下的前项挡住后续可用候选。

### F10（P2）：无损压缩能力未接入正常生命周期

- 位置：[archive.ts:232](../../PAO/packages/coding-agent/src/pao/memory/archive.ts#L232)、[capture.ts:395](../../PAO/packages/coding-agent/src/pao/memory/capture.ts#L395)、`K/memory/tools.ts:626`。
- 缺口：sealSegment 只有定义没有生产调用；archive 维护 handler 实际执行数据库备份，不封存事件段；archive.ts:129/209 每次追加前全读段内行数。
- 需求：S1-07 要求按一次提交批次写不可追加的事件段；S2-13 的空闲边界是既有安全点。原话：「在无该段 writer 的既有空闲/会话安全边界调用封存，并创建后续新段；保留失败原段。无需新建归档框架。」
- 影响：单会话一直追加未封存 JSONL，压缩测试能过但产品不压缩；长会话采集读量随段增长。

## 目标与取舍

| 修复 | 目标 | 取舍 |
|---|---|---|
| Q3 | 在现有来源归档业务内维护脱敏事件的词法索引，history 返回来源命中并复用有界回读；删除与重建同步接入该索引 | 只索引可保存文本和 sourceId，不预解压全部历史；不新增独立搜索引擎，复用 FTS5 |
| Q4 | 在现有记忆工具中增加明确的只读详情/来源操作，复用 service、可信范围、有界分页和 expand 记录 | 优先扩展已有入口，不另建来源读取服务；不开放写操作 |
| Q6 | 复用已有请求上下文估算，把整条实际渲染成本纳入可用预算；候选条数与注入条数分开；装不下的前项不挡住后续可用候选 | 保留简单上限作为资源约束，不新增重排模型或缓存框架；不追求精确 token 计数 |
| F10 | 在无该段 writer 的既有空闲/会话安全边界调用封存，并创建后续新段；保留失败原段 | 沿现有 archive/capture/scheduler 钩子，不新建归档框架；压缩失败仍读原段 |

## 完成验证（原表口径）

未提炼讨论可发现/分页回读；封存/删除/重建一致；长条件不截断，含来源的完整请求符合预算。
