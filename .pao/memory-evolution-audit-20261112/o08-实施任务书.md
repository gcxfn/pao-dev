## F11：成果登记与使用归因接入正常执行（高）

选 A+B 两个挂点（卡链主路），worker 结算登记留后续：

### 挂点 A：卡回执边界

- 位置：`PAO/packages/coding-agent/src/pao/cards/tools.ts:248-281` `executeSubmitReceipt`——worker 经 `pao_submit_receipt` 交回执时 `params.artifact_path`（:236 `artifact_path: string[]`）已在手且经 `appendReceipt`→`validateReceiptContent`（receipts.ts:73-105）核验真实存在。
- 此处把「产物清单 + card_no/attempt + 来源工具身份（sourceToolName="pao_submit_receipt"）+ 回执引用」交 `registerArtifact`。装配：`registerCardTools`（tools.ts:556-）由 `pao/index.ts:596-606` `register("cards")` 注册，options 加 `registerArtifact` 惰性回调（同 `resolveMemoryService`/`knowledgeMemory` 先例，index.ts:716/942——cards 注册先于 memory）。
- `registrationKey` 幂等（artifacts.ts:425-438 `versionByRegistrationKey`）用 `${card_no}:${attempt}` 或工具调用 ID，重放安全；来源走 `captureToolCallSource`（tools.ts:295-316）。
- **登记失败只补登记不重跑工具**：登记异常留痕不阻断回执落定。
- **使用归因挂回执边界**：`executeSubmitReceipt` 时查会话态「本会话 resolve 过的版本」（sessionMemory 态，同 freshnessPending 先例），有则一并 `recordArtifactUse(versionId, taskId, action:"reuse", receiptRef=本次回执引用, sessionId)`。不在 write/edit 粒度归因——避免误判无关写。
- `usageRefs` 登记本请求 requestId（`requestIdFor(ctx.sessionManager)`，O01 修的同一 ID）。

### 挂点 B：交卷边界（Git 定位）

- 位置：`cards/delivery.ts` `deliverCardOnce`（约 :1063-1292）返回 `SubmissionResult`{交卷,提交哈希,暂存文件,内容证据{交付Commit}}；挂点放 `executeDelivery`（:1334-1364）在 results 返回前逐卡登记，或 `deliverCard` 包装层（:1052-1062）。
- 只有 `交卷:true` 且 `提交哈希` 存在才登记；`skip`/`交卷:false` 不登记。`交付Commit` 为短哈希需 rev-parse 补全 SHA（resolveCommitSha 拒绝分支名）；`暂存文件` 为仓内相对路径。
- 这是唯一天然产生 Git 版本定位的点（registerArtifact 要求完整 SHA）。

## F12：Git 查重复用成果身份 + 补当前任务引用（中）

两层根因都在 `artifacts.ts` registerArtifact 事务（414-577）：

- **孤儿成果行**：Git 查重命中 `versionByGitIdentity`（:460-471）时 push 旧版本并 continue，但 `isNewArtifact`（:441-446）路径仍走到 :501-517 `INSERT INTO artifacts`，新行无任何版本；返回 artifactId 与 versions[].artifactId 不一致。
  - 修法：artifactId 决策后置到逐文件查重完成后——全部命中查重时取首个 `dup.artifact_id`；部分命中部分新建时，新建版本落到 dup.artifact_id 名下；`isNewArtifact` 只在全部文件均为新定位时才真建 artifacts 行。
- **当前任务引用缺失**：565-572 的 `originTaskId→artifact_refs 'task'` 只在 preparedFiles（新建版本分支）写入；查重命中分支不写。修法：查重命中分支补写 `INSERT OR IGNORE` aref 'task' 行（同 565-572 形），mergeUsageRefs 照旧（:467/493）。
- 受管查重分支（:481-497）同病同修；`syncArtifactFts`（:575）改按版本自身 artifactId 分组逐成果刷索引（mapVersion 已带）。
- 返回契约修正：`{artifactId: dup.artifact_id 或混合时首个 dup/新建成果, versions: 全部归属版本, replayed:false}`。
