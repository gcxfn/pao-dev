## E07：runner 实际装载版本副本 + 会话完成≠验收通过（P1）

### command 分支绑定版本副本

- `runValidationCase`（runner.ts:432-497）：在 `materializeInitialFiles` 后加「版本副本物化」——baseline 侧复制 `versions/<dirSafe>/<baseVersion>/`、candidate 侧复制 `evolution/candidates/<dirSafe>/<candidateId>/` 内容到 `workDir` 下固定子目录（如 `work/resource/`）。冻结 plan 的脚本/测试以相对路径引用它；verifier 在 workDir 内执行自然读到对应侧正文。两侧差异来自已固化版本/候选目录，不由调用方逐侧塞 initialFiles 制造。
- `resourceCopyDir` 不再只是回执标签。

### agent 分支共享工厂

- `AgentSessionFactoryInput`（runner.ts:58-77）补 `timeoutMs?: number`（O10 侦察确认未落盘，O11 补上）。
- 工厂生产实现=包现成函数，不新建框架：
  1. `DefaultResourceLoader`（resource-loader.ts）按 loadMethod 挂 resourceCopyDir；skill 用 `prioritySkillPaths` 保证候选版本压过用户目录同名技能（main.ts:781-928 createRuntime 现成参照）。
  2. `SessionManager` 用 layout.sessionDir 建隔离会话。
  3. `createAgentSession`（sdk.ts:183-493）注入 `modelRuntime/tools/resourceLoader/sessionManager/agentDir/cwd/settingsManager`；`tools` 按 `resolveValidationToolSet`（boundary.ts:52-64，VALIDATION_TOOL_ALLOWLIST ∩ allowedTools）算交集传入——E08「工具交集在工厂激活工具时执行」落点。
  4. 驱动 `session.prompt(text)` + `waitForIdle()`/`agent_settled`；output 从 sessionManager 条目读，usage 从 `getSessionStats()` 取；requestId/usageRef 由编排层预算账本传入。
  5. 取消：`session.abort()` + close；timeoutMs 用 `AbortSignal.timeout` + input.signal `AbortSignal.any` 合成。
- `AgentSessionRunOutcome` 加通过判定字段或编排层把「会话返回」与「验收通过」拆开：`executeAgentCase` 不得对正常返回直接 `passed:true`；消费 `abortReason`；执行故障（abort/超时/启动失败）记结构化失败，不当业务通过。

### 环境失败语义

- `ValidationRunResult` 加结构化字段（如 `executionFailure?: "start"|"timeout"|"cancel"`）；runner 在 `proc.failureKind` 处写它，不再塞进 `failureReason` 字符串。
- `isEnvironmentFailure`（evaluate.ts:127-132）改认该字段而非 output/exitCode 启发式；环境失败 → `incomplete`（不可 passed，不按业务 failed）。
- reproduction 组 baseline「真失败」判定区分：业务失败（exitCode≠0、无执行故障）才满足复现前提；执行故障 baseline 不能充当旧版不行的证据。
