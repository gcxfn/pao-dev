# O04 修复任务书：适用分支解析、候选截取前资格核对、历史准确 ID

状态：已完成，I01—I03 已关闭，最终验收见[最新复核](o04-修复后独立复核.md)。对应[优化任务 O04](优化任务.md)，业务代码在 `PAO/packages/coding-agent/src/pao/`。

目标：**conditions 明示的「适用分支」按声明值生效（与来源分支解耦）；分支受限与来源排除在 perLane/limit 截取前完成核对，无效候选不占位；准确 ID 定点读遵循 historyRevisions 范围**。

## 缺口与修法

### 修复一（I01，P1）：`isBranchScoped` 返回适用分支，不按来源分支比对

现状：`isBranchScoped(content): boolean` 只判「conditions 是否声明分支限制」，`searchMemories` 拿 `hitScope.branch`（来源分支）与 `scope.branch`（调用方分支）比较——A 写「仅适用 B」会在 A 命中、B 返回空，正好相反。

改 `scope.ts`：
- 把 `isBranchScoped` 改为 **`appliesToBranch(content): string | undefined`**（或保原名改签名，二选一，在报告注明），返回 conditions 中解析出的适用分支名；未声明/无法解析返回 `undefined`。
- 解析复用现有正则的两组模式：「分支名+关键词」与「关键词+分支名」，捕获分支名组。现有 `/[A-Za-z0-9][\w./-]*\s*(分支|branch|worktree)/` 与 `/(分支|branch|worktree)\s*[:：=]?\s*[A-Za-z0-9][\w./-]*/` 各取一个分支名捕获组。
- 注意第一组「分支名在关键词前」：「仅适用 feature-b 分支」命中；第二组「关键词在分支名前」：「仅适用分支 feature-b」「branch: feature-b」命中。两组任一捕获即返回该分支名。
- `searchMemories` 的分支核对（search.ts:554-561）改为：调用方 `scope.branch` 存在 且 `appliesToBranch(content)` 返回分支名 `target` 且 `target !== scope.branch` → 剔除。**不再比较 `hitScope.branch`**——适用分支由 conditions 声明，与来源分支无关。

### 修复二（I02，P1）：无效候选在截取前剔除

两处要修：

**(a) 分支适用核对前移到候选阶段**。现剔除在 `merged.slice(limit)` 之后的回表循环里，无效候选已占 limit。把 `appliesToBranch` 核对挪到 **`mergeSearchCandidates` 之前**：对 lexical/semantic 两路候选先按「适用分支==调用方分支 或 未受限」过滤。但候选此时还没有 content——需要按候选 `(memoryId, revision)` 批量读 `memory_revisions.content_json` 判 `appliesToBranch`。候选量 ≤ 2×perLane，一次 `IN` 查询可接受；或直接在 lane 函数内对每行 `revStmt` 后过滤。**推荐在 `mergeSearchCandidates` 调用前加一个 `filterBranchEligible(db, candidates, scope)`**：候选为空/调用方无 branch 直接返回原集；有 branch 时读各候选修订 content，`appliesToBranch` 返回 undefined 或与 `scope.branch` 相同的保留，否则剔除。

**(b) 来源排除同样前移到语义 lane**。现 `filterExcludedMemories` 只在合并后核对，21 条已排除候选把 perLane=20 占满导致有效条目进不来。`semanticCandidates` 在 `scored.slice(0, perLane)` **之前**调 `filterExcludedMemories(db, scored)` 剔除已排除项（`scored` 已有 memoryId+revision）。词法 lane 已有 SQL 下推；最终回表 `filterExcludedMemories(db, merged)` 保留兜底。

注意：`filterExcludedMemories` 签名收 `{memoryId, revision}[]`，`scored` 元素兼容（多出的 score 字段不影响）。核对后 `scored` 再排序截取。

### 修复三（I03，P2）：准确 ID 定点读遵循历史修订范围

现状 search.ts:505-517：history 模式定点读固定 `historyScopeFilter(...,"all")` + 候选取 `current_revision`；`historyRevisions="superseded"` 时该候选被回表 `matchesHistoryRevisionSelection` 剔除 → 返回空。

改定点读分支：
- `mode === "history" && historyRevisions === "superseded"`：命中 memories 行后，候选取 `revision = current_revision - 1`（即最大旧修订）；`current_revision - 1 < 1` 时无旧修订、不追加候选。
- `mode === "history" && historyRevisions === "all"`：保持 `current_revision`。
- `mode === "current"`：不变。
- 回表核对不变：superseded 候选 `rev < current_revision` 自然通过 `matchesHistoryRevisionSelection`。

说明：superseded 定点只取「最新一个旧修订」，不枚举全部旧修订（与任务书「旧修订若含查询词走正常 lane」一致——词法 lane 可召回其他旧修订，定点只保证该记忆在 superseded 范围有可返候选）。若复核要求返回全部旧修订，再改为 `SELECT revision FROM memory_revisions WHERE memory_id=? AND revision < current_revision` 全量入候选；本任务书按「最新旧修订」最小实现。

## 不改的部分

- RRF 合并公式、`exactIds` 置顶、`perLane = max(20, 4×limit)` 不动。
- `filterExcludedMemories` / `isSourceExcluded` 语义不动；最终回表核对保留。
- 词法 lane 已有 `f.revision = m.current_revision` + NOT EXISTS 下推不动；向量范围 JOIN 下推不动。
- scope.branch 仍是来源身份，不新增 `appliesToBranch` 持久字段——适用分支只从 conditions 解析。
- O05 范围（Q3/Q4/Q6/F10）不接。
