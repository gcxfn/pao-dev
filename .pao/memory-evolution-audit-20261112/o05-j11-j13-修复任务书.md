## 核心口径：按最终决定返回的表示扣预算

`filterVisibleMessages` 已对每条 automatic 块调 `budgetAutomaticRecallHits` 按 `cost` 扣 `remainingBudget`。但 `cost` 与「外层最终返回的消息表示」不一致，三处偏差：

- `cost` 按刷新短头（当前可见 N 条）计费；外层 `unchanged` 时 `return [raw]` 复用的却是**首次注入长头**（renderRecallSection）原消息 → C5。
- 复用判定 `budgeted.hits.every(h===remaining[i])` 不查数量；只留前缀时仍判「未变」返回含全部条目的原消息 → C6。
- 无可容纳命中时 `cost` 仍含 `headerChars`，外层先扣再 `return []` → 整块省略仍占预算 → C7。

## J11（P2，C5）：复用按原消息完整文本扣费

- 仅当**命中列表完整相同（数量+逐项同对象）**且**原消息实际可见文本能放入剩余预算**时才 `return [raw]` 复用。
- 复用时 `remainingBudget -=` 按 `recall.message.content`（首次注入长头原文）的完整可见文本码点，不按短头 `cost`。
- 原消息文本装不下剩余预算 → 不复用，走裁剪/省略路径。

## J12（P2，C6）：复用判定核对数量

- `unchanged` 复用条件在「逐项同对象」之外补 `budgeted.hits.length === remaining.length`（且 remaining===recall.hits 已隐含），只留前缀时不算未变。
- 列表裁剪/正文替换/原消息超限 → 输出预算处理后的副本，`remainingBudget -=` 按该副本实际文本（头+保留项渲染+附注+分隔）实扣。

## J13（P2，C7）：整块省略成本为零

- `budgetAutomaticRecallHits` 无可容纳命中时返回 `cost: 0`（不把 headerChars 计入被省略块）。
- 外层 `budgeted.hits.length===0 → return []` 时 `remainingBudget` 不变；每块只扣一次。
- 后续可放入的消息继续正常处理。

## 实施约束

- 单次 `filterVisibleMessages` 调用内完成，不新增跨请求状态/包装层/独立预算框架。
- 「装不下整项省略、依据留 structured state」口径不变；manual 召回不占此预算。
- 每块预算只扣一次；最终 `remainingBudget` 累计 = Σ各返回消息实际文本。
- 不削测试；C5/C6/C7 是验收基准。
- 跑 `o05-context-budget`（C3—C7）、`o05-budget-rereview`（C1/C2）、`o05-deep-review`（B1—B8）、`memory-o05`、`memory-session`、`memory-recall-inject`、`memory-resident`、`memory-context-usage`。
