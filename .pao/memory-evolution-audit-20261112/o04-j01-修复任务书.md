# O04-J01 修复任务书：分支适用核对下推到 lane 截取前、history 不误伤

状态：已完成，A5/A6 通过；词法最终补取实现见 [J02 任务书](o04-j02-修复任务书.md)，验收见[最新复核](o04-修复后独立复核.md)。对应[优化任务 O04](优化任务.md)，业务代码在 `PAO/packages/coding-agent/src/pao/`。

目标：**分支适用核对在各路 perLane 截取前生效（不止合并前），history 查阅模式不做分支剔除**。不新增字段、不动 RRF/perLane 值。

## 缺口与修法

### J01-A：分支适用核对仍在 lane 截取之后（A5，P1）

现状：`filterBranchEligible`（search.ts:540）在 `mergeSearchCandidates` 前对 `[...exactIdCandidates, ...lexical, ...semantic.hits]` 核对。但 `lexical`/`semantic.hits` 已各自 `slice(0, perLane)` —— 21 条「仅适用 feature-a」的受限候选在 feature-b 调用方下占满 perLane=20，有效共享条目进不了候选集，合并前再剔也救不回。

**词法路**（`lexicalCandidates`，search.ts:158-248）：lane 内候选是 SQL 行，无法在同一查询里调 `appliesToBranch`（content 在 `memory_revisions.content_json`）。修法：**lane 内超额取候选再核对**——
- 把 lane SQL 的 `LIMIT` 从 `perLane` 放宽（例如 `perLane + 余量` 或 `perLane * K`），或在 lane 候选收集后、最终 `slice(perLane)` 前用 `filterBranchEligible` 过滤。
- 推荐做法：lane 函数末尾 `return` 前，把 `hits` Map 的去重排序结果先经 `filterBranchEligible(db, 排序后候选, scope)` 过滤，再 `slice(0, perLane)`。这样被剔除的受限候选不占 perLane 位。
  - 代价：SQL `LIMIT` 仍是 perLane，若受限候选正好占满 perLane 则过滤后 lane 可能不足。需放宽 SQL `LIMIT` 到 `perLane + BRANCH_HEADROOM`（余量取一个常数如 perLane，即 `LIMIT 2*perLane`），保证剔除后仍可能凑满 perLane。
  - 注意词法 lane 有 FTS+LIKE 两路各自 `LIMIT`——两处都要放宽同样余量，且合并去重后再过滤+截取。

**语义路**（`semanticCandidates`，search.ts:360-379）：`scored` 排序前已前移 `filterExcludedMemories`；同样在这里补 `filterBranchEligible`——`eligible` 排序前先经 `filterBranchEligible(db, scored, scope)` 剔除受限候选，再 `sort` + `slice(perLane)`。调用方无 branch 时 `filterBranchEligible` 直接放行（已在函数内处理）。

### J01-B：history 查阅模式不该做分支剔除（A6，P1）

现状：`filterBranchEligible` 在合并前对所有候选生效，history 模式也剔除受限条目；但 history 是查阅性质——「仅适用 feature-a」的历史修订在 feature-b 下查历史仍应可见（分支适用是「当前生效」语义，不是「历史上不可见」）。

- `filterBranchEligible` 只在 `mode === "current"` 时调用；history 模式跳过（合并前核对处加 mode 判断，或 `filterBranchEligible` 内部加 mode 参数——**推荐在调用点判断**，`filterBranchEligible` 保持无 mode 参数，语义更纯：「这个候选在当前分支下是否可召回」）。
- 回表核对（search.ts:580-583）已有 `mode === "current"` 判断，history 天然不剔除——保持一致，无需改。
- 词法 lane 的 `filterBranchEligible`（J01-A）同样只在 current 模式调用。

## 不改的部分

- `appliesToBranch` 解析逻辑、回表兜底、I03 定点读 superseded、向量 JOIN 下推、`filterExcludedMemories` 均不动。
- `filterBranchEligible` 对「调用方无 branch 直接放行」语义不动；本次只加调用点的 mode 判断与 lane 内核对。
- perLane = `max(20, 4×limit)` 定义不变；只是 SQL `LIMIT` 放宽取候选余量，最终 lane 返回仍 `slice(0, perLane)`。
