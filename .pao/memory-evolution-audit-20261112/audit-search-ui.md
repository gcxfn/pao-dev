# 召回、上下文与管理页审核

核实日期：2026-11-12。范围：S3 全部、S4-01—11/16—18；S4-12—15 由存储与提炼审核承接。当前源码深入阅读 search/scope/resident/session/service 查询、tools 装配和修订感知，以及桌面列表/详情/来源/管理的主要调用链；桌面 IPC、driver、布局和发行路径按相关入口与既有证据核对，本轮未重新启动 Electron 或打包。

## 结论

双路召回、修订级去重、纠正刷新、停止使用与管理页已有实质实现。S4 的真实模型、语义查询及发行物证据支持其已验证情景；当前实现仍有召回正确性、历史检索和模型来源展开的缺口，S3 不能整体认定为满足全部要求。

### Q1：当前查询先截结果再排旧修订，造成漏召回

- 位置：[search.ts](../../PAO/packages/coding-agent/src/pao/memory/search.ts#L130) 的词法候选、456 行合并截取、469 行当前修订复核；[scope.ts](../../PAO/packages/coding-agent/src/pao/memory/scope.ts#L38) 的 current 过滤没有候选修订条件。
- 触发：用户纠正同一条记忆后，旧新修订都包含查询词；请求 `limit=1`，旧修订占据第一位。当前修订位于截取范围外，回表排除旧修订后返回空。默认 top3 遇到多个历史修订会产生同类漏召回。
- 证据：[隔离复现](evidence/search-results.json) 中 `current-revision-before-limit` 返回空，扩大到三条后返回 rev-2。使用当前搜索源码和数据库结构，固定数据，无网络请求。
- 依据：S3-02/04/05 的当前索引身份与候选完整性；详细路径要求在候选形成时只取当前修订。
- 修法：词法路在各自 LIMIT 前加入 `f.revision=m.current_revision`；保留异步召回后复核。实际排除来源亦应在最终截取前处理或补足候选，避免已知不可用条目耗掉结果名额。
- 验证：一次和多次纠正、短词与 FTS 查询、低 limit 均返回当前修订，历史模式仍能返回旧版。

### Q2：准确记忆 ID 无法独立召回

- 位置：[search.ts](../../PAO/packages/coding-agent/src/pao/memory/search.ts#L392) 仅提取 ID；456 行将其交给已有候选排序。FTS 的 memory_id 为 UNINDEXED，词法只搜索正文；没有按 ID 直接取候选。
- 触发：用户或模型拿到返回中的准确 `mem-…`，以该 ID 调用召回工具；正文未包含自身 ID，返回空。语义端点可用时可能靠偶然相似结果进入候选，仍不能保证定点取回。
- 证据：隔离复现 `exact-memory-id` 无命中；同条记录用正文可以找到。
- 依据：详细路径 S3-05/07 的精确记忆 ID 优先；超预算提示也要求按 ID 回读。
- 修法：在相同可信范围和状态约束下直接解析 ID 对应修订，再与双路候选合并。不增加全文扫描。
- 验证：纯 ID、ID 与自然语言混合、停用和其他项目 ID，分别核对准确命中与范围约束。

### Q3：未提炼原文的历史检索没有实现

- 位置：[search.ts](../../PAO/packages/coding-agent/src/pao/memory/search.ts#L130)、[store.ts](../../PAO/packages/coding-agent/src/pao/memory/store.ts#L180)、archive.ts 的来源段写入。
- 证据：history 仅在 `memory_fts → memories → memory_revisions` 与结构化向量中查询；来源归档只有定位与回读，没有原文词法索引及其查询分支。全相关源码搜索未发现其他归档历史检索入口。
- 触发：对话已采集保存，但某段讨论没有形成结构化记忆，之后用户按原文关键词寻找该讨论。即使原文仍可按已知 sourceId 回读，搜索也无法发现它。
- 依据：S3-06 明确要求归档事件段可重建词法索引，包含从未形成结构化记忆的旧讨论。
- 修法：在现有来源/归档业务内维护脱敏事件的词法索引，history 返回来源命中并复用有界回读；删除与重建同步接入该索引。
- 验证：新采集且未提炼的事件、封存后、删除后和索引重建后的关键词发现与准确来源。

### Q4：模型缺少受支持的来源展开入口

- 位置：[tools.ts](../../PAO/packages/coding-agent/src/pao/memory/tools.ts#L704) 的工具注册；service.ts 的 readMemorySource；桌面 memory.ts 的 readDesktopMemorySource。
- 证据：模型侧只注册写入、召回、忘却、成果读取四个工具。召回结果有来源 ID 和摘要，`readMemorySource` 由桌面、提炼器、项目上下文等内部调用；未发现供当前模型按 sourceId/准确修订分页展开原文的工具。召回错误提示本身也将原文查证交给宿主。
- 触发：当前任务需要核对原决定的完整条件或超预算记忆正文。桌面可手动展开，模型却不能沿同一来源契约完成按需查证。
- 依据：S3-11 及详细路径要求来源展开工具和任务内预算；设计要求当前任务按需阅读原始证据。
- 修法：在现有记忆工具中增加明确的只读详情/来源操作，复用 service、可信范围、有界分页和 expand 记录。优先扩展已有入口，避免另建来源读取服务。
- 验证：由实际会话工具调用展开准确修订和来源，缺失/排除来源正确返回，分页和用量记录成立。

### Q5：分支适用范围没有执行判定

- 位置：scope.ts current/history 只使用 projectId/taskId/department；session.ts 选择器只做身份、可见性与字符预算筛选。
- 证据：隔离复现中 feature-b 查询仍返回 scope.branch=feature-a 的记录。代码没有使用 branch 判断适用性；渲染也不携带结构化 scope.branch。
- 依据：S3 路径要求明确不符的分支不注入，I06 要求分支条件不串。
- 影响：当前只能靠正文条件和模型自行理解，不能证明分支适用判据已落实。
- 修法：先在现有契约中明确“来源分支”和“仅适用于某分支”的区别，再对明确受分支限制的条目执行筛选并展示范围。项目共享决定不能仅因记录时所在分支不同而被排除。
- 验证：公共 API 写入明确受限条目与项目通用决定，在真实 worktree/分支装配下验证前者隔离、后者共享。现有复现证明分支字段未被消费；它不证明所有带 branch 的记忆都应被过滤。

### Q6：固定 top3 和正文字符上限尚未兑现完整上下文预算

- 位置：resident.ts 54/284 行固定三条；session.ts 43/44 行固定正文 2000/800 码点；selectForContext 仅累计正文，不接收当前模型上下文余量，来源元信息与渲染头不在该预算内。
- 依据：S3-11 要求按当前上下文余量计算结论、完整条件和出处，并在已有依据足够时停止补查。
- 已有效行为：builtin 条目正文装不下时整条省略，避免截断否定条件；可见修订去重和压缩后重注入均存在。
- 差距与修法：复用已有请求上下文估算，把整条实际渲染成本纳入可用预算；候选条数与注入条数分开，装不下的前项不应挡住后续可用候选。保留简单上限作为资源约束，无须新增重排模型或缓存框架。
- 验证：当前上下文接近上限、多来源、长条件、前项超预算而后项可容纳。比较完整请求而非只比较正文长度。

### Q7：语义查询先解码全库向量，再过滤项目

- 位置：search.ts 302—311 行；embeddings.ts::readMemoryVectors 只按 model/dimension 读取。
- 触发与影响：同一 PAO_HOME 中其他项目及旧修订增加时，当前小项目查询也会读取并解码这些向量。范围过滤在余弦计算前执行，但读取和内存开销仍随全库增长。
- 结论：静态确认的可维护性与效率优化，未测得当前用户任务的延迟退化。
- 修法：把范围和当前修订条件下推到现有向量 SQL，避免不相关 BLOB 解码；复用范围表达，不增加向量缓存或独立索引引擎。
- 验证：多项目、旧修订数据下比较读取行数和同组命中，必要时测延迟；不承诺未经测量的加速比例。

## 参考机制与效果判断

本轮重新读取 Hindsight 固定提交 fusion.py、consolidator.py，Hermes memory_tool.py/skill_usage.py，以及 LobeHub 固定提交 DetailPanel.tsx。来源提交沿[原调查](../../plans/未完成/2026-11-08-记忆与自进化方案调查.md#7-源码核实与采用结论)和[调研](../lobehub-research-20261109/调研报告.md)。

- Hindsight 的独立召回与 RRF 在 PAO 有实际实现，来源和修订也参与结果；Q1/Q3 表明候选有效性与历史发现仍不完整。
- Hermes 的有限常驻与按需召回在 PAO 有对应入口。PAO 不冻结整会话的旧认识，而是通过修订感知更新可见副本，符合本项目纠正优先的取舍；固定字符/条数预算仍需补齐。
- LobeHub 的当前结论、条件、来源和修订组织在桌面有具体实现；来源页可读不等同于当前模型能按需展开。

S4 I01 原始证据包含真实跨会话回答，能解释 SQLite/常驻服务的取舍；对应同义查询具有真实 semantic 命中。因此持久记忆在已覆盖情景中确实工作。少量受控样例不能推导长期减少纠错的普遍收益；本轮没有新增付费调用。
