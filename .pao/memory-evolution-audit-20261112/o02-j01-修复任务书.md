## 总原则

- 证据类别升级只能「升」不能「降」：`model_inference`→`user_statement`/`execution` 且候选 `confirmed` 时允许经 `correctMemory` 转正；`user_statement`/`execution`→`model_inference` 是降级，仍走 `semantic_conflict`，不静默改写依据身份。
- 升级路径仍走 `correctMemory`、保留同一 `memoryId`、来源取候选 ∪ 旧修订并集；不把升级伪装成新建，也不写死 evidenceKind 不变。
- 条件/理由任一变化都不进升级分支——升级只解决「同一结论同一条件同一理由，依据从推断升级为真实确认」；带差异的组合仍由 flag/conflict 分派处理。

## 修改清单（1 项，3 处调用点统一）

### `pao/memory/extract-commit.ts` — 放宽确认升级的证据类别限制

当前 `dispatchSameConclusion` 内的 `upgradeOnly` 及第 4、5 关外层前置检查都要求 `!delta.evidenceKindChanged`，把「目标 tentative + 候选 confirmed + 证据类别变化」全部挡到 `semantic_conflict`。改为：

- 升级条件改为「目标 `confirmation === "tentative"` + 候选 `confirmation === "confirmed"` + `delta.confirmationChanged` + `!delta.conditionsChanged` + `!delta.rationaleChanged` + 证据类别为允许升级的组合」。
- 允许升级的证据类别组合：目标 `model_inference`，候选 `user_statement` 或 `execution`——依据从助手推断升级为经校验的真实用户/执行依据。
- 其他证据类别变化（`user_statement`→`model_inference`、`execution`→`model_inference`、`user_statement`→`execution` 等）不属于纯升级，仍走 `semantic_conflict`；目标已是 `user_statement`/`execution` 时 `evidenceKindChanged` 的组合同样不进升级。
- 实现：抽一个判定（如 `isEvidenceUpgrade(targetEvidenceKind, candidateEvidenceKind)`：仅 `model_inference→user_statement|execution` 返回 true），`dispatchSameConclusion` 的 `upgradeOnly` 与第 4、5 关外层 `upgraded`/`upgradeOnly` 前置检查三处统一改成同一口径——同一规则只实现一次。`delta.evidenceKindChanged` 仍在「unchanged」判断里起作用：完全相同才走 duplicate 补链。
- `correctMemory` 的 `replacement.evidenceKind` 取候选值（现有代码已如此），升级后记忆的 evidenceKind 与真实确认来源一致，evidence 身份闭合不被破坏。
