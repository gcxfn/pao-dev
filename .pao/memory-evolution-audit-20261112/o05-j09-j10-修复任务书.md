# O05 追加修复任务书（J09/J10）

日期：2026-11-14。依据：[修复后再次审核](o05-修复后再次审核.md) C3/C4、新增场景 `evidence/o05-context-budget.test.ts`（验收基准，不得改以通过检查）。B1—B8、C1/C2 已通过，本任务书只补最终上下文累计预算两处缺口。

范围：`PAO/packages/coding-agent/src/pao/memory/session.ts`（`filterVisibleMessages` 共享入口）。完成标准：C3/C4 过 + B1—B8 + C1/C2 + 既有记忆套件不回退。

## 背景：两缺口同根

`filterVisibleMessages(messages, currentSessionId?, budgetChars)` 是 resident 与 builtin freshness 两个 context 钩子共用的可见副本处理入口，逐条 `flatMap` 处理召回消息。当前缺陷：

- `budgetChars` 已是本轮收紧预算（J07 修复），但**逐条各自用整份**，无跨消息累计（C4）。
- 内容未变（`replaced===0 && !renderSources && remaining.length===recall.hits.length`）时 `return [raw]` 原样返回，**跳过预算检查**（C3）。

## J09（P2，C3）：未变化消息也接受本轮预算检查

**缺口**：`session.ts:818` 早退分支直接返回原消息。上下文增长、记忆不变时，旧召回消息仍占原体积，超本轮收紧预算。

**修复**：所有自动召回可见副本统一经预算判断。

- 「内容未变可复用」只在**实际可见文本仍符合剩余预算**时成立；未变不是跳过检查的理由。
- 装不下时省略整项或整块；完整条件不截断；结构化依据沿 `state.visibleHits`/`details` 保留。
- 注意：manual（非 automatic）召回不受此预算逻辑，保持既有「整块删除/排除说明」语义——预算裁剪只针对 `recall.kind === "automatic"`。

**验收**：C3——仅增上下文长度不改记忆，最终保留自动召回文本 ≤ 本轮预算。

## J10（P2，C4）：跨消息累计剩余预算

**缺口**：`flatMap` 每条召回消息独立把整份 `budgetChars` 传给 `budgetAutomaticRecallHits`，多条合计超本轮上限。

**修复**：同一次 `filterVisibleMessages` 调用内累计整份上下文剩余预算。

- 遍历开始时 `remainingBudget = budgetChars`；每条 `automatic` 召回消息刷新只用 `remainingBudget`，按其**最终实际渲染**（含消息头、各命中渲染、行间分隔）扣除后递减 `remainingBudget`；下一条只能用剩余空间。
- 预算来源：`budgetAutomaticRecallHits` 已能按 headerChars+逐条渲染实计，把第 3 参由整份改为当前 `remainingBudget`；返回值需带出该条最终实际渲染成本供外层扣除（或在调用点按返回文本实算）。
- 无可容纳条目时移除该 `automatic` 整块（返回 `[]`），避免空消息头占位——与既有 `remaining.length===0 → []` 语义一致。
- 「内容未变复用」分支同样计入 `remainingBudget` 扣除（复用时按原消息渲染成本扣），不能让未变消息免费占位。

**验收**：C4——多条历史召回块同时进入上下文，实际渲染总量 ≤ 一份本轮预算；覆盖内容未变与修订刷新两路径。
