# O04-J02 修复任务书：词法路按批补取有效候选

状态：已完成，固定批数上限已移除，A7/A8 通过，见[最新复核](o04-修复后独立复核.md)。对应[优化任务 O04](优化任务.md)，业务代码在 `PAO/packages/coding-agent/src/pao/`。

目标：**词法路按批补取候选，累计到足量有效候选或查询耗尽为止**，替换固定 `LANE_FETCH_FACTOR=2` 余量。A7（41 条受限 + 1 条共享，limit=1）必须返回共享条目。语义路无此问题（`scored` 来自范围内全部向量，无 SQL 截断），不动。

## 缺口

`lexicalCandidates`（search.ts:158-267）FTS/LIKE 各取 `perLane * LANE_FETCH_FACTOR`（=40），分支核对在取完之后。41 条「仅适用 feature-a」受限候选排前面时，第 42 位的共享条目进不了 SQL 结果，feature-b 调用 `limit=1` 返回空、`limit=30` 才返回。固定余量只提高触发门槛，没完成「无效候选不占位」。

## 修法：按批补取（分页游标）

把「一次 `LIMIT laneFetch` 取满」改为「分页循环取批 → 逐批累计 → 有效候选足量或耗尽即停」。

**设计要点**（推荐实现，可按源码实际调整但语义不变）：

- **分批大小**：每批 `BATCH = perLane`（或 `perLane` 的一个倍数，取值写理由）。
- **FTS 路**：`ORDER BY f.rank` 已有稳定序，直接 `LIMIT ? OFFSET ?` 分页。每批取 `BATCH` 行进 `hits`（`memoryId#revision` 键保留最小 rank）。
  - 每个 FTS term 是独立查询——补取按「全部 term 都耗尽」或「有效候选够 perLane」判定。
  - 实现建议：把所有 ftsTerms 的「取下一批」收敛为一个游标循环——每次对每个 term 各取一批汇入 hits，批末用 `filterBranchEligible` 判定当前 hits 的有效候选数；够 `perLane` 或本轮所有 term 都取空则停。
- **LIKE 路**：无 `ORDER BY`，OFFSET 分页不可靠。**补稳定序** `ORDER BY f.memory_id, f.revision`（或 `f.rowid`）再 `LIMIT ? OFFSET ?` 分页；同上游标循环。
- **有效判定**：`mode === "current"` 时批末 `filterBranchEligible(db, [...hits.values()], scope)` 统计有效候选数；`mode === "history"` 不做分支核对、直接按 hits.size 判定（history 无受限剔除，有效数=hits.size，等价于旧的「一次取满」语义——但既然改成批取，history 也走同一补取循环取够 perLane 即停，保持一致）。
- **循环终止**：`有效数 >= perLane` 或「本轮所有 term 的该批都返回空」。
- **终止条件**：不设固定批数或固定总取数上限；每批 OFFSET 正向推进，有效候选足量或查询耗尽时终止，保留有限结果集的完整补取。
- **lane 末尾**：`hits` 去重排序（FTS rank 升序、LIKE rank=0 按 id 稳定）→ current 模式 `filterBranchEligible` 过滤 → `slice(0, perLane)`。lane 末尾核对保留为最终口径（批内判定是提前终止优化，最终仍以末尾 `filterBranchEligible`+`slice` 为准）。

**简化替代**（若子代理评估更稳）：把 FTS+LIKE 两路候选先合并收集、不去重截断，统一在一个「补取循环」里按批从两路各取 `BATCH`——但需保持「FTS rank 升序优先、LIKE rank=0 排后」的排序语义不丢。不推荐拆散两路结构，按上游标循环最小侵入。

## 不改的部分

- `LANE_FETCH_FACTOR` 常量删除（被批取替代）。
- history 模式分支核对仍不做（J01-B 已修，保持）。

## 关键事实

- A7 复现：41 条 `仅适用 feature-a`（FTS 词 `lexical-saturation` 命中）+ 1 条共享，feature-b `limit=1` 空、`limit=30` 命中共享。共享条目 BM25 rank 排第 42。
- 词法 lane SQL：FTS `:208-215`（`ORDER BY f.rank LIMIT ?`）、LIKE `:237-246`（无 ORDER BY `LIMIT ?`），hits Map 汇入 :217/:252，排序+过滤+截取 :259-266。
- `filterBranchEligible`（scope.ts:180）逐候选 `revStmt.get`；批内判定的候选量随批增长，单批 ≤ perLane，可接受。
- FTS `f.rank` 是 BM25 负分，ORDER BY 升序稳定；`memory_id#revision` 唯一可作分页稳定键（ORDER BY 加 tie-break `f.memory_id, f.revision` 保 OFFSET 不重不漏——FTS 同 rank 时必须加，否则分页可能重复/遗漏）。
