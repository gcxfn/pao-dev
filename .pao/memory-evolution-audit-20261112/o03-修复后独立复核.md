## 1. 修复验证

| 缺口 | 修复要点 | 独立验证 |
|---|---|---|
| I01：stale failed 阻断新来源 | `finishJob` 在 needs-reevaluation 的 last_error 追加 `attempted_through=<sourceId>`；`reopenFailedJobForNewSources` 只放行 stale 前缀；`runSessionJob` failed 分支按 `attemptedThroughOf` 判据重开 | C1 通过；I01 反例通过 |
| I02：busy 实例口径 | `foreground-busy.ts` 共享 `Map<paoHome, Set<sessionId>>`；两调度器共用 | C2/C4 通过；I02 用例通过 |
| I03：抢占计为失败 | `signal.aborted` → `releaseJob` 交回 pending，不占 `consecutive_failures` | C3 通过；I03 对照通过 |
| J01：失败批后已有来源误当新增 | `attempted_through` 从「失败批末尾」改为「本轮组批时整个来源快照的末尾」（`afterCursor[afterCursor.length-1].sourceId`） | C5 通过：无新增来源时请求数、attempt_count 不变 |

**J01 关键修正**：`attempted_through` 原记 `last.sourceId`（失败批的最后一个来源），但调度器按 task 切批，失败批后面的其他 task 批次在本轮开始前就已存在。改为记 `snapshotEnd`（`afterCursor` 快照末尾）后，重开判据变成「快照末尾之后有没有真实新增来源」，已有后续批次不再误触发。
