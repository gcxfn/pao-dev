# 内核优化验证

- 验证日期：2026-10-11
- 范围：PAO 内核的桌面只读投影、结果聚合、知识库检索取消与查询嵌入；不含 pi 本体、TUI、桌面仓。
- 代码基线：同一工作树改动前的 HEAD 版本；当前版使用本轮工作树源码。
- 正式 PAO_HOME、真实会话和真实凭证均未作为测试对象。

## 已修改内容

1. packages/coding-agent/src/pao/desktop/read-model.ts
   - 卡路径建立一次 realpath 索引，执行映射复用索引。
   - worker 会话目录每次读取只枚举一次，再按执行标识建立后缀索引。
   - 修复以下划线开头的会话文件导致 lastIndexOf 反复命中 0 的循环。
   - 保留映射身份、路径越界、重复会话等原有错误口径。
2. packages/coding-agent/src/pao/status/results.ts
   - 一次结果聚合内按真实工作目录和完整 Git 参数缓存 Promise。
   - 符号链接指向同一工作目录时共用查询；目录不存在时仍把原路径交给 Git，保留原错误语义。
   - 相同参数的成功和失败结果都只启动一次。
3. knowledge/embed.ts、search.ts、auto-route.ts、tools.ts、gate.ts
   - 用户取消和超时同时覆盖 HTTP 请求头等待与 response.json() 正文等待。
   - 每段等待在 finally 清理 AbortSignal 监听；取消不会被当作普通网络失败降级。
   - 超时继续词法降级；查询嵌入在已通过外发授权的库之间按配置和查询词复用。
   - 取消前不写新的向量缓存，额度审计仍记录取消回执。

## 取消与真实 Git 验证

- knowledge-cancellation.test.ts 使用真实 127.0.0.1 HTTP 服务：
  - 响应头延迟 500ms、超时 100ms：得到 EmbedTimeoutError，服务端观察到响应连接在正文结束前关闭。
  - 已返回响应头但正文延迟 100ms：用户 AbortController 取消后请求拒绝用户原因，服务端观察到正文结束前连接关闭。
  - 成功请求用 addEventListener/removeEventListener 监视器确认两段等待的用户取消监听各自清理。
- results-aggregate.test.ts 增加真实 Git 集成：临时仓库提交基线后修改已跟踪文件并新增未跟踪文件，结果页正确读取 git diff 和 git ls-files。
- 同一聚合内的合法四卡场景验证相同项目、相同基线的 diff/stat/ls-files/status 复用；不同基线只复用不带提交参数的 ls-files，带基线的查询分别执行。
- desktop-read-model.test.ts 增加 _execution.jsonl 回归，确认索引扫描能结束并继续报告重复会话。
