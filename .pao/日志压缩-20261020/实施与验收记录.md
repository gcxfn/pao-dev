# 执行日志无损压缩（2026-10-20）

## 目标与范围

用户授权实施日志优化。沿用完整证据、运行中监督、异常中断留痕与原生用量核查的设计，不删减 pi 事件字段，不修改 pi 上游输出协议。

- 新运行日志执行期间继续原样追加，可实时查看；进程结束且停止已确认、句柄关闭后，仅对大于等于 256 KiB 的新日志进行 gzip 无损压缩。
- 小日志继续原格式。压缩失败保留原文件并告警，不能因为节省空间损失证据或伪报成功。
- 回执与执行映射指向实际存在的证据；既有普通日志兼容，运行中已发出的原始路径允许读取对应归档。
- 复用 pi 公开 read 工具适配入口，不另建日志查看器；保持分页、图片、取消及现有权限检查。
- 不扫描、压缩或删除既有历史，不触碰正式 PAO_HOME；不引入新依赖、配置和后台清理任务。

## 分工与验收

主代理实现运行器结算接线、真实子进程整合测试并审核。子代理独立实现标准库压缩/解压及 read 适配，写集分开。

测试包括真实字节回读一致、小文件与阈值、目标冲突/错误保留原件、损坏压缩可见、旧路径读取、运行中可读、正常结束/取消/失败/停止未确认边界，回执/用量/权限不回归。定向类型与导入边界检查；桌面有实际受影响读取入口时补真实 Electron 证据，不将模拟进程当作真实模型调用。

## 最终实现

- `shared/evidence.ts` 使用 Node 标准库流式 gzip；先完成临时压缩文件，再以硬链接独占发布 `.gz`，不覆盖已有目标，最后移除本次原文。任何失败均保留有效证据并说明残留；不支持独占发布的文件系统同样回退原文并告警。
- 运行器仅在进程退出、停止没有失败、live 完整且句柄结算后压缩 stdout/stderr。回执、live 字段及执行映射使用实际返回文件；压缩告警沿已有派发告警通道传回，任务结果与用量不因压缩失败被改写。
- PAO 注册同名 read 增强，复用 pi 的 `createReadToolDefinition` 与 operations 接口；普通文件、图片、分页、取消和动态 cwd 继续走原实现。禁用的 read 不被激活；worker 也没有新增派发或管理权限。自定义 operations 不被改成本地文件系统。
- 旧 live 路径读取先直接读原文，仅原文读取发生 ENOENT 时回退同名 `.gz`，避免“先检查存在，稍后原文被归档”的并发窗口。原文存在时不读取旁边的其他归档，不替任意文件猜后缀，损坏 gzip 或权限错误明确报告。
- 主代理审核发现同名 read 覆盖可能忽略用户图片缩放设置，已改为每次执行从 pi 公开有效设置 `getSettings()` 读取开关；不改上游 core，不另读设置文件。相关测试验证运行中设置更新生效。

## 失败与修复记录

首次 worker 定向检查有一项 PATH 垫片夹具失败。隔离 TMP 放中文目录后，夹具把 UTF-8 中文绝对路径写进 `.cmd`，被 Windows 默认代码页读成乱码，stderr 明确为 MODULE_NOT_FOUND。夹具改为 `%~dp0fake-worker.js` 定位，不改变产品的命令执行逻辑；原失败日志保留。

主代理目标碰撞整合测试曾拦下临时版本使用 rename 覆盖既有 gzip，已改为独占 link；新的真实文件碰撞检查通过。角色装载旧测试只允许 todo_write 的注册名称，与新增同名 read 增强冲突；更新为精确断言 read/todo_write，并额外断言 read 默认不激活，保留不允许 pao 管理工具的边界。不是删除失败断言或放宽权限。

## 实际日志副本验收

运行 `实际日志副本验收.mjs`，先复制历史日志到本轮隔离夹具，使用新实现压缩，再逐字节比较解压结果与原文，并验证旧路径读取。19 份日志合计 84,234,362 字节，处理后 2,787,921 字节，约减少 96.7%。所有副本字节回读一致，原历史日志未修改；数字与文件清单在 `实际日志副本验收.json`，stdout/退出状态在 `checks/corpus.*`。

## 验证层级与交付边界

测试使用真实文件、真实 gzip、真实 Windows Node 子进程及真实 AgentSession；子进程发出的是明确标注的模拟 pi 事件，不是实际模型运行。图片设置测试模拟图片处理函数核对配置传参，不宣称真实图片质量验证。未调用模型或记忆供应商。

本轮不改桌面代码：现有桌面定位证据只打开所在文件夹，执行历史读取的是映射和 pi 会话，没有直接读取 live 证据正文的独立入口。未运行真实 Electron 或重新打包，不替换当前安装应用。普通系统工具直接读取 `.gz` 仍需其自身支持 gzip；本轮保证 PAO read 的解压读取，不宣称所有命令都能透明读取。

类型检查与源码导入边界检查通过。额外运行的 `gate-kernel-import` 导入的是既有 dist/vendor，保留结果但不将其通过算作本轮新源码的构建产物验收。本轮未重新构建内核或 vendor。
