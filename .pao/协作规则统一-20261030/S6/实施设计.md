## 3. 旧实现的进程模型（S0 实测）

每次 `captureDispatchMap`：4 次 `rev-parse`（toplevel / git-common-dir / HEAD / HEAD^{tree}）+ 2 次 `ls-files`（tracked、untracked）+ 每文件 4 次（`show HEAD:path`、`show :path`、`cat-file -e HEAD:path`、`cat-file -e :path`）+ 1 次 `ls-files --stage -z` = **4n+7**。覆盖路径在磁盘不存在时每个再加 1 次 `ls-files`。Windows 单次 spawn ≈ 97ms。

## 4. 新实现的候选命令计划（目标 ≤9 个进程，与文件数无关）

固定部分（保留原语义）：
1. `rev-parse --show-toplevel`
2. `rev-parse --path-format=absolute --git-common-dir`
3. `rev-parse HEAD`
4. `rev-parse HEAD^{tree}`
5. `ls-files -z --cached --others --exclude-standard -- <coverage...>`：一次拿覆盖范围路径清单（须实测等于旧的两条命令并集：`ls-files -z --` ∪ `ls-files --others --exclude-standard -z --`）
6. `ls-files --stage -z`：全仓索引，用于 `repo.indexDigest`（保留原有"全仓、不按覆盖过滤"语义）

对象内容部分（替换 4n 次）：
- 方案 A（首选，语义最贴近旧实现）：单进程 `git cat-file --batch`，输入行为 `HEAD:<path>` 与 `:<path>`（与旧 `show`/`cat-file -e` 完全同源解析）。每条输入返回 `<oid> <type> <size>\n<内容>` 或 `<input> missing`。
  - `missing` → 该侧 undefined（等价旧 `cat-file -e` 失败路径）。
  - 输出必须完整读入后再解析；内容长度不足 `<size>` 或进程异常退出 → 抛 `missing_input`（不得用半份数据生成地图）。
  - **maxBuffer 风险**：单个 64MB 上限只在旧实现按文件生效。若总量可能超限，须先 `cat-file --batch-check`（1 个额外进程，输入同上）取 `oid/type/size`，再按字节预算（建议 32MB）分块用**纯 oid** 调 `cat-file --batch` 取内容。进程数 = 1 + ceil(总字节/预算)，随内容体积增长、不随文件数增长。
  - 方案 A 的已知限制：输入行不能含 `\n`/`\r`（行分隔），PATH 名含换行的文件在 Windows 无法创建（NTFS 禁止），在 POSIX 存在。→ 回退条件：**路径含 CR/LF** 时对该路径走旧的逐文件 4 条命令。此回退必须写清触发条件，并在 POSIX 上验证（本机 Windows 只能记录"平台不支持、未验证"，不得声称通过）。
- 方案 B（备选，免路径输入）：`ls-tree -r -z --full-tree HEAD -- <coverage>` 取 HEAD 侧 oid、`ls-files --stage -z` 取索引侧 oid，再用 1 个 `cat-file --batch`（纯 oid）取内容。
  - 风险点须先实测并与旧实现对照：submodule/gitlink（`show HEAD:sub` 与按 commit oid 取对象的输出是否一致）、intent-to-add（`git add -N` 后 `cat-file -e :path` 的行为，`ls-files --stage` 报出的 oid 是否会导致新实现凭空多出 indexDigest）、unmerged 索引（stage 1/2/3 与 stage 0 缺失）。

**选择规则**：以"与旧实现 artifact 逐字节等价"为唯一裁判。方案 A 不能满足（如 gitlink、超大文件）则用方案 B + 明确回退，或 A/B 混合（回退仅限实测证明有差异的条目类别），回退条件必须能被测试触发。

## 5. 语义保真清单（实现与审查都要逐条对照）

- 覆盖路径归一与校验：`normalizeCoverage` 的空数组/非法字符/越界/去重/排序错误码 `missing_input`、`bad_reference`、`unsafe_path` 不变。
- 覆盖存在性：`coveragePathExists` = 磁盘存在 或 `ls-files -z -- <path>` 非空；缺失时错误消息与 details `{coverage, missing}` 不变。
- 路径清单：显式覆盖项若是磁盘上的文件也要加入；排除项按 `path === item || path.startsWith(item + "/")` 过滤；结果 sort；路径串统一 `/`。
- 每文件三份摘要：head ⟺ 该路径在 HEAD 树中；index ⟺ 该路径在索引 stage 0 中；working ⟺ 磁盘存在且 `isFile()`（空文件 Buffer(0) 也算存在）。`contentDigest = working ?? index ?? head`，都无 → `sha256Text("<pao:missing>")`。`size = working?.length ?? 0`。
- `repo.indexDigest = sha256Bytes(<ls-files --stage -z 原始字节>)`，`untrackedDigest = digestObjectExcluding(snapshots.map(fileIdentity), [])`。
- `scopeConfirmed/scopeBasis/scopeReviewRequired/status/reason` 逻辑不变；`capturedAt` 缺省用当前时间（基准测量时固定）。
- 错误传播：`spawnSync` 的 `error`（ETIMEDOUT/EACCES/被杀）→ `DispatchBriefError("missing_input", "Git 读取失败：…")`，消息要含 `gitProcessErrorText` 的输出（超时含 `30000ms`、含 partial stderr）。

## 6. S6-4 并发变化与取消（必须有明确结果）

- 采集期间文件变化：一次采集内不混合"旧快照+新快照"形成可用地图——同一批读取的索引字节与工作区字节来自同一时刻附近；若单个文件在读取时报错（如被删除/占用），抛 `missing_input`（与旧实现一致）。
- 文件在 ls-files 之后被删除：工作区侧缺失 → working undefined（旧实现同样按磁盘读，行为一致）；不得把半份内容当有效。
- Git 失败/超时：批处理进程整体失败 → 明确报错，无部分结果。
- 取消/中断：不额外注册信号处理；同步调用本身不可中断，保持现状（不新增行为）。
- 子进程回收：仅用 `spawnSync`（已回收）；不改成常驻或异步子进程。
