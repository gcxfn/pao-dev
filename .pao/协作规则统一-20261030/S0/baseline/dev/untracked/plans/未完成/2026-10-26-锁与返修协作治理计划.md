## r36 回执候选唯一性返修补救（2026-10-28）

上一节把“JSON 加坏候选继续拒绝”写成已验证，但主控用无模型 Node 探针复现了缺口：

```text
inline_second_receipt accepted=false
inline_malformed_second_receipt accepted=true kind=fenced
unlabelled_malformed_second_receipt accepted=true kind=fenced
PROBE_EXIT=0
```

探针进程本身总以 0 退出，验收必须读取三个 `accepted` 值。两个 `accepted=true`
分别来自说明文字后同一行的损坏 JSON，以及无语言围栏里的损坏 JSON；当前行首/
冒号启发式没有把前者计入候选，未标语言围栏又只统计可完整 `JSON.parse` 的正文。
因此“先忽略坏候选、再选择剩余合法围栏”仍可发生。上一节的完成记录保留为历史，
以本节返修和最终证据替代其验收结论。

### 共同候选语义

1. Markdown 围栏边界仍由单一原文行扫描器负责：成对围栏才进入围栏候选；未闭合、
   嵌套或伪围栏继续失败。显式 `json` 语言围栏无条件计为回执候选；无语言围栏只有
   正文明确像 JSON 尝试时才计候选，未标语言 shell 方括号命令仍不计。其他语言的
   普通命令块不计回执候选。
2. 围栏外文本由单一 JSON 外层边界扫描器负责。任何明确像 JSON 对象或数组尝试的
   `{`/`[` 都形成候选起点；找到配对结束符后直接跳过整个值的内部，内部
   `artifact_path`、`changes` 等数组不得再次形成外层候选。不能按行首、冒号、
   语言名或具体样例内容筛选。
3. “候选计数”和“候选解析”分开：先按上述边界统计所有候选，必须恰为一个；
   多于一个立即因不唯一失败。唯一候选再交现有 `JSON.parse`、严格 schema、真实
   产物存在和自报字段校验，不能解析失败后回头挑选另一个候选。
4. 明确像 JSON 的损坏候选必须计候选并失败；普通说明中的 CSS/HTML 花括号和
   未标语言 shell 判断不计。为拒绝这些损坏候选，可以保守识别带引号对象键、

   语义全部保留。恢复只是把同一候选送入原严格正文解析，不等于 delivered，不跳过
   机械验收或 owner 审核。

## r36 观察器终态事实与新轮 wrapper 修复（2026-10-28）

r36 主控已签收当前回执修复；本轮只处理无人值守观察器的终态事实报告与下一轮
wrapper 的退出传播，不扩大 receipt 或 benchmark 题目边界。

### 已确认缺陷

- r36 控制状态为 `execution_error`、已停写；当前
  `terminal_facts.business_failed` 仅判断 `status == "failed"`，错误报告为
  `false`。
- r36 唯一 `result.json` 含 `exception_info` 且
  `verifier_result=null`。当前观察器把任意 result 文件当作正式结果，
  将缺失 reward 记为 `formal_result_without_valid_reward`，再概括为
  “存在正式评分结果但奖励畸形”。这是 trial 异常结果，不是官方 verifier
  运行，也不是畸形 reward。
- r36 collector 实际 exit 0，但旧 wrapper 在 `PSCustomObject` 上直接新增完成
  字段而 exit 1。旧 wrapper 与 r36 收据冻结，不改写。

### 定案

1. `bench_controller.control-status.json.state` 保持唯一控制状态来源。
   观察器报告原始 `business_status`；缺失时为 `unknown`。
2. 增加 `business_finished`，仅 `finished` 为 true。
   `business_failed` 兼容为 `bool | null`：明确失败状态 true，`finished` false，
   `paused`、`running`、`preflight`、`unknown` 等未知/非终态为 null。
3. trial result、官方 verifier result、有效/缺失/畸形 reward 分开表达。
   含 exception 但没有 `verifier_result` 的 result 只作为异常 trial 证据，
   不冒充官方评分。真实 0.0 有效；布尔、字符串、NaN、Infinity 仍畸形。
4. 暂停不等同成功或正常作答；控制器 crash、预检失败、机制停止和缺失分均保留
   原异常并如实分类。
5. 正式终态仍要求控制器、全部本轮容器、身份范围和 writers 停写/既有明确异常
   路径同时满足；容器身份、scope 与停写门不放宽。
6. 新轮 wrapper 仅新增于本轮临时目录。用安全属性更新方式写收据，等待一个真实
   collector 并以其真实 exit code 退出；旧 r36 wrapper 不改。
