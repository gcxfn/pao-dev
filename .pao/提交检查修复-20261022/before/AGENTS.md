# PAO 内核开发规则

本目录是 pi 的 PAO fork。项目级长期规则以父目录 AGENTS.md 为准；本文件只补充内核开发约束，不记录版本、测试数字、当前进度或历史经过。

## 代码边界

- 内核公开接口与 CLI 启动入口分离；导入内核不得自动解析命令行、启动终端、修改全局工作目录或注册进程退出钩子。CLI 与桌面分别装配会话与生命周期，复用同一内核实现。

- PAO 业务代码放在 `packages/coding-agent/src/pao/`，上游 pi 代码保持原样，除非公开接口确实无法满足需求。
- 优先使用 pi 的配置、公开 API 和扩展钩子；必须改上游时，先记录接口缺口、影响范围和升级验证办法。
- 模块通过小而明确的公开接口协作。入口文件负责装配，业务规则、文件读写、进程管理和界面表达分别归属对应模块。
- 工作流只决定流程，执行层只负责执行，卡片模块只负责状态与回执；底层不依赖桌面或终端。
- 可插拔只指可替换实现的接口与装配点。没有真实需求时，不新增插件市场、动态加载、注册中心或通用依赖注入框架。
- 终端、桌面和不同执行入口复用同一业务规则与数据契约，不各自维护状态真相。

## 修改与验证

- 修改前先读相关模块和调用链；已有代码图时先查影响面。
- 一次重构只处理一个清晰边界；计划要求的内部英文命名可在本模块同批迁移，不夹带无关改名或格式化。
- 不擅自删除能力或改变产品流程；经用户决定后，更新开发根 `plans/` 定案再实施。
- 代码改动后按本仓库要求运行检查；修改测试文件时运行对应测试。不要运行全量测试或构建，除非任务要求或项目规则指定。
- 禁止在 `packages/*` 成员包目录内单独执行 pnpm/npm install——会在成员包内生成局部 node_modules，把 workspace 依赖劫持成 registry 上游副本，构建按真实路径解析后打进错误内核且难排查（2026-10-08 bundle 回归实证）。装依赖只在仓根做。
- 不提交本轮之外的文件，不重置、清理或覆盖其他工作区改动。

## 命名

- 新代码标识符使用 ASCII 英文；注释、界面文案和文档使用中文。
- 卡片协议的中文 frontmatter 键是外部契约，不能因重构改名。
