# 分层监督与后台结果

主控负责部门，部长负责本部门工人。派发受理后，上级结束当前模型轮次；宿主继续运行后台任务。结果先落到卡和回执，再投递给直接上级并唤醒。可自动推进的依赖仍由工作流驱动器处理，主控接收部门交付、异常升级和待裁决事项。

模型结束回答不会关闭会话；用户关闭会话或显式停止仍结束受控后台进程，不自动重启。

## 配置

配置位置为 `PAO_HOME/pao配置/保温.json`，合并到已有文件，不覆盖其他键：

```json
{
  "工人监督分钟": 15,
  "部门监督分钟": 30
}
```

时间监督默认分别为15、30分钟；显式设0关闭对应级别。旧的 `工人监督轮次`、`部门监督轮次` 不配置或设0时不触发。工具调用数不作为默认周期触发条件。轮次、调用提示线与预算上限仍是各自独立的功能，不等于周期监督。

`worker 静默分钟` 仍是另一条保护：默认连续30分钟没有输出才提醒。时间监督即使工人持续输出也会到期检查，不能用静默提醒代替方向检查。

## 检查与交接

监督材料包括任务目标、近期实际进展、改动、检查结果、阻塞和证据入口。上级对照目标判断偏航、重复劳动及无关扩展；需要时才展开原始证据。普通监督不自动暂停或终止工人。

同一上级同时到期的事项合并投递；已投递待处理的检查不重复唤醒。收到提醒并实际检查后，调用 `pao_ack_supervision`，把提醒中的对象标识原样填到 `key`，才从处理时间重新计时。多项提醒逐项确认。单纯收到通知、模型结束回答都不表示已经检查。

完成、失败和需要裁决的结果立即投递，不等定期检查。已完成或正在等待用户决定的对象不参与定期检查。会话切换与关闭会清理该会话监督，结果和回执仍可按原有入口查询。

小任务通常交一张卡，只有独立风险、接口边界或可分别验收的成果才拆开。已有证据能够覆盖的检查可直接复用。同一执行目录按写锁顺序运行；需要真正并行修改时，使用项目已有的独立受管工作树，不能通过取消写锁实现并行。

## 验收与失败恢复

可以机械判断的卡验收使用现有 `跑:`、`存在:`、`包含:` 句式。自然语言条目需要负责者判断，不能把0项机械检查称为完整通过。非Git项目仍可使用，但自动核查不能据此证明“没有越界”。

工人末消息严格解析失败时，运行器只尝试提取唯一、完整且符合原格式的 JSON 围栏；保留原始末消息、严格错误和恢复说明证据，同次处理，不重做整卡业务。没有唯一有效候选仍失败，历史已终结卡不会倒填。恢复仍核对卡片、当前尝试、执行绑定和产物，并经过原机械验收与交付审核。

具体实现与验证范围以开发项目的[实施报告](../../.pao/分层监督与后台交付-20261021/实施与验收报告.md)为准；离线模型替身测试不代表真实模型协作效果或费用收益。
