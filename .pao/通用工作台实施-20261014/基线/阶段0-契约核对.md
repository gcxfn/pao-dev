# 阶段 0 第 5 项：实施契约核对（会影响实现的决策）

记录日期：2026-10-14。完整契约见计划第 4 节；本文件只固定「阶段 3 开工前必须没有未决」的存储、身份与启动关联，并记录核对现有代码后得出的结论。

## 1. 三个对象与落盘归属（已固定）

| 对象 | 归属 | 说明 |
|---|---|---|
| 临时计划定义 | `<项目>/.pao/临时工作流/<planId>/计划.md` | 稳定 `planId` 由内核生成；同目录保留最小「未执行编辑版本」供撤销；首次执行后冻结 |
| 执行实例 | 现有 v2 控制正本 `<工作区>/工作流实例-<派生配方名>.md` | 只存冻结配方、实例 ID、owner、节点轮次、任务卡、回执、控制记录；不复制到计划目录 |
| 已保存模板 | 现有部门/全局模板库（`readDesktopRecipeCatalog` 读取处） | 白名单字段提取；不含会话、卡号、实例状态、本次成果路径 |

显示名可重名、可含空格，**不参与拼磁盘路径**；内部配方名由稳定 `planId` 派生。证据、设定与正文放项目普通目录（如 `创作成果/<planId>/<步骤ID>/<轮次>/`），**不能**放 `.pao/`（整区被排除在差异检测面外）。

## 2. 执行目录与启动关联（已固定的结论）

核对现有代码（`src/pao/workflow/control.ts`）：

- `controlPath(recipe, options)` = `join(options.workspaceDir ?? dirname(options.cardsDir), "工作流实例-<配方名>.md")`。
- `startControl(recipe, params, options)` 的入参就是**配方对象**，它自己 `structuredClone` 冻结配方并写进控制正本；**不读全局模板库**。因此「把项目内临时定义接到 v2 启动」不需要改动执行核心，只需要在共享工作流边界新增一个分支，负责：
  1. 解析计划定义 → 适配成 v2 配方（步骤 ID → 合法节点名）；
  2. **先持久确定本次启动请求对应的执行目录**（写入计划目录下的启动关联记录），再调用 `startControl` 受理；
  3. 返回真实实例身份（实例 ID、控制清单路径、卡目录）与受理状态。
- `startControl` 已有守卫 `实例已存在；保留原件，禁止隐式重启覆盖`；`startControl` 还要求 `options.ownerSessionId` 非空、`recipe.版本 === 2`。
- **差异与补法**：现有入口把「已存在」直接当失败抛出，不能支持「同一启动请求重试必须找回原实例」。新分支在捕获该错误前先按逻辑启动请求 ID 查启动关联记录，命中就回读该实例并返回真实身份；只有「关联存在但实例不完整」才报待恢复原因，绝不再启动第二份。

结论：**第 4 节不存在会影响实现的未决存储/身份问题**；待阶段 3 落实的只是边界适配与关联记录，不是执行核心改造。

## 3. 主控串行与外部忙碌守卫（已固定）

- 主控工具在原会话内串行执行，不能照搬外部入口「会话必须空闲」的判断；外部请求的忙碌守卫保留。
- 新通道通过「原 owner 内串行工具入口 + 同一业务检查」启动，不新增第二套调度状态。
- 创建工具成功只表示**计划落盘**，不表示已启动；启动不保存模板；保存模板不改变当前执行。

## 4. 重复请求与显式确认（已固定，对应计划 4.4 的 7 条）

1. 创建/启动/保存模板各带可持久识别的逻辑请求 ID；同逻辑操作重试沿用原 ID，参数变化仍复用同一 ID 则拒绝。
2. 在项目/计划锁内重读并检查版本；并发重复创建只落一个定义，启动只受理一次，模板保存只产生一个目标版本。
3. 启动器先有稳定执行身份再建关联；控制文件已形成但返回丢失时，重试必须找回原实例；只有不完整启动才显示待恢复原因，禁止再启动第二份。
4. 不用「内容相似」合并不同任务；同名计划可并存，靠项目/来源会话/稳定 ID 区分。
5. 对话确认必须关联当时展示的计划版本；确认事实只能由宿主确认回调或可信用户交互事件提供，并绑定 `planId + 定义版本 + 启动请求 ID`。**模型传入的 `confirmed: true`、自行转述「用户已同意」、普通助手文本均无效**；等待确认期间不持长期文件锁，返回后重核 owner/版本/预检再在锁内受理；无桌面集成时用明确模拟的宿主确认回调。
6. 创建不启动，启动不保存模板，保存模板不改变当前执行；未请求保存不自动入模板库。
7. 重开应用只恢复查看与连接现有状态，不静默重派；机器重启后遗留在途按现有租约/恢复规则显示，用户明确恢复后才继续。
