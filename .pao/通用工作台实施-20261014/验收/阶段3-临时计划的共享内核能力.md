## 逐项对应与验收

### ① 计划定义读写、版本与编辑撤销（在 workflow 边界内）
- `createTemporaryPlan`：稳定 `planId`（`p-YYYYMMDD-<6 hex>`）、定义版本从 1 起、步骤 ID 按顺序发号（`s1`、`s2`…）且**改标题不改 ID**；落 `<项目根>/.pao/临时工作流/<planId>/计划.md`，同目录保留关联与撤销记录；**创建只落定义，不落执行目录、不落卡、不启动**。
- `modifyTemporaryPlan`：带 `预期定义版本` 的修改，版本递增；`undoTemporaryPlan` 也是一次带版本检查的修改（写 `已撤销: true`，保留定义文件不删用户内容）；已启动的定义被冻结（`PLAN_FROZEN`）。
- 用例：`test/pao/workflow-plan.test.ts` → **24 passed**；工具面 `test/pao/workflow-plan-tools.test.ts` → **11 passed**（含真实启动一次 v2 实例）。
- 命令：`npx vitest --run test/pao/workflow-plan.test.ts test/pao/workflow-plan-tools.test.ts test/pao/workflow-driver.test.ts` → **3 files / 58 passed**。

### ② 接入既有配方校验
- `planToRecipe` 把计划步骤适配成 `WorkflowRecipe`（`版本: 2`），再交给既有 `parseRecipe` 校验；未知部门、环形依赖、失效版本、审核缺部门标准、回边越界都在这一层被拒，不另写一套规则。
- 配方名由稳定计划 ID 派生（`planRecipeName`），**不拿显示名拼磁盘路径**；显示名可重名含空格。
- 用例：`workflow-plan.test.ts` 的「结构/依赖/成环/未知部门」组。

### ③ 第 4.3 节业务动作
- 创建：必须带逻辑 `request_id`，同一请求重试是回放、**参数变化复用同 ID 被拒**；并发重复创建只落一份（同项目锁内查重）。来源会话由宿主注入（`resolveOwnerSessionId`），项目根由宿主解析。
- 修改/撤销：带 `expected_version`；版本漂移被拒。查询/恢复查看：`queryTemporaryPlan` 列定义、版本、步骤与已启动关联（含实例/工作区/卡目录），读不出来的定义或坏关联逐条点名，**不重建假状态**。
- 保存模板：字段白名单，不含会话、卡号、实例状态；本次特有路径默认拒存并列出，显式允许才原样保留且点名；同名不覆盖；保存模板不改变当前执行。
- 对步骤/文件提意见不在本阶段（属阶段 4 界面面）。

### ④ 项目内定义启动分支（重复启动恢复、关联回读、部分启动错误）
- 执行目录在**首次启动受理时先持久确定**（`planExecDir(项目根, planId, 启动请求ID)`），同一 `start_request_id` 重试复用原目录并**找回原实例**，不会起第二份。
- 复用既有 v2 启动：`startWorkflowCore`（预检 → owner → 冻结配方 → 控制正本 → 自动链），既有模板启动入口保持兼容（本阶段未改其行为）。
- 真实实例身份只从盘上读（`readPlanInstanceIdentity` → 控制正本 frontmatter），不拿请求参数当结果；控制正本已形成而关联丢失时报 `PLAN_START_PARTIAL`（可恢复原因），不擅自再启第二份。
- 验收用例（工具面真实链路）：`用户确认后真实受理：返回真实实例与执行目录；同启动请求重试找回原实例`；`已启动的计划被冻结：不能再改再撤`。

### ④ 显式确认边界（第 4.4 节⑤）
- `pao_plan_start` 必须有宿主确认事实：**模型传 `confirmed: true`、转述「用户已同意」都构造不出该对象**（工具参数里根本没有该字段）。
- 确认事实只能来自：宿主注入的 `requestConfirmation`（`来源: "宿主确认回调"`），或复用既有 `ctx.ui.confirm` 的真实用户交互（`来源: "用户交互事件"`）。两者都必须与 `计划ID + 定义版本 + 启动请求ID` 三者一致，否则拒。
- 等待确认期间不持文件锁；确认回来后**复核定义版本与撤销状态**再受理（旧确认在计划被改后失效）。
- 用例：`没有宿主确认回调也没有界面时一律拒`、`确认事实必须与计划/版本/启动请求三者一致：错版确认被拒`、`界面确认（ctx.ui.confirm）也认，且用户拒绝就不启动`。

### ⑤ 保存模板
- 白名单字段：部门/目标/验收/依赖/约束/技能/预算/人工门/审核回边；参数化本次特有路径；同名模板不覆盖；落 `<PAO_HOME>/工作流/<模板名>.md`。
- 用例：`本次特有路径默认拒存并点名；显式允许才原样保存，且不含会话/卡号/实例状态`、`同名不覆盖`。

### ⑥ 用例覆盖（正常/非法/并发/写失败/响应丢失/进程中断）
- 正常：创建、修改、撤销、查询、真实启动、存模板全链路。
- 非法：未登记部门、依赖越界、环形依赖、未知字段类型、错版确认、无确认事实、已撤销再改/再启、已启动再改。
- 并发：同 `request_id` 并发创建只落一份（`Promise.all` 两路）。
- 响应丢失：控制正本已形成但关联丢失 → `PLAN_START_PARTIAL`（不重复启动）。
- 进程中断/重开：关联回读按盘上控制正本恢复（`resolvePlanExecution` 的 `找回`），不静默重派。
- 既有 v2 流程与 v1 读取无退化：`workflow-driver.test.ts` 23 passed、`workflow-auto-chain.test.ts` 48 passed（第 10/11 项反向验证已复原）。
