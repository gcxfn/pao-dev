# 最小交接契约建议

A 时已有卡、尝试、回执、锁、工作流和桌面工作树能力。后续修复应复用这些结构，只在必要处增加关联，不另建任务状态源。

## 1. 身份

一次执行至少绑定：

```text
cardsDir + cardPath + cardNo + attempt + owner
workflowInstanceId + roundId（适用时）
requestId
repositoryId + projectRoot + executionRoot + worktreeId
baseHead + baseTreeId + currentTreeDigest + inputVersion
```

`projectRoot` 说明源码和任务上下文属于哪个项目；`executionRoot` 说明模型实际在哪个工作树读写；`cardsDir` 仍归属共享任务状态。三者不能靠路径尾名或标题猜测。

稳定 `requestId` 的规则是：同一逻辑请求复用同一 ID，同 ID 同参数返回原受理或结果，同 ID 不同参数明确冲突。重复建树、派发和整合请求都沿这条规则查回，不能重复产生副作用。

## 2. 源码基线

基线引用应携带：

```text
sourceRef + HEAD + tracked/index/working digest
includedUntracked + excludedPaths
archive/snapshot location + capturedAt
```

摘要用于确认输入一致，可恢复字节用于实际恢复。用户已有 tracked 修改、相关 untracked 源码和文档应保存；运行数据、发行物、依赖目录和凭证按清单排除。捕获前后变化必须重核，不能靠“HEAD 相同”推断工作区相同。

任务开始、取得写锁和真正启动前应核对同一基线身份。没有安全基线时停止写入并报告缺口，不自动 stash、reset、提交或把用户主目录的内容猜测复制到工作树。

## 3. 地图

地图引用至少包含：

```text
ref + digest + schemaVersion
repo + HEAD + tracked/untracked digest
coveragePaths + excludes + sourceRefs
facts + unknowns + relations + risks + replacementOf
validity: valid | stale | unknown
invalidatedBy + integrationOwner
```

事实标明证据位置，未知项不能升格为事实。地图只服务调查复用，不存任务完成状态。派发前按覆盖范围重判；局部变化只补对应范围，核心输入变化才扩大复核。旧版地图和替代链要保留，使旧尝试仍能解释当时依据。

## 4. 接口契约

每项跨部门接口指定唯一正本引用、版本、内容摘要、用途和受影响任务。简报只携带本任务必要摘要并指向精确版本。升版时记录原因和影响，派前拒绝已知冲突旧版本；运行中通知相关任务重新确认。自然语言“理解一致”不能代替类型、契约测试或实际调用。

## 5. 简报与冻结

简报正文应直接进入接收方本次输入，至少包括任务目标、范围与限制、已确认结论、未知项、接口与依赖、验收、证据入口、执行及整合位置。路径清单和“先读卡”不能代替正文。

派发时冻结：

```text
briefRef + briefDigest + frozenAt
mapRef + contractRefs + evidenceRefs
inputVersion + executionRoot + integrationOwner
```

任务后续编辑不能静默改写正在使用的简报；新要求沿现有版本或轮次回流。接收方可在任务范围内读目标代码和依赖核验，首次发现的新缺口正常退回，不要求全过程零追问。

## 6. 依赖、写保护与执行

- 依赖未满足不启动；共享卡、额度、预算和依赖用现有共同短锁或原子更新保护。
- 同一执行目录的代码写入必须互斥；不同工作树不应被整项目长锁无谓串行化。
- 取得锁和实际启动前核对同一输入版本。
- 取消或停止未确认时保持占用；只有真实停止后才能释放 `StopProof` 和写保护。
- 崩溃或重开先只读盘点，不自动清锁、重跑、删除或覆盖成果。

## 7. 回执、整合与清理

回执绑定上述任务和执行身份，并记录实际改动、工作目录、证据版本、命令、退出状态和完整日志位置。测试后修改代码，原测试不能证明新字节；未运行、未知、失败和通过分别表达，用量缺失不填零。

整合在受控工作树进行，记录输入、目标基线、输出和检查结果。文本合并没有冲突不等于接口兼容；语义冲突交负责人修订后重验。局部检查、整合检查和独立审核是不同结论。

清理前至少确认：没有活动执行；成果已提交保留、合入或明确放弃；目录属于本任务管理范围；真实路径和工作树身份安全。任何条件不满足都保留目录和证据。

`dispatch-brief` 新目录属于 B/C 实施中的候选模块，A 基线时尚未进入产品入口；上面的字段是交接要求，不是对其现有持久化字段的验收声明。
