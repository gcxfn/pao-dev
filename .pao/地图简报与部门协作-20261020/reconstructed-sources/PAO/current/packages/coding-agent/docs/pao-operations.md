# PAO 运维任务与交付复核

## 部门与复核责任

`dept` 用于选择部门配方、工具权限、默认模型档位和任务归属。它不自动启动部长，不代表部门已经复核。直通卡由 owner（任务负责人）检查成果；需要部门复核时，显式启动部长或另派审查卡。

需要运维配方时，经现有建部工具显式创建，例如 `pao_create_dept` 的 `name="运维"`、`preset="operations"`。模板包含环境诊断、清理预演、安全跳过、证据与 JSON 回执约定。普通建部沿用既有骨架，重复建部不覆盖已有定制；程序不会自动在正式 PAO_HOME 新建部门。

## 卡状态与尝试结果

卡状态描述任务当前由谁处理、是否交付；回执结果描述某一次工人尝试的结果。例如 `in_progress` 与最近尝试 `failed` 可以同时存在，表示工人本轮失败，负责人尚未裁决卡片后续。不能仅凭回执成功就宣称已交付，也不能仅凭缺少 JSON 就断言实际工作没有完成。

回执格式缺失时，实际成果处于待复核状态。负责人检查当前尝试的文件与证据后，可使用 `pao_change_status` 转为 `delivered`，填写 `basis`（验收依据）；工具仍会核对机械验收、越界和当前回执，失败项不能靠一句依据绕过。已经落入 `failed` 的卡仍遵守原状态机，不通过手改卡面改变状态。

## 自报未达项的逐项复核

工人自报 `verification` 中的 `fail/not_run` 会停在人工复核。负责人必须确认本次未达项的实际影响，在 `pao_change_status` 的 `accepted_deviations` 中逐项填写：

```json
{
  "attempt": 1,
  "verification_index": 0,
  "condition": "当前回执中该条件的完整原文",
  "basis": "核对过的证据，以及接受这个未达项的具体原因"
}
```

`attempt` 必须与当前卡片尝试号一致；`verification_index` 从 0 开始，与本次回执的 `verification` 数组对应。同名条件也要按索引分别复核。必须恰好覆盖全部未达项，同时填写整体 `basis`，旧尝试的参数不能用于新尝试。真实机械失败、越界、验收声明变更与 `blocked/checkpoint` 仍会阻断交付。

## 删除前预演

需要删除的卡在正文显式声明目标，逐行列出项目相对路径或明确的绝对路径，不使用通配符：

```markdown
## 删除目标
- `缓存/旧文件.log`
- `临时产物/`
- `C:/Users/某用户/AppData/Local/Temp/明确待删目录/`
```

负责人先调用 `pao_preview_cleanup`，提供 `card_ref`、`operator`，必要时指定 `cards_dir`。它只扫描待删内容与 Git 跟踪情况、保存预演，不启动工人执行删除。核对清单、授权和保留要求后，再调用 `pao_confirm_cleanup`，使用相同卡号与负责人，并显式传 `confirm=true`。最后沿原派发入口启动任务。

目标或文件状态变化需重新预演确认。目标没有可用 Git 时清单明确标记未核查，不能拿任务项目的 Git 结果冒充目标所属目录的核查；证据、卡片、预演确认文件与 Git 元数据不得成为删除目标。目录内出现链接时拒绝穿透扫描，不把链接指向的外部目录当作可删内容。这里只约束声明了删除目标的任务，不承诺识别所有任意脚本中的删除行为。

确认仅在发出确认的应用进程内有效；应用重启或扩展重新加载后需重新确认，卡正文中手写“已确认”不能替代确认工具。

## 证据、路径与环境

- 工人证据默认存任务工作区的 `worker-evidence/`，不再依赖系统 TEMP；清理时必须保留本任务证据。
- `存在:` 和 `包含:` 的相对路径以项目根为基准，不以报告所在目录或卡目录为基准。查不到文件时先核对报错中的项目根与实际读取路径。
- 非 Git 目录允许执行合法任务，但“越界核查未执行”必须按未检查理解，不能当作无越界。
- PAO_HOME 是运行数据根，不是开发源码目录。诊断应显示实际根与缺失配置；缺少注册表也可能是尚未建部，不能单凭这一点判断误指开发仓。
- Windows 本地写入 `.ps1` 使用 UTF-8 BOM，使 PowerShell 5.1 能识别中文；其他文件和远程自定义写入操作沿原行为。通过 `powershell`、其他程序自行生成的脚本，仍须由生成方指定正确编码。

自动交付不会替负责人接受自报未达项。磁盘空间验收未纳入本轮修复。
