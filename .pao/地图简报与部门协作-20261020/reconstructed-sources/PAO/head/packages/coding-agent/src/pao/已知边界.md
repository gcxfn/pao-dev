# 已知边界（pao 自有代码）

2026-10-03 K3 审码修复批遗留的观察项：都是「知道、拍板暂不修」的边界。动相关代码前先读这页；修掉一条就把它从这页删掉。

1. **散场审计与树杀顺序耦合**：`host/host.ts` `#散场Entry` 先树杀、后落监督审计行——若 killTree 本身抛错，该次散场不会留下审计记录（交接页若已落盘则仍有痕）。修法（审计包进 try/finally）极小，按 2026-10-03 拍板暂不修。
2. **「留 owner」停因靠文案匹配**：`workflow/tools.ts` 的结构化挂起字段是主判据，`chain.停因.includes("留 owner")` 只是兜底。改停因文案会静默击穿兜底——改文案前先改判据。
3. **派发超时的分钟粒度**：保温.json「派发超时分钟」只收 ≥1 的整数，小数或 0 会被拒收并回落默认值。派卡非阻塞化（静默提醒）重构落地时会重写此段，届时一并处理。
4. **工作流节点名的空格不对称**：流名三入口已禁空格；配方节点名带空格时写入与读取的规范化路径不一致（同病、流名已治节点名未治）。新配方节点名避免空格；收口时补同款禁令。
5. **卡状态机读-合并-写后的小竞态窗**：`cards/statemachine.ts` `changeCardStatus` 会重读最新卡再校验写入，但两个写者同毫秒读到同一版本时仍可能互相覆盖。单写者协议（只有 owner 改状态）下窗口几乎不可达；真要堵需文件锁，代价大于收益，故只记。

另：事件线型教训（测试注入的形状必须与生产线型一致）已固化在 `test/pao/host-events-wire.test.ts` 的反漂移钉里，不再作为观察项列此。
