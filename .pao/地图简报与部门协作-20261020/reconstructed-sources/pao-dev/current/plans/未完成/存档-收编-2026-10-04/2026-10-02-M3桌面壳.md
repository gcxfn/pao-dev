# M3 桌面壳

建稿：2026-10-02。状态：**完整计划已编制；待终端核心稳定后执行**。

依据：需求 §1/§5/§6，架构 §2.2/§8.9。用户要的是独立桌面入口，但内核依旧为外部锁版 pi＋PAO，不另造 agent 产品。

## 目标

桌面里能对话、选项目/档位、派卡与取消、查看队列/回执/证据、完成需要人的确认；与终端读取同一套真实卡片和 pi 会话。关闭桌面及其所拥有的主会话时，受管执行停止。

> 2026-10-02 用户给出关键需求三件：**可视化**（队列/回执/证据看得见，对应 M3-02 只读看板为核心卖点）、**快速稳定**（启动/刷新响应与故障退出进选型验证标准）、**与 CLI 同一后端**（纯壳定案的重申，零第二状态）。详细需求持续对齐、逐步细化，不在此刻定死。

不要求桌面首版复刻所有终端装饰。必需确认不能因为 UI 不支持而默认同意；不支持的交互明确说明和阻止相关危险路径。

## 开工条件

M2 核心终端能力和卡片契约稳定；可以没有启用 worktree/历史检索等条件项。明确“桌面拥有哪个 pi 会话/进程”及双窗口的只读/接管规则。

先读锁版 `docs/rpc.md` 与 `docs/rpc-extension-ui.md`，查看实际 RpcClient/类型；不要拿最新网页接口直接套旧安装件。官方 RPC 区分命令接收、运行事件与结束；这些都不能直接等于 PAO 的验收通过。[E5/E10]

复用 pi RPC/RpcClient、M1/M2 队列与文件解析、既有配置和身份校验。壳仅调用现成 PAO 操作，不通过界面直接改卡 frontmatter。

框架已随 fork 定案（Electron＋React＋TS，随 pi-gui 上游）。仍守两条边界：壳不嵌 pi/pao 源码为第二内核（驱动走 driver 适配层指 pao 构建产物）；不引入服务端和登录系统。

## 桌面在场调度（2026-10-02 用户拍板「用户态常驻就是我要的」）

桌面端＝**用户态常驻调度器**（架构 §16.2 v2 的宿主），桌面开着时承担：

- **定时机械活**：巡检/归档/保温——到点由桌面主进程 spawn headless 机械子会话执行（值守角色最小工具集，登记红线照 §16.2；子会话不参与会话锁，桌面关闭即死）。
- **实时通知**：文件监听→Windows toast（卡交付、后台扇出完成、巡检 ⚠️）——补 §19「有人在场的时刻」在桌面形态下的实时性。
- **缓存预热**：知识库索引/嵌入向量留在桌面进程内存，查库零冷启动。

三条铁律（架构 §16.2 同款）：调度器只触发，状态真相在文件；机械子会话生命周期绑定桌面壳（M3-04「壳关闭停止自己拥有的子进程」）；桌面不是必需品，终端用户有惰性兜底。桌面要不要开机自启＝用户对 Electron 应用的常规选择，不算系统注册垃圾（pao 自身不注册任何系统项）。

## 可视化面板与实时进程（2026-10-03 讨论定案，用户拍板）

> **形态**：编排可视化是**右侧（或上方）独立面板区域，不嵌在对话消息流内**（用户原话「卡片渲染是在右侧或者上方单独的区域，不在消息内」）。倾向右侧 Work Panel（可折叠）：pi-desktop 同款、对话流保持主视图不被顶部横条挤压、部门树纵向结构适合竖栏；终版随 M3-02 实测定。参考对象＝vastsa/pi-desktop（github.com/vastsa/pi-desktop，Electron＋React＋TS＋Rust host core，LGPL-3.0）——**仅交互参考，不搬代码**：其布局正是右侧 Work Panel（插件可向右侧工作区加视图），其 Session Orchestrator＝主会话→并行 worker（前端/后端/测试/评审），worker 是「完整、可检视的会话」，与本设计钻取模型一致。壳母体仍为 pi-gui（MIT），fork 定案不变。
>
> **面板两模式，一套组件**：①会话内模式——当前主控会话的编排树：主控（协调 N 卡）→部门分组→在途卡/工人节点，节点字段＝状态（运行中/待验收/完成/失败）＋耗时＋「**N 轮 · M 次工具 · T token**」（三数口径，用户拍板，从 worker 会话 JSONL 事件聚合：assistant 消息数/工具调用数/usage 累计）；回执到达→节点定形（成功带摘要/产物路径，失败带类型），settle 后退入最近完成。②项目级模式＝跨对话看板：全部门在途/积压/最近完成，同一钻取。**聚合口径＝按部门**（用户拍板「正常的就按部门聚合，我们没有对齐需求」）。**工作流是显式启动的执行模式**（专用界面里手动启动才跑，类 LangChain 形式），不进自动编排面板——2026-10-03 专题定案，见「工作流模式」节。
>
> **活数据源定案（2026-10-03，用户点破后核实定稿）**：目标态＝worker 的**会话 JSONL 就是活数据正本**——干活时事件实时追加，桌面/面板直接 tail 渲染（与 pi-gui 读主会话同机制），**不建新通道、不做心跳文件**（早前「运行态心跳」提案作废——那是给 WorkerRunner 内存 stdout 缓冲找跨进程出口的弯路）。点进工人/部门＝只读打开对应 worker 会话视图。**现状缺口（代码核实）**：worker 派发默认参数 `--mode json -p --no-session`（worker/runner.ts）——内存会话不落盘，worker 目前**没有**会话文件；「直接展示对话进程」的前提是先把 worker 会话化（见下条定稿）。
>
> **卡号↔会话桥定稿（2026-10-03 用户确认「确认，不开工」，未实施；fork 侧小改，不依赖桌面壳，可先行）**，三件套：
> ① **worker 会话化**（改 runner 默认参数）：去 `--no-session`，加 `--session-id <执行标识>`＋`--session-dir <项目根>/.pao/worker会话`；项目根复用卡文件「最近 .pao 祖先」解析（卡路径推出，退化 cwd 再退化 PAO_HOME）。执行标识（randomUUID，过 pi 会话 ID 合法性校验）**一键四联**：回执.用量、进程登记表、证据文件名、会话文件名（`<时间戳>_<执行标识>.jsonl`）——桌面 glob `*_<执行标识>.jsonl` 一发命中。测试用 `参数` 覆盖起假进程的老路不受影响。
> ② **在途映射（唯一新文件）**：`<项目根>/.pao/运行中/<卡号>.json`＝{卡号, 尝试, 执行标识, PID, 部门, 开始时间}；spawn 后原子写（tmp＋rename）、close 删、主控启动清扫 PID 已死残留。在途需要它的原因＝执行标识要等回执落卡才上卡，飞行中的卡在盘上无指针。两段式＝**在途靠运行态文件（R25：重启归零、真相以卡为准），完成后靠回执（卡＝真相）**；读写频率＝派发/结束各一次，是映射不是数据流。
> ③ **零改动面（代码核实）**：回执用量对象已带执行标识（worker/dispatch-core.ts，§15 落的）——「完成后」的桥已存在，回执七必填/序列化/解析一字不改；ProcessRegistry 保持纯内存；证据文件不动（带 stderr/exitCode/契约尾部，与会话文件分工不同）；TUI /pao pano 实时页不动（进程内已够用，桌面才是第一消费者）。
>
> 附带定案：worker 会话放 `.pao/worker会话/` 不入 `~/.pi/sessions`（pao 拥有的待在项目命名空间，不污染 pi-gui 主会话列表）；`worker会话/` 随派发累积＝已知事项，归档清理挂巡检待办不阻塞。实施时测试面＝参数断言＋映射写/删/残留清扫＋会话目录解析退化链，全套跑绿＋build＋bundle 复查。M3-02 依赖此项。

## 工作流模式（2026-10-03 专题讨论定案，用户拍板）

> 定案过程推翻了早前「不做可视化编排」的倾向——**工作流就是要画布编排**。信息架构与部门编排面板分立：右侧面板仍是部门聚合/看板两模式，工作流是**独立界面**（从主界面点进），四区布局。
>
> **节点＝部门（不是卡）**：画布上每个节点承载 部门、工人数量、工作内容；节点内部由**部长操控**——把工作内容当任务书**自主拆解**派卡给工人（可一次多卡，2026-10-03 确认），节点内多卡并行。工人数量＝**并发上限**（2026-10-03 定案：上限而非固定数——任务书**明示**给部长〔含验收/预算等节点要求〕；派发收口层**并发闸＋自动排队**：在途卡满上限时新卡收下进队不 spawn，交付后按序自动补发；队列即卡盘面（落卡未派态），重启天然续跑；在途/排队数对部长明示）。**计数各脉络独立（2026-10-04「部门各算各的」）**——双开时两窗口两份额度不合并；全局资源保护归共享上游限额层（M2-03）。节点完成＝其全部卡交付**（前提：部长已交「拆解结束」信号——运行规则细则②，正本见引擎 v2 计划）**＋（审核节点）出判定。
>
> **新建与主控对话**：新建工作流＝拉起一个主控对话——跟它对齐需求后它帮建工作流，或用户自己造卡；对话与画布**常驻联动**（聊着建卡、画布实时长节点，用户也直接在画布上拖/连/改）。这个对话贯穿始终：新建期对齐需求 → 运行期承担**监督、根据用户要求调整工作流、审批裁定**。主控对话关闭＝它拥有的流全停（进程树纪律同现有主会话）；实例状态在文件，重开可续跑。主控不在场时收到裁定请求 → 降级停给人（不停等）。**两段式对齐协议（2026-10-03 借鉴定案）**：接活先三路分级并宣告（探针＝可行性答案不留代码／小改＝聊天短设计点头即干／工程＝建工作流走规格），拿不准走重路、棘轮单向（中途变复杂只升不降）；探索期一次一问（问题随答案演化）＋收敛期整轮确认（编号列完＋每题附建议答案＋只问不依赖未答的前沿＋事实自己查决策才问人）；写回理解（事实与假设分离，纠完才动工）；配方落盘前自检（占位符/矛盾/范围/歧义）＋用户过目。部长判定需澄清时同款提问纪律。
>
> **审核节点＝三态判定（部长决定，三态都带理由同步）**：pass → 进入下游；change request → 沿回边打回指定上游节点重做（理由＝重做输入）；reject → 阻塞、工作流停止（带理由）。**回边循环**：打回上限默认 3 次、每条回边可改、0＝无上限；**超限动作二选一**（停滞＝reject 语义停流、理由注明超限 / 修完这轮直接放行继续）。
>
> **节点选项**：「是否允许请求主控裁定」——开启时阻塞/判不了上报工作流主控对话裁定后续跑；关闭或主控不在场 → 必须人来决定。
>
> **启动向导**：填参数 ＋ **每个部门（节点）与主控各自选模型和思考强度**（节点级覆盖既有档位体系的部门默认）＋ 诚实预览（**2026-10-04 修订**：只显示确定的——节点数、各部门工人上限、预算合计；**将落卡数承诺不了**——部长启动后才自主拆卡，显示「待拆解／尚无法估算」，不编数）。启动/裁定/确认走同一 owner 入口（RPC 扩展命令映射随 M3-01 核；核不通的降级路径＝桌面把参数拼成一句话发给主控对话启动，零新通道）。
>
> **画布＝配方的编辑器，不是第二真相**：拖动卡片、连线成并行/串行/**循环**，改动落盘仍是配方 md 文件（真相唯一）；运行中**图冻结**——要改就停流、改配方、重启新实例。「根据我的要求调整工作流」＝主控对话里商定后走这条停流-改-重启路径。
>
> **节点编辑面（2026-10-03 用户增补＋审计补齐）**：画布节点可编辑的完整字段清单＝**部门**（选既有部门）｜**任务指令**（文本，给部长的工作内容，支持参数占位符，启动向导填值）｜**挂载技能**（多选自 `pao配置/skills/`，与部门配方技能**合并去重**——复用 §11.6 按需挂载既有机制）｜**工人数量**（并发上限：任务书明示＋派发层并发闸·自动排队）｜**验收标准**（卡协议必填项的着落，缺省由部长拟）｜**预算**（可选，缺省部门/全局）｜**模型/思考档覆盖**（缺省部门默认档）｜**判定配置**（无＝工作节点／三态审核＋change 回边目标＋上限＋超限动作）｜**裁定开关**。优先级等低频字段留在配方文本，不占编辑面。右侧面板**双态**：未启动/已停＝节点编辑面板；**运行中＝实时详情（配置只读）**——与图冻结同构。编辑落盘即配方 md（图=配方唯一真相）。
>
> **布局（工作流界面四区，窗格大小可拖放、可折叠）**：中＝画布；左＝工作流列表（储存的配方）；右＝当前选中节点（部门卡片）的**实时详情/编辑面（双态，见上条）**——点进卡片看部长/工人在干嘛（卡＋worker 会话，走卡↔会话桥，与部门编排视图同一套钻取组件）；下＝主控聊天。
>
> **分工**：引擎 v2（fork 侧，可先行，不依赖桌面）见 [2026-10-03-工作流引擎v2.md](2026-10-03-工作流引擎v2.md)；桌面界面＝任务 M3-07；TUI 不做画布，`/pao flow` 只读跟进新模型；**桌面调度器永不启流**（显式启动是定案，调度器只做定时机械活）。

## 小议题定案（2026-10-03：锁接管 UX＋部长归属）

> **锁接管 UX**（配合「运行时形态定案」的锁机制；2026-10-04 锁降为会话粒度后作用对象＝会话锁）：①活锁（对方 PID 活着）→ 拒绝附身并亮出对方信息（形态、PID、启动时间、拥有者会话），**不提供强抢**——同一会话被两个交互面同时驱动是唯一要防的事（全局写点已靠原子化保障，不靠互斥）；②死锁（崩溃残留、PID 已死）→ 提示「上次 形态 于 时间 启动，进程已死」，确认后接管——终端一行 y/N、桌面对话框，不静默清；③锁文件 keyed by 会话 ID（`运行时锁/` 一会一文件，形态＋PID＋时间戳——配合卡↔会话桥，提示可直接指到那个会话看它在干嘛）。正常退出自动清锁不变。
>
> **部长归属＝任务脉络制**（用户拍板「a，但新的对话部长也应该是新的，否则上下文污染」）：部长跟任务脉络走、不跟窗口走——**工作流＝一个流一套部长班子**（流内常驻复用；跨流各自新开互不污染——两个流同时有前端节点就是两个前端部长实例，绑定键在 部门×项目根 之上加脉络维度，引擎 v2 改动点）；**普通对话＝对话期间一套，对话关＝散场留交接页**（同现状，交接兜底）。**2026-10-04 统一与双开**：普通对话脉络＝会话本身——多对话并行定案后部长双开合法（同部门多值班窗口，人格在盘上共享不分叉）；交接页按脉络分文件；部门并发上限各脉络独立（各算各的）。「桌面常驻」据此修正为：**常驻的只是调度器**（定时机械活/通知/缓存），不承诺部长进程常驻；任务部长句柄仍在主控会话进程内（与现状同，无挪桌面主进程的成本）。
>
> **值班部长**（无任务语境的部门日常值守：保温/盘点/应付巡检，§16.2「桌面＝在场宿主」完整形态）：**v1 不做**（省进程省 token），**登记为后置愿景**——真实用出需求再加，加了也不带任务语境、与任务部长分立。

## 任务与顺序

### M3-01｜pi-gui fork 起步与驱动切换

三步：① clone pi-gui 并原样跑通（Windows 构建已知未签名，本地 dev 模式起）；② 通读 `packages/pi-sdk-driver`，把驱动从 npm 包 `@earendil-works/pi-coding-agent` 切到本地 pao 构建产物（fork 定制集中在此层）；③ 桌面里发一句真实请求、流式显示、取消并正常退出（中文/空格路径顺带核）。pao 侧同步落**会话锁**（一会一锁，见选型节 2026-10-04 改版）——多对话并行与桌面↔终端混用从第一步就是支持态，锁只防同一会话双附身。

记录命令、事件、扩展对话框、卡片读取与模型设置的可用映射；传输完成、agent 结束、卡验收三个层次分开。先有这张清单再写大界面。**侦查面随工作流定案扩大（2026-10-03）**：①扩展命令触发——桌面按钮（启流/交判定/裁定/锁接管确认）能否经 RPC 调主控侧扩展命令，核不通的降级＝把参数拼成一句话发给主控对话；②事件流——运行图实时着色的事件源（活数据兜底＝卡↔会话桥的会话 JSONL tail）；③确认对话框（G3-06）——工作流启动/裁定/人工门/死锁接管的确认语义。

**交付**：fork 仓库初始化（主分支策略同 pi fork）、driver 切换记录、最小真机样例、会话锁＋全局写点核实清单。**不做**菜单动画、主题市场或高级看板。

### M3-02｜只读看板与项目切换

可视化形态、右侧面板、钻取与活数据源见「可视化面板与实时进程」节（2026-10-03 定案）；本任务信息架构以该节为准展开。

直接读 `.pao/` 卡片，复用 `/队列` 分组/排序/依赖/协作/待验证/警告规则。桌面不保存第二份卡片状态；解析坏文件、目录暂不可读要显示异常，不能把它们解释成“队列空”。

跨项目通过既定项目清单聚合。任意点击路径先解析其归属，不按两个项目相同卡号合并。基础刷新可用文件变化通知加手动刷新；通知丢失后重读文件恢复，不以事件流作为正本。

点击回执和证据打开实际文件；大文件不整页自动塞进模型。UI 可以缓存展示，但重新读取正本后应一致。

**交付**：项目切换、只读队列/详情、证据定位与异常展示。**前置**：01。

### M3-03｜对话、派发、取消与人工确认

用户输入经当前 pi 会话；派卡和队列修改走同一 PAO owner 入口，不在桌面再写一套调度逻辑。操作带关联标识，响应丢失先查状态，不重复发送一个会写项目的请求。

接入暂停发新活/取消当前任务的既有语义，显示“正在停止”与“已停止”区别，不能按钮一按就假报取消完成。高风险操作的确认要正确回送，关掉对话框、超时或断线不能默认授权。

扩展的终端专用 UI 可能无法原样用于 RPC；需按官方支持面处理。核心确认能力缺失时阻断功能，纯显示件可明确降级。[E10]

**交付**：真实对话、派发、取消、确认与重复操作防护。**前置**：02。

### M3-04｜配置与多窗口归属

桌面只编辑既有允许编辑的配置：项目入口、模型菜单/档位、已批准工具等；敏感值不展示在日志或截图。配置校验失败保留原值，设置不静默覆盖全局 settings/models。

一个目标会话只有一个写控制方。第二窗口默认只读；显式接管前让原 owner 退出或按已有规则交接。UI 断线、进程仍活与进程死亡要区分，不能每次重连都另开一个 worker 树。

壳关闭时停止自己拥有的 pi/PAO 子进程；不得杀用户另开终端的独立 pi。关闭但继续后台运行不作为默认功能，以免违背无常驻纪律。

**交付**：配置读写与恢复、多窗口/接管边界、可诊断的连接状态。**前置**：03。

### M3-05｜桌面故障与真实日常验收

复跑取消、强退、丢连接、重复响应、慢输出、坏卡片、权限确认、项目切换与日志展开。使用相同任务在终端/桌面各做一次，核对相同卡片状态和执行结果，而非只核对 UI 截图。

新增的壳延迟/资源开销单列，模型 token 不应因 UI 无故增加一份；确有新的对话/审查则计入实际调用。保存 Windows 构建/启动与可复现日志。

**交付**：桌面验收报告、终端对照、已知 UI 降级清单。

**拆批（2026-10-04 外部评审，用户批）**：验收拆两批——**M3-05a 基础桌面**（M3-01..04 完成后即验收投用：本节全部故障与日常场景＋终端对照，先投用攒真实使用）；**M3-05b 工作流界面**（随 M3-07 完成后第二批：画布/启动向导/运行图/裁定交互全链）。基础桌面不等工作流界面。

### M3-06｜交付与条件升级

发布能独立启动的桌面入口，说明如何选择已安装锁版 pi、如何退出/取消、证据在哪、如何退回终端。桌面升级与 pi 锁版升级分开，不强制同时更换内核。

条件升级：部门专场仅在中继聊确有重复往返问题时加入；实时 JSONL 活动流只作可丢弃展示，不成为恢复正本。基础桌面没稳定前不做终端完全复刻、标签市场、多用户/租户或云端同步。

**交付**：构建产物/启动说明、版本兼容说明、回退指南和当前未支持项。

### M3-07｜工作流界面（画布＋启动向导＋运行图）

编号在 06 后。**执行顺序（2026-10-04 评审调整，原「执行排在 M3-05 验收之前」作废——M3-05 已拆两批）**：前置 M3-03、工作流引擎 v2（见「工作流模式」节）；本任务完成后触发 M3-05b 工作流界面验收。信息架构按该节定案：四区布局（中画布/左工作流列表/右节点实时详情·编辑双态/下主控聊天，窗格拖放＋折叠）；画布编辑器（拖节点、连线并行/串行/循环，节点配置面板＝部门/任务指令/挂载技能/工人数量/验收/预算/模型思考档/三态判定/回边与超限/裁定开关，见「节点编辑面」条）；启动向导（参数＋每节点与主控的模型/思考强度＋诚实预览）；运行图实时着色＋节点详情钻取（卡↔会话桥）＋人工门/裁定交互＋终态复盘视图。新建＝拉起主控对话并常驻联动。

**交付**：新建（拉主控对话）→ 搭图 → 保存 → 启动 → 监督/裁定 → change 循环 → 终态复盘全链真机可走。**不做**：TUI 画布（`/pao flow` 只读跟进）、运行中热改图（图冻结）、调度器自动启流。

**第一条真实样例（2026-10-04 定案）**：开发→测试→审查→打回一次→修复→通过；另跑一遍中途退出＋人工恢复（检验回边轮次、超限文案与恢复正本分层）。

### M3-08｜「需要我处理」统一入口（2026-10-04 外部评审立项）

把散在各会话的**待确认（人工门/裁定）、缺输入、审核打回、超限放行、恢复请求**聚成一个跨对话待处理列表。每项固定四行：为什么停在这里／需要用户决定什么／推荐怎么处理／证据点开哪里看。数据全部来自既有正本（卡状态、实例清单、通知事件），零新真相源；**TUI 侧最小版＝首跑清单扩展（本会话范围）**，桌面版跨对话聚合。**交付**：列表聚合＋逐项处置动作（跳转/确认/打回）。**不做**：自动处置。

### M3-09｜结果审阅页（2026-10-04 外部评审立项）

同一任务的**原始要求（卡面）＋实际改动（diff）＋验证结果（验收条目与运行证据）＋遗留问题**一页呈现；打回时直接对比「这一轮相较上一轮修了什么」（复用打回轮次归档，运行规则细则①）。复用既有卡/diff/验收文件只做聚合展示；挂在节点详情钻取，与 M3-02 证据定位同链。

登记后置（随既有任务落地，不单独立项）：**恢复前现场摘要**（已完成/中断/已改未验/准备续跑清单＋确认续跑）→ 随 M3-05 恢复验收面；**「这次实际用了什么」**（实际模型/思考档/挂载技能/知识来源、升档原因）→ 随 M3-07 节点详情。
