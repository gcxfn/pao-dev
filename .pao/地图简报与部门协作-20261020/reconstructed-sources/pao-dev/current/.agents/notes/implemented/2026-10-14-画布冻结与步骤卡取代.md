# 画布冻结与步骤卡取代画布（2026-10-14）

## 决定

1. 桌面工作流画布（ReactFlow 总览/详细图、配方编辑器、向导、运行控制）**冻结**，快照存
   `desktop/archive/canvas-frozen-20261014/`（23 文件，含 README 与基线提交号），只读、不追加。
2. 工作流的默认工作界面改由**步骤卡**承担：一个实例的节点以步骤卡列表呈现（含状态、部门、
   owner、轮次、回执与异常），画布不再是默认入口。
3. 冻结不等于删除能力：需要恢复画布某能力时从快照复制回原路径，契约/IPC/驱动三层一起恢复。

## 为什么

- 计划第 2 节「现状承接」已定：画布的后续扩展由步骤卡替代，**不新建布局引擎**。
- 画布是「按位置排布」的编辑器（`ui.positions`、并行组、回边都在图上画），对第一版小说工作台
  的目标（讨论 → 建计划 → 分部门 → 落步骤卡 → 确认执行 → 阅读产物 → 提意见 → 审稿 → 确认）
  属于过度投入：用户要的是「现在该看哪一步、这一步的产物在哪」，不是拖拽布局。
- 保留快照的理由：画布承载了配方编辑、向导对齐协议、运行控制三块已经调好的实现，删掉再重写
  是纯浪费；冻结后仍可回看与按需恢复。

## 被否方案

- **直接在画布上加步骤卡页签**：两种心智模型混在一个入口里，用户仍要先理解图；否。
- **删除画布代码**：没有收益，且丢掉配方编辑/向导/运行控制的既有实现；否。
- **把画布快照放 git 分支或 tag**：本轮约束是不提交开发仓，用归档目录更直接且可读；否。

## 影响与边界

- `desktop/archive/` 不在 tsconfig/eslint/prettier/架构守卫的扫描面内，冻结不阻塞构建与检查。
- 画布相关内核侧能力（`workflow/control.ts`、`driver.ts`、`recipe.ts`）**不冻结**：它们是
  临时计划与步骤卡共用的执行内核，继续维护。
- 冻结快照不是干净提交的副本（含当时未提交的画布改动），以工作树实际状态为准。
