# fork 路线（2026-10-02 定案）

## 决策

pao 本体 = pi 0.99.2 源码 fork，放 `PAO/`：独立 git 仓库（从 pao 主仓库 .gitignore），保留上游 remote 便于同步，主开发分支 `pao-main`，基线 tag 0.99.2。全部定制直接改 fork 源码；不再走扩展包路线（原方案已否决，见 `../rejected/插件优先扩展包路线.md`）。

## 为什么

用户要直接修改源码的自由度（2026-10-02 拍板），接受升级成本换改源码便利；OMP（oh-my-pi）验证过同路线可行。

## 代价（知情接受）

- 跟上游更新从「适配扩展 API」变为「rebase fork 上的改动」，每次升级成本变高（需求 §5.4 四步照旧，第③步变重）；由慢推节奏与锁版缓冲。
- 需求 §4.1 复用清单中「直接用官方扩展 API」的项，含义变为「在 fork 内直接实现/改造」，参考对象不变。
