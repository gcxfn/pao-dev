## 件一：git-review devNull 缺陷

### 根因与修法

`apps/desktop/electron/platform/files/git-review.ts` 的 `readPatch` 把 `os.devNull`（Windows 为 `\\.\nul`）作为 `git diff --no-index` 的文件路径参数传给 git。实测（`证据/件一-NUL设备实测.log`，git 2.55.0.windows.3）：git 打不开 `\\.\nul`（`error: Could not access`，exit 1，空输出），而 `NUL` 与 `/dev/null` 均正常出 patch 且输出标签统一规范为 `--- /dev/null`（UI 两平台显示一致）。同时 `git()` helper 对 exit 1 有意容忍（`--no-index` 有差异时正常退出 1），导致 access 失败被静默吞掉→空 patch 继续→coverage 误标 complete。

三处修法（一个函数修清，readPatch 仅此一处调用方）：

1. **null 设备**：`git-review.ts:984` missing 侧改 `process.platform === "win32" ? "NUL" : devNull`——沿仓内既有先例 `checkpoint-store.ts:1086` 的 hooksPath 写法；POSIX 分支保持原样字节不动。
2. **显式报错**：diff 调用后加守卫——`result.code !== 0 && !result.truncated && result.stdout.length === 0` 即 throw（exit 1 有差异时 patch 必非空，故 exit 1＋空输出＝读侧失败）。throw 经调用方既有 try/catch→`gitReviewIssue` 落成 `failed` ReviewIssue，不再静默空补丁。
3. **coverage**：守卫使失败以异常上抛，不再走到 `COMPLETE`；截断路径维持原有 partial＋truncated 注记。

## 件二：catalogs 原子写 EPERM 退避

### 根因与修法

`packages/catalogs/src/node/atomic-write.ts` 的 rename 单次执行：Windows 上并发场景（读方/索引器/杀软握住目标文件句柄且无 FILE_SHARE_DELETE，或 40 并发写互相竞争同一目标）rename 覆盖被拒 EPERM（errno -4048），无退避重试。

修法：抽出 `renameRetrying`——rename 失败遇 `EPERM`/`EBUSY` 时有界退避重试 **3 次×25ms 递增**（25/50/75ms，最长加时 150ms），其他错误码与重试穷尽后按原错误面抛出（外层 rm tmp 兜底不变）；不加锁框架、不引依赖。测试导入 `dist/` 产物，`pnpm --filter @pi-gui/catalogs test` 脚本自带 tsc 构建，无需额外步骤。
