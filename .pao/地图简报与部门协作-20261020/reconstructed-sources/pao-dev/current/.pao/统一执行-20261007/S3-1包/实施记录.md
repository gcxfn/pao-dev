## 一、缺陷与根因（已实证定案）

缺陷：未保存新配方被标签切换丢失 → 后续编辑落到旧配方，保存覆盖旧配方文件
（e2e `tests/core/workflow-canvas.spec.ts:353` 家族，原失败点 :388）。

完整机制（诊断 spec 4/4 确定性复现，证据见 `证据/运行日志/诊断-标签消失机制-末跑.log`）：

1. 点「新建工作流」→ changeTabs 发 IPC-B（含新标签）。
2. 同一批渲染中骨架编辑器挂载，其 selectionId effect 上报
   onSelectedElementIdChange(undefined) → updateSelectedElement（canvas-page.tsx:137-149）
   从滞后的 tabSelectionRef 取**旧 tabs** 做全表写 IPC-A'（FIFO 排 B 后）。
3. 主进程严格 FIFO → 终态＝新标签被覆灭。
4. activeTab 同步 effect（:209-218，dirty=false 分支）把 selection 回写旧配方。
5. editorEntry 退化为 catalog 旧行 → 编辑器重挂载为旧配方 → 配方名称输入框消失（T09/:388）。
6. 用户继续编辑保存＝写旧配方文件（T08/:417-427）。

任务书列的四件叠加根因（守卫判据与徽章分叉／newEntry 全局单槽／draft 随卸载即弃／
editorEntry 解析退化）全部成立；实跑中发现第三、四处独立帮凶（见第四节），按纪律实修。
