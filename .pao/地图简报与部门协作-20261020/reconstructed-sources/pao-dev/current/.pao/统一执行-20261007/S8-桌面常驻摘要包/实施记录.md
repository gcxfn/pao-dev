## 一、结论

桌面常驻摘要落地并过全部本轮验证门：新 `extensions/pao/todo-summary.ts`（155 行，rpc 皮肤投影）＋`index.ts` 接线 2 行。**零新增 IPC、零新增 renderer 代码**——通道用内核扩展事件既有出口 `ctx.ui.setStatus/setWidget`（桌面 supervisor 原生桥为 hostUiRequest status/widget 事件，per-session extensionUiState 订阅时重放＝查询＋订阅恢复），渲染面复用输入区上方既有 ExtensionDock（composer-surface 挂点）。取数与 TUI 同源：todo_write 成功结果用 tool_result 事件自带 details 权威信封（实测该事件先于 toolResult 落会话，扫分支会拿旧表，故分路）；切会话/恢复走 session_start/session_tree 分支重扫（内核 scanTodoState 同款口径，含 pao-todo-snapshot 压缩快照续读），不重放时间线。折叠行「待办 n/m · 当前任务」、四态符号 ○◐✓⊘、8 行上限＋剩余计数、空清单隐藏、分母扣 cancelled，全部与 TUI/内核同口径。原 TodoTable/parseTodoList 链零改动并有实测钉子。TDD 红→绿在案；renderer 侧预计新增组件未写——复用 dock 即满足（见 §四）。

2. 通道选型：计划预估「desktop.ts 投影＋renderer 新组件」。实际盘点发现更好的既有路：桌面 supervisor 的 `ExtensionUIContext` 已实现 setStatus/setWidget→hostUiRequest（session-supervisor.ts:2346-2368），`extension-ui-state.ts` 维护每会话状态且订阅重放（:1701/:2603，查询＋订阅恢复语义现成），renderer 侧 ExtensionDock 已挂在输入区上方（composer-surface.tsx:255，样式防长文破版 main.css:2704-2796，另有 e2e `tests/core/extension-dock.spec.ts`）。按 ponytail 梯子复用，零新增 IPC 面、零 renderer 改动。

4. 两处机制实测纠偏：
   - **时序**：`agent-loop.ts` finalizeExecutedToolCall（含 afterToolCall→扩展 tool_result 事件）先于 createToolResultMessage 落会话——tool_result 里扫分支拿到的是旧表。改用 `CustomToolResultEvent.details`（事件自带内核刚写入的权威信封）。会话切换/恢复无此问题（事件在分支装载后），走扫描。
   - **导出面**：内核包 exports 只有 `.`/`./rpc-entry`/`./pao`/`./pao/desktop`，`./pao` 不转出 todo 与 ui/todo-summary（dist 实查）——无法直接 import scanTodoState/formatTodoStatusLine。按 S8-内核包 §六明示预案落「scanTodoState 同款扫描」本地实现（23 行）＋同口径格式化（guard/计数/符号与内核逐一对照，见 §三表）。
5. TDD 红→绿：先写 driver 7 用例（模块不存在，首跑 ERR_MODULE_NOT_FOUND，退出码 1，留档红灯-首跑.log）→ 实现 → 7/7 绿。renderer 5 用例为兼容钉子（钉既有链路，设计上先绿）。其间修两处测试件自身问题：夹具数据 pending 无当前任务后缀却断言了后缀；测试用了未导入的 ExtensionAPI/ExtensionContext 类型名；声明改仓内 `await test(...)` 约定过 no-floating-promises。
