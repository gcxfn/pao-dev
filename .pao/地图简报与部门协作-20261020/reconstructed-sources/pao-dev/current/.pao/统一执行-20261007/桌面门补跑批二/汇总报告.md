## 新增红清单（相对批一基线口径）逐条归因

严格新增只有 kanban 两条新用例红（新测试，基线中不存在）；session-lease:31 对批一清单是「新观察」但 T00 证明既有。

1. **kanban-board :658「拖放反馈：拖到已交付列被拒点名验收链，拖到取消列真实执行」**（复跑同红）：
   `TimeoutError: locator.dispatchEvent: Timeout 30000ms exceeded`，等
   `[data-testid="kanban-card"][data-path="C:\Users\...\卡0002-乙卡进行中.md"]` 30 秒不解析（spec:671 dragByPath）。
   归因＝**S7-B 新增 e2e 的 spec 侧选择器缺陷（Windows 路径特征）**：同测试 liveCardPath（spec:704-708）经
   getAttribute 读到**同一 data-path 属性值**＝元素在且值相等，而同一字符串字面量进 CSS 属性选择器永不匹配——
   反斜杠路径在 CSS 属性选择器里按转义序列处理（`\U`/`\A` 等非十六进制转义＝吞反斜杠留字母），属 spec 写作对
   Windows 路径失察；同 fixture 的 :613/:711 用 testid＋hasText 定位全过为旁证。**产品面（拖放拒完成点名验收链）
   本次未被 e2e 覆盖到**（测试在第一次 dragByPath 即挂）；该拒绝逻辑已有单测 kanban-command:19 纯函数覆盖。
   全绿预期被打破的原因＝该用例从未被跑过（S7-B 留档「e2e 新增 4 条门待跑」），非回归。
2. **kanban-board :748「租约真实值：旧代行不覆盖新代呈现，被接管如实亮出」**（复跑同红）：
   `electronApplication.evaluate: TypeError: A dynamic import callback was not specified`（spec:762 registerOwner，
   在 evaluate 的函数体里动态 import 内核 dist/pao/desktop/index.js）。
   归因＝**spec 侧技术缺陷（平台无关，确定性）**：Playwright 的 electronApp.evaluate 把函数体在主进程 eval 执行，
   不传 importModuleDynamically 回调，ESM 动态 import 在该上下文必抛此错——注入手法不可行，与产品代码无关。
   **产品面（租约按认领代数取最大）未被 e2e 覆盖**；该逻辑已有单测 kanban-query:107-117 覆盖。
3. **session-lease :31「a second pi-gui process cannot open a thread the first one holds」**（新观察，非新增回归）：
   lease 文件记录 pid（1312）≠ 第一实例 pid（5860），spec:63 断言失败。归因＝**既有**：T00 桌面 core e2e 基线
   （2026-10-05，`.pao/整体重构-20261005/基线失败归因-桌面侧.md` #27＋`日志/T00-桌面core真实Electron.log` :282）
   同 spec 同用例同断言已红（当时 lease pid 37516≠实例 pid 45988，登记候选「lease 写入者主体差异或 pid 语义
   （Windows 进程树）」，未决）；:88（退出释放租约）当时与本次均绿。两包三天后才提交，无罪。
