## 当前实现

- 内核 `PAO/packages/coding-agent/src/pao/desktop/` 只读投影，卡解析复用既有实现，队列文本复用 `renderQueue`。按项目清单聚合跨会话待处理，卡身份使用完整路径，不按同号卡合并。坏卡、坏控制清单、不可读路径显式呈现。
- 桌面 `桌面端/packages/pi-sdk-driver/extensions/pao/` 是真实文件扩展；浏览器资源就在其目录，走原 `registerDesktopView` / Chord 安全边界，没有额外 IPC 或任意文件接口。driver 的 `additionalExtensionPaths` 接线；build 构建浏览器 bundle 并检查类型。声明现有 Chord 与 extension-ui 依赖，无新依赖安装。
- 任务、待处理、结果与恢复、上下文与记忆四页，显示当前项目／会话／读取时间，沿用左侧项目与对话切换。worker 每次最多读取 1 MiB，字节偏移只跨完整行，半行等待、截短和坏 JSON 明示；工具调用与文本可查看，隐藏推理不展示。最近 500 行仅为视图上限，保留完整会话定位。
- 部长列表来自当前内核宿主 `host.list()`；工作流部长会话依冻结实例正本定位 `.pao/.../部长会话/<实例>`；普通部长使用所属 owner 会话目录定位。没有唯一可验证会话时返回错误，不猜测全局文件。历史流程部长也可钻取。
- 工作流人工门、挂起、裁定、轮次、回边历史与恢复摘要来自 `readControl` / `controlReport`。动作经当前真实 owner 的 `/pao flow control <JSON>`，该路由由 S2 作者复用原 `pao_节点控制` 工具实现。实例／节点／轮次重新检查；不同 owner 跳转原会话；恢复由内核核对旧 owner 并确认。没有绕过人工确认直写清单。
- 结果页显示原始卡要求、验收、正文、当前和历史回执、执行状态；按需运行只读 `git diff --no-ext-diff --no-textconv`。有冻结节点基线时展示相对基线；缺启动基线时明确仅当前工作树相对 HEAD，不能证明任务全部改动。未跟踪文件仅列路径，不假装包含其内容。恢复摘要区分已完成／挂起、已改未验仍需结合差异和机械验收核对，未自动续跑。
- 上下文复用 S3 按需真实请求捕获；记忆来源来自真实内核主扩展的 SessionMemory。内核主扩展注册 `registerDesktopOwner(pi, { getMinisters: () => host.list() })`，避免文件扩展另一 ExtensionAPI 查到空状态或误用别的命令闭包。记忆动作绑定原会话和记忆内容版本，调用原 owner 的控制权检查与记忆确认流程；旧版本、旧会话拒绝。失败返回后要求先刷新正本，不自动重发写请求。
