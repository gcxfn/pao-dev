## 机制与最小建议

高概率原因是 `windowsHide:true` 导致 Windows 启动信息包含 SW_HIDE，影响首次显示。libuv 的 Windows spawn 源码明确在 `UV_PROCESS_WINDOWS_HIDE` 时设置 `startup.StartupInfo.wShowWindow = SW_HIDE`：[libuv process.c](https://raw.githubusercontent.com/libuv/libuv/v1.x/src/win/process.c)。微软说明首次 ShowWindow 在父进程提供启动信息时采用该信息：[ShowWindow 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-showwindow)。这仍需实际复验闭环，不能仅凭机制称已修复。

建议主代理先使用同 profile 启动第二实例，让现有 second-instance 回调（main.ts 第 940 行）再次 show/focus：若旧窗口出现，能在不重建下验证首次显示被隐藏的判断。正式最小修复为仅本 GUI 启动设置 `windowsHide:false` 或省略；保留 IPC、父生命周期和后台 worker 隐藏策略，不增加轮询 show 或绕过 renderer 安全边界。然后按正式 CLI 冷启动复验，并核关窗回收进程。
