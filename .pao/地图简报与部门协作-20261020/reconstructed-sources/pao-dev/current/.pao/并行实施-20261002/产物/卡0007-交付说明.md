## 并发与补位语义

- **规划**:`planFanout` 对卡引用去重保序(首次出现入队,重复记入 `重复剔除`),产出四位卡号拉起顺序与静态波次切分。**波次只是展示/审计视图;执行不按波次等待**。
- **执行**:并发上限个车道(默认 4),每个车道从队列取卡——**前一个进程一退出立刻补位拉下一张**,全部卡入队,不拒绝不丢弃。测试用假进程 start/end 时间戳验证:同时活进程数不超上限,且短任务后下一张的启动远早于长任务结束(补位而非等波)。
- **拉起前逐卡处理**(owner 侧动作,操作者=「主控」,经 `changeCardStatus` 走状态机,不手写 frontmatter):
  - 待认领 → 认领进行中(尝试 +1,无主则 owner=主控);
  - 失败 → 扇出点名即重派决定:失败→待认领(校验 owner 与尝试上限)→认领进行中;
  - **进行中 → 不拉起**(在先前尝试手中,防双跑;先由 owner 查现场落终态再重派,架构 §2.1);
  - 已交付/取消 → 不拉起(已终态,重做另立新卡)。
  以上不拉起的卡在摘要记「未拉起」+原因,不影响其余卡。
- **回执**:每张卡的 worker 结构化回执**逐卡**经缺省回调落卡——重读卡 → `appendReceipt`(尝试号=卡面当前尝试,失败带缺省分型),不混批;worker 交回执只是待审,状态不推终态。落卡失败不丢证据,摘要注明证据路径。可用 `交回执` 覆盖,`每卡参数` 可按卡注入运行参数。
- **聚合摘要**:每卡终态 = 成功/失败/结果未知/取消/未拉起;失败卡带 `routeFailure` 同口径的路由建议(缺省分型:失败→瞬时故障(重试)、runner「未知」→结果未知(查现场);缺输入/能力不足的精细分型留给回执审查阶段订正,机器不冒充判断)。

## 停止行为(R05,复用 runner,本模块零进程管理代码)

- 全部进程经 `WorkerRunner.run` 拉起,进 runner 登记册;缺省用 worker 模块 `defaultWorkerRunner`,**pao_停后台 与 session_shutdown 钩子天然覆盖扇出进程**;本模块不自带退出钩子、不杀任何进程。
- 工具调用被取消(信号中止)= **先阻新调用**(补位车道停拉,排队卡不再拉起、终态记取消)→ **再 `runner.cancel` 树杀在跑进程并等真退出** → 已产生的证据与已落回执保留,摘要标「已停止」。
- 外部 `stopAll`(主会话退出路径):在跑进程被树杀、排队卡不再产生新进程(runner 拒绝,记取消+原因),批次照常收口不悬挂。
- 单卡 `runner.cancel(卡号)` 与扇出共存:被取消卡终态=取消,其余照常;取消后同卡本轮拒绝再派(runner 契约)。
