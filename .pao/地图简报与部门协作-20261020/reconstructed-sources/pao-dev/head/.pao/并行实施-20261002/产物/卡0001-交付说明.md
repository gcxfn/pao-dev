## 3. 锁实现依据

复用 fork 运行时依赖 **proper-lockfile 4.1.2**（`settings-manager`/`trust-manager`/`auth-storage` 已在用），不自造：

- 加锁 = `mkdir "<目标>.lock"`，mkdir 在 Windows 上原子，跨进程安全；
- 自带基于锁目录 mtime 的 stale 恢复（默认 10s），持锁进程崩溃不会永久死锁；
- 获取重试默认 9 次、指数退避（50ms 起），拿不到抛 `PaoCardError("LOCK_TIMEOUT")`。

测试覆盖：同锁互斥（并发临界区 maxInside=1）、重试耗尽报 LOCK_TIMEOUT、**真跨进程**（spawn 10 个独立 node 子进程各发 5 号，50 号不重号且连续，worker 经 Node 类型剥离直接加载 TS 源码，Node ≥22.18 默认开启）。

## 4. Windows 行为注记

- **原子写**：先同目录临时文件再 `fs.rename`。Windows 下 libuv 用 `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`，可覆盖已存在目标；被杀软/并发读短暂占用时抛 EPERM → 立即重试 2 次 → 仍失败回退 `copyFile+unlink`（非严格原子，最后手段防丢数据）。测试验证了覆盖写、无 .tmp 残留、并发写终态为完整单份内容。
- **路径**：全程 `node:path` join，未硬编码任何绝对路径；卡目录与计数器路径都是参数。
- **发号器子进程测试**：依赖 Node 类型剥离（本机 Node v24.18.0 默认开启）；若 CI 的 Node < 22.18，该用例需加 `--experimental-strip-types`，其余不受影响。

## 5. 语义定案与取舍（B 卡须知的暗默认）

1. **尝试号语义**：`尝试` = 已真实启动的尝试次数。创建为 0；待认领→进行中（实际启动）+1；失败→待认领不递增（遵模板 §2「下次实际启动才递增」）。重试门在失败→待认领处：`尝试 < 上限`（默认 2），提高上限只能由 owner 在改状态时显式传 `尝试上限`，worker 无入口。回执尝试号 = 认领后卡上的当前值；< 当前 → 旧尝试留档；> 当前 → INVALID_RECEIPT。
2. **单写者**：认领时若卡无主则调用者成为 owner；已有主则必须匹配。取消额外允许操作者传 `"用户"`（含无主卡）。owner 每次改状态都在正文追加 `## owner记录` 审计段。
3. **状态终态**：已交付/取消无出边，迟到回执只留档。任务卡原文「已交付→进行中须经失败重试路径」在本实现中表现为：已交付不可再迁移（模板 §2 终态表优先）；要返工就走取消后的新卡。
4. **依赖边只认 depends_on**；前置卡必须在同一卡目录才能查到状态，查不到按「不存在」阻塞。跨工作区依赖（同一项目跨任务）M1 由调用方保证同目录，交付说明在此留痕。
5. **队列渲染空分组不显示**（如「待认领（0）」不出现）；取消组按完成时间倒序（同已交付法）。
6. **frontmatter 冻结字段**严格按黑板第 5 条，未加私货；`创建/完成` 存 `"YYYY-MM-DD HH:mm"` 字符串。时间一律由调用方传（工具层取当前时钟），核心函数不取钟、纯函数可测。
7. **计数器文件**约定 `<项目>/.pao/卡号.txt`（createCard 默认 `卡目录/../../卡号.txt`，与任务工作区布局 `.pao/<任务名>/卡/` 对齐）；主控若用别的布局，用 `counterPath`/`计数器路径` 显式指定。
8. **pao_交回执 的失败类型是可选标注**（schema 未强制），因为失败状态的判定权在 owner（pao_改状态 转「失败」必带类型，强制）。
