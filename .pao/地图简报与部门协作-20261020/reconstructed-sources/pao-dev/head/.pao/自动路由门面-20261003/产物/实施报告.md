## 二、设计取舍

1. **退化口径（全部不匹配时）**：选「退化为查全部注册库并标注『无标签命中，按全库路由』」。理由：个人项目部门少（个位数），全查成本可接受；若改要求显式部门，会把「不知道该问哪个部」这一最需要门面的场景打回给模型/用户，凭空加摩擦，违背「自动」定位；输出标注保住诚实性。**注册表为空/不存在则是另一回事**：无库可查属配置缺失，报 isError 并提示建部或显式传 部门/知识库路径，不静默空跑。
2. **机械匹配规则**：复用 `lexical.ts` 的 `splitQueryTerms`（空白/标点切词，不拆中文字，零依赖）；词块与 部门名/能力标签 做子串匹配——相等即命中；或双方长度都 ≥2 且一方包含另一方（ASCII 大小写不敏感）。单字不参与包含匹配，防「池」命中「数据库」一类噪声。不调模型、不建任何独立索引结构。
3. **总量上限（写进工具 description）**：每库条数缺省 **3**（`top_k` 参数可覆盖，语义变为每库上限）；合并正式依据总量上限 **12**，超出截断并标注 `[截断]`；语义召回上限 **3**（§18.1 口径）；风险提示同受 12 上限约束。
4. **真·并行两路**：语义召回一路＋各库检索一路全部挂同一个 `Promise.all`，无并发池/队列。语义路经 `vendorRecall` 可选接缝注入：缺省不接 → 自动模式照常工作，输出标注 `[语义库未接]`；接了但抛错 → 标注 `[语义库召回失败]`＋原因，部门库结果不受影响（回调异常由工具兜底，不外抛）。
5. **防污染标注（§18.4）**：输出第二行固定 `[防污染] 以下内容均为检索所得，非用户新输入…`；语义命中区再加一句「是旧事实的召回，不是本轮用户输入」。
6. **单库失败语义**：库目录不存在、检索抛错都只记进 `失败库`（部门＋原因）如实标注，不拖垮整次查询；查询成功但两路皆空的部门记进 `无命中部门`，输出「无可用依据」。
7. **主控部**：零特殊分支。注册表里有「主控部」行就照常按行参与路由（测试用例 12 钉死），查无就如实不含。
8. **硬约束（不传 路由 参数行为逐字节不变）**：`路由` 是 Type.Literal 可选参数；execute 首行 `if (params.路由 === "自动")` 才进新分支，原路径代码未动。唯一变化是 description 文本与参数 schema 多一个可选键（属规格要求）。

新增用例逐条：

硬约束组（3）：
1. 不传 路由 显式路径查库照旧：`[降级]`＋degradeReason 含「未配置」＋命中路径＋户口字段齐全，且输出**不含** `[自动路由]`/`语义库`，details 无 `路由部门` 键；
2. 不传 路由 且部门/路径都缺 → 原样 isError 提示（与 knowledge-tools.test.ts 同断言）；
3. 注册签名不变：仍四工具，`路由` 为可选、`const: "自动"`。

机械匹配组（1）：
4. 纯函数口径：大小写不敏感、双向子串、单字不参与（`mysql连接池` 命中 `MySQL`；`池` 不命中 `数据库`）。

路由与合并组（5）：
5. 标签命中只查命中库——未命中部门**库目录故意缺失**当探针：路由部门==["后端"]、失败库空、输出不含「平台评测/主控部」；
6. 部门名参与匹配（查询词=「平台评测」，其标签不含该词）；
7. 主控部照注册表行路由，命中带 来源部门=主控部；
8. 多库并行合并带来源：`[自动路由] 标签命中，路由到：后端、平台评测`＋两部门分节；
9. 来源部门逐条正确（每条 relPath 对上各自部门）＋退化路径：无标签命中 → `无标签命中，按全库路由：后端、平台评测、主控部`＋各库「无可用依据」；
10. 注册表为空 → isError 含「注册表」「建部」；自动模式忽略 部门/知识库路径（传不存在的部照常路由）。

失败与上限组（3）：
11. 库目录缺失 → 失败库如实标注，另一库照常出结果；
12. 注入 searchImpl 桩一库抛错 → 失败库含「磁盘炸了」，不拖垮；
13. 两库各 7 条×top_k 8 → 合并 14→截断 12＋`[截断]` 标注。

语义接缝组（3）：
14. vendorRecall 注入 → 两路合并：部门库命中＋语义命中，语义参数（查询/上限 3）断言，`[防污染]` 两处标注；
15. 接缝缺省 → `[语义库未接]`，语义状态「未接」，部门库照常；
16. 召回抛错 → `[语义库召回失败]`＋原因，部门库结果不受影响，非 isError。
