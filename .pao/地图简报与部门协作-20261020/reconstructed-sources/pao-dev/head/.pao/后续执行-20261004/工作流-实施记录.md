# 工作流 v2 与真实宿主接线实施记录

截至 2026-10-04；本文件记录实现与离线检查，真实模型与 Windows 正式入口证据由本轮总报告统一引用。未调用模型端点。

## 已实现

- 显式 v2 配方：部门节点、多批卡、拆解结束信号、节点并发上限、审核两轴、pass/change/reject、回边次数与两种超限动作、节点模型与思考覆盖、第三次重做起升主力。
- 流程控制正本：冻结配方、实例与真实 owner、部长会话、轮次、历史、裁定与暂停；旧实例不盲目续跑，损坏控制清单不从卡重建控制状态。回边只失效相关下游，旧轮次请求拒绝。
- 判定包：真实 git 内容基线固定引用、卡面及运行证据、diff、派单登记理由、部门标准；已有未跟踪文件无法归因时明确缺证，不假造内容基线。
- 主控通过现有 RPC 宿主投递任务书；部长身份由真实 get_state 握手和实际执行上下文共同核对。部长模型不能提交任意会话 ID 或新轮次冒领身份。
- 部长只允许 read/grep/find/ls 与五个本节点工具；PowerShell、bash、写文件、改文件、任意未知工具和绕过保护链派单均阻断。
- 自动链使用已有受保护派发、验收和交卷；排队卡在显式续跑时继续。没有部长结束信号或判定时保留现场，不伪造成功。
- 宿主任务可用 AbortSignal 取消；取消与异常暂停控制清单并停止所属部长，停止失败保留登记。主会话关闭暂停拥有的流并停全部孩子；普通会话与工作流分别按脉络隔离交接文件。
- 人工确认与恢复工具必须走 UI 确认；主控仅能处理明确交给主控的裁定，人工裁定需 UI 确认。桌面可经已绑定 owner 的 `/pao flow control <JSON>` 调同一工具逻辑。
- 主入口已接桌面 owner（真实 host 列表）、全角色预压缩与输出裁剪。两个 S4 开关默认关闭，效果尚不作结论。

## 尚待真实验收或集成

- 主代理统一构建后，必须由正式 CLI/桌面 owner 驱动真实部长和工人完成业务；当前协议测试不能代替这项。
- 真正多卡并发、自动补发、跨进程取消及重开续跑、change/reject 与人工闸、实际判定包，均须用正式入口保留本轮证据。
- 引擎将流程绑定调用它的真实主会话；“新建工作流即新建专属主控对话”的客户端创建行为须由桌面启动入口保证，本桥不自行创建第二内核或隐藏主控。
- 判定包已包含真实可取得的信息；非 git、缺验收或无法归因的既有未跟踪文件仍如实缺证，不能报审核运行通过。
- 专属部长 session-dir 为 `<workspaceDir>/部长会话/<实例>`，桌面钻取须按该目录定位，不能只查主控的 session-dir。

## 接口

- `workflow/minister.ts`：`loadFrozenRecipe(名字, DriverOptions)` 从控制正本只读加载冻结图。
- `workflow/control.ts`：`readControl`、`controlReport`；控制工具入参至少带名字、实例，节点动作还带节点、轮次。
- `workflow/host-bridge.ts`：`WorkflowHostBridge.drive(recipe, AutoChainOptions)` 与 `shutdown()`。
- `host/host.ts`：`执行任务({部门,项目根,脉络,会话标识,文本,signal?})`，仅在真实协议结束后返回；`散场(部门,项目根,原因,脉络?)` 保留失败登记。
