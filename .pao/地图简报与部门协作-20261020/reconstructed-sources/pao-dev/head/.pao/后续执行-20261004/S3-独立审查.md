## 尚未证明的边界

压缩快照目前保留全部历史用户原文、全部工具错误和部分助手原文，再在 context 中完整追加。它能保存原文，但不能证明压缩后输入会变小；若溢出主要来自长用户输入或长错误，重新注入可能维持溢出。需用冻结长输入样本验证实际最终请求大小与再次压缩行为，不能仅凭原文存在测试声称压缩有效。若保留完整原文导致无法完成请求，应报告具体失败并修正任务态提取方式，不静默截断约束。

现有脱敏测试覆盖明显凭证字段、Bearer、sk 前缀和隐藏推理块；不证明任意自由文本秘密均可识别。上下文查看的安全结论应限定实际覆盖面，必要时增加当前凭证值和常见连接字符串的脱敏反例，不记录真实凭证。

## 已确认可保留的设计

记忆纠正区分写新与忘旧两步，忘旧失败返回新条目 ID 与部分成功；缺 ID 和不支持忘却明确拒绝。任务快照不写入共享事实库。上下文捕获默认关闭，存储前脱敏，读取返回深拷贝。这些均需保留。

### 追加发现 S3-R6

共享纠正/忘却必须核对命中记录的供应商与当前供应商一致。发现时 session.ts 虽保存 hit.供应商，却直接把旧会话 ID 传给当前 manager 获取的 vendor。配置改供应商并 reload 是支持用法，旧供应商 ID 不能作为新供应商身份；若新库存在同 ID，可能作用于错误条目。已通知实施代理修复。排除键同样应包含供应商，避免同 ID 跨库互相排除。修复前本项仍未关闭。

实施代理追加（2026-10-04）：R6 已修改为供应商名一致才执行共享修改，排除键包含供应商；新增同 ID 跨供应商互不排除测试通过。另修首跑清单：普通 context、压缩两消息数组、树摘要条目均过滤 pao-firstrun，保留可见历史原件；3 文件 44 测试通过。以上是实施验证，独立复核与真实验收仍由主代理判定。
