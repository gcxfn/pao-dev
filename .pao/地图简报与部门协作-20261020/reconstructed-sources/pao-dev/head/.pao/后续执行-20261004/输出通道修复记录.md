# Bundle 与外置扩展输出通道修复

2026-10-04。根因：正式 CLI bundle 与显式 -e dist/pao/index.js 各含 output-guard 模块副本；原模块局部 takeover 状态与 drain 队列不共享，扩展 writeRawStdout 实际调用已重定向的 process.stdout.write，把辅助费用/完成/预算事件送进 stderr。

修复只改原生 core/output-guard.ts：使用进程 globalThis 上版本化 Symbol.for 键，共享原始 stdout writer、takeover 与异步写队列；普通日志继续 stderr，任意副本 flush 都等待同一队列，restore 也同源。未另开 JSON 输出通道，费用及预算发送代码无需分叉。

查图 trace_call_path(writeRawStdout) 返回多同名候选，随后完整源码核实状态与调用路径。模块定向3文件22测试通过；新增真实子进程双模块副本用例覆盖128条顺序、共享drain、普通日志、restore。Biome通过；此前类型检查仅AI既有两项。

正式入口无模型验收：复制当前dist到 packages/coding-agent/.channel-check/dist，只替换隔离副本的output-guard编译文件，复用正式生产bundle脚本构建隔离bundle。正式dist未覆盖。正式bundle启动RPC并显式-e隔离dist/pao/index.js，get_state后关闭stdin，不发prompt，模型请求0。

- 输出通道正常退出/：真实进程exit0，stdout恰有一条pao_usage_complete，无辅助/预算事件，stderr无该完成标记。
- 输出通道真实进程/：额外挂离线夹具写入未知原生账目与合成预算标记；exit0，stdout辅助费用/完成/预算标记各一条，stderr只有普通扩展日志等诊断，不含三类协议事件。此用例验证真实通道，不代表真实费用或预算耗尽验收。

构建与验证脚本同目录保留。`.channel-check` 是本轮隔离产物，供复核，不纳入源码交付；清理需确认无在用进程。T1-A旧真实回执的缺账证据保留，不能用此修复改写为原运行成功；新构建用于后续验收须另记身份。
