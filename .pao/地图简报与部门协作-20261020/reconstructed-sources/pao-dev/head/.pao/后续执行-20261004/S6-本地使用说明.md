# 三模板与本地桌面入口

截至 2026-10-04。以下入口已实现并通过离线检查；真实模型业务、桌面窗口启动/退出和终端回退的最终结果，以交付总报告的运行记录为准。本说明不宣称这些真实验收已通过。

## 安装模板

在 PowerShell 设置使用现场后执行：

```powershell
$env:PAO_HOME = 'D:\AI\workspace\pao'
pao templates list
pao templates install bugfix
pao templates install feature
pao templates install review
```

分别安装 `小bug修复.md`、`明确功能开发.md`、`独立代码审查.md` 至使用现场的 `工作流/`。默认每卡预算为 12 轮、80 次工具调用；没有默认费用许可。拆卡前卡数未知，不能据此推断总价。整体请求仍遵守已批准的可信共享额度。

可先用 `pao templates install bugfix --check` 查看安装结果与差异，不写文件。同名内容不同会保留用户版本并展示差异。另存使用 `pao templates install bugfix --as 我的修复流程`；不会覆盖原配方，也不会同步回出厂源码。预算可在安装时通过 `--budget` JSON，或在安装后的节点 `预算` 对象中填写；桌面向导也使用这个真实字段。模型、思考强度、技能沿同一节点配置。

模板没有凭证和项目知识，也不自动建立部门。本轮主代理已通过官方建部实现补齐“开发”“测试”，保留已有“审查”，证据见 `S6-必要部门安装.json`。缺失部门仍会在启动前检查中阻断。模板没有强制附加技能；确需技能时填写已安装且与本任务相关的名称。

## 启动与恢复

每次新运行使用新的主控对话和新的任务工作区，旧实例保留。桌面启动向导负责创建专属主控对话；终端中应先进入目标项目再新建主控会话。

主控的结构化命令示例（把路径和验收换成实际任务；PowerShell 中不要直接执行斜杠命令）：

```text
/pao flow start {"名字":"小bug修复","卡目录":"D:/目标项目/.pao/修复-本次/卡","参数":{"项目":"D:/目标项目","目标":"修复 listRecipes 将 .md 目录列为配方的问题","范围":"配方列表函数及其回归测试","验收":"真实复现 .md 目录误判，修复后相关测试通过并保留命令与结果","执行部门":"开发","测试部门":"测试","审查部门":"审查"}}
```

明确功能开发使用同样参数，名字改为 `明确功能开发`。独立代码审查使用 `独立代码审查`，只填写项目、目标、范围、验收、审查部门；该模板由只读部长检查已有代码与证据，执行层拒绝交工人卡，不能写项目。缺运行证据时必须明确“未验证运行”。

`/pao flow control <JSON>` 与 `pao_节点控制` 共用实现：

- 确认：名字、卡目录、动作“确认”、实例、节点、轮次。工具路径须用户在界面确认。
- 暂停：名字、卡目录、动作“暂停”、实例、理由。
- 恢复：名字、卡目录、动作“恢复”、实例、原owner、理由（现场核查说明）。须用户确认，不因重启自动恢复。
- 裁定：名字、卡目录、动作“裁定”、实例、节点、轮次、结果、理由、引用；change/reject 还需失败轴，change 需目标。只有当前待裁定请求匹配才执行；人工通道还须用户确认。

传入错误实例或旧轮次会被拒绝，错误会回传桌面调用方。运行中的配方修改不影响冻结实例；要调整流程，先停旧流、修改配方，再以新工作区建新实例。

## 本地桌面与终端回退

```powershell
pao app --check
pao app
```

检查核对当前 PAO fork 身份、锁版版本、本地 SDK 链接和构建产物。默认桌面目录是当前开发布局中的“桌面端”；其他本地位置可设置 `PAO_DESKTOP_DIR`。不下载第二内核，不替换全局命令，不执行上游升级。

窗口关闭后启动命令返回；启动进程收到 Ctrl+C/终止信号时停止其启动的桌面进程树。活动主会话沿已有父控制通道保护管理自己的孩子。真实 Windows 退出矩阵须另留运行证据，不能用静态检查代替。

```powershell
pao app --terminal
```

这条命令直接进入现有终端主入口，不需要桌面构建可用。普通 `pao` 也仍是终端入口。桌面兼容检查不通过会明确报缺项，并给出终端回退提示。

## 桌面机械维护

桌面打开时读取 `PAO_HOME/定时/*.json`。没有这个目录或没有启用任务时，不创建任务、不调用模型。关闭最后一个窗口后停止；后台不会继续值守。配置文件是唯一任务正本，运行结果在同目录的 `留档/`。

当前只支持巡检、归档、保温三种固定操作，工具白名单每项只能选一种。巡检只读知识库并列问题；归档只修剪本调度器明确完成的旧留档，每任务保留最近30份，失败、未知和人工文件保留；保温只预读本地文件，不调用模型或付费嵌入服务。`prompt`只作说明，不解释执行任意自然语言任务；留档明确区分固定操作完成与任意任务未验证。

例如，需明确启用后才创建如下任务；本轮不自动在正式现场创建：

```json
{
  "id": "知识库只读巡检",
  "名": "知识库只读巡检",
  "prompt": "列出本地知识库需要人工处理的问题",
  "cron": "*/5 * * * *",
  "工作目录": "D:\\AI\\workspace\\pao",
  "工具白名单": ["巡检"],
  "repeat": true,
  "enabled": true
}
```

`cron`表示按本机时区执行的时间规则，此例每5分钟执行。`repeat=false`只执行一次，有留档后不自动重跑；重新执行须明确使用新id。未知字段形态、坏时间规则及不支持工具会留错误，不作为成功。各任务串行运行；本次未实现大库分片，超期会失败并保留结果，不承诺维护耗时。实际关壳/强杀验收及最新构建结果见交付报告。
