## 二、公开来源调研（Claude Code 及其他编码 agent 的 todo 工具）

### 2.1 Claude Code TodoWrite（官方工具描述，多源交叉）

来源：官方文档（code.claude.com "Track todos"，经搜索摘要）、系统提示词提取仓库（Piebald-AI/claude-code-system-prompts 的 tool-description-todowrite.md；x1xhlol/system-prompts-and-models-of-ai-tools 的 Claude Code 2.0.txt——后者经 jsDelivr 全文核实）。cchistory 为 pi 源码自引的同源提取（站点为 SPA 未直接抓取，不影响结论）。

- **输入 schema**：`{ todos: [{ content, activeForm, status }] }`
  - `content`：必填非空（minLength 1），祈使句任务描述；
  - `activeForm`：现在进行时形式（如 "Running tests"），进行中时显示于 UI spinner；**近期 CLI 更新已改为可选**（缺省回退 content）；
  - `status`：枚举 **`pending | in_progress | completed`——三态，无 cancelled**。
- **语义**：每次调用**全量重写整张清单**（整表替换）；空数组即清空。
- **行为规则**（描述文本要点）：任务 ≥3 步、多任务、用户要求或新指令到达时先列清单；单一简单任务/纯问答跳过；开始一项先标 in_progress（**同时只一个**）；做完即标 completed **不攒批**（"Do not batch up multiple tasks before marking them as completed"）；completed 必须真实完成并验证，不凭意图；条数指引**「不超过 20 项，简单任务更少」**。
- **近期演变**（知悉即可）：Claude Code 2.x 后期将 Todos 升级为 Tasks 体系（TodoWrite→Task 工具，磁盘持久化＋依赖关系）；但 TodoWrite 的 `{todos:[{content,status,activeForm}]}` 整表形状仍是各家模仿对象、模型生态最熟悉。

### 2.2 opencode（sst/opencode，MIT）

源码核实（jsDelivr 抓 `packages/opencode/src/tool/todo.ts`、`session/todo.ts`、`schema/src/session-todo.ts`、`tool/todowrite.txt`）：

- 工具名 `todowrite`（历史上叫 update_plan，2026 年迁移到 todowrite，issue #1686 有模型侧迁移提示）；**全量替换**（update 实现 = 先删该 session 全部行再插入，position=数组序）；空数组=清空。
- schema：`{ todos: [{ content, status, priority }] }`——**四态 pending/in_progress/completed/cancelled**（写在字段 description，非硬枚举校验）＋ `priority: high/medium/low`；**无 activeForm、无 id**。
- 描述文本（todowrite.txt 全文核实）与 Claude Code 高度同源：≥3 步用／<3 步跳过；一次一个 in_progress；**实时更新不攒批**；completed "Never based on intent"（须真实验证）；受阻则该项留 in_progress 并追加描述阻碍的跟进项；保留用户指令原文；条目具体可执行；"When in doubt, use it"。
- 执行前过 permission 询问（permission: "todowrite"）。标题取未完成条数。

### 2.3 Codex CLI（openai/codex，Apache-2.0）

`update_plan` 工具：`{ plan: [{ step, status }] }`（step 而非 content），**三态 pending/in_progress/completed**（app-server 协议线上序列化为 camelCase `inProgress`）；一次至多一个 in_progress；整表替换（重规划即重写全表）。来源：Codex App Server 协议文档＋codex-rs 类型镜像（pkg.go.dev 镜像 `PlanStep`，注释 "at most one step is in progress at a time"）。

### 2.4 gemini-cli（Apache-2.0）

有内置 `write_todos` 工具（官方文档 geminicicli.com "Plan tasks with todos" 提及：规划任务时生成结构化清单再逐项执行）；**字段/枚举细节未能取得**（文档页 404，landing 页无内容）。另注：2026-06 起 unpaid 用户被引导至 Antigravity CLI。仅作存在性记录，不作为形状依据。

### 2.6 跨实现收敛结论

**整表替换 ＋ 条目 {内容, 状态} ＋ 「一次一个 in_progress」＋「≥3 步门槛」＋「完成即勾不攒批」是各家收敛形状**。差异仅在：状态枚举（CC/Codex 三态 vs opencode 四态）、activeForm（CC 有、opencode 无）、priority（仅 opencode）。「四态含 cancelled」是 opencode（及本机 pi-desktop）对 CC 三态的扩展，且 PAO 计划（S8.2）与桌面 parseTodoList 已按四态定案。

## 五、结论与建议（供派包定案）

### 5.1 总倾向

**复用公开形状的最小自实现**：不引入依赖、不拷任何外部代码；形状取「Claude Code 骨架 ＋ 四态扩展（对齐 opencode/pi-desktop/桌面现状/计划定案）」。

### 5.2 建议契约

- **工具名**：`todo_write`（pi 内核工具全小写约定：bash/read/write/edit/grep；opencode 同名；桌面 `/todo/i` 命中；TUI 无碍）。附注：pi-ai stealth 映射只把**无下划线**的 `todowrite` 规范化成 `TodoWrite`（`claudeCodeTools` 小写 key 无下划线），`todo_write` 不受影响、也无副作用；S9 英文化时此名已是终名，不进迁移表。
- **schema（TypeBox）**：`{ todos: Array<{ content: String(非空，trim 后非空), status: Enum(pending|in_progress|completed|cancelled), activeForm: Optional(String) }> }`。activeForm 收下但消费可选（模型生态熟悉该字段；桌面/首版可不渲染）；**不收 priority**（仅 opencode 有，两端无消费点，YAGNI）。
- **校验**：未知 status／空 content／条数>**20**（对齐 CC "aim for fewer than 20"，硬上限拒绝）／content trim 后重复——一律返回错误结果**不覆写旧清单**；空数组＝清空（合法）。
- **持久化/恢复**：循 todo.ts 示例——每次调用 details 携带整表快照，`session_start/session_tree` 从 `getBranch()` 扫描重建（分支/切换/恢复天然正确；getBranch 含被压缩条目，文件级安全）。压缩一致性两道防线：promptGuidelines 纪律段（模型侧自查对账）＋可选把快照存 `CompactionEntry.details`（首版可只做前者，验收「压缩后两端不串」以重建口径判）。
- **陈旧提醒（afterToolCall，阈值 5）**：经扩展事件 `tool_result` 实现（agent-session 已把 afterToolCall 分发为该事件，零内核改动）。计数口径：**会话当前清单非空**时，`isError===false` 且 toolName ∈ 实质调用集合（write/edit/bash/powershell 等写/执行类）才 +1；失败（isError）、读取类（read/grep/glob/ls）、`todo_write` 自身不计数；自上次 todo_write 起累计满 5 且本陈旧期未提醒过 → 在该次工具结果 content 末尾追加一行中文对账提醒；新 todo_write 后计数与提醒标志重置。阈值为模块常量，不建配置系统。
- **系统提示纪律段**：ToolDefinition.promptGuidelines（注册即注入）：≥3 步或用户要求先列清单；每完成一步立即更新；计划变化重构清单；交付前对账。promptSnippet 必给（否则 Available tools 段不出现，验收「工具真实注册可发现」过不了）。
- **worker 对账（S8.4）**：`pao/cards/delivery.ts` deliverCard/deliverCards 回执组装处读会话 todo 快照，pending/in_progress 项显式列出（cancelled 语义单列不混入未完成）；全勾不等于卡验收通过（验收逻辑不动）。
