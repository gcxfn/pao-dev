## 结论先行

1. **六条中只有第 4 条（时间线 active）接近一行改动的量级，其余五条全部有实质空白**：①1:1 唯一性校验与反查索引全缺（绑定写入处零查重）；②bug5 修复机制在位但「寄生全局当前会话」的架构未动，且发现一个**降级遮蔽缺口**（identity 内存回退让「失效绑定降级可重建」不成立，见专段）；③单工作流嵌入视图**零基础**（AppView 只有单一 canvas，无分流无回中心）；⑤内核无 `open(request)` 形状接口（现有＝单宿主 ctx.ui＋桌面 HostUiRequest 通道，可作承载）；⑥A6 竞态窗口**三层结构确认仍在**（内核前置窗＋driver 入口只查 isStreaming＋IPC 账本不覆盖不同 requestId），是否实际可触发仍须 S4 实测。

3. **最大的派包决策点**：第 2 条「主控按标签而非全局当前会话激活」的落地口径。现状＝按标签激活是**通过改写全局选中会话实现的**（转录通道单流），行为上已满足「画布内显示的必是标签主控」；若改为真·按标签双流，动 main 进程转录发布面，改动量级完全不同。建议按行为口径验收＋维持寄生实现（详见决策点 2）。
4. **发现一个 S0 已预警、本轮具现的新缺口**：controller 被对账剥离（归档/删除）后，渲染层 `controllers[controllerKey]` 内存回退仍供 identity → 「建立主控会话」按钮保持禁用、保存仍用已失效会话，直到重启。这正是 S0 存疑 1 点名的「identity 内存回退不绕过标签绑定」未验项，S4 第 2 条「标签降级为无主控，可重建」当前不成立。

**专段：identity 内存回退遮蔽降级（本轮新具现）**

- identity 取值：`activeTab?.controller && project ? {sessionId, project} : controllers[controllerKey]`（canvas-page.tsx:147,153-157）。controllers 为渲染层内存 map，键 `[project, kind, name]`，创建主控（:700-701）或保存（:646-650）时写入，**仅重启清空**。
- 后果链：归档/删除 controller 会话 → 主进程对账剥离 tab.controller → 内嵌面板正确隐藏（渲染条件要求 activeTab.controller 真值 :726）→ 但 identity 仍从内存 map 取到旧值 → 「建立主控会话」按钮保持禁用（masterSessionDisabled=!!identity，:690-697）→ 无法重建；且配方保存仍以失效会话为身份（recipe-canvas-editor.tsx:489-492 要求 identity、:497-501 用于 saveWorkflowRecipe）→ 保存走已归档会话，报错面在内核。
- 这正是 S0 存疑 1 点名的「identity 内存回退（controllers[controllerKey]）不绕过标签绑定」未验项（W-逐项核对.md:101），S4 第 2 条验收「失效绑定正确」当前不满足。
- 修复方向（供派包定口径）：identity 收敛为标签绑定单源（内存 map 仅作新建未落绑定的瞬时缓存，或直接随 controller 剥离同批清除）；连带决定 controllers map 是否可整体退役。

   - 归档/删除绑定会话：标签降级为无主控、「建立主控会话」可重建、保存身份不再用失效会话（专段缺口修复后）。
