## 既有机制核查结论（先核再动手）

### 档位.json 的正本与 schema（内核仓，只读）

- 源码正本：`PAO/packages/coding-agent/src/pao/routing/config.ts`。
- schema：`TierConfig = { provider: string(缺省 "pao"), 档位: TierDefinition[](至少一档，名唯一), 部门默认?: Record<部门, 档名> }`；
  `TierDefinition = { 名, provider, model, thinkingLevel, contextWindow?, maxTokens? }`，`thinkingLevel ∈ THINKING_LEVELS`（off/minimal/low/medium/high/xhigh/max）。
- 读写入口（全部导出）：
  - `loadTierConfig(configPath)`：读＋`validateTierConfig`（缺字段/重复档名/部门默认引用未定义档名等直接抛结构化中文错误）；
  - `saveTierConfig(configPath, config)`：**写前自校验＋旧文件时间戳毫秒备份（.bak-YYYYMMDD-HHmmss-fff，同毫秒追加序号）＋原子写**——「坏 JSON 不覆盖旧文件、先备份」内核已内置；
  - `resolveTierConfigPath(paoHome)`＝`$PAO_HOME/pao配置/档位.json`；序列化 tab 缩进。
- 包导出面：`@earendil-works/pi-coding-agent/pao` → `export * from "./routing/index.ts"` → `export * from "./config.ts"`。
  桌面 pi-sdk-driver 的 node_modules 内该包 v1.0.2（与 PAO 仓同版本号）dist 运行时已验证导出 `loadTierConfig/validateTierConfig/saveTierConfig/resolveTierConfigPath/THINKING_LEVELS`。

### /pao model 命令的复用程度

- 正本：`PAO/packages/coding-agent/src/pao/routing/model-command.ts`。它是 TUI 交互流（ctx.ui.select/input/confirm），**交互流本身不可在桌面复用**；
  但其写回底座就是 `saveTierConfig`，经包入口完整导出——**写路径 100% 复用，零内核改动**。
- fork 的 `/pao model` 编辑流语义（本包照抄）：新建时档名已存在→拒绝（"要改请直接选它编辑"）；物理模型支持手输 `provider/model`；
  部门默认引用被改丢的档名时由 `validateTierConfig` 在写前拒绝。

### 桌面现有档位消费面

- 向导预检步「主控档位」下拉：`apps/desktop/src/features/canvas/workflow-wizard.tsx`（WizardPreflightStep，Master tier select）。
- 向导节点步「模型/档位」下拉：同文件 WizardNodesStep。
- 数据链：`getWorkflowCatalog` IPC → `electron/platform/pao/workflow-wizard-bridge.ts`（normalizeTier）→ driver `loadPaoDesktopWorkflow` →
  fork `readDesktopRecipeCatalog(paoHome)`（`PAO/.../pao/desktop/editor.ts` 内 `loadTierConfig`）→ 档位.json。
- conversation 的 model-selector：档位以虚拟模型形式出现在模型注册表；注册时机＝会话启动（`PAO/.../pao/index.ts:269` `registerTiers(pi)`）。
- 别名归一现状：全仓无归一代码，档位名即虚拟模型 id 原样使用（归一属 S9 范围，本包不做）。

### 关键机制限制（已接受并写进 UI 提示）

`registerTiers` 只在会话启动时执行：**新写入的档位对已运行的会话不生效，需重开会话**（fork TUI 侧同形状限制：其他会话要 /reload）。
向导启动经 `startDesktopWorkflow` 的 `modelRegistry.find(provider, 档名)` 校验，未注册会得到明确报错，不静默兜底。

## UI 放置定案

放**向导预检步「主控档位」字段旁**的「管理档位」内联面板（任务书第一选项）：

- 理由：向导预检步是桌面唯一以档位为单位的直接消费点；用户痛点（要档位却只能手改文件）发生在此。
  设置区无档位现有面，从零建一页改动面更大。model-selector 是通用模型选择器，不适合塞档位管理。
- 面板内容：编辑对象下拉（新建/现有档）＋档名＋`provider/model`（手输，与 fork 手输后门同口径）＋推荐思考档（目录 thinkingLevels）＋保存；
  保存成功后刷新向导目录（新档位立即可选），失败原样透出中文错误。

## 数据流（新增 1 条 IPC 通道，属「确需」）

既有通道无档位写入面（渲染层无通用文件写通道，窄接口设计使然），故新增一条走同一三件套模式：

```
WizardPreflightStep 管理面板
 → api.saveWorkflowTier({tier, editing?})                    [contracts/ipc.ts + preload.ts]
 → expectWorkflowTierSaveInput                               [electron/ipc/request-validation.ts]
 → owners.workflowWizard.saveTier(input)                      [ipc/register-desktop-ipc.ts]
 → driver loadPaoTierAdmin().upsert(home, tier, editing?)     [packages/pi-sdk-driver/src/pao-tier-admin.ts 新增]
 → 内核 loadTierConfig ＋ saveTierConfig（备份＋原子写＋写前校验）
```

- driver 是薄封装（既有架构约束：主进程 CJS 不能静态引 ESM-only 内核包，经 driver 动态加载是既有模式，先例 `pao-workboard.ts`）。
- `editing` 语义：undefined＝新建（档名已存在→拒绝）；有值＝编辑该档（原名不存在→过期拒绝；改名后与其余档重名由内核 validateTierConfig 拒绝）。
- `部门默认`、`contextWindow/maxTokens` 等本包不编辑的字段原样保留（`{...原档, ...新值}` 合并）。
