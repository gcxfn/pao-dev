# S10-B canvas 关闭挂起族 debug 包 · 实施记录

- 开工 HEAD：desktop `832fbfd`（树核对干净）；内核参考 `58e3927cb`（只读）。
- 任务：定位并修复 workflow-canvas e2e 4 例（:508/:595/:676/:727）「quit 30s 未关闭」产品债。
- 结果一句话：**根因＝canvas 带脏态时退出，主进程离开守卫等页内「未保存修改」对话框的人选，测试无人应答 → quit 永久停摆 → harness 30 秒 kill（并掩盖真实失败）**。修法＝harness `close()` 在 quit 期间代答该对话框（放弃并继续），脏态退出 30s 挂死 → 3.1s 完成；run2 全 spec 0 例 quit-killed。

## 一、根因证据链

1. **复现（run1，修前）**：2026-10-08 19:00:51，HEAD 832fbfd，构建 16:02:19（晚于 HEAD 提交 15:19:42，版面成立），隔离口径（临时 PAO_HOME＋PI_OFFLINE=1＋PI_NO_LOCAL_LLM=1，background）。结果 9 过 5 红：4 债例全部「quit 后 app 仍运行 30s 被 kill」（:36 为并行负载 60s 超时噪音，run2 已自愈转绿）。每例失败栈都落在 finally 的 `app.close()`（:591/:672/:723；:727 挂在中测 :784 的 close 转 60s 超时）——测试体本身全过。
2. **卡点定位**：harness 已有插桩（`[test quit]` 阶段日志）。三份失败输出的 app stderr 全部**只有一条 `[test quit] before-quit`**，无 will-quit、无 window close 日志 → quit 停在 main.ts `before-quit` 处理器第一段＝`workflowLeaveGuard.requestAll()`，后续 quit 链（flush→will-quit→窗口关闭）从未执行。
3. **守卫机制**（`electron/windows/workflow-leave-guard.ts` + `src/features/canvas/canvas-page.tsx`：345）：quit → 主进程向渲染层发 `workflowLeaveRequested` → 渲染层 handler：干净＝立即放行；脏＝弹页内「未保存修改」对话框等人选（守卫约定「不使用超时自动批准」）→ 无人应答则 quit 无限等待。真实用户交互可应答，行为属设计内；测试环境的「用户」是 harness，而 harness 不会应答。
4. **脏态→quit 必挂单例证明（run595，修前）**：19:19 单跑 :595，测试体在 :634 断言失败（骨架未保存），finally quit → 30s kill。击杀时截图：编辑器「B独立配方 ● 未保存」＋标签脏点、**无对话框**（应答窗口期内无人交互的正常形态）。同轮对照：净态测试（:196/:245/:337/:453/:876/:915）quit 均秒级完成。
5. **债务 4 例为何体过仍挂**：测试体最后一断言为「已保存」，quit 前画布又被翻成脏态（保存后迟到异步/环境时序），进 teardown 即撞守卫。该「翻脏」环节依赖 canvas-model.ts（并行包 A 在改）与内核 dist（内核包并行在改，19:27 重建），且环境 floor 在波内移动，不在本包内追钉——本包钉死的是「脏态×无人应答＝30s 挂」这一唯一挂起机制。
