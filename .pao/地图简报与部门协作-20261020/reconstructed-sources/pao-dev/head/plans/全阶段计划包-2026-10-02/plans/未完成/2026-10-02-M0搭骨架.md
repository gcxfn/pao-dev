# M0 搭骨架

建稿：2026-10-02。状态：**待核当前现场；本文件不证明 M0 已实施**。

依据：需求 §6/§8、原 M0 计划、项目 AGENTS。原范围保留：空壳扩展、GLM 接入、目录约定、日志；卡片/查库/蜂群/档位路由都不提前到 M0。

## 目标

让 `PAO/` 成为能够被锁版 pi 加载的自含扩展包，GLM 能实际处理日常任务；建立后续可重复使用的配置、测试、证据与备份基础。

## 开工条件

读两级 AGENTS 与需求/架构；检查是否已有 M0 文件和代码。已有则补缺口，不重建。不把附件所写 `D:\PAO` 的旧变更数量当现场事实。

在动用户配置/全局工具链之前明确授权范围。备份现有可用配置并检查凭证；新项目或新目录是否需要治理文件按现有公约处理，不为本计划新建一套平行根规则。

## 复用与不自建

复用锁定 pi 的扩展、模型/provider 配置和项目已有测试工具。查现有包、测试、提示词与旧冒烟范式，只借可独立使用的部分；不迁旧 Kernel、桌面仓和控制协议。详见 [来源 E1/S2/S4](../附件/复用核验与来源.md)。

测试框架优先用项目现成依赖；没有则选一个能覆盖最小冒烟的成熟方案，不为一个空壳搭大型测试平台。具体版本以现场锁定，不在本计划伪造已经安装的环境。

## 验收

| 编号 | 场景 | 通过条件 | 证据类型 |
|---|---|---|---|
| G0-01 | 锁版 pi 加载 `PAO/` 并执行 `/pao` | 成功，版本与加载路径可核对；错误配置有明确提示 | 真实 Windows 运行 |
| G0-02 | 自动冒烟与重启 | 测试命令实际通过；重新启动仍加载同一包，无重复注册副作用 | 命令/退出码 |
| G0-03 | GLM 日常任务与工具 | 至少一件真实低风险任务完成；至少一次有效工具调用与结果消费 | 脱敏会话/产物 |
| G0-04 | 思考档与兼容参数 | 支持/不支持/被忽略如实区分；不支持时有可用配置，不假称生效 | 配置与响应 |
| G0-05 | 上下文溢出/错误识别 | 做受控模拟或可控真实复现，标明类型；已知会影响日常使用的错误需处理 | 模拟/真实明确分开 |
| G0-06 | Windows 中文、空格路径与解释器 | 在实际使用的 PowerShell/Git Bash 路径下启动、读写、测试可复现；不能验证的 shell 标未验证 | 真实本机记录 |
| G0-07 | 凭证、目录与备份 | 示例不带密钥；凭证不进 git/日志；已知可恢复的配置副本；目录约定与日志存在 | 文件核对/恢复抽查 |

GLM 接入要测的是需求 §8 **第一项的三个子项**；skills 和 MCP 留 M1。溢出模拟通过只能证明分类/处理分支，不等于真实 provider 已验证；不为获得一个日志故意消耗大笔上下文费用。

## 完成与进入 M1

包能真实运行，GLM 有日常活证据，工具调用与关键配置可用，测试命令与目录归属落地。无法验证的环境现象列明，不假填成功；若基本工具调用或装载不通，则 M0 不完成。

M1 的预算/模型测试将继续复核实际端点，不以 M0 的一次成功替代全部兼容性验收。记录本阶段全部修改、证据和回退方式，更新唯一焦点。

## 不做

不做卡片、建部、查库、入库、蜂群、虚拟档位路由、长期部长、协作、巡库或桌面。不开空等的“裸奔周”，也不在空壳阶段承诺已经具备子进程治理。

## 失败与回退

扩展加载失败先停用本轮扩展或恢复本轮前配置，不修改 pi 源码兜底；GLM 接入失败保留原可用入口并定位实际端点问题。不要覆盖其他 provider、删除旧项目、全量提交含密钥工作树或改变系统服务。

本阶段只回退自己新增/修改且可确认的内容。阶段完成后按 `plans/AGENTS.md` 归档；若执行前发现旧 M0 已通过，只补本次新增验收的证据链接。
