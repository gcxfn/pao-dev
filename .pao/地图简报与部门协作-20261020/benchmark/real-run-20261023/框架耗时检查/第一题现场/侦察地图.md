## 3. 解析行为实测（决定「尽量保留原有 HTML 结构与格式」的可行边界）

测试夹具均落在 `/tmp/recontest/`，**未写入 app 项目**（符合只读约束）。

### 3.1 两种解析器的规范化差异

```
$ python3 - <<'EOF'   # 输入 t.html，BeautifulSoup 解析后 str(soup)
== html.parser ==
<!DOCTYPE html>

<html><head><meta charset="utf-8"/><script>alert(1)</script><style>a{color:red}</style></head>
<body class="x" onload="evil()"><a href="javascript:alert(1)" onclick="x()">l</a>
<img src="javascript:alert(1)"/><iframe srcdoc="&lt;script&gt;1&lt;/script&gt;"></iframe>
<p>a &amp; b</p><br/><input disabled=""/></body></html>
== lxml ==
<!DOCTYPE html>
<html><head><meta charset="utf-8"/><script>alert(1)</script><style>a{color:red}</style></head>
<body class="x" onload="evil()"><a href="javascript:alert(1)" onclick="x()">l</a>
<img src="javascript:alert(1)"/><iframe srcdoc="&lt;script&gt;1&lt;/script&gt;"></iframe>
<p>a &amp; b</p><br/><input disabled=""/></body></html>
```

差异点：
- `lxml` 会**补齐 `<html>/<head>/<body>` 包裹**并重排空格；`html.parser` 保留原文的分行位置（`<!DOCTYPE html>` 后多一个空行）。
- 两者都把标签名转小写、属性值统一加双引号、空元素写成 `<tag/>`、`<br/>`/`<input>` 变成自闭合形式。

片段输入时的包裹差异：

```
$ python3 ...  # 输入 frag.html = '<!-- top --><p>中文 &copy; &#169; &nbsp;</p><div ...>'
html.parser: '<!-- top --><p>中文 © © \xa0</p><div class="a" data-x="1"><script>bad()</script>tail</div>'
lxml       : '<!-- top --><html><body><p>中文 © © \xa0</p><div ...>...</div></body></html>'
```

结论：**用 `lxml` 会给片段凭空加 `<html><body>` 包裹**，破坏「尽量保留结构与格式」；`html.parser` 不包裹。若测试输入可能是片段，`html.parser` 更安全。

### 3.2 实体 / 编码 / BOM / 换行

```
$ python3 ...  # crlf.html = BOM + '<!DOCTYPE html>\r\n<html>\r\n...'
html.parser: '<!DOCTYPE html>\n\n<html>\n<head><title>t</title></head>\n<body>ok</body>\n</html>\n'
             has doctype: True | BOM: False | CRLF kept: False | nbsp entity: False
lxml       : '<!DOCTYPE html>\n<html>\n<head>...</head>\n<body>ok</body>\n</html>\n'
             同上：BOM 丢失、CRLF → LF
```

- `&copy;` / `&#169;` / `&nbsp;` 全部被解成字符（`©`、`\xa0`），**命名实体不会原样保留**。
- 中文 UTF-8 内容往返无损：`'<p>中文 © © \xa0</p>'`。
- BOM 被吃掉；CRLF 统一成 LF。这属于「解析带来的规范化」，任务允许，但需要在产物里知悉。

### 3.3 文档声明的 charset 会被改写（**高风险点**）

```
$ python3 ...  # gbk.html：GBK 字节 + <meta charset="gbk">
original_encoding: gbk
out repr: '<html><head><meta charset="utf-8"/><title>中文</title></head><body><script>a()</sc'
utf8 write bytes head: b'<html><head><meta charset="utf-8"/><titl'
```

结论：BeautifulSoup 解析后，**`<meta charset>` 被改写为 `utf-8`**，而写出时若用 `encoding='utf-8'` 则内容与声明一致（不会乱码）；若原文件是 GBK 且测试按字节比对，会看到 charset 与字节双双变化。这是「就地写回」时必须显式决定的一点（见 6）。

### 3.4 属性顺序 / 大小写

```
$ python3 ...  # '<div z="1" id="i" class="c" a="2"></div>'
html.parser <div a="2" class="c" id="i" z="1"></div>
lxml        <div a="2" class="c" id="i" z="1"></div>
```

- **属性按字母序重排**（两种解析器一致）——`z,id,class,a` → `a,class,id,z`。
- 属性名转小写：`attributeName` → `attributename`。

## 4. HTML 中 JavaScript 危险面清单（实测，逐条给出当前解析器下的表现）

夹具 `t2.html`（`/tmp/recontest/t2.html`）集中覆盖下列面。命令与输出摘要：

### 4.1 `<script>` 标签（含内联、外链、SVG/MathML/template/noscript 内嵌）

```
-- find_all script: [(None,'x'), ('//e/x.js',None), (None,'2'), (None,'3'), (None,'4'), (None,'5')]
```

`BeautifulSoup.find_all('script')` 能**全部 6 个**都找出来，包括：
- `<script type="text/template">`（非 JS MIME，但仍是 script 元素）
- `<script src="//e/x.js">`（外链，无 text）
- `<svg><script>`、`<math><mtext><script>`
- `<template><script>`、`<noscript><script>`

移除验证：

```
removed 6 remaining script tags: 0
```

`decompose()` 后剩余 script 数为 0；`<div></div>` 这类空壳父元素**保留不动**（`remaining empty div survives: 1`）。

### 4.2 事件处理属性 `on*`

```
$ python3 ...  # <body ONLOAD="evil()"> <svg onload=alert(1)> <a onclick="x()">
-- attrs on svg: [('svg', {'onload': 'alert(1)'})]
event attrs removed: 1
```

- 属性名被转小写（`ONLOAD` → `onload`），所以匹配必须**大小写不敏感**或直接小写化后判断前缀 `on`。
- 实测遍历删除 `on*` 属性可行。

### 4.3 `javascript:` URL（href / src / action / formaction / data / xlink:href）

```
<a href="javascript:alert(1)">
<a href=" JaVaScRiPt:alert(1)">    → 前导空格 + 混合大小写
<a href="&#x6a;avascript:alert(1)">→ 解析后已还原成 'javascript:alert(1)'
<img src=&#106;avascript:alert(1)>
<form action="javascript:1"><button formaction="javascript:2">
<object data="javascript:1">
<a xlink:href="javascript:2">
<svg><set attributeName="x" to="javascript:1"/>
```

解析后实际属性值：

```
attrs sample: [('a', {'href': 'javascript:alert(1)'}), ('a', {'href': 'jav\tascript:alert(1)'}), ...]
```

要点：
- **HTML 实体编码（`&#x6a;` / `&#106;` / `&colon;`）在解析时被解码**，所以只要在 DOM 属性值上判断即可，无需自己解实体。
- **混合大小写 + 前导空格存在**（`' JaVaScRiPt:alert(1)'` 原样保留）→ 判断需 `strip()` + 大小写不敏感。
- **制表符/控制字符插入**（`jav\tascript:`）在 `html.parser` 下**原样保留**（`'jav\tascript:alert(1)'`）。浏览器会忽略这些控制字符从而执行，因此严格防护需先剥离 `\t\r\n` 等控制字符再判断。
- 仅删 script + on* 属性后，`javascript:` 仍有残留：

```
residual "javascript:": 7
```

即**只删 script/on* 不构成完整 XSS 防护**，`javascript:` 协议属性是独立面。

### 4.4 CSS 中的 JS（`style` 属性 / `<style>` 文本 / `<meta http-equiv=refresh>`）

```
<style>body{background:url(javascript:alert(1))}</style>
<div style="x:expression(alert(1))">css</div>
<meta http-equiv="refresh" content="0;url=javascript:alert(1)">
```

这些**不是** `script` 元素也不是 `on*` 属性，`decompose()` 不会碰它们：

```
<body><svg></svg><math><mtext></mtext></math>
<style>body{background:url(javascript:alert(1))}</style>
<meta content="0;url=javascript:alert(1)" http-equiv="refresh"/>
```

结论：`<style>` 正文、`style=` 属性、`<meta http-equiv="refresh">` 的 `content` 是**三类独立危险面**。是否处理取决于任务口径（「移除全部 JavaScript」——CSS 表达式与 refresh 跳转是否算 JS，需由实现决定并记录）。

### 4.5 其他载体

```
<embed src="data:text/html,<script>1</script>">
<iframe srcdoc="<script>1</script>">     → 解析后 srcdoc 值被转义为 '&lt;script&gt;1&lt;/script&gt;'
<textarea><script>notscript</script></textarea> → 解析后为文本 '&lt;script&gt;notscript&lt;/script&gt;'
<!-- <script>comment only</script> -->    → 注释内容原样保留，不被当作元素
<svg><![CDATA[<script>alert(1)</script>]]>
```

- `srcdoc` / `<textarea>` 内的 `<script>` 被当作**文本而非元素**，`find_all('script')` 找不到它们（上面 4.1 只找到 6 个，刚好不含这些）。风险在于注释/CDATA 中残留的 `<script>` 字符串若被二次解析仍可能生效——`html.parser` 输出**保留**注释与 CDATA 原样。
- 两种解析器对 CDATA 处理不同（`lxml` 会把 CDATA 拆成注释+文本：`<!--[CDATA[<script-->alert(1)]]&gt;`），这是 `lxml` 的额外失真证据。

### 4.6 危险面清单（汇总表）

| # | 载体 | 示例 | 是否 DOM 可见 | 备注 |
|---|---|---|---|---|
| 1 | `<script>` 元素 | 内联/外链/type=text\/template | 是 | `find_all('script')` 全覆盖 |
| 2 | `on*` 事件属性 | `onload`/`onclick`/`ONERROR` | 是（小写化） | 需大小写不敏感前缀匹配 |
| 3 | `javascript:` URL 属性 | href/src/action/formaction/data/xlink:href/to | 是（实体已解码） | 需 strip + 控制字符剥离 |
| 4 | `style=` 属性内 JS | `expression()`/`url(javascript:)` | 是 | 非 script 非 on* |
| 5 | `<style>` 正文 | `background:url(javascript:)` | 是（文本子节点） | |
| 6 | `<meta http-equiv=refresh>` | `content="0;url=javascript:…"` | 是 | 属性被重排为 `content` 在前 |
| 7 | `srcdoc` / `<textarea>` 内脚本文本 | 转义后为文本 | 作为属性/文本可见 | 防二次解析 |
| 8 | 注释 / CDATA 内脚本串 | `<!-- <script> -->`、`<![CDATA[…]]>` | 保留原样 | 防二次解析 |
| 9 | `data:text/html` 载荷 | `<embed src="data:text/html,<script>…">` | 是 | |

## 6. 对实现的直接约束（由上述证据推出）

1. 解析器：`html.parser`（标准库 bs4 内置，无需额外依赖）或 `lxml`；**`html5lib` 不可用**。片段输入推荐 `html.parser`（`lxml` 会补 `<html><body>`）。

3. 属性重排序（§3.4）与自闭合写法（§3.1）属解析规范化，任务允许，但**逐字节比对型测试会失败**。
4. `decompose()` 删除 script 后父元素保留（空壳不塌陷），符合「保留结构」。
5. 至少要覆盖 §4.6 的 1/2/3 类；4/5/6/7/8/9 是否处理需按「全部 JavaScript」口径决策并记录。
6. 只能依赖 `beautifulsoup4` / `lxml` / 标准库；不得 import `html5lib`、`bleach`、`nh3`（均未安装）。
