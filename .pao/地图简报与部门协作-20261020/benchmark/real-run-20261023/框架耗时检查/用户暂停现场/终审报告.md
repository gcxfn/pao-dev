## 1. 方法与边界

1. **不采信前轮结论**：B-1/B-2/N-2 的每一项都用自己的夹具实跑；前两份报告（`审核报告.md` 卡0007、`复审报告.md` 卡0009）只当背景，不作为证据引用。
2. **容器分支覆盖法**：先读 bs4 的 parser 事实（`HTMLTreeBuilder.DEFAULT_STRING_CONTAINERS`），确认「文本节点类」分支只有 6 个非 `PreformattedString` 成员，再逐类构造夹具，而不是只测卡面点名的 3 个容器。
3. **判据走 DOM 而不是正则**：危险面断言用 bs4 + lxml 双解析器（`//script`、`on*`/`srcdoc` 属性、危险 scheme 值），同时检查序列化字节里是否含字面 `<script`（防止「文本里留着可被宽松解析器识别的开标签」）。
4. **幂等一律 `cmp` 字节级**，且连跑 3 次（不是 2 次），并记录每次字节数，用来证明「不再增长」而不是「恰好两次相等」。
5. **新旧差分**用于区分「真修复」与「顺手改坏了别的」：22 组危险载荷 + 25 组良性文档，逐字节对比旧实现。
6. 自测 ≠ 官方验收；官方基准形态见 §10。

bs4 事实（本次实测，用于界定「全部容器分支」）：

```
$ python3 -c "from bs4.builder import HTMLTreeBuilder as T; print(T.DEFAULT_STRING_CONTAINERS)"
{'rt': RubyTextString, 'rp': RubyParenthesisString, 'style': Stylesheet,
 'script': Script, 'template': TemplateString}

NavigableString 子类树（非 PreformattedString 者即 `_mark_raw_text` 必须覆盖的分支）：
  PreformattedString=True : CData, Comment, Declaration, Doctype, ProcessingInstruction(>XMLProcessingInstruction)
  PreformattedString=False: RubyParenthesisString, RubyTextString, Script, Stylesheet, TemplateString
```

现行 `_mark_raw_text` 的判定是 `not isinstance(node, NavigableString) or isinstance(node, PreformattedString) → continue`，即「保护所有非 PreformattedString 的 NavigableString 子类」——与上表 6 个非 preformatted 类完全对应，且对 bs4 将来新增子类自动生效。

## 8. 残留风险（明确列出，不为了通过而回避）

| # | 载体 | 复现 | 当前行为 | 严重级别 | 判断依据 |
|---|---|---|---|---|---|
| R-1 | `data:text/javascript,…` | `<a href="data:text/javascript,alert(1)">y</a>` | **原样保留**（`_DANGEROUS_SCHEMES` 只有 `data:text/html` / `data:image/svg+xml`） | **一般** | 现代浏览器在 `href` 里不执行 `data:text/javascript`（无导航执行语义），但属「移除全部 JavaScript」口径下的已知缺口；卡面第 3 项未把它列为必查，故不判 fail |
| R-2 | `data:application/xhtml+xml,…` | `<a href="data:application/xhtml+xml,<script>…">` | 保留（实体被转义为 `&lt;script&gt;`，仍可解出脚本） | **一般** | 同 R-1；实际利用需用户点击导航 + 目标浏览器渲染 XHTML |
| R-3 | `srcset` 中内嵌 `javascript:` 片段 | `<img srcset="a.png 1x, javascript:alert(1) 2x">` | **原样保留**（`_is_dangerous_url` 用 `startswith`，整串以 `a.png` 开头） | **一般** | 浏览器不从 `srcset` 执行 JS（只取 URL 描述符），风险低；纯 `srcset="javascript:…"` 是会被删的（实测 `<img/>`） |
| R-4 | 带命名空间前缀的事件属性 | `<svg><a xlink:onload="alert(1)">` | 原样保留（`lowered.startswith("on")` 不命中 `xlink:onload`） | **低** | HTML/SVG 的事件属性不带前缀，`xlink:*` 是链接命名空间，非事件处理器；`xmlns:onclick` 同理 |
| R-5 | `livescript:` / `mocha:` 等历史伪协议 | `<a href="livescript:alert(1)">` | 原样保留 | **低** | 仅上古 Netscape/Firefox 有语义，现代浏览器按未知 scheme 处理 |
| R-6 | raw-text 容器内的载荷文本 | `<iframe><img src=x onerror=alert(1)></iframe>` | 文本原样保留（只有字面 `<script` 被中和为 `&lt;script`） | **低（有意取舍）** | raw-text 内容浏览器当文本读，不生成元素/属性；bs4 与 lxml 双解析器均断言无 `img`/无 `on*` 属性。若下游用宽松解析器重解析该文件需另行注意 |
| R-7 | 注释在 HTML5 不执行，但条件注释在旧 IE 有效 | `<!--[if IE]><img/src=x/onerror=…><![endif]-->` | **已删除**（N-2 修复后），但 `<!--[if IE]><p>hello</p><![endif]-->` 保留 | **低** | 无载荷的条件注释保留是正确的（B-2 的另一侧），有载荷的删除 |
| R-8 | `data-*` 属性值里出现 `javascript:` 字面量会被误删 | `<div data-foo="javascript:not-a-url">` | 属性被删（值以危险 scheme 开头） | **低（过度删除，不破坏安全）** | docstring 已声明「按值判定，覆盖任何 URL 承载属性」，属声明行为；仅影响携带此类字面量的 `data-*` |

另记录两项**非安全**观察：

- `_MAX_SETTLE_PASSES = 8` 不收敛时仍静默返回最后一次结果（N-3 未改）；本版实测 800 组随机拼接 `nonconv=0 worst=2`，已不会被触发（§9 O-2）。
- 含 `<?xml …?>` 声明/XML 风格文件会打印 bs4 的 `XMLParsedAsHTMLWarning`（stderr 噪声，`exit=0`、输出正确，`/tmp/f11/rob/nonhtml.xml`）。

## 9. 缺陷 / 偏差清单（最小复现、期望 vs 实际、级别）

### 阻断级缺陷：无

B-1（含 template/rt/rp/plaintext 全部分支）、B-2、N-2 均已修复；卡0007 的 9 项全部 regress 通过；没有发现可触发 XSS 残留的容器分支。

### O-1（一般，文档口径）docstring 第 9 条对「doctype 后纯空白兄弟节点」的描述与实际不符

- 位置：`filter.py:253-271`（`_normalize_doctype_spacing`）+ docstring 第 9 条（"a doctype is not followed by a redundant extra newline when non-blank content follows it … no trailing newline is appended to the document"）
- 最小复现：

```
$ printf '<!DOCTYPE html>\n<html><body><p>x</p></body></html>' > d.html   # 50B
$ python3 /app/filter.py d.html; wc -c < d.html; od -c d.html | head -2
51
0000000   <   !   D   O   C   T   Y   P   E       h   t   m   l   >  \n
0000020  \n   <   h   t   m   l   > …
$ printf '<!DOCTYPE html>\n' > d1.html           # 16B（doctype-only + 尾换行）
$ python3 /app/filter.py d1.html; wc -c < d1.html
17                                               # 尾换行从 1 个变 2 个
```

- 期望（按 docstring 字面）：doctype 后有非空内容时不出现多余空行；doctype-only 文档不追加尾换行。
- 实际：纯空白文本节点（`'\n'`）不被 `_normalize_doctype_spacing` 处理（该函数只剥「有内容且以 `\n` 开头」的文本节点），于是 bs4 的 `\n` 与本节点叠加成 `\n\n`，看上去多一个空行/多一个尾换行。
- 影响：**纯排版**。不破坏内容、不破坏 idempotency（`d.html` 再跑仍是 51B，`d1.html` 仍是 17B）、不涉及安全；`<html>`/文本/注释等兄弟节点情形（`<!DOCTYPE html>\nhello`）实测不变（30B→30B）。
- 判定：归入第 9 条「doctype/换行规范化」这一**已声明类别**，故不计格式保持 fail；但第 9 条的措辞需要收窄（例如改成「doctype 后仅补 bs4 固有的一个换行；有内容的文本节点再去掉一个重复换行」）。级别 **一般（文档口径）**，建议后续卡修文档，非阻断。

### O-2（观察，沿用 N-3）settle 循环不收敛时静默返回

`filter_html`（`filter.py:380-386`）跑到 `_MAX_SETTLE_PASSES=8` 仍未固定点时直接返回最后一次结果，不告警、不报错。本版实测（800 组含 plaintext/template/rt/rp/CDATA/doctype 随机拼接）`nonconv=0 worst=2`，已无触发路径；仍建议后续把「8 轮未收敛」当异常处理。级别 **观察**。

### O-3（观察，非回归）`once=`/`online=`/`only=`/`onion=`/`onset=` 仍被删

```
once=1  DELETED   online=1 DELETED   only=1 DELETED   onion=1 DELETED   onset=1 DELETED
person=1 kept     season=1 kept      lesson=1 kept     button=1 kept    version=1 kept
slogan=1 kept     icon=1 kept        选项=1 kept        revision=2 kept   options=1 kept
```

与旧实现完全一致（新旧对照均 DEL/KEEP），是「`on` 为词首」的既有策略，不是本卡引入的回退。级别 **观察**。

### O-4（观察）`<!-- onclick = alert(1) -->`（等号带空格）两侧都保留

`_ON_PAYLOAD_RE` 要求 `name=` 紧邻等号。新旧实现都保留该注释（实测 OLD/NEW 输出相同）。注释在 HTML5 不执行，且带空格的 `onclick =` 在 HTML 属性文法里**是**合法赋值形式，因此这是一个**潜在漏点**（低级别：仅注释内，无执行面）。级别 **观察**，建议后续卡把 `\s*=` 纳入（但会与 `options = 1` 的保留冲突，需一并设计）。

- **不漏清：pass**。14 个容器形态（含 template/rt/rp/plaintext/嵌套/组合）DOM 断言 `fails=0/14`，bs4+lxml 双解析器 0 残留，347 个输出文件无字面 `<script`，15 种 `javascript:` 混淆变形全删。
