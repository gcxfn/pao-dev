## 5. 新增风险复检（修复是否引入新问题）

### N-1（阻断，与 B-1 同根）raw-text 在 template/rt/rp 内仍转义放大 —— 见 §2.2

- 夹具：`<html><body><template><iframe>t &amp; u</iframe></template></body></html>`
- 断言：连跑两次 `cmp`；期望 identical，实际 109B→145B。
- 之前（卡0007 版）同样失败，所以严格说不是「新增」，而是**修复未覆盖的分支**；但卡0009 要求「B-1 确已修复」，故计 fail。

### N-2（一般）B-2 的正则把「注释内 on\* 载荷」的判定面收窄了

新正则 `(?:^|[\s"'])on…=` 要求 `on` 前是注释开头/空白/引号。实测 60 格前缀 × 载荷矩阵（`/tmp/rv9/q/`）：

```

new-missed prefixes: ['(', ',', '-', '.', '/', ':', ';', 'x']
```

具体夹具与结果：

```
IN=<p>a</p><!--x;onclick=alert(1)-->                              OUT=<p>a</p><!--x;onclick=alert(1)-->      （旧实现：删除）
IN=<p>a</p><!--a.b.onclick=alert(1)-->                            OUT=<p>a</p><!--a.b.onclick=alert(1)-->    （旧实现：删除）
IN=<p>a</p><!--[if IE]><img/src=x/onerror=alert(1)><![endif]-->   OUT=…原样保留…                              （旧实现：删除）
IN=<p>a</p><!--[if IE]><svg/onload=alert(1)><![endif]-->          OUT=…原样保留…                              （旧实现：删除）
```

- 期望（按卡0007 的彻底性口径）：注释内含 `on*=…` 载荷即删。
- 实际：`;`/`.`/`/`/`(`/`-`/`,`/`:`/紧邻字母 之后的事件处理器不再命中。
- 风险评级：**一般/低**——注释在 HTML5 浏览器中不执行（`<!--[if IE]…-->` 条件注释只在 IE≤9 生效，IE10+ 已废弃），因此不是可直接触发的 XSS；但它是相对卡0007 的**行为回退**，且 `<!--[if IE]><img/src=x/onerror=…>` 这类 iframe/IE 场景在旧浏览器里曾有实际风险。
- 若后续要收紧：把边界字符集扩到「非字母数字」即可（如 `(?<![\w])on[a-z0-9_:-]+=` 但要保留 `options=` 不误伤——需 `(?<![a-z0-9])on` 或白名单），本卡不改。

### N-3（观察）settle 循环不收敛时静默返回

`_MAX_SETTLE_PASSES = 8`，`filter_html`（`filter.py:350-356`）跑到 8 轮仍未固定点时直接返回最后一次结果，没有告警/异常。这是 N-1 表现为「每跑一次长大一点」而不报错的原因。建议后续把未收敛视为错误（本卡只记录，不改）。

### N-4（结论：无漏清）raw-text 内 `javascript:` / `on*` 载荷因「不转义」而保留，是否成为安全问题？

设计上 raw-text 内容被浏览器当**文本**读，不会生成为元素/属性；修复后输出把原文原样写出（只中和字面 `<script`）。逐夹具验证（`/tmp/rv9/nr2/`、`/tmp/rv9/domassert/`、`/tmp/rv9/lx/`、`/tmp/rv9/foreign3/`）：

| 夹具 | 输出 | bs4 DOM 断言 | lxml DOM 断言 |
|---|---|---|---|
| `<iframe><img src=x onerror=alert(1)></iframe>` | `<iframe><img src=x onerror=alert(1)></iframe>` | `tags=['html','body','iframe']`、`bad_attrs=[]`、文本节点 `<img src=x onerror=alert(1)>` | 无 img 元素（`lxml_tags_with_attrs=[]`），iframe.text 为那段字面串 |
| `<xmp><svg onload=alert(1)></svg></xmp>` | 原样 | `bad_attrs=[]`，无 svg 元素 | 无 svg 元素 |
| `<noembed><a href="javascript:alert(1)">x</a></noembed>` | 原样 | 无 a 元素 | 无 a 元素 |
| `<plaintext><a href="javascript:alert(1)">x</a>` | 原样 | 无 a 元素 | — |
| `<svg><iframe><img src=x onerror=alert(1)></iframe></svg>` | `<svg><iframe><img src=x onerror=alert(1)></iframe></svg>` | 属性残留 0 | 无 img 元素 |
| `<iframe><script>alert(1)</script></iframe>` | `<iframe>&lt;script>alert(1)</script></iframe>` | `script_tags=0` | — |

结论：**没有漏清**——载荷在 DOM 里只是文本，不是可执行的 script/on\* 属性；`&lt;script` 保证序列化字节里不出现 HTML 解析器可识别的脚本开标签（`</script>` 单独出现无对应开标签，仍为文本）。附带说明：raw-text 内的 `javascript:` 字面量保留是浏览器语义正确的（它本来就是文本），但若下游消费方用别的宽松解析器重解析，则需自行注意——列入 §10 未验证。

### N-5（观察）条件注释中的无害 iframe 不再被删

`<!--[if IE]><iframe src="x"></iframe><![endif]-->` 现在保留（旧实现删除）。这不是载荷（无 script/on\*/javascript:），属 B-2 放宽带来的正向变化，不算缺陷。
