## 口径与准备问题

Harbor 的试验重试次数仍为 0，但 PAO 内部已发生一次工作卡重派；两者必须分别报告。内部重派的时间和用量属于本次正式样本，不得从对比结果中扣除。

本轮组织配置的验收表达仍以自然语言为主，而且所选首题环境不具备 Git 边界核查条件。准备阶段的“配置可装载”检查不足以证明流程能连续自动推进；此前准备放行只代表真实 API、SDK 和配置装载通过。这是本轮设置和验收覆盖的实际不足。

## 建议处理顺序

1. 将自动可判定的验收写成真实可执行检查；需要判断的部分交给明确的审核职责，不让主控反复重复技术验收。
2. 核查 worker 完成通知到主控的消费过程，区分“工人在跑”和“回执已到、等待 owner 处理”；避免长时间 sleep 后只查仍未交付的卡状态。
3. 为“工作完成、回执格式错误”提供保留原成果的补交路径；仍须严格校验回执和真实产物，不能把提取到 JSON 直接冒充正式成功。
4. 将 Git 缺失和自动链连续推进条件纳入组织执行预检；不在当前样本中途补装依赖、修改实现或削弱检查。

建议先修流程再继续用新一轮试验评价收益。当前试验仍按原授权运行，本次检查未停止或重启正式题目。
