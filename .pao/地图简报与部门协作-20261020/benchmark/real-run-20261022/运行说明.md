# 修复后 PAO 三题后台复测

启动日期：2026-10-22。用户批准三题测试及性能占用监控。本轮独立运行，旧九项结果和停止记录保持原样。

三题为固定 Terminal-Bench 4.0.0 的 html-js-filter、bun-sourcemap-leak、nextjs-performance，各一次、题间串行。所有角色使用 group/deepseek、high；沿用原授权不设费用和 token 上限，保留官方时限，不自动追加尝试、重启或恢复。模型自定义服务的单价仍未知。

源码来自已验收的开发仓并已冻结为 source.zip；文件身份见 source-manifest.json。四部门流程为侦察→规划→实施→审核，侦察/规划保存结构化地图，实施按任务规模提交工人卡，质量判断由绑定部长留证。派发后结束模型轮次，部长每15分钟检查工人、主控每30分钟检查部门，结果落档后再投递唤醒。

每题模型启动前，在官方任务目录创建或保留真实 Git 输入基线，记录 HEAD 和工作区状态，供地图与改动范围核查使用。这是本次新运行的统一环境准备，不给旧样本补环境；新结果同时包含源码、组织配置和环境准备的影响。

## 当前与结束后的入口

- [运行状态](status.json)：由控制器记录，不把“运行完成”等同于“验收通过”。
- [后台观察状态](watch-state.json)：控制容器状态、性能进程是否存活。
- [控制器日志](controller.log)：安装、模型执行和官方验收的运行日志。
- [三题结果](三题结果.md)：结束后自动生成，逐题链接官方 result.json。
- [资源采样](resources.jsonl)：每30秒采样的原始记录；首次差值、采集失败或无法判断的阶段保持未知。
- [性能摘要](性能摘要.md)：结束后生成 CPU 采样峰值、内存首末值与采样峰值、进程数及缺失范围。

资源监控只采集本轮明确名单中的容器，记录容器 CPU、内存、进程数、网络和磁盘读写；Node 进程分为 PAO runtime、题目进程和无法归类的进程，再按角色/部门统计。PAO 与题目构建器、任务服务分开归因；监控不额外调用模型或改动题目。持续高占用、内存增长是调查线索，不能仅凭一个峰值判断代码结构。

## 后台与停止

控制容器为 `pao-bench-fixed-three-20261022`。后台程序与性能采样进程独立于当前对话运行，进程记录见 background-launch.json、monitor-process.json。结束或报错会落盘；控制器不会自动重启。

如需停止，可在当前对话要求停止本轮。程序支持本目录 user-stop.json 标记，仅停止名单中属于本轮的容器；失去可靠 Docker 状态会留下错误并停止监控，不伪造完成结果。

离线准备已通过真实 SDK 的主控/部长/工人工具与权限核对、Git/组织初始化、Harbor 配置校验。监控程序通过明确标注的假 Docker 自测；真实采样以 resources.jsonl 的实际记录为准。这些准备检查不代表三题已经通过。
