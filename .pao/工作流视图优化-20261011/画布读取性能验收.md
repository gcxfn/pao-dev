- 验证日期：2026-10-11。
- 结论：模拟夹具中，当前查询索引消除了逐节点重复扫描卡目录和读取执行映射；两版节点状态、会话标识、会话路径、会话状态及其他视图内容保持一致。
- 范围：真实调用 readDesktopCanvas；本任务没有修改产品源码，没有构建、checkout、reset、提交或发布，没有使用正式 PAO_HOME 或发起供应商请求。

## 方法与来源

复用项目 serializeCard、formatProjectList 和现有 desktop-canvas.test.ts 的 v1 清单形状。每个隔离项目都有 23 张卡、23 个节点、一个 23 节点配方和一份无版本键的 v1 实例清单。执行映射分别为 100 和 500 个 JSONL 文件，每个文件两条记录，首个文件多一条运行中记录；分别共 201 和 1001 条记录。模拟会话路径只供锚点显示，没有创建或读取真实会话文件。

本轮现有大图测试为一个文件内含 500 条映射；性能夹具补充测量多个映射文件的真实读取开销。所有数据均为模拟数据，不能代替真实工作流运行验收。

旧版基线仅将 Git HEAD（a2380612e69f38a0d21e7dd9586e65c42f8fb20e）的 canvas.ts 文本通过 Node registerHooks 在内存加载；其相对导入仍用当前工作树依赖，不是整个旧版内核。当前版读取本轮工作树 canvas.ts。两版分进程运行，使用相同磁盘夹具，均先预热 3 次，再测 7 次，取中位数。Node：v24.18.0。

计数器包装 node:fs 的 readdirSync、readFileSync、realpathSync，并 syncBuiltinESMExports 同步命名导入。计数统计真实函数调用次数，包含操作系统缓存可能命中的读取，不等于物理磁盘次数；测量不包括模块加载、夹具创建、内容断言和哈希计算。

## 内容与定向测试

- 每次读取得到一个实例和 23 个节点，没有异常行；每个节点的 in_progress 状态及预期会话逐项断言通过。
- 首节点重复执行标识按追加记录取运行中状态，并优先于其他成功会话；其余节点按时间取最近成功会话，会话路径一致。
- 两个规模分别对两版全部 20 次读取进行哈希核对：去除整个 envelope（视图传输信息，包含每次不同的发布时间）后的完整载荷哈希相同；完整节点数组哈希也相同。
- 定向命令在 packages/coding-agent 执行：pnpm exec vitest run test/pao/desktop-canvas.test.ts。结果：1 文件、18 项通过。日志：canvas-定向测试.log。
