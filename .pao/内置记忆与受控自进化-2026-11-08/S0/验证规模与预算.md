# S0-12 验证规模、前台延迟目标与真实模型验证预算

日期：2026-11-08

## 本地规模目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 首轮验证规模 | 1,000 条决定 | 首期最小可用规模 |
| 扩展验证规模 | 10,000 条决定 | 评估是否需要引入成熟向量索引 |
| 并发宿主 | 2（CLI + Electron） | 验证双宿主读写 |
| 本地查询 p95 | ≤300ms | scope 过滤后的词法+向量合并查询 |
| 网络语义前台等待 | ≤3s | 嵌入端点可用时的语义召回 |
| 超时降级 | 词法结果返回 | 语义超时后仍能返回本地结果 |

## 真实模型验证预算

按 C3 定案：**首次真实模型验收批次不另设总金额上限**；仍完整记账、普通任务优先，达到验收目的即停止。不扩展为长期后台无限额度。

| 场景 | 样本数 | 说明 |
|---|---|---|
| I01—I10 冻结情景 | 10 条 | 每个情景至少 1 次完整链路 |
| 同义改写召回 | 20 条查询 | 验证语义路不被词法截断 |
| 中文决定提炼 | 10 条对话 | 验证确认状态与证据类别分离 |
| 纠正与修订 | 5 条 | 验证 correctMemory 单事务与冲突返回 |

## 达不到目标时的缩小/优化路径

| 瓶颈 | 处理 |
|---|---|
| 向量线性计算超时 | 先按 scope 过滤减少候选数；仍超时则评估 sqlite-vec 或固定维度索引 |
| FTS trigram 短词漏召回 | 短词自动走 LIKE '%词%' 补充，已在 S0-06 验证可行 |
| 语义端点延迟高 | 本地词法先行返回，语义异步补充；标注 semantic_unavailable |
| 并发写冲突频繁 | 提高 busy_timeout 至 10000ms；事务粒度细化到单条修订 |
