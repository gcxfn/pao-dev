## 冻结任务对比（S7-11）

`S7/comparison/run-memory-benefit.mjs`，同一冻结任务两遍逐字相同、`magpie/group/deepseek` thinkingLevel=low、隔离 PAO_HOME；有记忆臂经 `service.createMemory` 正式预置 3 条 confirmed 记忆。每臂 3 轮真实调用。报告 `S7-11-无记忆与有记忆对比报告.md`：

- 空记忆 3/3 需用户重述原文；预置历史 3/3 免重新解释且正确复述已定方案；

- 结论限于本冻结任务与该模型，小样本不写确定收益。

## Windows 发行物（S7-12）

`apps/desktop/tests/production/packaged-s7-12.spec.ts` 用 `ELECTRON_RUN_AS_NODE` 起发行物 `win-unpacked/PAO.exe` node 子进程、从 `app.asar` 内 dist 导入内核，五段 phase 串一条链，全程 `execPath===PAO.exe` 证明双宿主都是发行物运行时。实测证据：

1. **整理中退出→重启→继续**：宿主 A（`pid-34388`）claim organize 作业并推进 `ckpt-1` 后进程结束（running 死持有者）；宿主 B `recoverJobs` 重取 pending → claim 从 `ckpt-1` 续到 `ckpt-2` done——cursor 接续不从头重跑；
2. **CLI/桌面并行开同一 home**：宿主 B（`pid-34804`）在 A 仍 running（死持有者未 recover）时直接 claim 如实得 `null`，不重复消费；B recover 后才以新 owner 领取；
3. **成果复用**：`aver-9128b2c6…` 受管版本经 `resolveArtifactVersion` 回读确切内容（seq=1）+ `ause-e2c2db9e…` `recordArtifactUse` 归因；
4. **全程用量**：`openPersistentMemoryLedger` 后台账本写 `kind=extract` usage `req-s7-12-job-4497`，`readMemoryUsage` 聚合出该 requestId、input 111/output 22/total 133 token、cost 0.00133，unknownCount=0。

完成判据「状态、版本、费用和来源链全部可追溯」逐项落实：job `cursor+owner_process+status`、artifact `versionId+seq`、usage `requestId+jobId+sourceSessionId`、artifact_uses 归因行。证据：`S7/packaged-validation/packaged-s7-12-evidence.json` + `packaged-s7-12-memory.sqlite`。

## 验证范围与边界

- S7-10 spec（41.9s）与 S7-12 spec（3.2s）通过、桌面 typecheck（renderer+electron 双侧）通过；发行物为本轮 `pnpm run package:win:dir` 产出的 `win-unpacked`（exit 0，含 vendor 内核与 asar 签名）。
- 全部验收用隔离 PAO_HOME，不触正式现场；脚本 provider `base_url` 指不通地址，无真实外部请求。
- S7-12 只验发行物运行时内核链路（重启续作/双宿主/成果复用/用量聚合）；页面级发行物行为已由 S6-11 发行物验收覆盖，本轮不重复走 UI。
- 费用字段：脚本 provider 返回固定 cost 时可验证聚合；真实供应商（如 S7-11 的 `magpie/group/deepseek`）无 `cost.total` 时如实标 unknown，不折算。
