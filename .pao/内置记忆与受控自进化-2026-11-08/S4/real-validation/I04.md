# I04：页面纠正后旧提炼结果返回

日期：2026-11-09。状态：adapter 与离线验证完成；尚未执行真实模型请求，I04 未通过。

## 冻结目标

输入以
`PAO/packages/coding-agent/test/pao/fixtures/memory/scenarios/I04.json`
为唯一冻结源。原始对话为：

1. 用户问“自动召回每轮取几条？”
2. 助手回答“目前缺省 top3。”
3. 用户说“改成 top5。”

页面操作把“自动召回每轮 top5”纠正为“自动召回每轮 top3”。随后旧提炼结果返回 top5。
最终要求同一 memory ID 保持唯一 active，当前 revision 为 2，结论为 top3；旧请求携带的
r1/top5 身份不得被当成 r2/top3。`src-sess-e-001` 映射实际最后一条用户消息，
`src-sess-e-page-001` 映射实际页面操作来源。

## 入口与门控

入口为 [memory-acceptance-stale.mjs](../../../../scripts/memory-acceptance-stale.mjs)
导出的 `runStaleScenario(options)`。从项目根调用：

```javascript
import { runStaleScenario } from "./scripts/memory-acceptance-stale.mjs";

const controller = new AbortController();
const result = await runStaleScenario({
  runRoot: "D:/tmp/i04-real-<run-id>",
  executeReal: true,
  authPath: "<现有只读 auth.json 路径>",
  modelsPath: "<现有只读 models.json 路径>",
  tierConfigPath: "<档位 JSON 路径>",
  tierName: "fast",
  scope: {
    taskId: "<隔离任务 ID>",
    department: "<隔离执行部门>",
  },
  allowFixtureEmbedding: true,
  semanticSample: false,
  signal: controller.signal,
});
```

也可以传 `tierConfig` 对象代替 `tierConfigPath`。`runRoot` 必须是尚不存在或空目录；所有
运行数据只写在该目录下，正式 PAO_HOME 不被修改。`scope.projectId` 不是调用参数：adapter
用隔离 workspace 调用产品 `resolveMemoryScope()`，`projectId` 与 `executionRoot` 均取
解析结果。调用方只可按需补 `taskId` 与 `department`。

只有 `executeReal === true` 才创建 `ModelRuntime` 并调用真实模型。其他值，包括字符串
`"true"`，都不进入真实模式并要求提供 `mockRequestExtraction`；真实模式禁止 mock。
真实模式缺 `authPath`、`modelsPath` 或档位来源时在模型调用前失败。

真实路径复用现有授权与模型路由：

- `ReadOnlyAuthStorage(authPath)` 直接读取现有凭证文件，不复制或改写 `auth.json`。
- `ModelRuntime.create` 使用 `InMemoryCodingAgentModelsStore`，关闭创建期模型目录网络刷新。
- `ModelRegistry`、`requestExtraction`、`commitExtractionCandidates`、
  `embedCurrentMemories` 和 `ledger.appendUsage` 均为产品 dist 公开入口。
- `ModelRuntime` 的 `allowModelNetwork:false` 只关闭模型目录刷新；真实模型请求仍由
  `requestExtraction` 通过 `streamSimple().result()` 发起。

`allowFixtureEmbedding` 默认关闭。显式为 `true` 时，adapter 只向隔离 home 写本次 fixture
所需的外发许可，再用真实 scope、execution root/resolver 调用产品 `embedCurrentMemories`。
r1 在页面纠正前仍为 current 时嵌入；页面纠正生成 r2 后再嵌入。adapter 只读产品生成的
vector 行作为证据，不给历史 revision 手工造向量。

`semanticSample` 默认关闭。显式设为 `true` 必须同时满足 `executeReal=true` 与
`allowFixtureEmbedding=true`；满足后才在同一个 I04 隔离 home 上运行 20 条同义查询采样。
它不会改变 I04 判定，也不会默认扩大模型或嵌入调用。

## 请求快照与提交

首次 commit 使用首次请求开始时冻结的相关记忆快照：

```javascript
relatedMemories: initial.input.relatedMemories ?? []
```

旧提炼请求返回后进入页面纠正阶段。旧结果的 commit 只使用旧请求输入中已经冻结的
`relatedMemories`：

```javascript
relatedMemories: stale.input.relatedMemories ?? []
```

commit 返回后不重新 list/search/read 相关记忆。当前产品对页面纠正后 revision 已变化的
候选返回：

```json
{
  "status": "skipped",
  "reason": "stale_request_snapshot",
  "memoryId": "<首次提交的实际 memory ID>",
  "snapshotRevision": 1
}
```

判定按 `memoryId + revision` 身份执行：允许初稿 top5/r1 与当前 top3/r2 使用同一 memory ID，
但不会仅凭 ID 把两者折叠，也不会把 r1 当成 r2。

## 执行顺序

真实模式按以下顺序运行：

1. 读取并原样保存冻结 I04；用隔离的 `SessionManager` 建立实际 `sess-e` 会话及三条
   message entry。
2. 用 `createCapture` 采集实际 entry，得到真实 `sources` 行和归档位置；随后通过
   `MemoryService.readMemorySource` 按 `offset: 0, limit: 1` 取回每条完整来源事件。
3. 首次调用真实 `requestExtraction`，把通过校验的候选交给真实
   `commitExtractionCandidates`。top5 memory ID、revision 和提交结果取自实际返回，
   不从 expected 创建记忆。
4. 若 `allowFixtureEmbedding=true`，在 r1 仍 current 时调用产品 `embedCurrentMemories`。
5. 通过桌面公开 list/detail API 读取当前 active 记忆，构造旧请求的 `relatedMemories`
   请求前快照，并写入旧提炼输入。
6. 发起旧提炼请求。脚本包装 `streamSimple().result()`，在真实模型结果返回后、交给
   `requestExtraction` 做解析/校验之前暂停。
7. 暂停期间调用真实 `mutateDesktopMemory({ op: "correct" })`，按首次提交返回的 memory ID
   和 revision 把内容纠正为 top3；若已允许 fixture embedding，再调用产品
   `embedCurrentMemories` 嵌入 r2。
8. 释放旧模型结果，让其继续解析和校验；commit 使用旧请求快照，并核对每个候选实际返回
   `skipped + stale_request_snapshot`。
9. 通过桌面公开详情/列表/搜索 API 与 SQLite 实际行核对：唯一 active 行为同一 memory ID
   的 revision 2、结论 top3；不存在 active top5。

页面纠正不创建聊天 session。`mutateDesktopMemory` 的产品归档入口生成
`sessionId: "desktop-page-operations"`、`entryId: "page-operation-<uuid>"` 的真实用户
操作来源。`sources.json` 把冻结逻辑 source 别名映射到该实际身份。

## 费用与未知值

`usage.cost.total` 是产品归一化成本，不等于供应商账单。adapter 的分项规则是：

- provider 费用始终标为 `providerFee: "unknown"`。
- 归一化值大于 0 时保留数值，费用来源标为
  `provider_or_catalog_normalized_nonzero`。
- 缺失、非有限值或归一化值恰好为 0 时不写成“实际零费用”，来源保持 `unknown`。
- 离线模拟不构造供应商费用；model 证据明确标 `mode: "simulated"` 和
  `modelInvoked: false`。

延迟分别记录 `streamSimple().result()` 的调用延迟和整个提炼阶段延迟。取消或失败的模型
调用仍保留 provider/model、错误、已观察延迟和已有 usage。

## 取消

`options.signal` 会传入 `ModelRuntime.create`、`streamSimple`、旧结果释放等待和各阶段边界。
取消返回 `status: "cancelled"`，写 `failure.json` 和 `run_cancelled` 事件；已开始的输入、
模型调用、嵌入和页面纠正证据保留。提炼请求开始时输入已经落盘，因此取消发生在模型结果
返回前时，仍能回查当时发送的完整请求快照。
