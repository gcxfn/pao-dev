## 调用链（renderer → 内核）

```text
MemoryPage (D/src/features/memory/)
  → DesktopApi (D/contracts/ipc.ts)
  → electron/preload.ts
  → registerMemoryRequests (D/electron/ipc/memory-requests.ts)
  → createMemoryBridge (D/electron/platform/pao/memory-bridge.ts)
  → loadPaoMemoryModule (B/src/pao-memory.ts)
  → loadPaoDesktopModule (B/src/pao-desktop-module.ts)
  → K/desktop/memory.ts (内核公开桌面入口)
  → MemoryService (K/memory/service.ts)
```

规则：renderer 不传任意文件路径、不拿数据库句柄；IPC 层只校验契约形状，业务判定（scope、停用、删除范围）在内核；页面变更与对话纠正走同一 `correctMemory`/`setMemoryUsage`/`mergeMemories`/`deleteMemory` 入口。

## 子任务一契约（内核桌面入口 + B 转发）

### `K/desktop/memory.ts`（新增）

导出四个函数，全部只依赖 `openMemoryService(home)`，不需要活动 session owner，后台直接按 PAO_HOME 查库：

| 函数 | 输入 | 输出 |
|---|---|---|
| `readDesktopMemoryList` | `{home, scope, query, status, kind, page, pageSize}` | `{items: MemoryListItem[], total, hasMore, degraded?, degradeReason?}` |
| `readDesktopMemoryDetail` | `{home, id}` | `{memory, revisions[], sources[], usageSummary}` |
| `mutateDesktopMemory` | `{home, op}` | op ∈ `correct`/`setUsage`/`merge`/`deletePreview`/`deleteConfirm`；返回各 op 的结构化结果（含 revision 冲突信息） |
| `readDesktopMemorySource` | `{home, sourceId}` | `{events, metadata, missing}` |

- 返回纯结构化 DTO（可 JSON 序列化），不返回数据库句柄、函数、Date 以外不可序列化对象。
- scope 由调用方传入已解析的 `{projectId?, deptId?, taskId?}`；内核不替桌面猜项目身份。
- 从 `K/desktop/index.ts` 导出。

### `B/src/pao-memory.ts`（新增）

- `loadPaoMemoryModule()`：经 `loadPaoDesktopModule()` 拿公开函数，导出上面四个 + 类型。
- 不导入内核私有路径（`src/pao/...` 深路径），不复制业务判定。
- 更新 `B/src/index.ts` 导出（把要加的行写清楚给整合者）。
- `B/test/pao-memory.test.mts`：验证实际导出函数存在且签名匹配（可 mock loadPaoDesktopModule）。

## 子任务三契约（IPC + 页面）

### IPC/preload（S4-03、S4-04）

- `D/contracts/memory.ts`：renderer 侧 DTO 与 channel 名。
- `D/electron/platform/pao/memory-bridge.ts`：`createMemoryBridge`，经 `checkPaoHome/loadDriver` 取 PAO_HOME，调 `loadPaoMemoryModule`。

- `contracts/desktop-state.ts` `AppView` 增 `memory` + `expectAppView`；`features/threads/sidebar.tsx` 加入口；`App.tsx` 分支。
- 新窗口、重启恢复视图、无活动对话均可进入；不自动创建会话。

### 页面（S4-05 ~ S4-11），`D/src/features/memory/`

| 文件 | 职责 |
|---|---|
| `memory-page.tsx` | 布局：左范围/类型筛选、中搜索结果、右详情；query+scope+status 组请求，筛选变更重置分页、丢弃迟到旧请求；列表/加载/空态/不可用/语义降级态 |
| `memory-detail.tsx` | 当前决定 + 修订时间线；理由/条件/来源独立区块，按 sourceId 加载历史；长中文、未知理由、多次替代可读 |
| `memory-source.tsx` | 点来源调 `readDesktopMemorySource`；显示原会话/时间/原文位置；不存在版本明确失效 |
| `memory-actions.tsx` | 纠正表单（带 expectedRevision，冲突保留草稿展示最新）、多选合并（先展示保留项+理由）、停用/恢复（明确按钮，不乐观更新）、删除（先 preview 列受影响会话/共享来源/不受管位置，按 operationId 显示进度，pending 不标完成） |
| `memory-usage.tsx` | 「本任务参考」视图：按 sessionId/taskId 查使用记录，区分注入/展开/明确引用，指向当时 revision |

- 状态易辨：正式/未定/推测/停用有视觉区分，无需读原始 JSON。
- `D/tests/unit/memory-page.spec.ts`：A 项目请求迟于 B 返回也不覆盖；切范围不混结果。
