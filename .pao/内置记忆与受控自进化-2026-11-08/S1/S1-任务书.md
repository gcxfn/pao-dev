## 各批关键实现口径

### A：paths + store（S1-01、S1-02）
- `memoryPaths(home)` 返回 `<home>/memory/` 下 `memory.sqlite`、`archives/`、`artifacts/`、`attachments/` 根；所有调用显式传 home，禁止从 cwd 推测。
- `store.ts`：`openMemoryService` 按 PAO_HOME 共享连接、引用计数关闭；首建表/索引/约束；WAL + 外键 + busy_timeout。
- 表结构按实施路径「表与事务的最小形状」：`projects`、`project_roots`、`memories`、`memory_revisions`、`sources`、`memory_source_links`、`archive_segments`、`memory_fts`（FTS5 trigram 占位，首期先建表）、`source_exclusions`、`deletion_operations`、`scope_revisions`。成果/向量/作业/使用记录表 S1 不建。

### B：service + sources（S1-03、S1-04、S1-09—11）
- `createMemory`：要求明确 scope 与 ≥1 条 sourceId；confirmation 缺省 tentative；正文+来源关系一个事务。
- `getMemory`：当前修订 + 可选历史 + 来源摘要 + supersedes 链。
- 修订事务：`expectedRevision` CAS；追加修订、来源、替代关系、scopeRevision 递增、旧索引失效，一个事务提交。
- `setMemoryUsage`：active/stopped 切换走同一 CAS；默认查询排除 stopped；恢复不复活旧内容。
- `mergeMemories`：只合并用户明确选定项；canonical 保留，旧 ID 记 mergedInto；矛盾结论拒合并（返回错误而非强制）。

### C：capture + archive（S1-05—08）
- `capture.ts`：挂 `turn_end`/`agent_settled` 事件；按 sessionId+entryId 去重；首次启用记边界，只收增量。
- 凭证剔除：复用现有脱敏入口；已知凭证字段不进入原文/数据库/异常/附件说明。
- `archive.ts`：事件段写临时文件 → 流式 gzip（复用 `K/shared/evidence.ts` 原语）→ 发布 → 更新 `archive_segments` 位置；未封存段可直接读。
- `readMemorySource`：sourceId→segmentId→事件范围；兼容未封存与压缩段；缺来源返回 `source_missing` 而非伪造。

### D：deletion（S1-12、S1-13）
- `previewMemoryDeletion`：沿来源关系展开修订/索引/注入消息/附件/原会话；标出被其他记忆引用的共享部分；返回精确对象，不删数据。
- `deleteMemory`：先停用+写 `source_exclusions`→等受影响会话安全点→重写已关闭 JSONL 目标段→重写归档→清库及索引→重载会话；operationId + complete/pending/failed；失败保留状态可重试，不先报完成。只删 PAO 管的对象，用户项目文件/Git 历史不动。

### E：工具接线（S1-14）
- `memory/index.ts` 三工具改调 `service.ts`；`K/index.ts` 只装配同一服务引用。
- 忘却默认转 `setMemoryUsage(stopped)`；彻底删除走 `deleteMemory` 明确动作。
- 不再为数据库包文本型 gbrain 适配器；同步 SDK 类型导出。

### F：定向测试（S1-15）
- `memory-store.test.ts`：事务中断、缺来源、双进程写、修订 CAS 冲突、停用/恢复/合并。
- `memory-source.test.ts`：采集去重、凭证剔除、归档封存/回读、跨重启定位、缺来源标缺失。
- `memory-deletion.test.ts`：preview 范围、删除后正文/索引/归档清理、共享引用保留、pending 重试。
- 验收演示：工具写入→退出→重开→查详情→原文回读完整结果写报告。
