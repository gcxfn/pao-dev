## 2. 场景设计

种一个 `skill:test-skill` 资源，SKILL.md 正文含一个可机器检测的错误（如缺少必要步骤 `步骤三: 验证输出`）。造三个样例：

- **reproduction**：`node -e` 检查 SKILL.md 含 `步骤三` → baseline 时文件不含 → 应 failed
- **normal**：`node -e` 检查 SKILL.md 含 `步骤一` → 两侧都应 passed
- **holdout**：`node -e` 检查 SKILL.md 含 `步骤二` → 两侧都应 passed

`proposeCandidate` 的 fakeRegistry 返回预设 JSON edits，把 `步骤三` 写进 SKILL.md → candidate 侧 reproduction 转 passed，全链 verdict=passed。

## 3. 链路步骤（测试主流程）

```ts
// 1. 种资源
registerResource(store, { resourceId: "skill:test-skill", kind: "skill",
  relativeRoot: "pao配置/skills/test-skill", allowedOps: ["edit-content"],
  capabilityScope: ["text-effect"], loadMethod: "skill-path", paoHome: home })

// 2. 写文件 + 快照
// home/pao配置/skills/test-skill/SKILL.md 内容缺「步骤三」
snapshotResourceFiles(store, { resourceId: "skill:test-skill", paoHome: home })
// → baseVersion = "v-{hash12}"

// 3. 声明问题
declareImprovementIntent(store, {
  kind: "implementation_defect", action: "modify",
  summary: "test-skill 缺少步骤三",
  expectedBehavior: "SKILL.md 应含步骤三: 验证输出",
  actualBehavior: "SKILL.md 只有步骤一和步骤二",
  evidenceRefs: ["src-ev-test-001"], // 夹具 sourceId，sources 表种一行
  resourceId: "skill:test-skill", baseVersion,
})
// → problemId, status=observed

// 4. 分类
classifyProblem(store, { problemId }) // → classified, resourceId 不变

// 5. 冻结验收
freezeValidationPlan(store, {
  problemId, resourceId: "skill:test-skill", baseVersion, paoHome: home,
  reproduction: [{ input: "检查步骤三", initialFiles: {}, allowedTools: [],
    acceptance: "SKILL.md 含步骤三" }],
  normal: [{ input: "检查步骤一", initialFiles: {}, allowedTools: [],
    acceptance: "SKILL.md 含步骤一" }],
  holdout: [{ input: "检查步骤二", initialFiles: {}, allowedTools: [],
    acceptance: "SKILL.md 含步骤二" }],
})

// 6. 生成候选（fakeRegistry 注入）
proposeCandidate(store, {
  modelRegistry: fakeRegistry(JSON.stringify({
    rationale: "补充缺少的步骤三",
    edits: [{ path: "SKILL.md", action: "edit",
      content: "# test-skill\n\n步骤一: 输入\n步骤二: 处理\n步骤三: 验证输出\n" }],
  })),
  ledger: fakeLedger(), paoHome: home, tierConfig: TIER,
}, { problemId, resourceId: "skill:test-skill", baseVersion,
  allowedFiles: ["SKILL.md"], devCases: [], testPlanId })
// → candidateId, status="proposed"

// 7. 跑验证（command 型，真实 runCardProcess）
// verifier: { cmd: "node", args: ["-e", "fs.readFileSync('SKILL.md','utf8').includes('步骤三')"] }
// reproduction 组 baseline 侧应 failed（缺步骤三），candidate 侧应 passed

// 8. evaluateCandidate → verdict=passed
// 9. recordEvolutionObservation + countEvolutionObservations
```

## 4. 断言

1. problem status 沿 `observed→classified→candidate` 推进。
2. testPlanId 绑定 baseVersion；plan.json 落盘在 `evolution/validations/<testPlanId>/`。
3. 候选目录 `evolution/candidates/skill_test-skill/<candidateId>/` 存在且 SKILL.md 含步骤三。
4. reproduction 组 baseline run 的 `result.passed=false`（验证前提成立）。
5. candidate run 的 `result.passed=true`。
6. `evaluateCandidate` verdict=passed，score.reproduction.passed=1。
7. 候选 status=passed；`passed ≠ active`（resource.effectiveVersion 未变）。
8. evolution_validations 行写入库；source_links owner_kind='validation' 行存在。
9. 回执落盘在 `evolution/validations/<testPlanId>/runs/`。
10. 观察计数 record+count 一致。
11. scratch 目录已清理（keepScratch=false 时 runs 外的临时目录不存在）。

## 5. 辅助断言（边界场景，同文件 describe 分组）

- reproduction baseline 也 passed → verdict=incomplete（前提不成立）。
- holdout candidate failed → verdict=failed（关键失败不覆盖）。
- allowedFiles 为空时 edit.path 含 `..` → 被跳过不穿透（验证 applyEdits 修复）。
