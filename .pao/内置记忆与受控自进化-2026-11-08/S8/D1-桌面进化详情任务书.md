## 2. 三个 DTO 函数（`K/desktop/memory.ts` 追加）

全部只读、`withService`/`openMemoryStore` 借关连接、`databaseExists` 库未建空态、返回纯 DTO。

### `readDesktopEvolutionProblems`

```ts
interface ReadDesktopEvolutionProblemsInput extends DesktopMemoryHomeInput {
  scope: DesktopMemoryScope;
  /** 资源类别过滤；缺省全部。 */
  kind?: string; // 'skill'|'template'|'command'|'extension'|'memory-policy'|'recipe'
  /** 状态过滤；缺省全部。 */
  status?: "observed"|"classified"|"candidate"|"no_change"|"development_suggestion";
  page?: number;
  pageSize?: number;
}
interface DesktopEvolutionProblemItem {
  problemId: string; kind: string; action: string | null;
  summary: string; reason: string | null;
  expectedBehavior: string; actualBehavior: string;
  occurrenceCount: number; resourceId: string | null; baseVersion: string | null;
  projectId: string | null; taskId: string | null; sessionId: string | null;
  status: string; disposition: string; createdAt: string; updatedAt: string;
}
interface ReadDesktopEvolutionProblemsResult {
  items: DesktopEvolutionProblemItem[]; total: number; hasMore: boolean;
}
```

### `readDesktopEvolutionDetail`

```ts
interface ReadDesktopEvolutionDetailInput extends DesktopMemoryHomeInput {
  problemId: string;
}
interface DesktopEvolutionDetailResult {
  problem: DesktopEvolutionProblemItem;
  /** 该问题的全部候选（含 diffs、rationale、usageRefs、status、failureReason）。 */
  candidates: DesktopEvolutionCandidateItem[];
  /** 来源链接（evolution_source_links → sourceId/memoryId/revision）。 */
  sourceLinks: Array<{ linkId: string; sourceId: string; memoryId: string | null; revision: number | null }>;

interface DesktopEvolutionCandidateItem {
  candidateId: string; problemId: string; resourceId: string;
  baseVersion: string; testPlanId: string;
  diffs: EvolutionFileDiff[]; rationale: string;
  usageRefs: string[]; status: string; failureReason: string | null;
  createdAt: string; updatedAt: string;

```

### `readDesktopEvolutionValidation`

```ts
interface ReadDesktopEvolutionValidationInput extends DesktopMemoryHomeInput {
  candidateId: string;
}
interface DesktopEvolutionValidationResult {
  validation: {
    validationId: string; testPlanId: string; candidateId: string;
    problemId: string; resourceId: string; baseVersion: string;
    caseResults: Array<{
      caseId: string; group: string;
      baseline: ValidationRunResult | null;
      candidate: ValidationRunResult | null;
      verdict: string; // 'passed'|'failed'|'incomplete'
    }>;
    verdict: string; totalUsageRef: string | null; createdAt: string;

}
```

`ValidationRunResult`/`EvolutionFileDiff` 从 `../evolution/types.ts` 导入类型（桌面 DTO 不重复定义内核类型——driver 层会 re-export）。

## 3. `evolution-detail.tsx` 界面

`memory-page.tsx` 的 kind 筛选器加 `<option value="evolution">`；选中时：

- 左列渲染问题列表（`readDesktopEvolutionProblems`，替换 MemoryList），行内显示 summary/kind/status/occurrenceCount。
- 选中问题 → 右列 `EvolutionDetail` 组件：
  - **顶部**：problemId、kind、status、resourceId、baseVersion、expectedBehavior/actualBehavior、occurrenceCount、createdAt。
  - **问题依据区**：evidenceRefs（来自 problem 行，`evidence_refs_json` 解析后逐条展示 sourceId）+ sourceLinks（来源跳转用 `onOpenSource`）。
  - **改动区**：candidates 列表，每项显示 candidateId、status、rationale、diffs（path+kind 摘要；`newContent` 可展开）。status="proposed" 标「待验证」、"passed" 标「验证通过，尚未生效」、"failed" 标「验证失败」、"cancelled" 标「已取消」。
  - **验证区**：选中候选 → `readDesktopEvolutionValidation` 取 caseResults，按组（reproduction/normal/holdout）逐项显示 baseline/candidate 两侧 passed/output 摘要+verdict。incomplete 标「未完成」不画成失败。

界面只读——不给「发布」「生效」按钮，不把 passed 显示成 active。受阻原因（failureReason）原样展示。

i18n 用 `useI18n` + `t()` 函数，中英文案成对写（同 memory-page.tsx 现有模式）。`data-testid` 覆盖关键交互点供 Playwright 断言。

## 4. 测试（`tests/core/memory-evolution.spec.ts`）

用 `launchDesktop`+`makeWorkspace`+隔离 home 模式（照 `memory.spec.ts` 的 fixture 做法）。

用 `DatabaseSync` 直接种 evolution 数据（照 `memory.spec.ts` 第 29-46 行 `sourceExpandRows` 的裸库写法）：种 `evolution_resources`（一个 `skill:test-skill` 行）、`evolution_problems`（一行 observed→classified）、`evolution_candidates`（一行 proposed+diffs）、`evolution_validations`（一行含 caseResults）。

断言：
1. kind 筛选器有 `evolution` 选项，选中后左列显示问题行。
2. 点击问题行 → 右列显示 expectedBehavior/actualBehavior。
3. 候选区显示 diffs（path/kind）。
4. 验证区显示 caseResults 分组。
5. 无发布/生效按钮。
6. 库未建（空 home）时显示空态不报错。
