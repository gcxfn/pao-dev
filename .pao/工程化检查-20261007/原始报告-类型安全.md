# 原始报告：类型安全（子代理产出，2026-10-07）

## 维度小结

**总体水位：高。**

- **tsconfig**：PAO 与 desktop 两侧 base 均为 `strict: true`，所有子包 tsconfig 无一放宽（无 `noImplicitAny: false`、无 strict 例外）。
- **`@ts-ignore`/`@ts-expect-error`/`@ts-nocheck`**：全范围 **0 处残留**。
- **desktop/apps/desktop/src**（含 features/canvas）：除 1 条注释外 **零 `any`**；contracts/ 与 electron/platform/pao/ 桥接层几乎全部走 `expectRecord`/`expectString`/`record()`/`asText()` 整形后再收窄，属合法模式。
- **PAO/packages/coding-agent/src** 约 114 处 `any` 命中，其中约七成是 `Model<any>`（对齐 pi-ai SDK 泛型签名，低风险）；JSON/JSONL 解析普遍采用 `JSON.parse → unknown → 类型守卫 → 收窄` 的规范写法。

**最危险区：desktop 工作流向导链路（渲染层 → ipc/request-validation → pao/workflow-wizard-bridge → 内核）**。整条链是全仓唯一"契约类型与运行时校验脱节"的路径：配方对象（深层嵌套、渲染层可控）只验骨架就以 `as WizardRecipe`/`as PaoWorkflowRecipe` 透传进内核。

## 问题清单

**P1（跨层裸断言，IPC 输入可信化）**

1. `desktop/apps/desktop/electron/ipc/request-validation.ts:788-796` — `expectWizardRecipe` 只验名字＋`参数`＋`节点`是数组，`...record` 透传渲染层任意字段并 `as WizardRecipe`，节点行内容零校验即进内核 preview/start/save。建议对 `节点` 逐行 expectRecord＋名字/部门字段校验，或把透传口径显式化为契约类型。
2. `desktop/apps/desktop/electron/platform/pao/workflow-wizard-bridge.ts:165-169`（另 :94）— `validRecipeShape` 同样只查 `节点` 数组即 `recipe as PaoWorkflowRecipe`，输入来自 IPC，绕过了本文件自己的 asText/整形惯例。建议复用 request-validation 的 expectWizardRecipe，不要在桥内二次裸断言。

**P2（一般 any / 双重断言 / 契约与校验脱节）**

3. `desktop/apps/desktop/electron/platform/pao/flow-control-query.ts:130` — `record(row, ...) as unknown as PaoDesktopFlow`：record() 只验"是对象"就声明整行形状。建议改声明窄接口并逐键校验。
4. `PAO/packages/coding-agent/src/pao/knowledge/judgment.ts:59` — `JSON.parse(line) as PatrolJudgment` 只挡语法错，形状错的行会当初判记录进终审。建议仿 `pao/usage/ledger.ts` 的 `isLedgerRow` 写守卫。
5. `PAO/packages/coding-agent/src/pao/knowledge/gate.ts:83` — 同款 `JSON.parse(line) as QueryReceipt` 后直接取字段，无字段守卫。建议补 typeof 校验。
6. `PAO/packages/coding-agent/src/core/extensions/types.ts:1059,1069-1070,1080` — 扩展事件契约 `args: any`、`partialResult: any`、`result: any`。建议改 `unknown`＋按工具泛型参数化。
7. `PAO/packages/coding-agent/src/core/tools/tool-definition-wrapper.ts:51` — `parameters: tool.parameters as any`。建议用双边受约束泛型收敛。
8. `PAO/packages/coding-agent/src/core/agent-session.ts:1248` — `target as unknown as Record<string, unknown>` 后 delete 全键＋Object.assign 原地换体，双重断言绕过 AgentMessage 契约。建议集中封装并注释不变量，或改不可变替换。
9. `PAO/packages/coding-agent/src/modes/interactive/components/tool-execution.ts:38,45,58` — `rendererState: any`、`args: any`、`details?: any`。建议 `unknown`＋渲染器入参泛型收窄。

**P3（琐碎）**

10. `core/tools/renderers/{grep:74,79, find:69,74, ls:62,67, bash:51,136}.ts` — 一批 `args as any`/`result as any`，纯展示路径。
11. `core/tools/grep.ts:221` — `let event: any`，改 `unknown` 即可。
12. `core/tools/read.ts:189` — `catch (error: any)`，改 `unknown`＋instanceof 收窄。
13. `pao/panel/index.ts:376` — `(ctxRaw ?? {}) as PanelCtx` 把 undefined 伪装成空对象再整体断言；同款见 `pao/command-router.ts:108`、`pao/context/index.ts:121`、`pao/memory/session.ts:143`。建议至少去掉 `?? {}`，让缺失显式失败。
14. `pao/host/host.ts:373,396` — 部长子进程事件行 `JSON.parse(line) as {...}`，parse 可能二次抛出。建议 absorb 直接返回已解析对象复用。
15. `desktop/apps/desktop/electron/preload.ts:164-232` — 约 25 处 `ipcRenderer.invoke(...) as Promise<T>`；main 侧已有整形，方向安全、属 Electron 惯例，可接受。

**说明**：`Model<any>`（约 80 处）是与 pi-ai 库签名一致的泛型占位，未列为问题；若想清零可在 SDK 层引入 `Model<unknown>` 默认参数统一收敛。
