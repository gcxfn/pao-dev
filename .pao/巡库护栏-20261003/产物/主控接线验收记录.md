## 接线设计（需求 §6 预案①「巡库 worker 上线前必须已装」）

- **派发侧**：buildDispatchRunOptions（pao_派单/pao_扇出 共用构造点）检测 isPatrolGoal(卡.目标) → 注入 锁定工作区＝resolve(合并参数.cwd ?? process.cwd())——与 runner 实际 spawn cwd 同一口径。
- **runner 侧**：WorkerRunOptions 增 锁定工作区；有值时子进程 env 注入 PAO_SHELL_GUARD_WORKSPACE（在 PAO_ROLE 强制键之后 spread 无冲突；未设不注入键）。
- **会话侧**：patrol/wire.ts registerShellGuard 在 pao/index.ts 顶层注册（不进任何被角色跳过的模块，三角色同装——仿用量页脚先例）；读到 env 才挂 tool_call 门禁，未设零行为（有人盯的日常派发不受影响，符合「有人盯可等事故、无人值守必须已装」的预案口径）。
- **门禁面**：只管 bash/powershell 两类 shell 工具；命令过 审查Shell命令 纯函数，不放行即 block，reason 带 拒绝类型＋人话说明（模型可见——修正命令或如实交回执的依据）。CustomToolCallEvent 的 toolName 是 string 联合成员导致窄化不净，取参前自证形状（typeof string 检查）。
