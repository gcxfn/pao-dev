# 桌面接入重构

审查与实施日期：2026-10-22  
范围：`desktop/packages/pi-sdk-driver/`、`desktop/packages/session-driver/`、`desktop/apps/desktop/` 中与桌面 PAO 接入、模型模式合并和 IPC 装配有关的源码与测试。  
报告：本文只记录本轮桌面接入重构，不覆盖 `.pao/整体简洁性审核-20261022/` 的历史审查。

## 结论

完成了两项保持行为与公开契约的实现：

1. `pi-sdk-driver` 的画布、节点详情、运行态、工作流、控制、部门、计划和看板读取，改为经一个公开 `@earendil-works/pi-coding-agent/pao/desktop` loader 加载。原先这些桥各自反推构建目录并重复加载的多处规则已删除；卡片操作改为加载公开根入口 `pao`。
2. `session-driver` 新增 `mergeEnabledModelPatterns`，桌面应用与 `pi-sdk-driver` 的两个逐字相同私有实现已删除，两处调用现在共用一个纯函数。

前轮报告的 IPC 重复 `flowControl` 在当前共享工作区中已经改为使用注入的 `owners.flowControl`，本轮核对后保留，无需再改。

桌面源码、类型、聚焦单测和带新内核的 5 项 core Electron 场景均通过。主控随后完成隔离 Windows package、运行时依赖、packaged smoke 与隔离 `PAO_HOME` 验收，均通过，最终证据见下方主控补记。

## 实施内容

### 公开 PAO 桌面加载器

新增 `desktop/packages/pi-sdk-driver/src/pao-desktop-module.ts`：

- 唯一动态入口是 `@earendil-works/pi-coding-agent/pao/desktop`。
- loader 直接 `return import(publicEntry)`，不再维护模块级 Promise。Node 原生 ESM 缓存负责复用同一模块实例；没有新增缓存层。
- 代码图与当前源码没有找到依赖两侧 Promise 身份相同的调用者。旧测试的 `assert.equal(firstPromise, secondPromise)` 只锁住实现，已改为实际注入后的模块函数与原生 import 对上，并验证真实 bridge 调用。
- 不把读取结果缓存起来，继续由各桥按调用现读磁盘。
- 工作流与控制仍使用同一个公开模块实例，因此 `owners` 表共享、会话与 owner 校验、确认和停止等保护不变。

已切换的桥：

| 文件 | 原重复动作 | 现在 |
|---|---|---|
| `pao-workflow.ts` | 反推 `dist/pao/desktop/index.js` | 从公开 loader 取工作流函数 |
| `pao-flow-control.ts` | 反推 `dist/pao/desktop/index.js` | 从公开 loader 取控制函数 |
| `pao-dept.ts` | 反推 `dist/pao/desktop/index.js` | 从公开 loader 取部门目录与详情 |
| `pao-canvas.ts` | 反推 `dist/pao/desktop/canvas.js`、`read-model.js` | 从公开 loader 取画布、节点详情、运行态 |
| `pao-kanban.ts` | 反推 `dist/pao/desktop/read-model.js` | 从公开 loader 取待处理、执行与部长会话读取 |
| `pao-plans.ts` | 反推 `dist/pao/desktop/index.js` | 从公开 loader 取临时计划投影 |

本轮把 `canvas`、`card-ops`、`flow-control`、`workflow`、`plans`、`dept` 的公开最小类型和函数签名恢复到本轮前形状，没有把 driver 的公开 API 迁移成完整 native 类型。尤其是：

- `PaoCardOpsCard` 保持最小卡片形状，`PaoCardStatusChangeInput.to` 保持 `string`；
- `PaoCanvas*`、`PaoNode*`、`PaoDesktopCard` 等保持手写最小投影，节点详情读取保留可选 `cardRef`；
- 工作流、控制、计划、部门的公开接口继续接受旧最小替身，不要求完整原生结构。

完整 native 类型只用于 `pao-desktop-module.ts` 的真实模块声明。对最小投影与更丰富 native 返回相遇处，适配只在 loader 返回值边界使用 `as unknown as`。这里跨越的是公开最小投影和真实完整内核类型；`as unknown` 不是为了让普通对象绕过不兼容检查。公开函数仍保留真实 bridge 的返回形状和行为，真实读取、owner 拒绝和卡状态流均有运行测试。

另经公开边界核实：卡操作由 `pao/cards/index.ts` 导出，根 `pao/index.ts` 再导出 `cards`，因此 `readCard`、`changeCardStatus` 可直接从 `pao` 根入口取得；`scanWorkflowInstances` 与 `collectPending` 已由主控加入 `pao/desktop/index.ts`。原文件缺少入口时按具体函数 key 报中文错误，迁移后保留各入口的具体名称，没有统一成笼统错误。

`pi-sdk-driver` 的公开入口同时恢复并导出计划模块原有的 `PaoPlanArtifact`、`PaoPlanStepRecord`、`PaoPlanStepProgress` 三个最小类型，避免计划桥改走公开加载后丢失既有类型入口。

### 模型模式合并

`desktop/packages/session-driver/src/runtime-types.ts` 新增：

```ts
mergeEnabledModelPatterns(existingPatterns, providerPatterns)
```

函数保留原来的契约：

- 已有模式保持原顺序。
- 只追加尚未出现的 provider 模式。
- 输入中重复的模式只出现一次。
- 全部已存在时返回相同长度，调用方现有的“长度未变就跳过写入”逻辑无需改变。

`session-driver/src/index.ts` 公开导出该函数；`pi-sdk-driver/src/runtime-supervisor.ts` 和 `desktop/apps/desktop/electron/application/app-store.ts` 均改为导入它，两个私有 `mergeEnabledModelPatterns` 已删除。

新增纯函数测试覆盖顺序、交叉重复、重复 provider 项、空输入和长度不变语义。

### IPC 与未机械抽取项

`register-desktop-ipc.ts` 当前只从注入的 `owners.flowControl` 读取与运行控制，`main.ts` 仍是控制查询实例的唯一装配点。保留 handler 的工作区解析、请求校验、磁盘真值匹配和内核 owner 校验。

本轮没有修改以下静态候选：

- `scrollIntoContainer` 两处及 `apps/desktop/src/features/workbench/file-editor-pane.tsx`、`file-explorer.tsx`：已指定由主控或另一代理处理。
- `extensions/pao/desktop.ts` 的 `element` 与 `extensions/pao/flow-desktop.ts` 的 `el`：不按相同十行机械抽取。
- `optionalText` 的五行为包装、两个 `truncate` 的不同默认长度：没有足够证据说明统一不会改变展示或接口语义。

桌面接入不再反推 `dist` 路径。卡片操作使用公开 `pao` 根入口；工作看板的工作流实例扫描与待处理聚合使用公开 `pao/desktop`。`PAO/packages/coding-agent/src/pao/desktop/index.ts` 的两个命名导出由主控加入并已冻结，本轮没有继续修改该文件。

### 类型检查边界

`packages/pi-sdk-driver/tsconfig.json --noEmit` 与 package build 通过。仓库根 `tsconfig.lint.json` 会把既有测试和扩展源码一起编译，历史上有与本轮无关的 DOM、`.ts` 扩展名和测试替身错误；本轮没有把全仓 lint 失败当作公开类型通过证据。独立合同探针只编译新增兼容文件，并引用新构建的 `dist/index.d.ts`，已通过。

### 共享工作区与审查边界

工作区在本轮开始前已有大量未提交改动，目标文件也含有这些改动；本轮以当前内容为基线增量修改，没有执行 `reset`、`clean`、提交、rebase、依赖安装或正式 `PAO_HOME` 写入。

`app-store.ts` 的既有未提交内容还包括一个普通会话删除入口，以及把它复用于一次性会话清理的改动。它不在本轮公开 loader 与模型合并范围，本轮没有改变其业务逻辑；主控合并时应单独核对普通删除的限制和一次性会话的清理顺序。

代码图在本轮用于定位调用者；主控说明索引正在刷新，索引过期不作数。所有落点均以当前源码和实际导出的类型/运行时函数核对，未把历史审查中的行号或旧 `dist` 当作现值。
