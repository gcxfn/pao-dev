# 状态结果重构

执行日期：2026-10-22

## 结论

已完成 PAO `status/results` 读取边界重构。结果页现在复用共享的实例发现与版本读取入口，覆盖临时计划的深层实例，同时保留 v1 不可读说明、坏实例与目录异常逐项展示、`runGit` 注入和桌面桥统一脱敏。

`status/index.ts` 已改为直接导入 `dept/panels.ts` 的 `renderDeptPanels()`，去掉了对本包根装配入口的反向依赖。状态相关的 8 个测试文件共 87 项均符合预期：85 项通过，2 项是既有 `it.fails` 标记的预期失败，没有新增失败。

## 经过与证据

先读取公共简洁性技能、检查清单、项目规则、历史审查，以及代码图中 `collectInstanceResults()`、`readWorkflowInstance()`、`collectInstanceDirectories()` 和 `renderDeptPanels()` 的调用关系，再回到当前源码核对。

历史审查指出结果页自己分流 v1/v2，并只扫描 `.pao` 顶层与一层子目录；现有生产路径把临时计划实例写在 `.pao/临时工作流/<计划>/执行/<请求>/`。当前源码和临时计划测试证实了这个布局，因此结果页漏读深层实例是实际契约差异，不是纯文本重复。

主控整合审查后进一步收紧了实现：

- 项目清单不再预读，结果聚合直接调用共享 scanner，并在 scanner 抛出项目清单异常时保持原有异常行。
- `collectInstanceDirectories()` 保留原签名和“读取失败返回空”的语义；目录异常只在 scanner 的候选目录读取边界报告一次，没有新增回调或去重状态。
- 递归发现继续跳过 `node_modules`，沿用比浅层结果扫描更深、且与桌面流程读取一致的目录范围。

## 做了什么

- `PAO/packages/coding-agent/src/pao/status/results.ts`
  - `instanceResultLine()` 改用 `readWorkflowInstance()`，删除结果页自己的 frontmatter 版本判断、冻结配方读取和控制正本读取。
  - `collectInstanceResults()` 改用 `scanWorkflowInstanceFiles()`，删除结果页自己的目录遍历。
  - 目录异常、坏实例和 v1 旧实例仍进入原有结果结构；节点段错误继续降级为单项结果。
  - `runGit` 注入点和默认 Git 执行保持可用。
- `PAO/packages/coding-agent/src/pao/status/workflow-instances.ts`
- 新增仅供本模块使用的 `WorkflowInstanceFile`、私有 `WorkflowInstanceFileScan` 和 `scanWorkflowInstanceFiles()`；扫描结果只返回实例文件位置与目录异常。
  - `eachInstance()` 复用该发现接口，供挂起清单和待处理信号扫描共用。
  - 现有 `readWorkflowInstance()` 仍是 v1/v2 分流的唯一读取入口。
- `PAO/packages/coding-agent/src/pao/status/index.ts`
  - `renderDeptPanels()` 改为从 `../dept/panels.ts` 直接导入，消除对 `../index.ts` 的反向装配依赖。
- `PAO/packages/coding-agent/test/pao/results-aggregate.test.ts`
  - 增加真实临时计划深层实例用例，同时验证结果页与共享挂起扫描无异常。
  - 增加一个项目的 `.pao` 不可达用例，验证异常逐项展示且其他项目结果不受影响。

桌面 `readDesktopResults()` 仍调用 `redactContext(await collectInstanceResults(paoHome))`，本次没有改桌面代码。`test/pao/f-results-files.test.ts` 已运行，但不需要修改。

- 只读、零落盘、坏实例逐项展示、目录不可达显示原因、v1 四样不可读及人工重建说明均保留。
