# PAO Harness 完善与工作台迭代：需求与实施交接计划

建稿日期：2026-10-17。修订日期：2026-10-17（状态行更正）。状态：**实施中**，由用户于 2026-10-17 授权执行，批次 0→A→B→C→D→E→G→F→H 依次推进；**批次状态只看 §10 状态表**，本行不复制状态。已通过的批次仍带着各自的「未验」与「已知缺口」（见 `.pao/harness完善-20261017/执行记录.md` 各批小节），不等于下列能力全部验收完成。

Harness 在本文指模型周围的运行底座：准备任务和上下文、安排工具与执行者、核对结果、支持人工干预与恢复。本次目标是让用户通过对话安排工作，并在统一的工作台中看懂、干预和验收实际执行。

### 1.2 为交接完整性采用的推荐方案

以下是本计划的具体设计建议，未逐项取得新的用户选择；用户审阅时可修改。实施者不能据此扩大已确认范围。

1. **一份临时计划只受理一次运行。** 同计划换请求编号再次启动也返回已有实例或明确拒绝；需要再跑时，复制为新临时计划或从模板创建新计划，重新确认。普通重试不能意外再开一份工作。
2. **确定性字段操作直接调用业务入口。** 保存未运行计划、确认、暂停等无需先把内部说明塞入输入框；需要理解意图的意见、复杂改动交给来源主控。写操作仍由内核核对归属和版本。
3. **来源主控不可用时保留意图并解释原因。** 可定位或重新连接同一主控；本批不增加跨主控接管，不自动新建替代主控。
4. **小说首版复用 Git 交付。** Git 是本地文件版本记录；创作项目须有初始提交。非 Git 目录的新交付方式另行设计。
5. **运行中不改冻结图。** 已启动步骤的要求、依赖和部门保持本次冻结版本；新要求先记录为变更提议。可暂停、裁定、按已有审核回边修订或创建后续计划，不能只改 UI 冒充生效。

“一遍就成”指信息齐全时一次提交便能可靠受理并查回结果；不承诺模型永不出错、不需要必要确认或执行一定成功。权限、预算、人工门、审核与停止规则继续有效。

### 1.3 不包含的工作

- 视频剪辑器、编码、时间线和素材平台；本批保留通用任务与文件能力。
- 新工作流引擎、第二套任务状态、费用来源、消息中间件、插件市场或通用规则框架。
- 写任务并行、同部门并行、任意跳步、部分前置完成就放行、运行中直接改冻结图。
- 全库改名、删除画布历史、自动迁移全部 v1 数据或重写 pi 模型循环。
- 正式 PAO_HOME 写入、真实凭证读取、真实供应商调用、开发仓提交/推送/发布；相关操作需要另行明确授权。
- computer-use/CUA 操控；后续验证使用命令驱动的隔离 Electron/Playwright、ConPTY 和文件检查。

## 3. 从对话到交付的完整体验

### 3.1 标准过程

1. 用户说明目标，主控从已有上下文整理任务，查询真实部门、现有计划和所需输入。已知信息不重复问。
2. 简单独立任务走原生单任务受理；已商量为多步骤的工作走临时工作流。主控工具落盘成功后，对话出现摘要和“查看计划”。普通编号清单或助手说“建好了”不算真实创建。
3. 用户检查步骤卡，可对话修改或在主页面编辑确定字段。显示真实保存结果与版本，可撤销最近修改。
4. 启动前展示范围、分工、成果、人工门、已配置预算和缺失输入。可信确认绑定所展示版本；确认期间修改、取消或归属变化时不能按旧确认开工。
5. 信息与确认齐全后，主控一次提交，内核实际受理并尽快返回可查询身份。后台按真实依赖推进，回执通知唤醒，不让主控忙等。
6. 用户在侧栏/主页面看进度、处理待办。成果逐个打开，阅读版本、意见、审稿退回和修订轮次可追溯。
7. 机械验收检查文件与执行边界；内容质量由部门审查及用户判断。人工门通过才进入相应完成态。
8. 用户决定复用时保存模板；换项目选模板、填参数，生成新计划并重新确认，不带入上一轮状态和成果。

### 3.2 主页面与侧栏职责

| 区域 | 默认内容 | 可直接执行 | 转主页面处理 |
|---|---|---|---|
| 工作流主页面 | 临时任务、历史运行、模板；摘要、步骤卡、完整详情、成果右栏 | 未运行计划保存/撤销、部门下拉、模板使用/保存、合法运行控制、意见 | 本身提供完整管理 |
| 工作看板主页面 | 跨任务待办、在途/失败、部门负载、结果和读取异常 | 钻取任务/卡/原主控、处理合法待办、打开成果 | 复杂字段、依赖、模板及部门配置转对应页 |
| 对话内工作流侧栏 | 当前会话计划/实例、全局进度、当前步骤、下一待办、最新成果 | 看完整要求、处理本轮人工确认、暂停/申请恢复、打开成果、定向意见 | 多步骤/依赖/模板编辑、完整历史和复杂裁定 |
| 对话内工作看板相关面板 | 当前范围待办、失败原因、部门与执行摘要 | 处理支持的待办、定位原会话/步骤/卡、打开成果和记录 | 跨项目管理、长日志/完整 diff、部门配置 |

侧栏默认当前对话范围；查看其他任务时明确显示项目和来源主控。查看不转移操作权，内核拒绝错误主控写操作。全部视图引用同一对象/版本，侧栏没有独立任务状态或确认记录。

“进入主页面”携带项目、计划/实例、步骤、轮次或待办身份，返回对话恢复选择和草稿；对象不可用时解释，不能跳空首页。侧栏打开成果复用现有文件工具/标签，主页面在右栏预览；不叠加第二层侧栏或强制离开对话。

## 4. 原生派发机制

### 4.1 用户和主控各做什么

用户说明目标、必要输入和限制。主控整理结构化任务并选择现有执行方式；结构化指程序可直接读取目标、部门、验收等字段，用户不必手写这些字段。

| 任务情况 | 推荐选择 | 边界 |
|---|---|---|
| 单部门、单项交付 | 原生单任务受理 | 复用建卡与 `executeDispatch`，不让用户先建卡再派 |
| 需要部门规划/审查 | 现有部长/部门节点 | 保留部长规划/判定、Worker 执行，不为快绕过必要角色 |
| 多步骤、有依赖/审核/人工门 | 临时工作流 | 持久创建和确认后，由同一工作流核心推进 |
| 现有协作/扇出 | 已有入口 | 保留父卡/配额/并发；逐项结果，不把部分受理报整批失败诱导重做 |
| 只看状态/成果 | 查询 | 不启动模型执行、不额外建卡 |

主控不亲自改任务成果，Worker 不再派发子任务；部门协作沿既有卡和主控/部长通道。手动命令可以保留，但日常完成任务不依赖拼 CLI 字符串或多轮试命令。

### 4.2 原生入口的最小契约

在 PAO 共享业务边界提供“完整任务受理”；先复用或扩展现有结构化工具，确实不能表达才新增一个窄入口。正式导出名在批次 E 固定并写入长期接口文档，不假定一个尚不存在的工具名。

| 输入 | 来源 | 规则 |
|---|---|---|
| 宿主身份 | 绑定项目、来源主控、角色 | 内核核实，模型参数不能覆盖；显式路径不匹配拒绝 |
| 请求身份 | 一次逻辑操作的稳定请求 ID | 同请求同内容查回原结果，同请求不同内容冲突；重试不换 ID |
| 任务定义 | 目标、输入引用、成果要求、约束、验收 | 从对话填入；缺失影响执行的内容一次列全，不重复问已有信息 |
| 部门/方式 | 真实部门、能力、已有执行模式 | 主控推荐并提交，内核核实；歧义明显影响结果时集中提问 |
| 可选限制 | 模型/档位、技能、预算、只读/写权限 | 用现有可信默认，不虚构预算、扩大写权限或自动授权技能 |
| 对象关联 | 计划/版本、实例、步骤、轮次、父卡 | 按模式携带真实身份，不靠标题/位置推断 |
| 确认/取消 | 可信宿主确认、取消信号 | 模型 `confirmed:true` 无效；取消贯穿受理链 |

技能沿现有允许清单：关键技能未获允许时汇总到启动前缺项/确认，不能静默忽略后声称已具备；可选技能降级须披露。不能因新入口自动扩充允许清单。

### 4.3 一次提交的内部过程

1. 规范输入，核实宿主身份和请求记录；已受理则回读结果。
2. 集中预检必填项、部门/配方/档位/技能、依赖、Git 基线、预算和权限。可发现问题一次列齐并定位步骤，不自动替换部门/放宽限制。
3. 需要确认时锁外展示同一摘要；返回重核身份、版本、取消及会变化的条件。已可信确认且内容未变不重复问。
4. 在现有相应锁内形成稳定身份、建卡或启动预留及必要关联，复用认领、写锁和名额机制；不持文件锁等待模型/部长。
5. 通过宿主、工作流核心与 `executeDispatch` 受理。内部可有必要步骤，但不要求用户/模型再补一串独立命令才能连起来。
6. 返回每项真实状态与身份。只有受理成功进入后台；报“排队”必须已有真实持久卡/队列及后续触发，不能把拒绝叫排队。
7. 回执、失败、取消和人工门通过已有通知/查询更新；主控收到结果再处理，不循环查询忙等。

不新增通用事务系统。多文件操作可出现可解释的部分受理：卡已建、派发失败则返回卡身份、是否启动及恢复动作，重试沿原卡，不能重复建卡。批量返回逐项结果，不承诺全批原子成功。

### 4.4 返回、失败与重试

结果至少包含请求 ID、项目/来源主控、相关计划/实例/步骤/轮次/卡/尝试、受理状态、已产生动作、原因、可重试性和下一步。用户默认看中文摘要，机器保留结构化字段。

| 情况 | 返回 | 重试规则 |
|---|---|---|
| 预检失败且未写入 | 未受理，列齐定位问题 | 修正内容后新操作，不盲重放 |
| 等待确认 | 待确认，标版本/范围 | 同一确认请求复用；取消则结束未受理操作 |
| 已建卡未启动 | 卡身份和具体原因 | 查回/恢复原卡，不重复建 |
| 已受理返回丢失 | 原身份及当前状态 | 同请求只回读；换启动请求也不让同计划二次运行 |
| RPC/供应商结果不明 | 未知、已有证据和查询入口 | 查真实请求/进程/回执，不能猜测重放写操作 |
| 受理后停止 | 请求及实际终止结果 | 显式停止，不宣称过去文件改动已撤回 |
| 批量部分受理 | 分别列已受理/未受理及原因 | 只恢复明确未受理且可重试项，已有项保留身份 |

旧 `pao_dispatch_card`、`pao_fanout`、`pao_collab_relay`、部长/工作流工具及 `/pao` 命令保持兼容，作为共享核心的薄适配；工具说明和主控上下文指向首选入口，不维护两套规则。精简常驻说明、按需取部门细节、合并重复目录查询；不为速度删校验或建全局缓存。

“一遍就成”验收记录真实工具轨迹：信息齐全且确认满足时，一次完整受理调用返回真实身份，后续无需手工建卡/补派发/补关联；必要确认之外不重复索取已有信息。同请求重放及中断不重复开工。受理耗时与模型执行耗时分开，不用脚本绕入口制造成功。

## 5. 部门机制

### 5.1 保留层级与明确归属

保留主控、部长、Worker。主控安排和跨部门协调，部长按现有模式规划/判定，Worker 执行获派任务。简单任务不额外增加一轮部长对话；是否需要部长沿现有方式和任务要求，不创造新角色。

| 信息 | 归属 | 用途/边界 |
|---|---|---|
| 名字、能力标签、知识库入口 | `<PAO_HOME>/部门/注册表.md` | 唯一部门目录，UI 与主控共用，不维护前端名单 |
| 职责、边界、默认档位、工具/技能引用 | 部门 `配方.md` | 稳定配置；保留自定义内容，修订检查版本，不写任务进度 |
| 干法与审查清单 | 现有配方“干法”和已有标准文件 | 概要常驻、详情按需读，复用“部门标准”引用/验收，不另建标准注册中心 |
| 本次目标、约束、成果和验收 | 计划/卡与冻结实例 | 要明确，不能只写“按部门惯例”；冲突定位具体项 |
| 负载与健康 | 宿主/队列/控制投影 | 空闲、忙碌、排队、离线、配置错误分别显示，不写回配方 |
| 知识与经验 | 部门现有知识库 | 沿验证出处和入库规则，回执不自动变高置信经验 |

目前配方模板“工具”占位说明同时提到 skills，而派发核心另读“技能/skills”字段。实施须核对实际读取路径，明确工具权限、技能引用与人设文字的区别；一句“擅长写作”不代表技能已装载。

### 5.2 配置、选择和协作

1. 部门详情展示职责/边界、可用技能、默认档位、标准、知识入口、配置问题和负载。技能/标准定位真实文件，不生成第二份副本。
2. 校验集中返回：注册表行、缺配方、重复文件系统身份、无效档位、缺失/未信任技能、标准不可读；旧无效值保留供修复，不跳过变空列表。
3. 下拉显示真实名字及简短职责，不可用项说明原因。未注册返回已有选项，不自动建部；建部沿唯一入口，不覆盖已有内容。
4. 主控按真实标签/职责推荐，多个候选说明理由，不另做评分模型。能力、标准与权限冲突启动前说明。
5. 审查引用本次验收与具体标准，逐项通过/未通过/未运行；模型自报不免检。创作内容判断与文件存在等机械项分开。
6. 交接携带目标、输入版本、已完成/未决项及验收责任，通过卡与既有通道；不开放 Worker 自由互聊和嵌套派发。
7. 配方变化保留热部长变更提示，新受理读取最新配置；运行任务使用冻结要求/记录的配置依据，不暗换标准，不自动杀在途任务。
8. 配置编辑在主页面设置/已有入口，侧栏只给摘要和定位；缺入口时仅补本批必需能力，不建组织管理平台。

隔离样例至少有写作/审查两部门，覆盖技能/标准加载、未授权技能、配方变化、失效部门、Windows 大小写重名、协作版本及忙碌/离线投递。不能改正式部门配置演示。

## 6. 数据与可靠性契约

### 6.1 一个对象一个事实来源

| 对象 | 权威内容 | 允许的关联/投影 |
|---|---|---|
| 临时定义 | 项目 `.pao/临时工作流/<planId>/` 中定义、编辑版本、最小历史 | 来源主控、稳定步骤、启动/模板关联；不复制卡和控制状态 |
| 启动关联 | 同计划持久启动意图与受理结果 | 定义版、稳定实例、请求、已完成阶段，与控制互核 |
| 执行实例 | 现有冻结配方、控制和节点轮次 | 沿现有目录/恢复，不随模板变化 |
| 卡与回执 | 现有卡状态、认领、尝试、执行记录 | 看板/工作流从中投影，UI 不覆盖 |
| 成果 | 实际文件及可读取版本 | 实例、步骤、轮次、卡/执行、版本依据；预期路径不算成果 |
| 意见/提议 | 最小意见记录、真实投递/处理关联 | 流程/步骤/成果目标明确；模型说明与核实结果分开 |
| 模板 | 现有 PAO_HOME 配方 | 仅可复用定义和参数，不含本次运行身份 |
| 费用/待办 | 原生账本、控制/卡/投递正本 | 可重建聚合，不成为第二套真相 |
| UI 草稿 | 已有会话/工作台草稿存储 | 按项目、会话、计划、步骤/文件版本与用途区分，不算业务提交 |

### 6.2 归属、取消、启动一致性（A）

- 计划写操作核宿主项目和原主控；`project_root` 只能匹配，不能覆盖。路径沿真实路径规则，处理 Windows 大小写/链接身份。只读可见不顺带获得写权。
- 工具进入、确认返回、拿锁后、受理前检查取消，复用取消辅助函数向下传信号。未受理取消不产生新控制/关联/执行；受理后停止不伪装撤回。
- 确认不持锁。返回在同一计划短锁内重核 owner、版本、取消和启动记录，固定实例并持久启动意图/冻结依据。编辑、撤销和启动共用冻结检查。
- 控制已形成、关联未完成的窗口仍须冻结。崩溃恢复已有实例，不能当未执行计划编辑或另建实例；锁外推进部长/Worker。
- 同计划换请求 ID 不能重复启动；新运行先生成新计划。
- 步骤 ID 与序号分离：修改带旧 ID，新增分配新 ID，重排只变顺序；删除检查依赖/审核和意见，保留可解释目标，不改绑其他步骤。

### 6.3 历史、撤销、查询与模板（C）

- 未启动定义保存最小版本历史，复用锁和原子写。“撤销最近修改”读旧版，核当前版后形成新修订；“撤回整份计划”独立动作，不混同。
- 历史/当前版写入中断后可定位原件或上一有效版；恢复只选通过校验版本，不用空步骤填默认。
- 查询区分简短列表和计划/步骤详情；详情含目标、输入、约束、验收、依赖/审核、预算/技能、人工门、来源和运行关联；长内容分页/按对象读取。
- 模板参数声明沿现有配方类型/默认/必填能力，同一解析器校验占位符。本次绝对路径须参数化或让用户处理，不能静默保留/丢约束。
- 保存白名单提取，剔除主控/实例/卡/回执/意见处理/完成标记；同请求查回，同名覆盖核预期版本和已有保护，另存明确。
- “用于本次任务”给摘要、参数、部门可用性和人工门，生成新计划再确认。未运行/已运行均能保存定义，模板变化不影响冻结实例。

### 6.4 成果版本与意见事实（B）

1. 文件携带项目、计划/实例、步骤、轮次、实际路径和版本依据，必要时卡/执行。整体意见为流程目标，不能写空步骤 ID。
2. 历史须能读当时正文，优先交付 Git 提交和按轮次保留的普通成果目录；不可读就显示记录与原因，不能贴旧标签读新文件。摘要只在有版本识别用途时添加。
3. 同路径不同轮次不得去重吞历史。路径由宿主核实；缺失/越界/链接/权限/过大/不支持明确报，renderer 不任意读盘。
4. 预览锁定版本，新版只提示，用户主动切换；正文/滚动/意见目标不抢换。旧文件覆盖且无历史须如实说明。
5. 意见先“已记录”；排队受理、送达会话、拒绝和超时依据真实宿主请求，未决可查。模型 `delivered:true` 或非空文字不能提升状态。
6. “已应用”关联可核查的定义修订、成果版本/差异或业务处理。文件变化不自动证明符合意见，可显示“已关联修订/待确认效果”；内容质量由审查/用户判断，模型解释标“主控说明”。
7. 意见 ID 与实际请求 ID 绑定，错 ID、跨实例、迟到/重复回执不能结算另一条意见；无法核实保持待确认/未知。

## 7. 人机交互细则

### 7.1 卡片、看板与阅读

- 顶部显示工作名、临时/模板来源、全局进度、待办和原主控；筛选显示过滤数量，全局统计仍含筛选外步骤。
- 卡片显示序号、名称、部门、真实状态、等待原因、实际文件。多前置写“等待第 2、3 步”，显式并行分组、窄屏纵排；保留审核回边、多卡、零卡审查与每轮执行。
- 等前序、等部长、待审、待人工确认、预算不足、暂停、失败、取消、交付和读取异常分别解释；未知不译成成功，状态不只靠颜色。
- 多卡汇总全部卡并可逐一打开，不能取首卡代表完成；坏卡/缺映射单独报，正常节点继续可读。
- 右栏是完整要求或成果正文，文件名附必要相对路径；可专注阅读、返回详情、复制路径。预览只读，编辑复用原编辑器和未保存保护。
- 查看步骤不改发言对象，“讨论这一步/就此文件提意见”才改。开文件不改已选步骤，“定位所属步骤”才切。
- 打回显示原因/目标/轮次，保留旧稿。重试说明步骤/尝试和下游影响，不误重跑全流。
- 暂停推进只阻后续启动，停止在途走终止入口并报实际结果，不把暂停称为停止全部。

### 7.2 草稿、发送和真实反馈

| 场景 | 必须行为 |
|---|---|
| 刷新/投影新对象 | 不重置未提交字段，按稳定身份/版本判断初始值 |
| 切步骤/项目/会话再返回 | 找回对象草稿、选择、阅读位置；应用重开复用现有草稿能力 |
| 同对象外部修改 | 保留草稿，提示版本冲突，可查看新值/重提，不能静默覆盖 |
| 输入框非空 | 不直接 `setComposerDraft(text)` 覆盖；确定操作走业务入口，需对话的意图暂存或明确合并 |
| 另一会话发起动作 | 定位来源主控，保留当前输入，不发给恰好选中的会话 |
| 来源会话不可连接 | 显示未发送/恢复入口并保留内容，不另建主控冒充 |
| 仅形成草稿 | 标待提交/未发送，不能报已修改/送达/撤销 |
| 真受理/保存成功 | 依返回版本/请求更新，异步回执到达再更新送达/处理 |
| 部分成功/未知 | 列真实已完成与未决，可查回，不笼统失败诱导重复创建 |

### 7.3 侧栏与视觉一致性

侧栏用紧凑卡片/列表，不嵌完整主页面，不保留画布、配方全文编辑和另一套底部聊天。“新建专属主控对话”不再承担临时流入口，当前对话是默认工作位置；历史专属会话仍可访问，不自动删除。

沿已有字体、色彩、边框、间距、按钮与状态词；扩展用宿主主题变量。共享字段/状态格式化，不为复用展示强行合并 React 和扩展框架。侧栏首屏突出进度、待办、最新成果，日志按需展开。

700/900/1280px 均可操作；窄窗右栏转下方或专注阅读。Tab、Enter/Space、Escape、焦点返回和中文控件名核实；刷新不抢焦点、不持续轰炸读屏。真实读屏与 125% 系统 DPI 分别验证，ARIA/浏览器 zoom 不替代。

### 7.4 JSON/技术文本全面检查

实施前重搜普通展示出口，形成“页面→入口→是否可见→处理/保留→证据”清单。九类逐项销项，四类疑点先验证，不能把所有 `JSON.stringify` 当 UI 缺陷。

| 类别 | 入口/范围 | 验收 |
|---|---|---|
| 预算对象 | 看板卡详情、步骤/确认摘要 | 轮次、工具、费用、协作额度带单位，未配/未知不填 0 |
| 取消/终止命令 | `kanban-command.ts`、操作区 | 中文目标/范围及真实操作或原主控入口，复制只报已复制 |
| 工具输入输出 | 对话 timeline、tool output | 常用 PAO 工具按任务/文件/结果，输入结果分开，未知工具安全回退 |
| 工作流复盘 | `workflow/tools.ts`、结果页 | 步骤/轮次/打回/成果/确认可读，原始可查 |
| 成果路径 | 卡片、结果、侧栏 | 核实文件逐项可点，说明不伪装文件，多卡/零卡正确 |
| 回执用量键 | 看板/侧栏 | 中文字段单位，Token/费用、已知/未知/部分分开 |
| 工具名/状态/耗时 | 时间线、注册工具 | 中文标签/状态，失败不显示 done，技术名可查 |
| 执行 ID/错误码 | 实例/执行记录 | 默认次数/时间/原因/下一步，技术项展开 |
| 扩展内部 key | 扩展状态与面板 | 已知状态中文摘要，通用扩展保留原文，不破坏内部比较 |

四类疑点：错误是否缺上下文/下一步；时间/摘要值域与时区；设置路径说明与宿主是否一致；部门预算 JSON 是否实际进入用户视图。无问题可记录保留，不为交差重写。

主动打开的 JSON/源码/终端/完整 diff/原始回执/导出保留原文；通信、持久化、比较结构不改展示文字。原始入口不得暴露凭证。

## 8. 运行底座补强（G）

### 8.1 上下文与待办恢复

主控重开/压缩后查询恢复目标、要求、约束、确认版本、待办、未决意见和必要文件引用；列表简短，详情按需取，沿 pi 会话/压缩和现有记忆，不常驻全历史或另做摘要库。

待办从控制、卡、确认及持久投递关联重建，含待确认、缺输入、失败、未送达和恢复。提醒可丢，事实不能只存内存。处理绑定实例/步骤/轮次/版本，旧提醒不推进新轮次，多视图同一待办仅生效一次；成功但提醒失败仍可查。

重开只恢复查看和连接，不静默重派。失败、取消和孤儿按现有租约/恢复识别，显示已有成果/未验内容和理由，明确恢复后推进。

### 8.2 原生用量与显式总预算

沿原生日志/账本汇总可归属的主控、部长、Worker、压缩/摘要用量；不能可靠归属则披露范围。区分 Token、已知费用、未知及估计，不把未配价格显示免费；分页/重读/重开不重复计数。

每卡预算与流程总预算分开，只有用户显式给总预算才启用跨任务额度，不凭空设总限额。复用已有保护补最小持久预留/结算：

- 派发前锁内核余额，并发不能各领一份完整总额。
- 明确未受理归还，已运行按实际结算，结果不明先查、不重复授额；重启能核原请求。
- 确定硬限额在派发/轮次边界拦继续；费用未知/迟到时披露局限，不能承诺绝不超支或用 Token/0 伪装准确费用。
- 加额度为显式操作，有版本/余额依据；取消不抹费用，不偷偷刷新默认额度。

### 8.3 工具错误、格式与维护

沿已有错误体系返回稳定状态/错误码、对象、已有副作用和可重试性。界面说清动作、原因、下一步；写操作仅在确定未受理或有持久去重时自动重试，未知先查，不靠自然语言猜测。

定义、启动关联、意见、历史及模板完整校验字段/类型/身份/格式版本。格式版本与编辑版本分开；支持旧格式须明确读取/转换，未知新版/损坏保留原件并阻止不可靠写，正常对象继续展示，不能补默认值假成功。

身份、取消、版本、原子写只在实际重复的业务边界共用；CLI/桌面/单卡/批量同一规则，不建全局规则框架，不扩大 fork 面。

## 9. 审查与范围覆盖矩阵

### 9.1 新审阅 12 项

| 编号/级别 | 批次/要求 | 必验反例 |
