# E 批离线样例仓：启动区参考布局

本目录是**离线样例的启动区（seed）**，供 `PAO/packages/coding-agent/test/pao/e-batch-sample.test.ts` 在每次测试时**复制到隔离临时根**使用。

> 用法见同目录 `E批-离线样例说明.md`。本文件只说明目录里每个文件的用途。

## 一、为什么用「启动区」而不是「现成可跑的仓」

E 批的部门模块（E1）与受理入口（E3）在写本样例时**尚未全部落地**，因此：

- 部门骨架不手写，而是由**真实代码** `createDept()`（`src/pao/dept/scaffold.ts`）生成后快照下来 —— 保证格式与运行时一致，不会「样例与真实格式漂移」。
- `配方.md` 保留脚手架原样（含 `<待填>` 占位）。等 E1 的配方模板（「工具」与「skills/技能」拆成两行、各自写清含义）落地后，按真实字段补写，**不在这里提前猜字段**。
- 受理链路的测试等 E3 的 `acceptIntake` 导出落地后再写。

## 二、目录

```
E批-离线样例/
├─ E批-离线样例说明.md          ← 总说明：怎么用、哪些是真数据、能证明什么
├─ 启动区-PAO_HOME/             ← PAO_HOME 快照（由 createDept 生成）
│  ├─ 部门/
│  │  ├─ 注册表.md
│  │  ├─ 写作/配方.md + 知识库/
│  │  ├─ 审查/配方.md + 知识库/
│  │  └─ 只读审查/配方.md + 知识库/
│  └─ pao配置/
│     ├─ 档位.json
│     └─ skills/小说文风校准/SKILL.md
└─ 启动区-项目/                 ← 样例项目根
   ├─ .pao/                     ← 项目编排目录（卡目录落在这里）
   ├─ 正文/                     ← 写作部门的产出落点
   └─ 待审查稿/                 ← 只读审查部门的输入（样例测试里会改成只读）
```

## 三、逐文件用途

| 文件 | 用途 | 真数据还是夹具 |
|---|---|---|
| `启动区-PAO_HOME/部门/注册表.md` | 部门注册表，唯一真相（名字/能力标签/库路径/建部日期），格式由 `formatRegistry()` 生成 | **夹具**（部门是样例部门，不是真实组织） |
| `启动区-PAO_HOME/部门/写作/配方.md` | 写作部门配方：人设/职责/默认档位/干法 | **夹具**，内容是样例文案 |
| `启动区-PAO_HOME/部门/审查/配方.md` | 审查部门配方（审稿改稿、含打回） | **夹具** |
| `启动区-PAO_HOME/部门/只读审查/配方.md` | 只读审查部门配方（只读，不改被审目录） | **夹具** |
| `启动区-PAO_HOME/部门/*/知识库/` | 六目录 + 四子索引 + 索引门面，由 `createDept()` 生成 | **夹具骨架**，内容为脚手架模板 |
| `启动区-PAO_HOME/pao配置/档位.json` | 档位定义（档位名→provider/model/thinkingLevel） | **夹具**，指向**假 provider**（见下） |
| `启动区-PAO_HOME/pao配置/skills/小说文风校准/SKILL.md` | 样例技能，用于验证「技能定位真实文件」 | **夹具** |
| `启动区-项目/.pao/` | 项目编排目录，卡目录与运行留档落点 | 目录占位 |
| `启动区-项目/正文/` | 写作产出落点 | 目录占位 |
| `启动区-项目/待审查稿/` | 只读审查的输入目录 | 含一份样例稿，测试中改成只读 |

## 四、硬约束（不可违反）

1. **绝不指向正式 PAO_HOME** `D:\AI\workspace\pao`。所有路径都是相对路径或临时根下的绝对路径，测试里用 `os.tmpdir()` 新建根。
2. **绝不调用真实模型供应商**。`档位.json` 里的 `provider` 是一个 **假 provider 名**，任何真实 SDK 都不认识它；配合 `FakeRunner`（只登记不 spawn）双重保证。
3. **不写进 git 仓库的运行产物**。测试自建临时根，结束清理。
