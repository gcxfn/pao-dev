## 4. PAO_HOME 取值路径（落到具体代码）

### 4.1 内核侧：只认环境变量，没有内置默认值

`node_modules/@earendil-works/pi-coding-agent/dist/bundle/chunks/chunk-ZWCKDLFY.js`（实为解包后 bundle 内该 chunk，原文为压缩后单行，此处摘其可读片段）：

```js
function resolvePaoHome(env = process.env) {
  let home = env.PAO_HOME?.trim();
  if (!home)
    throw new Error("缺少环境变量 PAO_HOME(使用现场根目录,应含「部门/」与「pao配置/」;开发仓与使用现场是两个仓库)");
  return home;
}
```

（同文件内 `PAO_HOME` 共出现 **30** 次，模式一致：全部是 `process.env.PAO_HOME` 直读或报错文案。）

**关键点：内核自己不会回落到任何默认目录，更不会回落到开发仓。** 缺环境变量就抛错。

### 4.2 桌面主进程：`out/main/main.js` 里的注入链

`out/main/main.js` 中 `PAO_HOME` 共 **26** 次、`homedir()` 共 **4** 次，**没有任何一处把 `homedir()+PAO` 当默认值**（实测 `"PAO"` / `'PAO'` 字面量在该文件中 **0 次**）。实际取值优先级由两个函数决定（`out/main/main.js`，函数名来自源码，打包后同名保留）：

```js
function resolvePaoHomeInjection(input) {
  const configured = input.configuredPaoHome.trim();
  const envValue = input.currentEnvValue;
  const externallySet = envValue !== void 0 &&
    (input.injectedValue === void 0 || envValue !== input.injectedValue);
  if (externallySet) return { action: "keep" };      // ① 外部设的环境变量优先，不覆盖
  if (configured) return { action: "set", value: configured };  // ② 设置里填的路径
  if (envValue !== void 0) {
    if (input.injectedSource === "portable") return { action: "keep" };
    return { action: "delete" };                     // ③ 设置清空则删掉自己注入的值
  }
  return { action: "keep" };
}
```

便携版另有（`applyPortablePaoHome`）：

```js
const PORTABLE_HOME_MARKERS = ["部门", "工作流", "pao配置"];
function resolvePortablePaoHome(exeDir, dirExists) {
  return PORTABLE_HOME_MARKERS.some((marker) => dirExists(path.join(exeDir, marker))) ? exeDir : void 0;
}
function applyPortablePaoHome(options) {
  if (!options.packaged || process.env.PAO_HOME) return;   // 已设则不覆盖
  const portable = resolvePortablePaoHome(path.dirname(options.exePath), ...);
  if (portable) { process.env.PAO_HOME = portable; ... }
}
```

**取值优先级实测结论**：
1. 用户已有 `PAO_HOME` 环境变量 → **原样保留**（`action: "keep"`）；
2. 否则用设置页里配的「PAO 主目录」；
3. 否则便携版看 exe 同级有没有 `部门/`+`工作流/`+`pao配置/` 三个目录，有就用 exe 所在目录；
4. 都没有 → **不注入，内核侧报「缺少环境变量 PAO_HOME」**（不猜、不默认、不回落到开发仓）。

`out/main/main.js` 里另一处（只读派生值，给界面显示"当前实际生效的 PAO 主目录"）：

```js
paoHomeEffective: (process.env.PAO_HOME ?? "").trim(),
// 注释：只读派生值：渲染层据此说明「当前实际生效的 PAO 主目录」。不进 this.state、不落盘。
```

### 5.1 `ws` 为什么无害

唯一副本在 `node_modules/@google/genai/node_modules/ws`（8.21.3）。需要 `ws` 的是 `openai`（peerDep `^8.21.0`，8.21.3 满足）。

从 `openai/client.js` 出发做 **require 图广度遍历（访问 192 个文件）**：

```
files visited: 192
files requiring 'ws': 0
```

在 192 个文件内没有任何一处 `require("ws")`。`ws` 只被 `openai/realtime/ws.js` 等**按需入口**引用，而 `openai/index.js` 只加载 `client.js`；`resources/realtime/realtime.js` 与 `resources/live/live.js` 也都不引用 `ws`。**PAO 走的是 chat/completions 类接口，到不了 WebSocket 路径。**

### 5.2 `@types/unist` 为什么无害

全 asar 无该目录，但它是**纯类型包**：全 asar 的 js/mjs 里搜 `@types/unist` **0 命中**（没有任何运行时 `require`/`import`）。运行时不需要。

### 5.3 `escape-string-regexp`：这是一条**我最初判错、随后自我纠正**的条目

**初次判断（错）**：我只看到 `node_modules/mdast-util-find-and-replace/lib/index.js:58` 有 `import escape from 'escape-string-regexp'`，且全 asar 寻不到该目录 → 判为"隐患"。

**纠正依据**：缺的只是**源码副本**，运行时代码已被构建器内联进 renderer bundle。证据（`out/renderer/assets/index-CIQZEBZk.js`，偏移约 2321930）：

```js
function escapeStringRegexp(string2) {
  if (typeof string2 !== "string") throw new TypeError("Expected a string");
  return string2.replace(/[|\\{}()[\]^$+*?.]/g, "\\$&").replace(/-/g, "\\x2d");
}
function findAndReplace(tree, list2, options) { ... }
```

对照 `escape-string-regexp@5` 的真实实现正是这两行 replace。**函数体已经在 bundle 里，运行时不需要再解析包。**

补充证据：renderer bundle 里裸 `require("<包名>")` 计数 **0**（全部已内联）；`react-markdown` 字样在 bundle 里存在但没有对应的 `import` 语句（已被 Vite 展平）。

**结论**：`escape-string-regexp` 缺失**无害**。它是构建期被吃掉、运行期已内联的包。
