## 3. 跑出来的两个夹具缺陷（都在 `驱动-从零.mjs`，都不在产品侧）

### 3.1 `selectWorkspace` 传参形状错 → 致命（第 5 个「猜签名」坑）

```
fatal: page.evaluate: Error: Error invoking remote method 'pi-gui:select-workspace': TypeError: workspaceId must be a string
    at main (…\现场\驱动-从零.mjs:344:33)
```
位置：`驱动-从零.mjs:349` `await api.selectWorkspace({ workspaceId });`。
而同一段里 `identity.workspaceIdType` 实测就是 `"string"`（值 `D:\AI\workspace\_t24现场B\工作区`）——
**所以不是值不对，是形状不对**：`selectWorkspace` 要的是**裸字符串**，不是 `{workspaceId}` 对象。
（对照：紧邻的 `api.selectSession({ workspaceId, sessionId })` 是对象，两条 API 形状不同。）
**修法**：`await api.selectWorkspace(workspaceId);`。

### 3.2 `waitIdle` 要求先看到 `running` → 白等 300 秒

```
turnOne = {"sawRunning":false,"timedOut":true,"elapsedMs":300690,"busyField":"status",
           "samples":[{"t":31,"busy":false,"field":"status","found":true}], ...}
```
会话在 **22:40:19 就已经是 `idle`**（标题与 preview 都是收尾文案），但 `waitIdle`（`:171`）等的是
「先 busy 再 idle」，而第一次采样（t=31ms）就已经是 idle，于是它一直等到 300 秒超时。
**修法**：把「已 idle 且 `updatedAt` 比进入 `waitIdle` 时新」也算收尾；或先看会话是否已 idle 再决定要不要等 `running`。

> 这两条与总报告 §6.5 记的 4 个签名坑同类，**建议并进 `运行须知-本机core-lane.md` 的陷阱清单**。

## 4. 缺口：为什么「从零建部」这条从来就没被测过

提示词第一条（`种子-从零.mjs:106`）写的是：

- 想真正验它，最小实验是：**让夹具发一个 `pao_create_dept` 调用**（参数照 `dept/index.ts:51` 的 schema），
  再看 `PAO_HOME\部门\注册表.md` 有没有出现、`getWorkflowCatalog().departments` 有没有变成 `["审校"]`。
  **这不是改产品，是补夹具。**
