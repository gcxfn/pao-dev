# R04 实际工具宽修复

日期：2026-10-19

结论：概况空间判定现在使用 Workbench host 的 CSS 实际盒宽，而不是保存的偏好宽度。保存工具宽 1200px、主区 1700px 时，CSS 实际工具列为 935px，剩余 765px；概况和正文下限 704px，因此保持展开，不再因用偏好计算出的剩余 500px 而误收起。

## 产品改动

只修改 `desktop/apps/desktop/src/features/task-status/use-task-status-collapsed.ts`：

- 复用现有父级 `ResizeObserver`，同时观察 `.main` 和直接子级 `.task-status-workbench-host`。
- `measure()` 读取 `.main.clientWidth` 和可见 Workbench host 的 `clientWidth`。
- `taskStatusCollapseState` 使用实测工具宽；初次测量前才使用现有偏好宽度作为回退。
- 开关工具、拖动工具宽、窗口 resize 都由现有测量通路重新计算。
- 不复制 55% 上限，不新增断点或测量框架；保存偏好不回写。
- 既有 narrow 约束和手动展开逻辑未改。

## 测试

`desktop/apps/desktop/tests/unit/task-status.spec.ts` 追加纯模型边界：

- 主区 1700px、实际工具 935px：剩余 765px，不约束。
- 主区 1638px、实际工具 935px：剩余约 703px，约束。

精确 CSS 边界：1700px 窗口减去侧栏后 `.main.clientWidth` 约 1639.16px；55% 工具列约 935px，剩余约 704.16px，达到 704px 下限。

`desktop/apps/desktop/tests/core/workbench-tabs.spec.ts` 新增独立用例：

1. 2400px 窗口按 `End` 把保存工具宽设为 1200px。
2. 重开后缩到 1700px，断言实际剩余 `main.clientWidth - host.clientWidth >= 704`、概况展开。
3. 缩到 1400px，实际空间不足，断言自动短条。
4. 扩回 1700px，断言概况展开，保存工具宽仍为 `"1200"`。

既有断言与 timeout 未改，未运行本 core 的 Electron；留给 P5 下次统一 build 后单跑这项。
