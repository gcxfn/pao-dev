# P2 证据留存规则

更新日期：2026-10-19

本规则适用于本项后续宿主、runtime 和 P5 验收检查。日志证据放在本目录，不把项目内会被下一次执行清理的临时输出当作唯一证据。

## 日志与失败

- 不覆盖已有 `.log` 文件，也不把旧日志重新指向新结果。
- 每个新执行轮次使用单独文件名，至少包含用途、轮次或日期后缀，例如 `P2-desktop-electron-typecheck-fix1-20261019.log`。
- 执行日志记录命令、工作目录、开始时间、标准输出、标准错误、结束时间和 `EXIT_CODE`。
- 首次失败、后续修复失败和最终复跑分别保存。修复通过不能覆盖失败历史。
- 执行前先确认这次检查是否已经做过；相同代码与相同输入不会为了刷新时间反复覆盖证据。

## Playwright 真实 Electron 产物

- 使用真实 Electron 的 P5 运行若失败，应在下一次测试运行前保存失败测试名、命令、退出码、截图、视频、trace、`error-context.md` 和 HTML 报告（如存在）。
- 本项产物目录按轮次隔离，例如 `P5-真实Electron-失败1-<日期>/`，不得覆盖前轮。
- 项目内 `test-results/` 或 `playwright-report/` 不是本项长期留档正本；复制完成后，下一轮测试可以按 Playwright 自身行为清理它们。
- 成功运行也保存命令、退出码和指针或摘要；截图、视频和 trace 只在产生时保存。

## 证据分层

| 层 | 可接受证据 | 不能替代的层 |
|---|---|---|
| 已改 | 文件差异和关键入口定位 | 编译、测试、真实运行 |
| 静态 | 当前代码与输入对应的类型检查、格式检查、架构守卫日志 | 真实 Electron 或模型调用 |
| Node 单元与源码结构 | Playwright `unit` 或 Node 测试日志 | Electron 主框架、窗口授权、IPC 往返 |
| 真实 Electron | 实际启动 Electron 的 P5 测试、失败截图/trace 或成功断言 | 发行物运行 |
| 发行物 | 从发行物启动并执行验收场景的证据 | 无法替代真实模型供应商质量 |
| 离线替身 | 明确标注替身/固定样例的问答链路证据 | 真实供应商的模型问答质量 |

每个交付轮次重新记录当前结果。旧通过只作为历史证据，不能自动沿用为当前代码状态。
