# 1100px 手动展开三列盒模型修复

日期：2026-10-19

结论：只修改 `desktop/apps/desktop/src/styles/task-status.css`，宽窗手动展开时概况轨道和卡片都受工具列之外剩余空间的限制，消除正文输入跨入概况的问题。compact 两列、980px 窄窗规则、工具列 `min(workbench-width, 55%)`、产品 handle 和其他产品代码均未修改。

## 真实失败证据

真实发行物在 1100px 下 `.main` 约 1080px，工具列 360px，概况列原有 360px 卡片加 24px 间距共 384px，正文列只剩约 336px；正文输入自身最小宽约 352px，实际右缘为 379.708px，概况左界为 368px，重叠约 11.7px。

## 修复

宽窗三列概况轨道：

```css
min(
  calc(var(--task-status-width, 360px) + var(--task-status-lane-gap, 24px)),
  calc((100% - min(var(--workbench-width, 360px), 55%)) / 2)
)
```

概况卡片宽度再扣除既有 12px 右外边距：

```css
width: min(
  var(--task-status-width, 360px),
  calc((100% - min(var(--workbench-width, 360px), 55%)) / 2 - 12px)
);
```

这样默认剩余空间充足时，轨道仍为 384px、卡片仍为 360px；空间不足时正文和概况平分工具之外的空间，且 `card width + margin-right <= overview track`。没有新增断点、状态、配置或测量 hook，也没有通过降低输入最小宽掩盖重叠。
