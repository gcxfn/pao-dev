## 结论

- 概况与 Workbench 已成为 `.main` 网格中的独立列。概况展开时占右上卡片列；收起时只显示短条，不保留概况空列。Workbench 打开时占工具列。
- Workbench 隐藏时保持 React 实例和终端容器挂载，外层 `display: none` 退出网格；重新打开仍是同一终端实例和同一输出，不停止或重建会话。
- 980px 是现有窄窗断点。工具外的可用宽度不足“概况 360px + 正文最小 320px”时自动显示短条；自动收起不写偏好，约束内仍允许手动展开。
- 概况偏好是三态：`undefined` 表示未选择，`true` 表示手动收起，`false` 表示手动展开。显式 `false` 在满足约束或当前约束刚建立时展开；临时展开在约束状态变化时复位，之后再次进入约束仍自动收起。
- 文件摘要复用 `getReview({ scope: { kind: "uncommitted" } })`，包含 untracked；无法统计行数时显示未知；`coverage.state === "partial"` 时显示 `coverage.notes`。
- 多目标分别读取自己的最近启动、控制正本和步骤；会话待办独立展示。部门严格按当前项目绝对路径和 `ownerSessionId` 过滤。
- 已批准并接入两种新工具引用：辅助对话 `{ kind: "side-chat" }` 是内建工具，部门 `{ kind: "department", groupId }` 是上下文标签。部门标签按 `groupId` 去重，旧布局继续可解码。

## §2.2 概况内容与归属

### 文件变更

- 真值入口是 `PiDesktopApi.getReview`，使用当前 `workspaceId/sessionId` 和 `scope.kind = "uncommitted"`。
- Git 查询包含所有未提交改动和 untracked。界面统计文件数、可计算增删行数及 `lines === null` 的未知数量。
- `coverage.state === "partial"` 时原样展示 `coverage.notes`，并明确统计不完整，不能报成全量。
- 读取失败和非 Git 状态显示原因，不以零值冒充成功。
- 点击文件变更使用现有 `changes` 工具，不创建第二套差异查看器。

### 目标、执行标识与待办

- 数据入口是 `getTemporaryPlans({ workspaceId })`；只保留 `sourceSessionId === sessionId && !undone` 的目标。
- 每个目标使用自己的最近一次 `starts.at(-1)`，再按该启动的 `recipeName/controlPath` 读取控制正本和步骤。
- “正在执行”只来自该目标控制正本的真实状态和进度。启动来源、当前执行目标和会话待办分别显示，不能把最近启动冒充任一目标正在执行。
- 多目标独立呈现失败、待确认、阻塞和当前步骤；一个目标读取失败不遮蔽其他目标。
- 会话待办来自 `latestSessionTodos(transcript)`，仅在来源主对话匹配时出现。

### 部门归属与详情

- 数据入口是 `getKanban(workspaceId)`，再以 `desktopPathKey(group.project) === desktopPathKey(workspace.path)` 和 `group.ownerSessionId === sessionId` 过滤。
- 部门卡片保留部门名、任务、真实执行数、轮次、状态、进度、等待或失败原因；不按同名部门合并不同工作流。
- 点击部门入口调用 `workbench.openTool({ kind: "department", groupId })` 并记录焦点，不再打开旧的 workboard 页面。详情组件按当前来源、会话和 `groupId` 重查。
- 长标题、路径和原因由详情组件与既有 `department-board.css` 处理，不把完整任务书塞进概况。

### 短条

优先级从高到低：

1. 失败或阻塞；
2. 待确认；
3. 进行中的部门；
4. 进行中的目标步骤；
5. 当前工作。

短条只显示最高优先级的一条摘要。展开概况后，所有分区可纵向滚动；已完成的步骤和列表默认折叠但可展开。

## P3 接口落实

已批准的最小形状：

```ts
type ToolRef =
  | { readonly kind: BuiltinToolKind }
  | { readonly kind: "extension"; readonly extensionId: string; readonly viewId: string }
  | { readonly kind: "side-chat" }
  | { readonly kind: "department"; readonly groupId: string };
```

- `side-chat` 是内建工具，按 `kind` 去重。
- `department` 是上下文标签，不冒充 extension，不持久保存正文；`toolRefId` 使用 `groupId` 生成稳定身份。
- strict decoder 拒绝新引用的多余字段，旧布局和已退役 `worktrees` 的兼容规则保留。
- 部门详情按当前 `workspaceId/sessionId/groupId` 重查；不使用保存的绝对路径。
- 辅助对话来源是当前 `SessionRef`。回填前复查来源主对话仍存在、未切换且草稿为空，只预填并聚焦，不覆盖、不自动发送。
- renderer API 以现有共享契约为准：`getSideChat(source)`、`sendSideChatMessage({ ...source, text })`；`SideChatSnapshot` 以 `packages/session-driver/src/side-chat.ts` 为准，包含 `busy`、同步边界、限制、失败状态和只读标记。
