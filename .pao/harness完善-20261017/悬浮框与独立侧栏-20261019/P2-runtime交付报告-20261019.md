## 复用接口与接口选择

| 选择 | 原因 |
|---|---|
| `SessionManager.buildSessionProjection()` | 直接取得来源主会话当前有效上下文边界，复用主控的压缩和转换语义 |
| `convertToLlm()` | 覆盖 `compactionSummary`、`branchSummary`、`custom`、`bashExecution` 等有效消息，避免手写转换器静默丢材料 |
| `getCurrentSystemMessage()`、`getSystemMessageText()` | 读取 system 的实际 `sections`，包括 AGENTS 和 Git 等材料；历史主 system 明确降为资料 |
| `PromptOptions.images` | 把来源 user/toolResult 的真实图片块交给模型，不将已有图片降级成无法读取的文本占位 |
| `createReadOnlyTools()` | 复用 pi 的标准只读工具，不另造路径沙箱；白名单为 `read`、`grep`、`find`、`ls` |
| `getBlockImages()` 与 `model.input` | 继承来源禁图设置并读取当前模型是否声明图片输入；辅助 runtime 不靠 `inMemory` 默认值绕过来源偏好 |
| `processImage()` | 以和 pi prompt 相同的缩放参数预检来源图片；坏图/超限图记入本次同步，问题消失后重新预检即可恢复 |
| `determineRunOutcome()` | 复用主控同一运行结果判断；`error`/`aborted` 的 partial text 保留但不进入后续成功历史 |
| 空 `ResourceLoader` 与隔离配置 | 不加载共享扩展、MCP、hooks 或扩展命令；辅助会话拥有自己的 `SessionManager.inMemory()` |
| `SessionSupervisor` 窄读取 | 让 live 来源与主控使用同一份 projection；闭来源的可读记录由公开 projection 返回 |
| `readFile + parseSessionEntries + SessionManager.inMemory` | 闭会话旧日志在内存迁移，不使用可能在读取时改写旧 schema JSONL 的 `SessionManager.open` |
| `<agentDir>/aux/side-chat/<hash>.json` | 仅由 runtime 持久化辅助问答；应用层无需重复保存，也不向模型授予该文件写权限 |
| 本次同步限制不持久化 | `busy`、坏图、禁图与附件可读性每次按当前来源重算；旧限制不永久 union，`contextComplete` 可在问题消失后恢复 |
| 两阶段 prompt 生成 | 先扫描附件并写入本次限制，再用最终限制生成一次交给模型的 prompt；不重复转换主材料或复制图片 |

持久化键包含 workspace、session 和真实目录；损坏记录会显式报错，不会静默清空。`busy.add()` 后的读取、写入、runtime 创建和模型调用均被 `try/finally` 覆盖，修复损坏文件后同一实例可重试。辅助 store 不再保存同步限制；旧回答的错误原因仍保留在该回答的 `status/error` 中，不会被冒充为当前同步状态。
