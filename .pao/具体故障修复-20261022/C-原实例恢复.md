# 空身份认领与原实例恢复

日期：2026-10-22。实施状态只维护在执行总册§10.17，本文记录本批改动及证据。

## 改动

- 公共建卡入口发号前拒绝空字符串、纯空白或非字符串owner。历史空白owner在状态机中按无主处理，合法认领才补写；真实owner不裁剪，不放宽单写者保护。落盘前重读并重新检查owner，防止覆盖读取之后发生的身份变更。
- `pao_control_node` 增加 `action=reopen`，仍走既有界面确认。需要当前实例、原owner、节点、轮次与现场核查理由。确认后在`.dispatch → 控制正本`既有锁序内重新核对，读取实时工人登记。
- 仅处理前置已完成且拆解已结束的当前故障节点。已完成节点、已交付卡、进行中卡、活工人、冲突回执、待裁定对象与已启动的下游均拒绝。独立旁支不参与重开。
- 与审核回边共用后继范围计算和旧轮留存/新轮重置。保持实例、owner及旧卡原文；轮次递增并清除旧部长身份、旧基线、确认和判定，由新一轮真实部长生成新卡。旧部长/旧轮提交不能冒领新轮。
- `WorkflowHostBridge.drive`收尾仅在实例完成或明确暂停、没有该脉络运行工人时，定向释放同项目同脉络且无后台工作的闲置部长；不因另起相似任务删除独立并行流程。会话文件保留，在途结果接收者保留。

## 验证事实

- `C1-tests.json`：卡读写、状态机两个文件51项通过，包括空身份、新卡拒绝、真实他人owner、普通迁移限制和落盘前身份变更。
- `BC-control-tests.json`：首轮65项通过、1项失败；失败因测试只匹配“已交付”而实际正确拒绝提示为“已完成”，未改保护逻辑。`BC-control-rerun.json`：66项通过。
- `C2-tool.json`：通过实际注册的`/pao flow control`入口验证，无界面恢复被拒，确认后同实例进入第二轮；其余既有工具回归同时通过。
- `C2-host-lifecycle.json`：30项通过，含本实例部长释放、无关脉络保留、后台接收者保留。
- 这些控制层和宿主测试使用真实磁盘文件，部分卡结果或宿主行为是明确模拟，不能代替真实模型四部门闭环。最终统一回归和独立审核结论归整合报告。

## 边界

重开入口用于故障恢复，不用于重复执行已完成成果。存在已启动下游或已交付卡的复杂返工继续由既有审核回边处理。CLI与桌面会话共用同一内核工具；本批未为桌面另造恢复状态机，也未新增专用重开按钮。无交互界面不能自动代替人工恢复确认。
