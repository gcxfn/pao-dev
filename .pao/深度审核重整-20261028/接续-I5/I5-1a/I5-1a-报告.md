## 修复

角色识别按互斥工具集合优先判断：

1. 主控协调工具。
2. 部长节点工具。
3. worker 回执、任务结果和原生执行工具。

工具无法判断时才读取明确的“你是/当前角色…”身份文本。“主控会话”和
“绑定节点”是引用文本，不再决定当前角色。每个请求把命中的工具或文本证据写入
`roleEvidence`。

工具结果处理从最新 `tool` 消息读取 `tool_call_id`，向前扫描
`assistant.tool_calls[].id`，取得对应 `function.name`。显式 `name` 存在且不一致、
`tool_call_id` 缺失或无法反查时，均返回带类型的 HTTP 422，不猜测工具名。

产品客户端真实第二轮请求还断言了 `tool` 消息包含 `tool_call_id` 且不含
`name`，证明服务确实走反查路径。第一轮工具调用和第二轮结束文本均由真实
HTTP 返回。

## API 与运行

库入口：

```js
const server = await createScriptedModelServer({
  scenarioPath,
  evidenceDir,
  host: "127.0.0.1",
  port: 0,
});
await server.close();
```

返回的 `baseUrl` 形如 `http://127.0.0.1:<随机端口>/v1`。端点：

- `GET /health`
- `GET /v1/models`
- `POST /v1/chat/completions`

命令行：

```powershell
node bench/rehearsal/scripted-model-server.mjs `
  --scenario <scenario.json> `
  --evidence <evidence-dir> `
  --port 0
```

进程收到 `SIGINT` 或 `SIGTERM` 后关闭监听。库调用方可等待 `close()` 释放端口。
所有响应 usage 固定为模拟 `input=1, output=1, total=2`，并带
`synthetic: true` 与“不是真实 token”说明，不能用于真实成本或性能结论。
