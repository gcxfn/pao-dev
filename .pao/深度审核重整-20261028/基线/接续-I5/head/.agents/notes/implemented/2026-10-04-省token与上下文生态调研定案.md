## 定案：抄（进 fork，纯 TS）

### 第一批：并入 auto-recall 注入位次迁移（同属注入/压缩层，一次动刀）

| 抄什么 | 来源 | 用途 |
|---|---|---|
| 冻结前缀＋消息只追加（appendOnlyContext 口径，缓存型 provider 自动启用） | OMP | auto-recall 缓存 bug 修法直接对齐：静态进系统提示、每轮变的走 context 事件消息层 |
| PreCompact 优先级快照（压缩前把带 type/category/priority 的事件状态存表，压缩后恢复） | context-mode（本地实物确认：session_resume.snapshot 表形态） | compaction 交接不丢关键状态 |
| 缓存命中/实耗对账（acp_cache 思路） | billion-context-pi | 接用量账.jsonl，验证迁移真生效 |

### 第二批：新立「工具输出侧修剪＋压缩增强」（排 auto-recall 迁移后）

| 抄什么 | 来源 | 用途 |
|---|---|---|
| 同文件重读剪旧读（supersedeReads，cache-aware） | OMP | read 同一文件，旧结果修剪 |
| 废结果消费后即剪（dropUseless，cache-aware） | OMP | 无匹配/超时工具结果用完即剪 |
| 命令压缩规则表（git log/npm ls 各留什么丢什么） | RTK（抄表不装进程） | TS 规则几十条 |
| async 投机预压缩（接近阈值后台预压缩、过阈值即拼，零停顿） | OMP compaction.asyncEnabled | 压缩触发时不卡顿（2026-10-04 用户拍板列入本批） |

### 记候选不排期（攒摩擦再说）

- 压缩方法链 fallback（remote→snapcompact→handoff→shake→soft 逐级回退＋工具循环安全点检查）——OMP compaction 骨架
- prewalk（强模型规划建 todo 后切便宜模型实施）——档位路由新角度
- TACO 自进化压缩规则（规则从用量数据里学，非人写死）——将来可从用量账.jsonl 起步
- 沙箱执行（写代码算、只有 stdout 进对话）——context-mode 主力件；若第二批修剪件不够用再考虑此形态
- snapcompact 图像化提示（vision 模型省 token 但丢缓存）——仅记录，倾向不用

## 定案：不装（理由存档）

- **billion-context-pi**（MIT，464K/月）：拦截 pi context 事件、取消原生 compaction、自任唯一管理者，README 明确「只能装一个压缩插件」——与 auto-recall 迁移（也要走 context 事件）直接冲突；且其定位（单会话吃百亿 token）与 PAO 短流程＋状态在卡的架构正交。
- **context-mode**：三重否决——ELv2 许可证（混入 MIT 仓污染）；机制重叠（会话连续性＝卡片档案制、FTS5 知识库＝gbrain）；**本地弃用实锤**（~/.pi/context-mode：8 月中～9 月中 50 会话/4260 事件后停用，知识库仅喂 4 源 13 块）。注意：否的是整装（MCP+SQLite 常驻壳），其输出限制机制的价值已由第二批抄件承接。
- **pi-rtk / pi-lean-ctx**：均为外部进程路线（Rust CLI/常驻 daemon）；lean-ctx 的 onboard 还会自动改写机器上全部 AI 工具配置。fork 内 TS 自研（第二批）更顺，零新进程零新依赖。
- **ponytail**：少废话提示词技能；context-mode 引研究称此类激进简洁提示词损害编码基准。
