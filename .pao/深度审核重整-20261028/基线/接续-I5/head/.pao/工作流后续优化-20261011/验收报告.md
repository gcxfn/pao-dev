# 工作流后续优化验收报告

验收日期：2026-10-12。范围：工作流视图计划的后续优化，包含 PAO 自有内核、TUI 和桌面。主对话直接实现与审查。没有改 pi 上游本体、正式 PAO_HOME，没有提交、推送、发布或调用真实模型。

## 结论

23 节点样例可在总览、详细图、专注和列表之间切换；搜索可以找到折叠组内节点和多卡节点的任一张卡。三种窗口宽度的总览和列表已有真实 Windows Electron 证据。只读并行调度已按用户确认的范围启用，写任务、失败阻断、人工确认和派发保护继续沿用已有规则。

本批完成主要的界面、状态正确性和可测量性能优化。整体计划仍在执行，条件候选和未覆盖的真实入口列在文末。

## 已修改

### 桌面视图

- 总览沿用首批的阶段/并行组折叠和按宽度折行，23 节点样例仍压缩为 6 个流程块。原有依赖、审核回边和冻结坐标保留。
- 新增节点搜索、状态筛选、下个待处理、上下游高亮，专注可选 1 层、2 层或全部上下游；普通等待前置不误报为“需要处理”。
- 列表与详情选择同步。多卡详情能逐张打开当前轮次卡片；内核、SDK 和 IPC 使用同一份卡号列表。
- 搜索、视图工具栏和列表按独立行排布；列表隐藏图时同时禁用其交互，防止连接点漏出和键盘进入隐藏画布。
- 专注画布在原组件上扩大，Esc 退出；窄窗口的入口可达。收起侧栏后不残留空列，底部画布按钮保持在窗口内。
- 保存实例的图模式、展开组、两个视口，以及应用的工作流库/详情显示偏好；只写本地查看偏好，不改配方或实例文件。
- 节点键盘聚焦时定位到可见区域；标题限制两行并保留完整提示。自动分层按前置行位稳定排序；冻结图外节点单列标为“未映射 · 依赖未知”。
- 普通依赖边去掉重复文字并保留方向箭头。菜单按真实尺寸夹在编辑器和屏幕内；详情使用容器高度。
- 聊天区或侧栏改变画布面积时保持画面中心和倍率，修复建立主控会话后节点落到裁切区的问题。
- Windows 路径比较集中到 `desktopPathKey`，应用于画布、看板、工作台和主进程查询；保留 POSIX 大小写，权限判断仍使用原真实路径核验。

### 内核与执行

- v1 清单拒绝重复节点、重复卡号和错误归属；start/tick/confirm 共用实例锁，锁内重读；自动链首次异步读取前预留受理位置，失败释放。
- v1/v2 首次建卡原子包含工作流标记；v2 保存中断留下的未登记卡明确隔离并拒绝重复新增/派发。
- `controlView` 一次读取卡面并复用依赖完成状态，坏卡只影响所在节点及依赖它的下游；TUI 和桌面以当前投影报告状态。
- v2 自动链每批重新建立卡状态快照，派发最终核验保留；同批各卡单独记步骤，全部结算后按输入卡序合并。
- `WorkflowHostBridge` 按显式组上限并行不同部门只读节点；同部门、写节点、未声明或非全部成功策略保持串行。分支全部结算才返回，异常暂停，取消传给各请求；漏结束信号、失败和人工门均阻止汇聚。
- 只读节点已有工具白名单和禁止交工人卡的保护；提示也明确要求只读检查、说明零卡理由并提交结束信号。
- 部门读取失败明确展示原因；验收外链扫描读取异常或超出容量时阻止自动验收。
- Worker 内存只留有限尾部，完整 live 文件作为证据正本；证据写入或丢失不冒充成功。
- TUI 命令列表按查询、可用行数和注册表对象复用；知识库入库只巡检当前条目正文，仍核对全区索引，显式巡检继续覆盖全区。

并行的原因、默认值和不支持的策略只维护在[并行边界决策](../../.agents/notes/implemented/2026-10-12-工作流只读节点并行边界.md)。

## 性能测量

每种改前/改后均运行三次，表内为中位数。本机隔离模拟数据，只证明对应重复工作的减少。

| 场景 | 改前 | 改后 |
| --- | ---: | ---: |
| Worker 约 31MB 输出处理 | 324.980ms | 149.580ms |
| Worker 堆增量峰值采样 | 158,240,480B | 6,362,288B |
| Worker RSS 增量峰值采样 | 223,346,688B | 3,264,512B |
| 50 命令面板，1000 次渲染 | 581.598ms | 568.449ms |
| SelectList 不同对象数 | 1000 | 1 |
| 1000 个同类型条目中新增入库 | 58.579ms | 7.217ms |
| 入库正文巡检条目数 | 1001 | 1 |

Worker 六次输出各 30,001 个事件，内容哈希相同：`087f1ffe799b4dba1553ef8b2020436d7e9fe2dede71ae064c34e9afddb62b52`。原始数字与限制见[性能记录](性能记录.json)。内存每 5ms 采样，可能漏过瞬时峰值；未完成 JSON 单行缓冲和最终助手输出仍按原协议保存，不能宣称总内存绝对固定。面板时间差约 2%，主要收益是减少重复对象构建。

首批画布 100/500 个执行映射文件的结果仍见[首批性能报告](../工作流视图优化-20261011/画布读取性能验收.md)，本批不重复测量、不将不同基线合并。

## 验收中处理的问题

真实桌面测试发现并修复：窄窗口导航遮挡专注入口、专注高度超出屏幕、关闭侧栏后残留 48px 列、列表边缘漏出连接点，以及建立主控聊天区后的旧视口裁切。没有使用强制点击、跳过断言或放宽交互超时。

检查还修复了测试代码中的错误 Playwright 导出用法、shell.showItemInFolder 的 void 返回约定、档位夹具的类型，以及验收扫描终止函数的 TypeScript 控制流识别。模拟数据、读取失败和未知结果继续明确暴露。
