## 五、推荐实现（已按最小改动推演过，可直接照做）

> 目标：收起后 `<main>` 只剩单列、右侧零像素；找回靠顶栏常驻按钮；`App.tsx` 零改动。

### 5.1 状态提升：新建模块级 store

顶栏按钮和右侧坞必须读到同一份「是否隐藏」，而坞在隐藏时不再渲染组件内部状态会丢（`TaskStatusRail` 还会因 `key={sessionKey}` 切会话重挂）。**照 `src/ui/active-theme.ts` 的模块 store + `useSyncExternalStore` 写法**（同目录 `ui/syntax-highlight.ts`、`ui/modifier-hints.ts` 也是这个模式）：

新建 `desktop/apps/desktop/src/features/task-status/task-status-dock-visibility.ts`：

```ts
/**
 * 右侧坞的显示状态。顶栏按钮与坞本身都要读同一份，
 * 所以放在模块级 store（同 ui/active-theme.ts），不放组件 state。
 */
const STORAGE_KEY = "pi-gui.task-status-collapsed"; // 沿用第四轮的键，true = 用户手动收起

let collapsedByUser = readCollapsed();       // try/catch 降级为 false
let expandedInNarrow = false;                // 只在本次运行有效，不落盘
const listeners = new Set<() => void>();
function emit() { for (const listener of listeners) listener(); }
function subscribe(listener: () => void) { listeners.add(listener); return () => { listeners.delete(listener); }; }

export function collapseTaskStatusDock(): void { /* 置 true + 写盘 + emit */ }
export function expandTaskStatusDock(): void { /* 置 false + 写盘 + expandedInNarrow = true + emit */ }

/** 顶栏按钮用：只看偏好，不看工具面板。 */
export function useTaskStatusDockHidden(): boolean {
  const narrow = useNarrowViewport();          // 从 ../../ui/narrow-viewport 导入
  useSyncExternalStore(subscribe, () => `${collapsedByUser}:${expandedInNarrow}`);
  return collapsedByUser || (narrow && !expandedInNarrow);
}

/** 坞自己用：工具打开时一律展开。 */
export function useTaskStatusDockCollapse(toolsOpen: boolean) {
  const hidden = useTaskStatusDockHidden();
  return { collapsed: !toolsOpen && hidden, collapse: collapseTaskStatusDock, expand: expandTaskStatusDock } as const;
}
```

要点：
- `getSnapshot` 必须返回**稳定值**（这里拼成字符串），否则 `useSyncExternalStore` 会反复判不等。
- **为什么分两个 hook**：坞需要 `!toolsOpen && hidden`（工具打开必须显示），而顶栏按钮要看的是「用户的偏好」——工具打开时点它的语义是「连工具一起关掉」，所以它必须读到不含 tools 短路的那个值，否则会出现「按钮显示已隐藏、面板其实还在」的矛盾。
- **保留原文件名 `use-task-status-collapsed.ts` 或改名都行，但必须同步改 import**：现在唯一引用点是 `task-status-dock.tsx:30`。推荐改名并把旧文件删掉（避免两份逻辑并存），参考之前的清理先例（上一轮删过 `app/sidebar-summary.tsx` 这种没引用的孤立件）。
- 语义**不要变**：窄窗默认收起不写盘、窄窗点开只在本次运行、用户手动收起才持久化、工具打开时展开。第四轮的 42 例回归是围着这四条建的。

- **删除** `:48-51` 的 `:has(> .task-status-dock--collapsed)` 规则、`:62-68` 的 `.task-status-dock--collapsed`、`:120-123` 的箭头翻转规则（都只为 40px 窄边服务）。

### 5.3 隐藏时把工具面板一并关掉（否则状态不一致）

如果只隐藏坞、不改 `workbench.view.visibility`，会出现一串别扭状态：`sidePanelVisible` 仍为 true → `App.tsx:802` 继续加 `main--with-side-panel`；`topbar.tsx:75` 的 `!panelVisible` 为 false → 顶栏面板按钮不渲染 → 工具没法再打开；`Alt+B` 语义反转。

所以 `collapse()` 的调用点要**先关工具**：

```jsx
onCollapse={() => {
  workbench.setVisibility("hidden"); // 工具面板同时收起；标签页与布局都保留
  collapse();
}}
```

`setVisibility` 来自 `TaskStatusDock` 已有的 `workbench` prop（`use-workbench.ts:185-188` 导出，`workbench-state.ts:138-141` 的 reducer 只改 `visibility`，不动 tabs）。

由此得到的行为闭环（写进验收）：
- 工具打开时点收起 → 工具先隐藏、`toolsOpen` 变 false → `collapsed` 为 true → 右侧零像素。
- 之后按 `Alt+B` 或顶栏面板按钮 → `workbench.view.visibility` 变 visible → `toolsOpen` true → `collapsed` 恒为 false → 坞自动带工具一起回来。
- 用户「手动收起」的偏好仍在盘上；关掉工具后回到收起态（与第四轮语义一致）。

### 5.4 顶栏找回入口

在 `topbar.tsx:73-95` 的 `.topbar__actions` 里，**在 `{children}` 之后、面板按钮之前**插入新按钮。`Topbar` 目前收 10 个 props（`topbar.tsx:7-18`），**不需要给它加 props**——`activeView` 已经有了（`:8` `readonly activeView: AppView;`，`App.tsx:1165` 传入），按钮内部自己调 `showsTaskStatus(activeView)` 判可用性：

```jsx
{showsTaskStatus(activeView) ? (
  <div className="shortcut-tooltip-wrap topbar__tooltip-wrap">
    <button
      type="button"
      aria-label={t("Toggle status panel")}
      aria-pressed={!statusHidden}
      aria-controls="task-status"
      data-testid="toggle-task-status"
      className={`icon-button topbar__rail-toggle${statusHidden ? "" : " icon-button--active"}`}
      onClick={statusHidden ? expandTaskStatusDock : collapseTaskStatusDock}
    >
      <SidePanelIcon />
    </button>
    <span className="shortcut-tooltip topbar__tooltip" role="tooltip">
      <span>{statusHidden ? t("Show status panel") : t("Hide status panel")}</span>
    </span>
  </div>
) : null}
```
