## 二、公开 API 签名(collab/index.ts 统一 re-export)

```ts
// 注册入口(注册给主控会话;worker 装载清单不装本模块即无再派发入口)
registerCollab(pi: ExtensionAPI, options?: CollabToolsOptions): void

interface CollabToolsOptions {
	resolveCardsDir?: () => string;                       // 当前任务工作区卡目录(与 A 卡工具同款注入)
	resolveDeptCardsDir?: (部门: string) => string;        // 目标部门卡目录;缺省=同一卡目录(§2.1 平铺布局)
	resolveAuditPath?: () => string;                       // 缺省 <卡目录>/../协作审计.jsonl
	resolveRegistryPath?: () => string;                    // 缺省 $PAO_HOME/部门/注册表.md
}

// 纯库
校验协作卡(卡: CollabCardDraft, 注册表: readonly DeptRegistryRow[], 既有卡状态: readonly ParsedCard[]): CollabReviewResult
落协作卡(cardsDir: string, 卡: CollabCardDraft, 创建: string, options?: { counterPath?: string }): Promise<ParsedCard>
审计追加(auditPath: string, 记录: CollabAuditRecord): Promise<void>

// 常量
COLLAB_VERDICTS = ["放行", "拒绝", "待主控裁决"]
RULING_FLAGS = ["插队", "新权限", "超预算覆写", "验收存疑"]
DEFAULT_COLLAB_QUOTA = 2
```

**工具** `pao_协作中转` 参数:`目标/部门/验收/parent`(必填)+ `输入/约束/depends_on/档位/预算{turns,cost,协作配额}/优先级/来源部门/卡目录`(可选)+ 四类裁决标记声明字段(可选,见下)。三路都返回文本;`details` = CollabReviewResult。

**命令** `/派`:`/派 目标 | 部门 | 验收` 或 `/派 目标 | 部门 | 输入指针(顿号分隔) | 验收`,经 resolveCardsDir 直接落卡(待认领、无 parent、不走注册表校验、不留协作审计);参数不全回中文用法提示不落卡,未注入 resolveCardsDir 回配置缺失提示。

**CollabCardDraft** = 协议字段(目标/部门/验收/parent 必填,输入/约束/depends_on/档位/预算/优先级 可选)+ 四类声明字段。**CollabReviewResult** = `{ 裁决, 原因: CollabRejectionReason[], 裁决声明, 裁决摘要?, 已有卡号? }`;拒绝原因 `{ 类型, 说明, 字段?, 卡号?, 阻塞? }`,类型八值:`字段缺失/字段非法/parent 不存在/深度封顶/部门不存在/重复落卡/配额超/依赖未满足`。

## 三、裁决标记四类:字段格式

协作卡草稿信封上的**四个可选字符串声明字段**(值为声明说明,非空即生效):

| 字段 | 含义(架构 §8.2) |
|---|---|
| `插队` | 请求优先于队列现状,值为理由 |
| `新权限` | 需要既有授权范围之外的能力,值为说明 |
| `超预算覆写` | 需超出父卡预算池,值为请求额度与理由 |
| `验收存疑` | 验收条件不明/不可判,值为存疑点 |

规则:任一声明 → 机械校验即使全过也不落队列,返回裁决摘要(含各声明内容+卡摘要)交主控;拒绝优先于待裁决(机械没全过先拒绝);**声明字段永不落盘**(协议零新增,§8.3——协作卡落盘=普通卡+parent,主控裁决通过后去掉声明/调整协议字段重新递交)。

## 四、审计 JSONL 格式

路径缺省 `<卡目录>/../协作审计.jsonl`(任务工作区根),一行一条 JSON,带文件锁追加,目录自动创建。放行/拒绝/待裁决**三路都留痕**:

```json
{"时间":"2026-10-02 11:00","来源部门":"前端","目标部门":"后端","卡号":2,"校验结果":"放行","目标":"帮忙压测"}
```

- 固定五字段:`时间`(YYYY-MM-DD HH:mm)/`来源部门`(缺省「主控」)/`目标部门`/`卡号`(放行=新卡号;拒绝/待裁决=幂等命中卡号或 null)/`校验结果`(放行|拒绝|待主控裁决)。
- 可选:`目标`(协作卡目标,人读)、`原因`(拒绝=结构化原因数组如 `["[部门不存在] …"]`;待裁决=声明数组如 `["插队：…"]`)。

## 六、取舍与说明

- **裁决标记 = 草稿信封上的声明字段,不落盘**:卡面说「卡带声明字段」,若落盘则违反协议零新增(§8.3)。折中:声明只存在于递交时刻的信封上,待裁决卡不落队列、放行卡不该带声明,故落盘文件永远只有协议字段;审计与裁决摘要负责留痕。
- **配额统计口径**:`既有同 parent 协作卡数` 按字面统计**全部状态**(含已交付/失败),对齐 §8.5「每卡 ≤2 张协作卡」的最坏情况封顶;取消不豁免。要放宽由父卡 `预算.协作配额` 覆写(测试覆盖)。
- **幂等口径**:「同目标」取「同目标部门」(卡.部门),不比对目标文本(同一部门改个措辞重交是合法补正,不该绕过幂等;不同部门同 parent 是并行的两张协作卡)。
- **既有卡状态来源**:工具内 = listCards(卡目录)∪listCards(目标目录);默认平铺布局两者相同。校验器本身是纯函数,不读盘,测试用内存夹具直接覆盖。
- **parent 卡不存在判拒绝**(卡面清单未列,程序可判且配额/深度检查都依赖父卡,拒绝最安全);parent 引用无法解析归「字段非法」。
- **/派 不走注册表校验、不留协作审计**:用户直派的卡是普通卡(无 parent),不属于协作中转;A 卡的 pao_建卡 同样不校验注册表,两者对齐。
- **审计追加复用 cards 的 withFileLock**(M2 允许 import 兄弟模块公开导出):锁目录建在目标旁,故先建目录再上锁(踩过一次 ENOENT,已修并有测试)。
- **落协作卡为异步**:createCard 内部发号走异步文件锁,同 A 卡约定。
- **未验证**:未在真实 pi 会话接线跑通(接线行由主控统一写);`/派` 与工具的注册面用极简 capturePi 间接覆盖,事件流行为(sendMessage 渲染)未在真实 UI 验证。
