## 行为与职责

主控派部门、部长派工人后，没有可立即处理的工作就结束当前模型轮次。宿主继续承载后台执行；结果先写卡和回执，再投递给直属上级，通过既有 followUp 唤醒。模型空闲期间不调用等待工具或 sleep。

部长默认每15分钟检查本部门仍在工作的工人，主控默认每30分钟检查仍在工作的部门。持续输出的对象也参与检查；只读部长仍在工作时不会漏掉。工具调用数和模型轮次触发默认关闭。同一上级的同期检查合并，未处理不重复提醒；上级实际检查后调用 `pao_ack_supervision` 才重新计时，收到消息或结束回答不算已处理。已完成和等待用户裁决的对象不参与周期检查。

普通部长自己的模型轮次结束后，如果其子进程仍有工人，程序事件 `background_work` 会把后台数量传回父宿主，继续保活；后台清空后才生成一次简短部门完成通知。RPC 已受理但尚未开始模型轮次的任务也计入活动，不能被空闲终止。热会话 inject 与 executeTask 两个入口都结算真实任务，错误和取消不会冒充正常完成。工作流部长由调用方汇总，避免每个模型轮次都向主控重复报告。运行登记、监督和消息均按项目、上下文和真实会话隔离。

## 结论范围

本轮使用单元测试、离线模型提供者替身、真实 AgentSession、真实 Git 仓库和受控 Node 子进程验证工程行为；替身明确不等于真实模型的协作质量、费用或速度收益。没有运行新的付费模型对比，没有启动 Docker，也没有替换或安装桌面发行物。桌面门禁是源码边界检查，不等于新版安装包运行验收。

正式 PAO_HOME 未参与测试。此前九项试验继续处于 `stopped_by_user / auto_resume=false`；仍为5项官方结果、1项基础设施中断、1项用户停止、2项未运行，历史成绩与费用记录不改写。历史卡3已终结的失败也不倒填；新的格式恢复只用于未来真实运行首次写回执前的同次处理。
