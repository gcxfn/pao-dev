### 2. 失败签名（本轮红灯与 10-07 门红灯逐字一致）

- 取消用例：`expected Error: Command failed: C:\Windows\System3… to match object { name: 'AbortError' }`——killTree 的 PowerShell 树杀脚本报错后，runCardProcess（src/pao/cards/process.ts:36-38）让 stopError 优先于 `reject(signal.reason)`，掩盖了 AbortError。

### 3. 定性结论

**环境/时序（负载依赖的非确定性），非确定性产品缺陷。** 依据：同一代码同一命令三次绿两次红（证据 1/2/3/4）；含新 killTree 的 10-04 12:34 全量基线绿（证据 6）；红灯仅在系统高负载触发，且该抛错路径是 killTree「宁报错不假报树已灭」的刻意安全设计（防 PID 复用误杀），产品另有 SIGKILL 兜底不悬挂。按任务规则：**留红灯与证据、不改代码不改断言**。

### 4. 留给主控的后续建议（不在本包动）

- killTree 的 PS 15s 超时预算与 WMI 慢的矛盾（全量跑后期系统负载高时必踩）；stopError 与 abort 语义的优先级（中止时应优先 AbortError）。均属设计决策，需主控拍板，不在「最小修复」范围。
