### 件二（已修）：kanban-board.spec.ts 租约用例 evaluate 内动态 import 不可用

- 根因：`electronApp.evaluate` 把函数体在主进程按 CDP 经典脚本 eval，无 `importModuleDynamically` 回调，
  动态 import 必抛「A dynamic import callback was not specified」（复跑同红，桌面门补跑批二已定性）。
- 修法（换注入道）：evaluate 内改走 `process.getBuiltinModule("node:module").createRequire(...)(require(esm))`
  加载 `dist/pao/desktop/index.js`（Electron 37＝Node 22，产物无顶层 await，实测同步加载成功），取
  `registerDesktopOwner` 后的注入逻辑逐字未动（假 pi 对象＋session_start 触发＋rows 闭包）。
- 同实例核实：pi-sdk-driver 与 apps/desktop 两条解析路径 realpath 同为
  `pao-dev\pao\packages\coding-agent\dist\pao\desktop\owners.js`（pnpm 链接同一份）；且夹具
  `PAO_DISABLE_BUILTIN_EXTENSION=1` 时内置 pao 扩展从未注册 owner，登记表只含本测试注入的行。
- **顺带修掉同用例潜伏第二缺陷**：夹具租约日期写死（租约至 2026-10-06），今天（2026-10-08）已过期——
  只修 import 也会红（active 断言变 expired）。租约四时刻改相对 now 取值（新代 now+24h 未到期、
  旧代 now−29h 已到期被接管），断言日期由同一变量算出，不再随日历腐坏。
