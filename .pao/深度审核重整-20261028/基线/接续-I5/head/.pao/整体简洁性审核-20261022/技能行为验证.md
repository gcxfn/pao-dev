# SDK 小项目简洁性审查

审查日期：2026-10-22

## 结论

这个项目有一项值得做的低风险简化：删除 `a.ts` 和 `b.ts` 中逐字相同的 `cleanKeys` 实现，把键清理规则收拢到一个内部模块。

没有发现其他应当立即删除或合并的结构。`Store` 是明确的公开扩展接口，`listA` 的授权检查是产品需求；`shortLabel` 与 `detailLabel` 虽然实现文本相同，但默认长度不同，当前保留两个公开函数更清楚。报告另列一项关于 `MemoryStore` 的接口疑点，但仅凭当前代码不能认定它应当删除或补写。

## 值得做的简化

### 1. 收拢重复的键清理规则

**位置**

- `src/a.ts:2-4`
- `src/b.ts:2-4`

**证据**

两个私有 `cleanKeys` 的表达式完全相同，都是 `keys.map(key => key.trim())`，先去除首尾空白、删除空字符串，再通过 `Set` 去重并保留首次出现的顺序。

现有调用关系为：

- `listA` 先执行授权检查，再清理键并读取 `Store`。
- `listB` 直接清理键并读取 `Store`。
- 当前仓库内没有其他 `cleanKeys` 调用、导出或字符串引用。

**方案**

新增一个内部键处理模块，例如 `src/keys.ts`，只保存一份 `cleanKeys`；`a.ts` 与 `b.ts` 都从该模块导入。不要让 `b.ts` 依赖 `a.ts`，也不要让业务模块从 `store.ts` 导入这个工具，以免破坏依赖方向。

**行为边界**

- 保留首尾空白清理、空字符串过滤、按首次出现位置去重这三项现有语义。
- 保留 `listA` 的授权检查，并确保检查仍在读取 `Store` 之前。
- 不合并 `listA` 与 `listB` 的公开函数。两者一个有授权参数、一个没有，合并会改变公开接口和调用条件。
- 不需要把 `cleanKeys` 暴露为 SDK 的公开契约；它只在包内部复用。

**收益与风险**

收益是让“键如何规范化”只有一个正本，后续边界规则不会在两条路径中分叉。风险较低，但需要未来加入测试，确认去重顺序、空白键、重复键和授权失败时的短路行为都没有变化。

**验证**

应在实现后运行 TypeScript 编译检查，并覆盖以下行为：

- `[' a ', 'a', '', '  ']` 只按首次顺序读取一次 `a`。
- `listA` 在 `authorized === false` 时仍抛出 `forbidden`。
- `listA` 与 `listB` 的返回顺序和读取次数保持原样。

## 不建议做的简化

### 合并 `shortLabel` 与 `detailLabel`

**位置**：`src/labels.ts:1-2`

**证据**：两个函数都调用 `slice`，但 `shortLabel` 的默认长度是 12，`detailLabel` 的默认长度是 40。它们通过不同名称表达不同展示用途，并且都是公开导出。

**判断**：再加一个内部切片函数只会让两层薄包装代替两行直接实现，没有形成真实复用收益。直接删除其中一个会破坏公开接口；统一默认长度还可能改变调用者看到的文本。保持现状更清楚。

### 删除 `Store` 或绕过 `MemoryStore` 的接口

**位置**：`src/store.ts:1-4`

**证据**：项目规则明确说明 `Store` 是对外导出的扩展接口，第三方可以实现。仓库内虽然只看到类型引用，公开 SDK 契约仍可能有仓库外使用者。

**判断**：不删除、不内联、不改成具体 `MemoryStore`。仓库内没有调用不能单独证明公开入口可删。

### 移除 `listA` 的授权检查

**位置**：`src/a.ts:6`

**证据**：项目规则明确把授权检查列为产品需求。它也控制读取 `Store` 之前是否允许继续。

**判断**：授权检查不是重复代码或防御性噪声。提取键清理规则时仍须保留检查本身及其执行顺序。

## 需要确认的接口疑点

`MemoryStore` 是公开导出的类，但当前实现只有一个只读的 `read` 方法和私有 `values` 映射，没有任何写入或构造时注入数据的方法。因此，在当前源码可表达的用法中，新建的 `MemoryStore` 永远返回 `undefined`。

这可能是刻意提供的只读空实现，也可能表示这个“内存存储”尚未完成。当前仓库没有测试、使用说明或调用方能决定预期语义，所以没有把它列为已确认缺陷，也不建议仅因“看起来无用”直接删除。若它本来就是给 SDK 使用者实际保存数据的实现，应先确认是否缺少写入接口；若只是空的只读占位，应通过文档明确用途，避免使用者误判。
