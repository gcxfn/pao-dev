# 基线复现与排除清单

## 1. 当前环境

截至 2026-10-20 实测：

| 工具 | 实际版本或要求 |
|---|---|
| Node | `v24.18.0` |
| npm | `11.16.0` |
| pnpm | `11.18.0` |
| PAO | Node 要求 `>=22.19.0`，使用 npm workspace；另有 `pnpm-lock.yaml` |
| desktop | 声明 `pnpm@10.25.0`，本机实际 `11.18.0` |

恢复源码时不能假设桌面声明的 pnpm 版本就是本机实际版本。真实包和锁文件版本、哈希见[A 批基线报告](A批基线报告.md#3-包和锁文件身份)。

## 2. 恢复源码

在本目录运行：

```powershell
Set-Location 'D:\AI\workspace\pao-dev\.pao\地图简报与部门协作-20261020'
pwsh -NoProfile -File .\baseline-reconstruct.ps1
```

默认输出是 `reconstructed-sources/{pao-dev,PAO,desktop}`：

- `head/` 是原 HEAD 内容；
- `current/` 是当前 tracked 真实文件字节加纳入的 untracked 源码；
- 解包时核对 ZIP 摘要，再按 manifest 核对每个文件 SHA-256；
- 不覆盖已存在目录；目录内已附加真实路径等值校验。

该 helper 已做解析检查，主审另行实际执行并核对三仓 tracked 与纳入的 untracked 文件真实内容 SHA，全部一致、退出 0。采集脚本内部也已完成临时解包和逐文件 SHA-256 核对。现有三份 reconstruction-check.json 均为 pass。

恢复只表示源码字节已还原，不表示完整修复前 PAO 已启动，也不表示依赖、宿主、供应商或产品行为可用。

## 3. 挂依赖与在隔离 Git 工作目录复现

推荐使用新建的隔离目录和独立 git 元数据；不要在原仓库解包后 `add`、`commit`、`stash` 或 `reset`。

### PAO

PAO 是 npm workspace：

```powershell
Set-Location '<隔离目录>\reconstructed-sources\PAO\current'
npm ci --ignore-scripts
```

若隔离环境要求离线且依赖缓存完整，可先设置 npm 离线参数；是否成功取决于缓存，不能预先保证：

```powershell
npm ci --ignore-scripts --offline
```

本机已安装依赖可复用，但基线和复现不复制 `node_modules`。恢复后如需复现类型检查：

```powershell
Set-Location '<隔离目录>\reconstructed-sources\PAO\current\packages\coding-agent'
..\..\node_modules\.bin\tsc.cmd -p tsconfig.build.json --noEmit
```

实施前真实命令在开发工作区 `PAO/packages/coding-agent` 使用相同参数，退出 0、无输出。隔离重建目录中的依赖和命令需重新运行，不能把主工作区结果倒填为恢复目录结果。

### desktop

desktop 使用 pnpm workspace。优先采用项目声明的 pnpm 版本；本机只有 11.18.0，不能声称与声明完全一致：

```powershell
Set-Location '<隔离目录>\reconstructed-sources\desktop\current'
corepack pnpm --version
corepack pnpm install --frozen-lockfile --offline
```

若 Corepack 或缓存不可用，显式记录失败；不要静默换锁文件版本后宣称一致。依赖恢复后可使用项目现有 `typecheck`、测试或 Electron 入口，但这些都属于后续层级，不在本次源码基线执行范围。

### 恢复当前 tracked 差异身份

若需要新 Git 身份用于差异核对，建议：

1. 从原仓库只读方式导出 HEAD 到隔离目录。
2. 把 `current/` 的源码字节放到同一隔离目录，保留任务开始时的 tracked 修改和纳入的 untracked 文件。
3. `git init` 后只在新目录提交“基线恢复”身份，或按原提交对象建立只读引用。
4. 用 `git status` 与对应 `status-before.txt` 对照；原状态里有大量历史运行产物，不能期待目录内容完全一致。

如要在新仓库引用原 HEAD，先从本机源仓库获取该提交再 `git update-ref`；不要把当前工作区 `git add --all` 后的新提交冒充原 HEAD。更直接的方式是对原仓库执行 `git archive <HEAD>` 导出 HEAD，再把 `current/` 覆盖到新目录。

## 4. 隔离 `PAO_HOME` 与离线运行

实验时新建独立临时目录，不指向正式 `PAO_HOME`：

```powershell
$env:PAO_HOME = '<本轮新建的隔离 PAO_HOME>'
$env:PI_OFFLINE = '1'
$env:PI_NO_LOCAL_LLM = '1'
```

这些开关用于避免真实认证、供应商请求和本机模型调用，但不能证明所有宿主都严格离线。启动前检查实际日志和网络边界；没有授权的供应商配置不填写，真实供应商实验也暂不执行。正式凭证没有复制，待实验授权后另行固定隔离配置。

## 5. 推荐复现顺序

1. 核对三仓 HEAD、ZIP/文件 SHA-256 和 `reconstruction-check.json`。
2. 解包 `head/`，再解包并覆盖 `current/`，核对 manifest。
3. 在隔离 Git 工作目录查看真实 tracked 差异和纳入的 untracked 文件。
4. 按锁文件恢复依赖，记录实际 Node/npm/pnpm 和失败。
5. 用隔离 `PAO_HOME` 与离线开关做允许的工程检查。
6. 另行取得授权后再连接真实供应商、验证 Electron/进程链路和做 V01–V18 验收。

## 6. 排除清单

| 排除项 | 原因与边界 |
|---|---|
| `.git/` | 不复制 Git 元数据；HEAD 与补丁用于定位，隔离目录另建 Git。 |
| `node_modules/`、`.pnpm-store/`、其他依赖缓存 | 体积大且可由锁文件/依赖缓存恢复，不是源码基线；本次不复制。 |
| `dist/`、`build/`、`out/`、release/发行物 | 可由源码和工程命令重建，不属于本次源码基线。 |
| `.pao/`、`.pao/archive/`、`archive/`、旧运行留档 | 运行证据不是源码基线；保留原处供人工对照，本轮没有复制。 |
| `临时文件夹/`、`.dsh-acl-recovery/` | 一次性过程数据和恢复辅助文件，没有复制。 |
| 日志、缓存、系统临时文件 | 不用于恢复源码；保留排除路径清单供审计。 |
| `.env`、密钥、令牌和其他凭证 | 明确禁止读取或复制正式凭证；依赖环境变量或隔离配置。 |

`pao-dev` 的 untracked 排除汇总包含 3271 个旧 `.pao` 条目、3504 个 `临时文件夹` 条目和 3 个 `.dsh-acl-recovery` 条目；PAO 排除 18 个 `.pao` 条目；desktop 排除 27 个 `.pao`、5 个 `临时文件夹` 和 32 个 `archive` 条目。具体路径在各仓 `untracked-excluded.json`。

排除这些运行留档和产物不会漏掉源码恢复所涉及的文件；若以后要恢复某次运行状态，应另建运行证据快照，不能把它冒充源码基线。
