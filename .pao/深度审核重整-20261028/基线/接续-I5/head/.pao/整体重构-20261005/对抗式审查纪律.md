# 对抗式审查纪律（v1）

> 本项目 R1—R22 审查波沉淀的方法论正本。剩余审查波（R23 起）派单时令审查子代理先 Read 本文件。
> 项目收尾（T10）时评估升级为 `~/.agents/skills/adversarial-review/` 全局 skill。
> 对照方法论：mattpocock/skills 的 code-review（双轴并行结构同构，本纪律多了证据链证伪与闭环修复复审）；其 tdd skill 的「接缝测试」纪律归实施侧派单引用，不在本文件。

## 1. 定位

- 审查对象是**实施者的声称**，不是代码风格：找「说了但没做」「做了但说法不准」「证据撑不住」。
- 审查子代理与实施子代理必须分离；审查者只读＋自跑验证，不修复、零 git 写。
- 「通过」的定义是**证伪尝试全部失败**，不是背书成立。

## 2. 输入契约（派单必须给齐，缺一退单）

1. 增量边界：仓、HEAD、文件清单、对照基线（开工快照或上一检查点）。
2. 原子声称清单：把实施留档拆成可单独证伪的条目并编号。
3. 计划验收段原文（Spec 正本）。
4. 验证门日志位置（须含命令行原文＋退出码）。
5. 已知存量与豁免清单（开工基线失败、环境敏感族、历史注记）——既防把存量当新犯罪，也防把新失败藏进存量。

## 3. 核验分层（全量与抽样的边界）

- **可枚举类必须全量**：成果保护（git status 逐项对照快照）、文件清单一致性、持久化/跨仓键面审计、门日志逐条核对、安全红线清单。
- **机械网先行**：tsc／测试门／AST 工具／键面 compare 脚本先跑全量，人只深读机器判不了的语义面。
- **判断类可抽样**，报告须写明抽样依据与数量；以下三类**禁止抽样**：安全红线、持久化面、跨仓消费面。
- **机械网盲区清单（必须手工追）**：消费方本地类型声明＋`unknown as` 桥接处；跨仓键消费读取（工具只扫声明不扫消费——R22 抓到的 desktop.ts 键漂移即此类）；动态拼接键；测试断言与实现的同源耦合。

## 4. 证伪动作

- **自跑复现**关键门，命令＋退出码记入报告；跑后清理自产残留（不留 pnpm 桩、临时目录）。
- **调用链从消费端反查**，不是只从实现端正查。
- 找「**应该坏而没坏**」：声称某改动无影响时，定位它必然影响的消费方去验证。
- **日志真实性交叉核**：退出码、时间戳、文件存在性、与相邻记录的因果一致性（例：声称 tsc=0 的时点恰有审批门拦截）。

## 5. 报告纪律

- 结构：结论（通过／退回／通过有保留）→ 逐项核验（声称编号 × 证据）→ P1/P2/P3 分级 → 自跑命令与退出码 → **未证实项单列**。
- 分级口径：P1＝声称失实且影响验收；P2＝证据缺口或记录失准；P3＝备案。
- **未证实项是诚实的一部分**：宁报「无法核实」，不编证据；叙述性数字与日志实录分开标注。
- 只报事实与分级，不替主控做裁定。

## 6. 对实施留档的核查点（审查者负责核查的记录纪律）

- 中间失败轮也须留日志（教训：伪败轮与首轮败无日志＝声称不可复核，R21-P2）。
- 偏离与过程失误如实列出，当场修复的也要留痕。
- 历史订正用「原文不动＋追加注记」，禁止改写既有记录。

## 7. 闭环

- 退回 → 修复子代理 → **复审子代理**（只验修复增量；主控抽查不闭环）。
- 主控职责：分级裁定、需求性审查（对照计划验收段逐条）、定稿落档。
- 双轴并行：对抗（Spec 忠实度）＋过度设计（Standards）互不稀释、不跨轴排名。
