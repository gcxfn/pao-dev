## 构建来源与 vendor

### 已落实的保护

`vendor-pao-kernel.mjs` 先复用仓内 `clean` 和 `build:offline` 的真实成功结果，再物化。它不再用 mtime 推断构建完整，也不再模拟构建成功回调。

| 保护 | 真实问题 | 实现 | 必要增量 |
|---|---|---|---|
| 构建输入冻结 | 源码可能在构建中变化，导致新源码摘要配旧 dist | 执行前后计算同一输入集合的 SHA-256 和路径，不一致即拒绝 | 根 `package.json`、lockfile、根 tsconfig、根 scripts、全部 workspace 的 manifest/tsconfig/src/scripts，以及本次实际运行时闭包 |
| 根命令清单 | `clean/build:offline` 由根 `package.json` 决定 | 明确纳入 before/after；测试在构建中改写根 `package.json` 时失败 | 修复“测试命令定义在快照外”的真实缺口 |
| 传递运行时来源 | 只冻结 sibling 的直接源码，transitive runtime 变化无反应 | `collectRuntimePackages` 从内核依赖递归收集，再复用同一集合做冻结和复制 | 避免维护第二套依赖发现规则；桌面已能解析的非 sibling 包沿原规则跳过 |
| 清理与完整构建 | 合并复制、部分构建或已删除源留下旧 dist | 对明确内核目标执行现有 `clean`、`build:offline`，再检查 `package.json` 声明的 `main`、`types`、`bin`、`exports.import/types` | 复用正式构建产物清单，不复制 tsconfig/copy-assets 生成规则 |
| 暂存与替换 | 一对一发布会使内核和 runtime 混合代际 | 两套产物先完整物化；旧目录成对备份，新目录成对安装 | 发布失败时同时撤销新物并恢复旧物 |
| 错误保留 | 主错可能被回滚/清理错误覆盖 | `AggregateError` 保留主错、撤销错、恢复错和清理错 | 可定位主因和后续清理问题 |
| 直接 node 入口 | 本机 npm 绝对路径破坏跨平台 | 优先使用真实 `npm_execpath` 的 JS 文件；否则使用平台通用 `npm`/`npm.cmd` | 不把 `C:/Program Files/...` 写进长期代码；Windows `.cmd` 只在直接 node 回退时使用 shell |

运行时递归集合遵循原补扫语义：`@earendil-works/*` sibling 缺失时失败；非 sibling 若桌面仓已经解析则沿用桌面依赖，否则只复制 PAO 仓存在的包。它没有实现第二套 npm/pnpm 版本解析器。构建与发布只使用当前明确内核目标；暂存目录在桌面仓后删除，不删除用户文件。

发布清单记录构建命令、输入内容摘要、运行时名称、来源路径、来源类型、manifest 摘要和最终文件摘要。正式发布前仍可人工核对输入和输出。

### 仍需主控判断的复杂度

- 递归运行时闭包和“桌面已解析则跳过”的规则沿用原脚本的实际物化行为，未另行验证所有 pnpm 嵌套版本边界。测试中的模拟包只证明 PAO 根下可解析集合，不算真实打包依赖树集成。
- 当前 `npm_execpath` 若存在但不是可执行 JS 文件，会退回系统 npm。这个回退保持直接 `node` 入口可运行，尚未在 Linux/macOS 实机执行。
- 输入冻结覆盖实际 checked-in workspace 与运行时闭包。真实安装树里未被该集合引用的额外包不会自动成为构建输入；这符合当前产物范围，但最终打包依赖仍需由已有 packaged-runtime 检查证明。

## prepare 唯一装配

`prepare_run.py` 先在内存中建立目标到唯一来源的装配表，再复制。

| 保护 | 实现 |
|---|---|
| 唯一目标 | 重复目标在写入前拒绝，不再先写后覆盖 |
| 显式来源 | 根 organized、SDK host、benchmark 源分别记录 `source_kind` |
| 激活器 | 先验证根 manifest 摘要，最终装配只采用 SDK `activate-tools.mjs` 一份来源 |
| 派生 kit | 记录模板 SHA、模型、思考强度、档位、变换参数、最终实际 SHA |
| 最终摘要 | 复制后重新计算，和装配表不一致即失败 |
| 离线来源 | Node、系统依赖、模型数据和元数据无可靠上游身份时保留 `origin=unknown`，同时记录声明摘要和最终副本摘要 |
| W7 接口 | 保留现有 `adapters` 投影和配置键，不改变配置契约 |
| 错误保留 | 准备失败后清理暂存目录；清理也失败时用 `BaseExceptionGroup` 保留“准备主错、清理错”，不覆盖首错 |

离线来源的 `declared_sha256` 只表示输入声明值，不能冒充上游发布身份。当前测试使用现场声明值和实际副本，来源不明没有改成成功验证。

清理边界只新增一个 `_cleanup_failed_prepare` helper。它只处理 `prepare()` 失败后的暂存目录，不扩大准备流程或构建框架。定向测试从正式 `prepare()` 入口触发复制失败，再模拟 `rmtree` 抛出 `PermissionError`，断言异常组顺序、`__cause__` 和暂存目录仍在；这是实际错误入口加模拟删除失败，不是 Windows 只读文件实机复现。
