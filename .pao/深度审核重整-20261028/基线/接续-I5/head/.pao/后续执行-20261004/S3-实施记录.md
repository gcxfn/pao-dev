# S3 实施记录

截至 2026-10-04。状态：核心实现、总入口／SDK 接线与离线定向检查完成，独立审查复核中，真实验收未完成。未执行共享 gbrain 写入、删除或模型调用，未提交。

## 已实施

- 动态召回从系统段迁到追加 custom message；静态常驻索引保留系统段，错误提示同样走消息层。
- 原有“自动交接”不再把任务压缩摘要写共享事实库。
- `memory/session.ts` 保存本次自动召回内容、来源、准确 ID、注入时间、供应商与作用范围；供应商不提供的记忆时间、置信度显示未知。
- `/pao memory` 查看；`exclude 编号` 仅本会话排除，后续请求明确纠正旧事实，已发送历史不能撤回；`correct 编号 新内容`、`forget 编号` 显示原文／新文／共享影响后确认。无 ID、不支持忘却、取消确认和确认期间切会话均不执行共享修改。
- gbrain 写入返回准确 ID 回执；两步纠正保留新条目 ID，忘旧失败显示部分成功；同 ID 返回或无新 ID 不执行忘旧。
- `memory/compaction-state.ts` 在压缩前保留用户原文、工具错误、显式待办／阻塞行和最近助手答复，压缩成功后作为会话自定义条目保存并恢复到请求；不复制隐藏推理，不写共享库。为避免误判任意表达的用户约束，不截用户原文；因此该方案的压缩收益可能有限，须由 S4 对照如实测量。
- `context/index.ts` 提供 `/pao context arm` 按需捕获下一次请求，查看与清除不调用模型。只保留单次视图；区分待发与收到供应商响应的已发送请求；系统、技能、工具等以实际装配对象展示，不列猜测文件清单。凭证与隐藏推理在保存前去除。

## 正式接线（已实施）

1. 总入口全角色注册 `registerTaskCompactionState(pi)`；主控／部长注册 `registerContextInspection(pi)` 与 S1 预检；worker 保持不注册用户子命令。
2. core/sdk 每个实际 stream 调用绑定会话 ID；全部请求变换后调用 `recordFinalProviderPayload(sessionId, payload)` 返回唯一请求标识；收到响应时调用 `recordProviderResponse(sessionId, requestId, status)`。前者仅证明最终待发装配，不证明发送成功。
3. 桌面仍需通过 `getContextCapture(sessionId)` 复用视图；本子任务未改桌面。

- 动态消息追加、部分成功、缺 ID、无忘却、写新失败、同 ID、取消确认、会话切换、原文快照、隐私脱敏、按需捕获和请求状态均有定向覆盖。

## 独审候选修复

- 自动召回外发许可改用 ctx.cwd，避免桌面宿主 cwd 误判项目。
- 自动召回异步返回核会话代次／取消状态；纠正与忘却异步完成不污染新会话。写新后会话变化则停止忘旧，原项目的 `.pao/记忆操作/` 保存绑定原会话 ID 的迟到结果证据。
- 原生树切换后重载当前分支的记忆与任务快照，不沿用离开分支。
- 首次最终 payload 即关闭捕获；无响应失败不会被下一请求覆盖，晚响应须匹配请求 UUID，不能标记新捕获。
- 全局命令路由会话隔离由 S1 代理修复，保留其改动。
- 召回排除键包含供应商；共享纠正／忘却前验证原命中供应商与当前供应商一致，不把旧 ID 发送给新库。
- 首跑面板 `pao-firstrun` 保留可见历史，在普通请求、压缩摘要、分支摘要三条输入路径过滤，避免把现场其他部门清单发给模型。相关 firstrun/session/resident 三文件 44 项通过；随后 resident 增补 cwd／迟到召回两例，单文件 25 项通过。
