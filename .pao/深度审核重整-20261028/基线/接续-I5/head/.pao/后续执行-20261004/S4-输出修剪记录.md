## 实现

源码：`PAO/packages/coding-agent/src/pao/output-pruning/index.ts`；测试：`test/pao/output-pruning.test.ts`。

复用现有 `context` 扩展事件和会话原文存储，不增加后台进程、第三方依赖或另存输出库。已有 `truncate.ts` 是字节/行数截断，不直接代替语义安全判定。本实现不再叠加该截断，以免删掉错误诊断。代码图工具未暴露，调用关系通过源码追踪。

- 同路径、同读取范围、同文本版本的再次成功读取，才将本轮之前重复输出替换成标记。标记包含版本 SHA256、后续 toolCallId、会话原文位置与原 toolCallId；新读全文保留。不同版本和不同范围不互相替代，失败读取不覆盖有效版本。
- 有用户比较、差异或诊断要求时，保留全部读输出；旧用户轮次前缀保持原样，减少缓存前缀扰动。只处理单文本块，不处理图片。
- 已知命令规则表目前是 `git log` 和 `npm ls` 的单一命令形式，只合并多余空白行，保留全部非空行与退出码、原文定位。未知命令、连接/管道命令、失败、空输出、超时均保留。未做可能删除依赖树/历史细节的语义缩写。
- 不删除任何工具调用或返回消息，不改变持久化历史。没有持久化会话位置时不修剪，避免无法定位完整原文。无全局内容状态，分支和会话不共享旧输出。

注册入口：`registerOutputPruning(pi, { enabled })`。不传 enabled 即关闭；由主代理总入口接线及可信配置控制。无需更改 core 或 SDK。
