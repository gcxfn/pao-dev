# 开工接口与记录模板

编制：2026-10-02。本文提供实施前需要冻结的接口意图与填写模板，**不是现成 API 或已生效的架构正本**。采纳后将规则并回架构；这里只维护执行模板，避免双份现行规则。

## 1. 责任与写入表

| 对象 | 正本/位置 | 写入责任 | 其他角色允许做什么 |
|---|---|---|---|
| 卡片 frontmatter、状态、规范回执 | 目标项目 `.pao/` 卡文件 | 卡 owner，经统一扩展写入入口 | worker 提交带卡号/尝试号的结果，不直接改终态 |
| 任务附件和项目代码 | 产物目录/项目本体 | 执行 worker；代码修改受项目单写调度 | owner/审查读证据；别的写任务不得并发改同一项目 |
| 黑板索引 | 工作区 `黑板.md` | 工作区 owner | M2 worker 写各自便签，由 owner 挂索引 |
| 待验证候选 | 部门 `待验证/` | 部长；直通卡由主控扩展按特例投递 | worker 在回执提候选，不直接转正 |
| 正式知识 | 部门四类型区 | 部长审核后走入库工具 | worker 只读；巡库不能改正文 |
| 向量缓存、搜索候选、机械状态 | 工具管理的派生文件 | 程序 | 不注入上下文，不作为事实正本 |
| 注册表 | `部门/注册表.md` | 建部工具 | 主控/部长加载快照，路由查最新版 |
| 会话 todo | pi 会话 | todo 插件 | 不驱动卡状态或跨会话恢复 |
| 桌面看板 | 内存视图 | 从卡片读取；操作经 owner | 不私自维护另一份任务数据库 |

上表按 R03/R06 的新增建议编制，未同步正式基线前不能据此越过原规则。

## 2. 五状态迁移的最小解释

| 起点 | 触发与检查 | 结果 |
|---|---|---|
| 待认领 | 前置全部已交付、额度可用、owner 明确、写入权限/互斥通过，实际启动尝试 | 进行中，登记本次尝试 |
| 进行中 | worker 交当前尝试回执，但未验收 | 仍进行中，派生显示“待审” |
| 进行中 | 当前尝试验收通过、证据可定位 | 已交付，写完成时间 |
| 进行中 | 执行失败、超限或明确缺输入，记录类型与现场 | 失败，等派卡方按规则处理 |
| 失败 | 同轮仍有尝试、问题已补、重试安全并获得所需授权 | 待认领；下次实际启动才递增尝试 |
| 待认领/进行中/失败 | 用户/owner 合法取消；进行中先停止执行 | 取消，保留既有证据与改动 |
| 已交付/取消 | 迟到回执或重复通知 | 不再变状态，只留可审计记录 |

重新进入活状态时清除当前完成时间，原终态及时间留在历史回执；验收看当前尝试，不能用旧完成时间代表新工作。

尝试从真实启动计，单纯编辑缺输入卡不算一次执行；API 内部重试另记请求计数。增加授权轮次或提高上限不能由 worker 自己做。旧 owner 恢复、双窗口、重复提交应被写入层识别；不靠文件名相同就覆盖。

卡片需能区分协议版本、授权轮次、风险、写入范围和审核责任；是否新增字段、如何编码，在 M1-01 按现有卡格式冻结，**不在这里偷偷改字段名**。项目 ID 可从目标项目上下文确定，跨项目卡号必须携带项目定位，不能把两个项目的“卡0001”混为一张。

## 3. 最小接口意图

| 接口意图 | 必要输入/绑定上下文 | 返回/副作用 | 不应该做 |
|---|---|---|---|
| 建卡/派发 | 目标、部门标签、指针、验收、档位、预算；宿主绑定项目/授权 | 稳定卡路径、尝试/队列结果 | 模型自己写任意目录或规避预算 |
| 提交结果 | 卡号、尝试号、结果、产物指针、证据、原始用量指针、候选 | 幂等接收/重复/过期判定 | 把进程 exit 0 自动等同已交付 |
| 验收与结卡 | 卡片验收、可信测试结果、审查决定 | owner 写规范回执与终态 | 只凭 worker 的“已完成” |
| 查库 | query/top_k，可信上下文绑定部门/项目/版本/外发 | 正式命中、风险提示、degraded、来源 | 未授权跨部/跨项目；把相似分当真值 |
| 受限补查 | 同上，加卡/授权轮次的次数限制 | 一次有限结果、检索记录 | 重启 worker 即刷新额度 |
| 候选入池/晋升 | 来源卡/尝试、内容指针、审核决定 | 去重候选或正式条目、可修复索引 | 无证据自动晋升、全库改权限 |
| 队列读取 | 项目清单/工作区范围 | 卡片派生视图、积压、异常 | 展开所有日志塞进主控 |
| 取消/停机 | 被取消任务、宿主拥有的进程记录 | 阻止新活、停止、落证据、释放互斥 | 杀全系统同名进程、清除不属于本轮的工作 |

这是接口验收要求，不要求建立一个独立服务。优先同一扩展内的函数和文件操作，避免重新造控制协议。

## 7. 摩擦与对照记录模板

摩擦建议一行含：日期、任务类型、症状、证据指针、影响（正确性/时间/费用/介入）、临时绕过、是否重复、关联改进与回归测试。没有摩擦时不为填表制造问题。

对照建议一行含：任务 ID、A/B/C 组、代码/库快照、冷热、模型/工具配置、合格否、墙钟耗时、规范化 token、已知/估算/未知费用、人工介入、返工/缺陷、证据。原始用量在证据文件里，不把长 JSON 塞满表格。
