# 实施任务拆分

日期：2026-10-30。按用户要求，将六路实施分解为可单独审核的小任务。架构与分路边界仍以[目标方案](目标架构与实施分路.md)为准，进度只记[执行总册 §10.22](../../plans/未完成/2026-10-17-Harness完善与工作台迭代执行计划.md#1022-2026-10-28-整体深度审核与架构重整)。下列是任务与验收要求，不是完成声明。

## 派发与交付办法

- 后续子代理统一使用 `group/deepseek`，`high`；一个执行回合只承接一个小任务。
- 每次派发给出当前准确路径、允许写入文件、依赖接口和明确反例；未分配文件由主控处理，不能自行扩散修改。
- 保留此前未提交成果。任务收口时已写但尚未验证的改动逐项列明，不为了缩小本次任务回滚他人成果。
- 验收用隔离 `PAO_HOME`、`PI_OFFLINE=1`、`PI_NO_LOCAL_LLM=1`。不访问正式现场、不调用真实模型、不操作真实 Docker 容器或网络、不提交或推送。
- 每项交付说明：触发的问题、具体文件和修改、每条验收对应的测试名、实际命令/退出码/日志、仍未完成的内容。主控审查差异与证据后，再给同路下一任务。
- 新增测试必须验证行为；模拟协议明确标注，不能算真实模型、真实 Docker 或完整产品链已通过。

路径缩写：K=`PAO/packages/coding-agent`，D=`desktop/apps/desktop`。跨路接线、公共导出、package 脚本和现有共享测试由主控独占。

## I0：修复验证前提

### I0-1 两处测试接口失配

可写 K/test/pao/ 的 `verifier-attempt-baseline.test.ts`、`workflow-host-bridge.test.ts`。按真实 `DispatchClaimInput` 补时间输入，按真实 read 工具五参签名调用；禁止用 `any` 或删断言掩盖问题。分别运行两文件及根 `tsc --noEmit`，把行为失败与类型失败分开交付。

### I0-2 关闭事件测试夹具

先交付一个与真实 `session_shutdown` 同形的辅助函数，再修改最多三个代表测试文件。覆盖所有处理器成功才执行确认后清理、某个处理器失败不得清理、错误向上暴露三种情况。主控确认后，下一回合只迁移列明的同类调用，不夹带产品关闭逻辑更改。运行每个受影响文件，不以通过两个示例代替全部验证。

### I0-3 隔离配置与运行时装配失败

让档位测试自行生成最小夹具，不从正式 `PAO_HOME` 复制。对四部门导入和 CLI 解析错误，先在当前环境单独复现；根据实际缺项使用仓库既有构建/依赖入口修复，链接已存在时不能仍宣称缺包或盲目重装。四部门文件必须实际收集并执行用例，0 test 不通过。

## I1：运行策略与完成路径

### I1-1 可信运行方式冻结

可写 workflow 的 `policy.ts`、`control.ts`、`driver.ts`、`tools.ts` 启动部分及独立策略测试。`DriverOptions.runMode` 来自可信调用方；工具注册用 `resolveRunMode` 接收主控装配。模型单独填写 `params.run_mode=unattended` 不能提权。新实例冻结方式，旧实例缺字段仍有人值守，推流不能切换已存方式。

验收：可信无人值守正常启动；未授权请求、非法值、参数冲突被启动前拒绝；旧实例读取不变；无人值守配方含人工确认门时拒绝。通过真实启动/工具入口验证，不能只测解析函数。

### I1-2 合并待决与普通裁定出口

仅处理 r37 对应的普通偏差、部长 hold 和普通裁定，不一次改完全部状态机。为实例、节点、轮次、卡和尝试建立同一待决身份及截止；重复请求幂等，旧尝试与迟到请求拒绝。新无人值守普通裁定交主控；明确人工确认和新权限请求保留人工含义。验收重复请求不叠加暂停、过期给明确失败、旧有人值守通道不变。

### I1-3 一次裁决办理确定手续

工具只让主控提供逐项处理依据，程序绑定待决身份、当前条件和尝试，不要求模型重抄。先验证全部条目：缺项、重复、旧 attempt、必需机械失败或未知现场不得生效。随后复用现有验收、交付、Git 交卷、续跑，记录阶段；任一步失败必须可定位，重放不得重复提交。以真实临时 Git 验证，不宣称多文件操作可以整体回滚。

### I1-4 其余停点与审核字段

按 S1—S21 逐项登记处理器和行为用例，包括额度、缺输入、地图、在途卡、拒绝、回边超限、返修中断、宿主关闭、旧 owner。保留未停占位与人工恢复。审核参数与控制层共用同一理由/引用约束，字段错误明确，不截断理由、不删除有效性检查。全部用例通过后才运行工作流相关完整回归。

## I2：共享工作树宿主

### I2-1 默认工厂与跨实例创建解析

可写 `worktrees/local-host/` 与一个独立创建测试。默认工厂仅接 `stateRoot` 和可选项目范围，不要求 CLI 另实现桌面目录接口，构造时不写磁盘。用真实 Git 的 tracked dirty 和相关 untracked 输入建立完整可恢复基线；另一工厂在相同目录解析同一 managed ID；同 request 重放幂等，不同 request 并发不覆盖；损坏状态和用户工作树不可接管。

### I2-2 桌面存储适配与子进程共享

只调整桌面 `platform/worktrees/` 的宿主适配，主控负责 SDK 动态载入与导出。桌面父实例创建后，默认子进程工厂能在同一 `userDataDir` 解析，不能各有一份互不认识的 catalog。保持 `catalogs.json` 和旧状态兼容；CJS Electron 主进程不能静态 require ESM 内核。真实父子装配通过后再跑桌面宿主既有测试。

### I2-3 清理与停止保护

覆盖清理和同根派发互斥、活动执行拒绝、停止未确认保留、分支/成果未保留拒绝、身份不符和用户工作树不删除。只清理本轮测试创建的目录。锁仅在等价证据充分时收拢；不为结束流程删除 StopProof 或释放未知占位。

## I3：工人结果与程序事实

### I3-1 窄结果工具到真实 runner

可写 worker 的 `result-tool.ts`、`receipt.ts`、`runner.ts`、`dispatch-core.ts` 和独立通道测试。非法摘要、缺 failure_type、非法产物当场返回字段错误。只能提交本次自述，无 card/attempt/owner/state 控制参数；runner 只接受成功 `tool_execution_end` 对应的本次调用，失败/拒绝/冲突不算交回执。成功后最后普通文本可接受，旧 JSON 仍兼容。

产物路径按该尝试执行绑定解析，绑定损坏不可回退主目录；实际身份、证据、退出码和用量由宿主补。用真实 Node 子进程模拟事件验证正常与错误路径，明确这不是模型测试。主控接 worker 注册和角色测试。

### I3-2 程序事实与提示减负

先列哪些字段确由程序采集、哪些仍是模型声明。实际改动和执行命令复用已有 Git/工具事件，不能让声明冒充事实。正常提示优先窄工具，历史文本说明只保留兼容所需部分。测量相同请求的实际声明与固定手续，不以文件变短声称 token 下降。基准激活器必须保留 worker 结果工具和侦察工具。

## I4：正式基准工具

### I4-1 源码迁移与新旧离线入口

可写 `bench/`（除 rehearsal）和旧 benchmark 顶层薄转发。`python -m bench --help` 与各子命令帮助可运行；最小运行证据能生成报告，缺分保持未知。旧入口和新入口指向同一实现，mock.patch 能改变真正调用；独立冻结目录可导入，不依赖开发仓路径。不得修改旧 real-run 冻结件。

### I4-2 观察与业务停止分离

只改观察异常处理及对应测试。普通 docker 查询失败、时间字段或进度发布错误记观察失败，不取消真实作业；身份变化、冻结损坏仍停止相关写入。测试必须能证明 cancel 在普通观察错误时未调用，完整性错误时仍调用，并保留首错与停止未确认。组织未完成不能退出 0 冒充成功。

### I4-3 自动选网与可重复清理

网络选择用标准库比较全部 Docker 子网和宿主路由，读失败报错而非假设空网络。模拟覆盖重叠、池耗尽和无冲突。清理默认预览，真实执行绑定精确 run 身份、资源归属和停止确认，仅处理本 run 容器/空网络，可重复执行。此任务只执行模拟测试，不实际运行 Docker 变更。

### I4-4 同产品入口与彩排命令

I2 和 I5 接口通过后，将新准备/适配器改为产品入口，移除活跃宿主副本的构建依赖。`run --rehearsal` 复用 I5 服务，真实运行、评分及清理保持明确授权。新冻结安装在独立目录完成实际导入与三角色装配，不能只在开发源码树通过。最后才订正 README 的正式命令。

## I5：离线彩排

### I5-1 回环 HTTP 脚本模型

只写 `bench/rehearsal/` 的服务和对应独立测试。监听 127.0.0.1 的随机端口，先支持产品当前使用的一种供应商协议。工具调用、文本、流终止和故障注入通过真实 HTTP；未匹配脚本、未知工具、乱序明确报错。用产品 pi-ai 客户端实际请求服务，不仅 fetch 自测。关闭释放端口，用量明确标记固定模拟，不读凭证。

### I5-2 同配方最小正常链

使用冻结 kit、可信无人值守启动设置、产品默认宿主、真实 Git 和真实主控/部长/工人进程。先只实现正常链，断言侦察→规划→两张实施卡→验收交卷→独立审核提交当前成果判定→控制正本 completed，且停止证据收齐。限 10 分钟；打印成功或审核启动都不够。记录每个检查点的真实证据入口。

### I5-3 旧实现失败与对应新实现通过

从已固定的 I5 源码快照建立可运行副本。先只做 r37 普通偏差加人工裁定门这一组，旧路径确实停住，新路径经逐项裁决完成；保存相同输入、命令和结果。没有旧路径可运行证据时标未验，不能用历史日志补成先红后绿。

### I5-4 历史矩阵与 G2 测量

再按 O-01—O-18 分批加故障，每回合只交付一个相关故障组。最后用同一计数组件分别计跨角色、跨进程和去重交接，状态文件种类与模型固定手续；不可复现的真实系统崩溃说明原因。全部矩阵及 G2 同口径数据齐全后，主控才执行 P4 总验收。

## 主控收尾

主控负责角色装载、可信运行策略、子进程环境、公共导出和 SDK/CJS 接线，审查上述每个小任务的真实差异。文档只保留正本和指针；历史不删除，未验证的产品改动不记完成。P4 必须各层通过、相对基线无新增失败；P5 真实模型与 Docker 运行另请用户授权。
