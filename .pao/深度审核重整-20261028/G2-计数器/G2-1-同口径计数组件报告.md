# G2-1 同口径计数组件报告

## 结论

G2-1 的独立计数组件已经完成并由定向测试验证。它只消费显式规范化、能回链原始证据的运行事件和文件清单；交接、模型固定手续及可变状态文件种类分别统计。覆盖不完整、身份缺失或记录冲突时返回 `unknown`，不会把缺证写成 `0`。

当前只完成计数组件，不代表 G2 前后效果已经测得。现有历史彩排样本缺少收发两端角色、PID 和逐事件原始证据映射，不能据此给出精确旧基线或目标收益。

## 冻结口径

口径来自 [目标架构与实施分路 §7.1](../目标架构与实施分路.md) 与 [G2-baseline.json](../基线/接续-I5/G2-baseline.json)：

- 跨角色是发送角色与接收角色不同；跨进程是发送 PID 与接收 PID 不同。
- 同角色跨进程计入跨进程；两个维度的去重总量取业务事件并集。
- 优先用 `eventId`，其次 `traceId`；都没有时使用发送/接收身份、操作、调用和业务对象组成的复合键。
- 工具名只作操作元数据，不能作为唯一去重键。
- 重试和地图召回单独列出，仍属于其发生时真实存在的业务交接。
- 模型 HTTP 请求、纯日志和遥测不进入业务交接。
- 模型固定手续按“启流、抄身份、验收、交付、交卷、推流”六类统计。
- 文件清单显式分为 `state`、`input`、`raw_evidence`、`derived`；只有 `state` 计入可变状态文件种类。
- 组件不按 `schemaVersion` 选择算法；新旧同格式输入走同一函数。

## 实现接口

入口位于 [measure-structure.mjs](../../../bench/rehearsal/measure-structure.mjs:381)：

```js
measureStructure({
  handoffs: [{
    kind: "tool_handoff" | "rpc_handoff" | "model_http" | "telemetry" | "log",
    eventId,
    traceId,
    sender: { role, pid },
    receiver: { role, pid },
    operation: { kind: "tool" | "rpc", name },
    businessObject: { type, id },
    callId,
    retry,
    retryOf,
    retryCount,
    mapRecall,
    evidence: { path, line }
  }],
  modelFixedSteps: [{
    eventId,
    traceId,
    callId,
    category: "启流" | "抄身份" | "验收" | "交付" | "交卷" | "推流",
    evidence: { path, line }
  }],
  files: [{
    path,
    category: "state" | "input" | "raw_evidence" | "derived",
    kind,
    producer: { role, pid },
    evidence: { path, line }
  }],
  coverage: {
    handoffs: { complete, evidence: { path, line } },
    modelFixedSteps: { complete, evidence: { path, line } },
    files: { complete, evidence: { path, line } }
  }
})
```

也可以运行：

```text
node bench/rehearsal/measure-structure.mjs <规范化输入.json>
```

输出包含 `boundaries.crossRole`、`boundaries.crossProcess`、`boundaries.deduplicatedTotal`、`retries`、`mapRecalls`、`modelFixedSteps`、`fileKinds`、`rawEvidence` 和 `issues`。每个指标有 `status`；非 `unknown` 时 `value` 是数字，并保留参与事件的 `eventKeys` 或文件清单项。`unknown` 的 `value` 固定为 `null`，`missing` 和 `issues` 给出具体缺失字段或冲突。

## 测试对应

| 验收点 | 测试名 |
|---|---|
| 同角色跨进程、跨角色同进程分别计数，总量取并集 | `模拟：同角色跨进程与跨角色同进程分别计数，去重总量取并集` |
| 同一事件同时跨两边只计一次，重复记录不重复计数 | `模拟：同一业务事件同时跨角色和跨进程只计一次，重复记录不按工具名重复计数` |
| 同工具不同业务身份不能合并 | `模拟：同工具不同业务对象保留为不同交接` |
| 重试、地图召回单列且仍计入交接 | `模拟：重试和地图召回单列，同时仍计入业务交接` |
| 重复事件冲突可见，不采用最后一条覆盖 | `模拟：重复事件冲突可见并令边界计数为 unknown，不采用最后一条覆盖` |
| 缺真实角色/PID 或原始证据时不能猜 | `模拟：缺真实 actor 身份时跨角色和跨进程均为 unknown` |
| 模型 HTTP 与遥测不冒充业务交接 | `模拟：模型 HTTP 与纯遥测不进入业务交接` |
| 模型固定手续六类计数与去重 | `模拟：模型固定手续按六类计数并去重` |
| 状态、输入、原始证据、派生视图分列，状态种类去重 | `模拟：文件清单分列状态、不可变输入、原始证据和派生视图，状态种类去重` |
| 文件类别或种类缺失时返回 `unknown` | `模拟：文件类别或种类缺失时状态计数为 unknown` |
| 覆盖证据缺失时所有空集合仍为 `unknown` | `模拟：覆盖证据缺失时所有指标为 unknown，空集合也不默认成 0` |
| 新旧同格式输入走同一算法 | `模拟：新旧 schemaVersion 的同格式输入走同一算法` |
| 命令行读取工作区夹具并输出结果 | `命令行从工作区夹具读取 JSON 并输出同一结果` |

这些测试事件和文件清单均是协议模拟，不是真实模型、Docker、Harbor 或历史彩排结果。

## I5 所需采样

真实工具/RPC 业务交接每条至少需要：

- `eventId` 或 `traceId`；
- 发送角色、发送 PID；
- 接收角色、接收 PID；
- 操作类型、工具/RPC 名；
- 业务对象类型和 ID、调用 ID；
- 重试关联与次数、是否地图召回；
- 原始证据路径和行号。

文件清单每条至少需要路径、显式类别、文件种类、生产者角色/PID、关联事件，以及原始证据路径和行号。覆盖清单还要证明事件的采集范围完整。任一必需字段缺失时，I5 应输出 `unknown` 和缺失字段，不能由工具名、角色、目录或模型叙述猜补。
