## 实现接口

```js
collectStructure({ runRoot })      // 完整候选、缺证、测量结果和来源索引
collectStructureInput({ runRoot }) // 直接交给 measureStructure 的 input
readJsonLines(path)                // 普通或 .gz JSONL，保留真实行号
```

命令行：

```powershell
node bench/rehearsal/collect-structure.mjs <runRoot> [输出.json]
```

主要输出：

- `input`：`measureStructure` 的统一输入。
- `candidates.handoffs`：有发送方、接收方、业务对象和原始证据的业务交接候选。
- `candidates.modelFixedSteps`：只含可客观识别的固定手续。
- `candidates.files`：文件候选和明确类别，producer 未采信自报。
- `observations.excludedJudgmentEvents`：保留但排除固定手续收益的专业判断事件。
- `observations.unclassifiedToolCalls`：没有足够客观依据分类的调用。
- `unknown`：缺证领域、精确字段和证据位置。
- `sources`：已读取原始文件的用途和行数。

## 专业判断口径

`pao_submit_decision` 已从固定手续表移出。其 `pass/change/reject`、理由和双轴证据是审核专业判断，只保留在 `excludedJudgmentEvents`，不进入 50% 固定手续收益。

`pao_minister_review_worker` 也不再默认计为“验收”。当前事件只能看到 `request_id`、`card_ref`、`attempt`、`result`、`basis`，没有宿主生成的客观字段区分“普通偏差逐项判断”和“单纯机械抄身份”。因此现有调用一律保留为事件并标 `unknown`，不进入固定手续数。采集器没有按自由文本猜分类，也没有按工具名直接计收益。

后续若主控增加采样，建议由宿主在 tool execution 事件中提供 `reviewKind`，至少区分 `professional_judgment` 与 `mechanical_identity_copy`。该字段不能由模型工具参数自报；缺失时继续返回 `unknown`。本任务没有修改产品工具 schema。

## 需主控转达 I5 的最小采样字段

每个真实业务交接需要：

- `eventId` 或 `traceId`。
- 发送方 `role/pid/session_id`。
- 接收方 `role/pid/session_id`。
- 工具或 RPC 名、`toolCallId`。
- 业务对象类型和 ID，含 card、attempt、run、instance。
- 重试关联和次数、地图召回标记。
- 原文件相对路径和真实行号。
- 交接覆盖范围及完整性声明。

每个文件需要：

- producer `role/pid`。
- 文件类别、具体种类和证据行。

审核复核额外需要宿主生成的 `reviewKind`，并明确它不来自模型自由文本或模型工具参数。
