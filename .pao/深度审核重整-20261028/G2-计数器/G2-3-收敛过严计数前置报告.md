# G2-3 收敛过严计数前置报告

日期：2026-10-30  
范围：`measure-structure.mjs`、`collect-structure.mjs`、两者独立测试及本目录证据。未修改产品源码、I5 成功现场、server、run-rehearsal、scenarios 或 `package.json`。

## 结论

已修正两处过严前置：

1. 文件种类统计不再要求逐文件 producer。路径、事实类别、具体 `kind` 和证据有效时即可计数；producer 缺失保留为 `null`，不把写入进程当成事实种类。
2. 分类不明的文件合法保留为 `category: "unknown"`，只影响未分类部分，不再让 state、input、raw evidence、derived 等已知类别全部变成 `unknown`。

成功样本 `I5-2-final-20261030-1` 的文件覆盖现在为完整，119 个文件均可分类或明确列入未分类。跨角色、跨进程、去重合计和模型固定手续仍因覆盖证据不完整保持 `unknown`，没有拿候选数冒充正式收益。

`pao_minister_review_worker` 已按实际产品作用归入专业判断。产品只在机械项全部通过、仍有需人工判断条件时调用它；它记录部长 `pass/hold`、依据和请求绑定，不能改卡状态或直接交卷。它和 `pao_submit_decision` 都保留事件、排除固定手续收益，不新增 `reviewKind`、用户工具或通用 trace。

## 实现变化

### 计数组件

`bench/rehearsal/measure-structure.mjs`：

- `FILE_CATEGORIES` 接受 `unknown`。
- `producer` 可选；合法 `{role,pid}` 保留，缺失或无效时写 `null`，不影响文件分类。
- 同路径重复记录仍按 `path/category/kind` 检查冲突，最后一条不能覆盖冲突。
- 已知类别继续只对 `Set(kind)` 计数。
- 新增 `fileKinds.unclassified`。有未分类文件时状态为 `unknown`，同时保留 `kinds`、`items` 和原因；无未分类文件时为已测 0。

### collector

`bench/rehearsal/collect-structure.mjs`：

- 删除对每个文件统一制造 `file_producer` unknown。
- 只有 `classifyFile()` 无法给出事实类别时，新增带路径和行号的 `file_classification` unknown。
- 冻结 runRoot 的普通文件递归清单作为文件覆盖证据；不跟随符号链接，并记录排除目录名 `.git`、`.tmp`、`node_modules`、`worktree-baselines.git`。
- `coverage.files.complete` 改为由真实清单遍历结果决定。
- `pao_minister_review_worker` 改为 `professional_judgment`，不再进入 `unknown` 分类，也不计固定手续。

固定手续仍只包含可客观识别且成功配对的：

| 类别 | 当前可识别工具或条件 |
|---|---|
| 启流 | `pao_start_flow` |
| 抄身份 | 当前没有客观证据时不识别 |
| 机械验收 | `pao_verify_card` |
| 交付 | `pao_change_status` 且新状态为 `delivered` |
| 交卷 | `pao_deliver_card` |
| 推流 | `pao_push_flow` |

`pao_submit_decision` 和 `pao_minister_review_worker` 属于专业判断，保留在 `observations.excludedJudgmentEvents`。
