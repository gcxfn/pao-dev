# I3-2a：从既有 worker 证据读取程序执行命令

结论：只读事实提取器已实现并通过定向验证。它只采信与当前 card / attempt / runId 匹配、外壳完整的 worker 证据中，按 call id 成功配对的 bash / powershell 命令与 `result.structuredContent.exit_code`。

## 实际接口

```ts
readWorkerExecutionFacts(
  evidencePath: string,
  expected: { cardPath: string; attempt: number; runId?: string },
): Promise<{
  commands: Array<{
    toolCallId: string;
    toolName: "bash" | "powershell";
    command: string;
    exitCode: number | null;
    completed: boolean;
  }>;
  complete: boolean;
  issues: string[];
}>
```

产品源码只改 `receipt.ts` 中回执与事实读取共用的工具事件类型/解析边界，并新增 `evidence-facts.ts` 和测试。没有新增落盘事实、用户工具、状态目录、scope，也没有修改 runner、index、cards、workflow、package。

## 主控接线与边界

I1-3 判定包接入时，应以当前卡路径、当前 attempt 和可得的 runId 调用该 helper；只有 `complete === true` 才能消费 `commands`。本任务没有修改主控接线，也没有把 helper 加入用户可见工具。

当前采集边界仅为 bash / powershell 的 `command`、event 配对状态和结构化 `exit_code`。没有采集 cwd、产物、changes、usage、模型 verification、任务状态或 host 最终判定；证据尾行的 worker 进程退出码也不作为命令退出码。
