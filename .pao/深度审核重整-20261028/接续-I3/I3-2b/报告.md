# I3-2b 当前执行真实文件改动事实读取

结论：已新增只读 helper，按“认领内容 tree → 当前执行根内容 tree”计算本次 attempt 的 created/modified/deleted。认领前 dirty tracked、已有 untracked、模型自报 changes 和任务根同名文件都不计入。现有 `diffAgainstBaseline` 已支持路径级内容 tree 差异，因此无需新增产品接口，也没有复制捕获规则。

## 接口

```ts
readWorkerChangeFacts({
  binding: ExecutionBinding,
  baselinePath: string,
  evidencePath: string,
  cardPath: string,
  runId?: string,
  signal?: AbortSignal,
}): Promise<{
  available: boolean;
  created: readonly string[];
  modified: readonly string[];
  deleted: readonly string[];
  reason?: string;
}>
```

返回路径均为执行根相对路径。`available=false` 时三个数组为空且 `reason` 说明未知原因；空数组本身不冒充“没有改动”。

## 主控接线

decisionPack 接入时传入真实当前 `ExecutionBinding`、`baselineSnapshotPath(...)` 生成的标准 attempt 基线路径、该 run 的 live 证据路径、完整卡路径，并尽量传入外层 `runId`。helper 会重新读取持久绑定并实时核验，不能只传调用方内存对象。

本任务未改 decisionPack、runner、control、cards 写逻辑，也未新增用户工具、持久 facts 正本或 scope；未提交 Git。

## 明确边界

本 helper 只支持有真实内容 tree 的 Git 执行根。非 Git 执行根、缺少内容基线或证据外壳不完整时返回 unknown，不按当前文件或 Git HEAD 猜本次改动。

内容事实沿用现有 `PROJECT_CONTENT_PATHSPECS` 边界：`.pao`、gitignored 内容不属于文件改动事实。命令、退出码和 usage 仍由 I3-2a 的其他事实读取处理；模型回执中的 changes/verification/summary 不进入本结果。
