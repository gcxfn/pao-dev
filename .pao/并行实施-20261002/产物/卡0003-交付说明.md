## 二、档位配置:格式与示例

位置:`$PAO_HOME/pao配置/档位.json`(`PAO_HOME` 从环境变量读,pi 不自行加载 .env,需启动方导出)。

```json
{
	"provider": "pao",
	"档位": [
		{ "名": "快", "provider": "glm", "model": "glm-4.7-flash", "thinkingLevel": "low", "contextWindow": 200000, "maxTokens": 8000 },
		{ "名": "主力", "provider": "glm", "model": "glm-4.7", "thinkingLevel": "high" }
	]
}
```

- 顶层 `provider` = 虚拟模型挂载的 provider id,缺省 `"pao"`;`档位` 至少一档。
- 每档必填:`名`(即虚拟模型 id,协议层只见它)、`provider`、`model`、`thinkingLevel`(推荐思考档,off/minimal/low/medium/high/xhigh/max 之一);可选 `contextWindow`、`maxTokens`(首个响应前的展示值)。
- 缺文件/坏 JSON/缺字段/字段不合法:**启动即抛结构化中文错误,指明哪个文件哪一项缺哪个字段**,不注册哑模型(架构 §4.1 红线)。
- 改配置 → 重新注册(重启/重载)即路由变;换模型零代码改动。

## 三、建部目录树

`pao_建部`(部门创建唯一正门)一次落齐:

```
$PAO_HOME/
  部门/
    注册表.md                      ← 唯一真相:名字/能力标签/库路径(markdown 表,带锁追加)
    <名>/
      配方.md                      ← 名字/人设/工具/默认档位/记忆目录(占位「<待填>」)
      知识库/
        索引.md                    ← 顶层门面:本部答什么问题、各区导引、条数占位(0 条)
        待验证/                    ← 候选池,不设索引
        归档/                      ← 退役区,不设索引
        教训/子索引.md
        导览/子索引.md
        做法/子索引.md
        评测/子索引.md
```

- 幂等:重跑只补缺(文件/目录/子索引),**已有文件与自定义内容绝不覆盖**;注册表同名行不重复追加。
- 注册表渲染:`registerDeptTools` 在 `before_agent_start` 每次运行前读注册表,渲染 `<pao_dept_registry asOf="YYYY-MM-DD">` 一行一部门快照进 `systemPromptOptions.sections`(结构化 section,不整段替换系统提示);注册表为空渲染空态说明;PAO_HOME 缺失时不渲染该 section 也不报错。worker 不装本扩展即天然不渲染,符合 §6.8。

## 六、取舍与遗留

- **`createDept`/`appendRegistryRow` 为异步**:proper-lockfile 的 sync API 不支持 retries(获取锁等待),故走异步锁,参数与 `cards/lock.ts` 同款(stale 10s,指数退避)。
- **锁代码未复用 `cards/lock.ts`** 而在 dept 内自含 20 行同款实现:遵守黑板「四模块互不相交」,避免 dept→cards 耦合;代价是有一份重复实现,主控若愿意可在 M2 收敛。
- **`resolvePaoHome` 在 routing 与 dept 各有一份**(4 行):同上,互不相交优先;dept/index.ts 另 import 了 `routing/config.ts` 的 `resolvePaoHome`——若主控要求彻底解耦,把该函数下放为两份本地副本即可(一行改动)。
- **推荐思考档的实现方式**:档位的 thinkingLevel 排在虚拟模型 `thinkingLevels` 首位,成为默认选中档;用户显式选档经 `request.thinkingLevel` 原样透传。注意 pi 的 `setModel` 默认沿用上一档位(见 agent-session `_getThinkingLevelForModelSwitch`),「默认=推荐档」主要在全新选档时生效。
- **注册表渲染挂在 `before_agent_start`**(卡给的备选是 session_start):每次运行前读最新注册表,「改注册表→下一次请求天然生效」比 session_start 一次快照更贴 §6.8;渲染进 `systemPromptOptions.sections`(结构化),不整段替换系统提示。
- **渲染失败不阻断会话**:PAO_HOME 缺失/注册表读不了时跳过 section(无部门环境合法);注册表存在但空 → 空态说明。档位配置缺失则**启动硬报错**——一软一硬,按「不做静默变笨」红线分别处理。
