环境变量（黑板约定）：`EMBED_BASE_URL` / `EMBED_API_KEY` / `EMBED_MODEL`。查询与条目文本分不清时**一律不嵌**：未配置端点、查询绑定项目未授权、条目适用范围未授权或缺失（未知）、调用失败——四种情况都降级为词法独跑，结果带 `degraded: true` 与 `degradeReason`。

## 二、向量缓存 JSON 格式（cache.ts）

位置：`<知识库根>/.pao-vector-cache.json`（衍生品，可删可重建，永不作为正本）。缩进 tab：

```json
{
	"formatVersion": 1,
	"embedModel": "mock-embed",
	"chunkParams": { "granularity": "whole-entry", "version": 1 },
	"vectors": {
		"教训/条目A.md": { "sha1": "…条目全文sha1…", "mtime": 1790880513963.75, "embedding": [0.1, 0.9] }
	}
}
```

失效规则（均已测）：
- `embedModel` 或 `chunkParams` 任一变化 → 整体重建；
- 条目内容 sha1 变化 → 该条向量失效、下次查询补嵌（不只处理新增）；
- 条目归档/删除 → 扫库时不在候选集，同批从缓存裁掉；
- 外发授权撤销 → 该项目条目向量同批裁掉（即使本次查询被阻断也收敛）；
- 入库转正 → 旧路径与新路径向量都丢弃。

## 三、禁外发配置项格式（outbound.ts）

位置：`<PAO_HOME>/知识库配置/外发许可.json`（可用 `PAO_OUTBOUND_CONFIG` 环境变量另指路径）：

```json
{
	"projects": {
		"pao": { "allowed": true, "asOf": "2026-10-02" },
		"secret-proj": { "allowed": false, "asOf": "2026-10-02" }
	}
}
```

- **未列出的项目 = 不允许**；条目「适用范围」缺失 = 未知 = 不允许；查询未绑定项目 = 不允许。空配置文件时全部词法独跑（保守默认，宁降级不外发）。
- **共享检查函数只有一个**：`checkOutbound(projects: string[], config): { allowed; blocked }`。查询嵌入（查绑定项目）、条目嵌入（查条目 scope）、批量重建（逐条 scope）三入口都调它，另有一个纯嵌入调用约定用例锁定。
- 撤销 = 把项目移出/改 `allowed:false` → 新外发当批阻断、缓存同批收敛。**不宣称撤回云端已收数据**（测试注释明示）。

## 五、做过的取舍

1. **「未知不外发」偏保守**：适用范围缺失、查询未绑定项目，一律不发云端（降级词法独跑）。宁可语义召回少一路，不赌外发边界。代价是部长不传 `绑定项目` 时语义路默认关闭——主控接线时可通过 `defaultProject` 从可信上下文绑死，模型不用自行填写授权（R01）。
2. **词法保底用「换入」实现**：合并排序按 0.5×词法归一 + 0.5×余弦，但精确命中若被挤出 top_k，会换掉排名最低的非精确命中。不做复杂重排（架构：重排暂缓，实测不准再开）。
3. **词法中文不分词**：查询按空白/标点切块、条目侧子串匹配（文件名×3、钩子×2、路径×1，整句也参与）。零依赖、可测；召回上限靠语义路补。
4. **状态加一档「未知」**：任务卡验收只列 有效/待验证/待复核⚠️，按 R08「适用范围缺失标未知，不自动认有效」加了第四值；文档已注明。
5. **补查额度三层防赖**：进程内 Set（同进程重开无效）+ 回执 JSONL 核对（跨会话无效）+ 占额在执行前（失败也消耗，重试不恢复）。追加授权 = 授权轮次 round+1。自定义 `appendReceipt` 注入后只认进程内登记（测试用）。
6. **入库顺序 = 移动 → 加行 → 失效缓存 → 巡检**，移动用 `renameSync` 原子先行，所以「只做一半」的中断现场只会是「已移未加行」，重跑必修复；目标位同名不同内容直接拒绝，不自动覆盖。子索引临界区用目录锁（mkdir 原子性 + 超时接管残留锁）。
7. **巡检会同步摘 ⚠️**：复检通过的行自动去标记（纯比对语义的自然延伸）；「⚠️ 消化归部长终审」不受影响——工具只动子索引行尾，不动条目正文。
8. **缓存收敛时机**：撤销/归档/删除导致的缓存裁剪，即使本次查询因禁外发被阻断也执行（R08「同批更新」），但不做后台进程——纯比对顺手做，无常驻服务。
9. **卡 C 依赖为零**：库骨架路径只作参数，`教训/导览/做法/评测/待验证/归档` 目录缺失时按空区处理；建部工具生成同款骨架即可无缝对接。
