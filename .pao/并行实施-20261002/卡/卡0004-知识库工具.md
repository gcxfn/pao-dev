## 设计要点

- 库结构按架构 §6.2(卡C 的建部工具生成同款骨架;本卡工具直接按该结构读写,不依赖 C 卡实现,目录路径作参数传入,测试用临时目录 fixture)。
- 语义路:OpenAI 兼容 `/embeddings` 端点,从环境变量读(`EMBED_BASE_URL`/`EMBED_API_KEY`/`EMBED_MODEL`,黑板约定);**端点未配置或调用失败 → 词法独跑,结果带 `degraded: true`**——今晚无真实端点,降级路径就是主测路径。
- 向量缓存:JSON 文件;记录嵌入模型名与切分参数(如条目粒度);任一变化 → 缓存整体失效重建;缓存可删除可重建,永不作为正本。
- 词法路:条目文件名 + 首行钩子 + 标题的分词匹配(中文友好:不做分词也可用子串/关键词计分,写明策略);**精确命中不被语义高分挤掉**(合并去重时词法命中保底在列)。
- 禁外发:配置「允许外发的项目清单」;查询嵌入、条目嵌入、批量重建三个入口统一检查(未授权项目的条目正文/查询词不发云端);检查点是一个共享函数,不是三处各写一份。
- 巡库卡是 M2 项,本卡不做;worker 受限补查只做**边界门**(见验收 7),补查工具本身 = 查库工具 + 门包装。

## 验收(全部机械可判,逐条附测试;嵌入用 mock fetch 测,不接真实端点)

1. **双路合并去重**:构造库(若干条目),mock 嵌入返回固定向量;查询同时命中词法与语义 → 合并后每条只出现一次;词法精确命中在 top_k 内不被纯语义高分条目全部挤掉。
2. **户口完整**:每条命中带 路径/标题路径/摘要/状态(有效|待验证|待复核⚠️)/适用范围/最后核验/来源/degraded;待验证区命中只列「风险提示」区,不挤占正式 top_k。
3. **降级**:不配 EMBED_* 环境变量 → 词法独跑 + degraded=true;mock 嵌入抛错 → 同样降级不崩;两路都无命中 → 明确「无可用依据」空态。
4. **缓存重建**:缓存 JSON 记录 embed 模型与切分参数;改变任一 → 旧缓存判定失效整体重建;删缓存文件 → 从库重建;条目修改/归档/删除 → 对应向量与候选同批失效(不只处理新增)。
5. **入库幂等**:转正 = 移条目进类型目录 + 子索引加行 + 触发巡检;重复执行同一次转正(条目已在目标位)→ 修索引不重复生成;模拟中断(只做一半)→ 重跑修复;子索引行可由条目文件校验生成。
6. **机械巡检**:扫条目首行日期与来源版本,超期(可配阈值)或版本不符 → 子索引行标 ⚠️;纯比对不起进程;巡检只标不说「错了」。
7. **受限补查门**:包装函数带 部门(锁死本部,拒绝 `全部`/别名)、次数(按 卡号+授权轮次 计一次,重试不恢复)、只读(无任何写路径)、回执记录(查了什么词、返回几条);二次调用 → 拒绝并说明;跨部参数 → 拒绝。
8. **禁外发**:未授权项目的库 → 查询词与条目正文均不进入嵌入请求(mock 断言请求体);配置撤销后新外发被阻断(注:不宣称撤回云端已收数据)。
9. vitest 全绿(只跑本卡测试文件)。
