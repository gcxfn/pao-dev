# plans/ 规范

需求与架构定案、一次性实施计划的归属目录。

## 结构与规则

- 活文档（`v2-REQUIREMENTS.md`、`v2-ARCHITECTURE.md`）长期修订，不进完成态分类；决策被推翻时改标「已否决 + 日期 + 原因」，不删除。
- 一次性计划建稿入 `未完成/`，命名 `YYYY-MM-DD-主题.md`；完成后移入 `已完成/` 并在正文补记完成日期。量大前不设日期子目录，翻不动再分层。
- **计划落笔前先找可抄的，不重复造轮子**：先查需求 §4.1 复用清单、pi 生态与本机既有实现，有现成的（直接用/抄改）就不自建；计划里记一笔「用了什么现成的、为什么不用」。
- 本文件兼作索引：「当前焦点」只维护一个指针；`已完成/` 目录本身即归档清单，不手工复述。
- 外部计划包：`全阶段计划包-2026-10-02/` 为 GPT 编制包的**只读存档**（含依据快照与校验说明，链接自成一体）；并入版才是活文档，后续不改冻结包。R01—R11 的[实施前契约修订](已完成/2026-10-02-实施前契约修订.md)已批入正本并关闭；它是审阅经过，不代表实现验收完成。新审查发现只维护在对应审查报告，任务与处理状态维护在总册。
- **计划收编（2026-10-04）**：原七份未完成计划已冻结存档于 `未完成/存档-收编-2026-10-04/`（细节、出处与历史进度以存档为准，不回写）；后续任务、批次顺序、验收面、候选与待用户事项**只维护在[后续执行总册](未完成/2026-10-04-后续执行总册.md)**。
