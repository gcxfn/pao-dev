## 1. 目标与已确认方向

把 PAO 工作流页面变成通用工作台，先完成小说创作场景，再根据实际需求增加视频剪辑等工作。当前主控对话负责讨论和安排任务，工作台负责让用户看清计划、分工、进度和成果。

用户本轮已明确：

- 主视图使用一张张步骤卡，取消画布作为工作入口；不要求用户画节点和连线。
- 延续现有 PAO 的灰白界面、应用导航、工作流标签、右侧详情和底部主控对话。
- 临时工作流由主控根据当前对话中商量好的计划直接创建并填好，不能增加“创建临时工作流”按钮，也不让用户重新填写一遍。
- 临时工作流可以直接执行。用户认可其复用价值后，再主动保存为工作流模板。
- 负责部门读取已有部门，使用下拉选择。
- 成果是一份份文件；点击文件名，在右侧栏打开。
- 检查普通界面里的 JSON、内部字段和难懂的操作，纳入同一份优化草案。

本草案承接[原工作流优化计划](2026-10-11-工作流视图与全项目优化计划.md)。原计划记录的实现、证据和未完成事项保留；其中继续加厚画布的设计方向由本轮卡片方向取代，不因此宣告原计划完成。

## 2. 从对话到执行的操作过程

1. 用户与主控讨论目标和计划，例如确定小说题材、拟大纲、写首章、审稿、人工确认。
2. 主控在本次会话中创建临时计划，填入步骤、已有部门、任务、输入、预期成果、约束和验收要求。创建成功后对话显示简短摘要和“查看计划”，工作台同步出现步骤卡。
3. 用户可以继续对话修改，也可以在右栏直接改具体字段。每次修改说明改了哪一步、哪个内容；保留撤销入口。
4. 用户通过当前对话确认执行，工作台显示真实执行进度。创建、开始执行、保存模板是三个不同动作，不相互代办。
5. 有成果时显示真实文件；需要用户确认、补信息或处理失败时，在对应步骤显示原因和下一步操作。
6. 用户可随时保存为可复用工作流。只保存步骤、分工、依赖、约束及验收要求；不把当前会话、执行进度、历史回执和本次成果当成模板内容。

临时指“尚未加入模板库”，不指刷新或关窗就丢失。正式实施应持久保存本次计划及其会话关联，恢复后继续查看；失败时明确报错，不能先显示“已保存”。

## 3. 工作台布局与信息层次

| 区域 | 默认显示 | 按需查看 |
|---|---|---|
| 左侧导航 | 当前任务与已保存的工作流 | 历史运行记录；不混淆模板与本次执行 |
| 工作区顶部 | 工作名称、临时标记、整体进度、需要用户处理的事项 | 来源对话、保存工作流 |
| 中间步骤卡 | 步骤名、负责部门、状态、等待原因、已产生的文件 | 选中后显示任务摘要；完整要求在右栏 |
| 右侧栏 | 选中步骤的要求，或点击文件后的预览 | 文件来源、历史版本和技术记录 |
| 底部主控对话 | 当前会话、输入框、明确的讨论对象 | 主控对步骤/文件的建议与处理结果 |

卡片按实际依赖顺序排列；多个前置用“等待第 2、3 步”，明确可并行的步骤在同一组显示，不把真实依赖强行改成串行编号。审稿打回时说明“回到哪一步、为什么”，保留此前成果和审查意见。

普通界面先回答：现在做到哪里、为何停下、产出了什么、需要我做什么。长路径、内部编号、原始回执和工具参数归入技术详情。

## 4. 部门选择

- 复用现有部门目录查询，从当前 PAO_HOME 读取，不在前端另建固定名单。原型仅采用 2026-10-14 只读核对的快照：审查、开发、测试、写作。
- 使用原生下拉框；不允许自由输入不存在的部门。对话指定未注册部门时说明未找到，并给出现有选项，不自动新建。
- 目录加载中、读取失败、目录为空分别显示；失败可重试，不能用空列表掩盖读取错误。
- 旧计划引用已删除或改名的部门时，保留原值并标记不可用，要求重新选择；不能静默指向下拉框第一项。
- 计划尚未执行时，修改同步到卡片与详情并可撤销。运行中的计划调整遵守第 7 节，不只改界面标签。

## 5. 成果文件与右侧预览

- 卡片显示该步骤已经产生的文件；“成果文件”页按步骤归集。预期交付写在要求里，未生成时显示“尚未产生文件”，不能把预期文件名当作已经完成的成果。
- 文件名可点击，附相对路径区分同名文件。右栏显示文件名、来源步骤、预览状态及正文；完整路径可以复制。
- 打开文件不改变当前选中的步骤；“定位所属步骤”才改变步骤选择。“返回步骤详情”恢复此前选择。
- 提供“专注阅读”，临时扩大正文区域；退出后恢复原布局。窄窗口右栏转为下方详情，保留返回入口和对话草稿。
- 默认只读；支持编辑的文件通过现有文件编辑器显式进入编辑，沿用未保存变更提示。不在预览时悄悄写回。
- 优先支持小说需要的 Markdown/文本；图片及其他项目已支持格式复用现有预览。视频等未支持类型显示真实格式和可用打开方式，不提前实现剪辑器。
- 文件不存在、被移动、无权访问、过大、格式不支持分别给出可理解的提示与可用操作；只对确认的文件路径提供打开入口，证据说明文字保留为文字。
- 运行中生成新版本时提示“有新版本”，不强制替换正在阅读的正文、光标或选区。审稿意见、修改稿和确认稿分开保留。

## 6. 补充的人机交互

| 情况 | 建议行为 |
|---|---|
| 对某一步提意见 | 点“讨论这一步”，输入框显示明确对象；用户可改回整个流程 |
| 对成果提意见 | 点“就此文件提意见”，关联具体文件及正式接入后的版本；原意见可回查 |
| 正在输入时切换步骤/任务 | 保留草稿；仅查看文件不偷偷改变发言对象 |
| 修改计划 | 显示修改内容与影响；简单修改提供撤销。多字段编辑保留输入焦点和草稿 |
| 执行进度更新 | 更新状态，不跳动用户当前选择、阅读位置或输入内容；提供“回到当前步骤” |
| 等待前序、人工确认或预算不足 | 给出具体原因和可执行入口，避免统一写“处理中” |
| 执行失败 | 显示影响范围、已保留成果和可选处理；重试应说明重跑哪一步，避免误重跑全流程 |
| 需要用户确认成果 | 直接列出待确认文件和审查结论，提供确认/提出修改意见；只有真实确认成功才完成 |
| 保存模板 | 预填名称与步骤，检查同名并明确覆盖/另存；保存失败保留内容并可重试 |
| 错误反馈 | 第一行说哪个操作失败及已知原因，提供下一步；原始错误可展开复制，不能吞错或伪报成功 |

修改意见的“已记录”“主控正在处理”“已应用”必须区分。只发送或收到了意见，不等于文件已改、计划已变或验收已通过。

## 7. 实施时必须保持的状态边界

- 工作台读取共享内核提供的真实计划、状态和成果，不在前端维护另一套执行状态。步骤卡是现有工作流的展示方式，不是第二个调度系统。
- 现有运行实例使用冻结配方，也就是启动时保留的计划。运行中改部门、依赖或任务范围不能仅修改前端，更不能覆写模板后假装当前执行已同步。
- 首批允许未执行计划编辑；执行中的变更通过主控提出，展示影响并在业务接口实际受理后更新。暂停与重试继续遵守已有内核规则。
- 正式实现前明确临时计划的存储位置、会话/项目关联、稳定标识及创建工具契约。工具成功返回后再显示卡片；重复通知和重复提交不得创建两份计划或启动两次。
- 主控应调用结构化工具创建/修改计划，不靠扫描普通回复中的“1、2、3”或特定句子判断动作；原型的固定命令匹配仅为演示。
- 原型中的暂停、推进、意见记录和确认都是模拟操作，不构成实际任务执行证据。

## 10. 建议实施顺序与验收

1. **先完成一个真实小说工作闭环**：对话创建临时计划 → 已有部门分工 → 步骤卡查看 → 执行 → 正文与审稿文件侧栏预览 → 用户确认。同步解决上述高优先级 JSON/路径展示。
2. **补齐日常使用恢复能力**：计划持久化、同名保存、未注册部门、意见状态、草稿和阅读位置保留、失败重试与变更受理反馈。
3. **统一其他页面**：预算/用量、复盘历史、工具状态、技术详情与报错说明。视频流程等出现实际需求后再扩展文件类型和工具能力。

正式实施验收至少包括：

- 从当前主控创建临时计划，无新建按钮；字段完整，重复事件不会产生重复工作流。
- 部门来自隔离 PAO_HOME；读取失败可见，旧部门失效有提示，不能悄悄换部门。
- 从步骤卡与成果页均可打开真实文件；同名不同目录、文件缺失、非文本文件有明确行为。
- 文件意见与步骤意见关联正确，切换任务后草稿仍在；更新进度不抢阅读位置。
- 未执行修改有反馈并可撤销；运行中计划不会只改界面而与实际执行不一致。
- 待确认不会自行完成；记录意见不冒充修改完成，复制指令不冒充任务已取消。
