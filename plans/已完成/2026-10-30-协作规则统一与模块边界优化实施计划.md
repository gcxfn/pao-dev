## 2. 执行纪律与文档归属

### 2.1 谁执行、如何防止范围漂移

1. 默认主代理串行执行，不启动并发子代理。若后续用户明确允许协助，最多一个子代理做不重叠的只读复核，主代理负责整合；不自动恢复旧计划的多路并行。
2. 每次只实施一个小任务：明确输入、允许修改文件、要替换的旧路径、验证命令和退出条件。完成并复核后才进入下一项。
3. S0→S1→S2→S3→S4→S5→S6→S7顺序固定。测试随代码推进；S7是最终整合验收，不是第一次测试。
4. 前阶段硬验收未通过，不把失败留给后阶段“顺手处理”。确属其他项目或环境问题时，登记精确阻塞和已完成工作，不假装本阶段完成。
5. 已通过的模块不因“更优雅”重复重写。新增接口必须替代已有重复职责；只新增转发层而不减少耦合，不能验收。
6. 所有操作先读当前源码。行号仅定位，实施前用符号与调用者确认；当前有大量未提交修改，不从旧HEAD覆盖现状。
7. 未来执行本计划涉及的跨仓源码修改仍限开发根、PAO、desktop。正式数据、外部发送、发布、付费和系统变更按已有实际授权核对；历史文档中的一次性授权不自动扩大到新运行。

### 3.3 必须保留的区别

执行停止、任务完成、验收通过、流程完成是四种不同事实。停止未确认时，不释放写占位；未运行检查不算通过；审核证据绑定实际成果版本；重试生成新尝试身份；旧结果不能改变新尝试。有人值守与无人值守不能由模型中途切换。返修只处理原范围缺陷，新增目标另建任务。

## 4. 统一停因、决定与兼容设计

### 4.1 固定设计：先统一内部解释，不新增持久化正本

2026-10-31用户批准协议调整，依据[S1协议缺口证据](../../.pao/协作规则统一-20261030/S1/验收记录.md)。保留卡片字段、工具公开参数、配方版本与控制文件路径；新控制文件使用v3，以单一`停止`对象替代`暂停/裁定/待决`的可变组合。旧三项仅在读取边界兼容和公开只读投影中保留，不写入v3文件，不另建stop.json或日志状态。主动暂停可在同一停止对象中保留原待决现场，但禁止办理该待决。

`ControlStop`是v3磁盘停止对象；`ControlStopProjection`是由它计算的只读查询结果，不另行保存：

| 字段 | 来源与规则 |
|---|---|
| category | `decision / manual_pause / recovery_required / terminal_block / legacy_unknown`；仅本次真实存在的五种情况 |
| identity | 现有实例、节点、轮次；有卡时附卡号/attempt；不得由模型覆盖 |
| pending | 需要裁决或保留暂停现场时，内嵌现有WorkflowPending；不再保存旧根字段`待决`副本 |
| route | 原请求的处理动作`rule / resolve_pending`；类别为主动暂停或需恢复时不可办理，仅保留来源 |
| reason | 展示原因；改变此文字不能改变动作权限 |
| authority | 仅查询结果含owner模型或human；由冻结运行方式、通道和停因类别计算 |
| deadline | 仅可办理查询从pending投影截止；沿用现有上限并取最早截止，不延长预算 |

允许动作由`category + pending类型 + 当前身份/版本 + 可信权限`计算，不将一份可自行过期的动作清单作为另一个状态保存。返回查询时可带动作说明，执行前仍重新核对。

旧数据处理顺序固定：

1. 旧待决、裁定先校验完整性、身份和通道；冲突明确报损坏。带有旧暂停文本或需办理的旧待决时，按`legacy_unknown`保守读取并保留原待决，须人工核查迁移；不借待决优先自动放行。
2. 仅旧裁定时，校验节点、轮次与通道后转换；缺失截止不伪造过去授权，按有人值守兼容规则处理。v2控制文件只读兼容，须通过显式人工恢复/迁移入口核查后才能写为v3；迁移持锁且备份原件。
3. 仅旧暂停文本且无法从其他结构化记录确定语义，归`legacy_unknown`，只读展示并保留人工恢复；不得通过猜文案自动放行。
4. 没有停因时正常运行；业务终态仍读取结果与节点事实，不因没有暂停就猜成功。
5. 保存仅编码v3单一停止对象；不把只读查询隐式写成迁移。未知版本或v3混入旧可变字段明确拒绝。旧内核拒绝v3，避免丢弃新停止事实后写回。

旧实例有完整待决时，显式人工恢复入口先备份并迁移，保留待决、原截止和卡状态，仍停在原通道处理；即使卡仍为`in_progress`也不把格式迁移当作恢复执行。后续办理继续核对当前attempt、真实执行占用及停止证明；已经到期则按原截止形成业务结果，不能因迁移重置预算或宣称写者停止。仅旧文本/无待决的恢复沿用既有在途卡检查。

上述兼容保留的是磁盘表达，不是保留三套内部判断。验收时分别统计“仍需兼容的字段”和“独立业务判断数量”，不能把字段没删误报为失败，也不能把字段分类改变冒充产品状态减少。

### 4.2 所有判断请求的共同语义

| 触发 | 登记与处理 | 不能做什么 |
|---|---|---|
| 工人fail/not_run，机械项已核查 | 复用逐项偏差待决，主控逐项给依据 | 用总体一句“接受”代替每项依据；接受机械必需项失败 |
| 部长hold、直接任务需语义验收 | 复用普通裁定请求，允许没有fail/not_run条目；绑定当前任务证据 | 为满足旧类型伪造一条not_run；强制增加部长 |
| 独立审核change | 有效版本与既定回边内返修 | 把审核副本的检查脚本合并进业务成果 |
| 独立审核reject | 明确失败或原有人值守处置出口 | 自动改成pass继续 |
| 缺输入或证据不足 | 记录缺项，按已支持的补充/返修路径处理；不支持则明确阻塞或终止 | 凭文件存在猜成果合格 |
| 范围变化、权限升级 | 人工处理，普通质量裁决不能解除 | 将无人值守授权解释成任意操作授权 |
| 用户暂停 | 保存明确暂停事实；只有原有合法恢复入口解除 | 到期自动当成用户同意恢复 |
| 未知执行状态、关闭中断 | 停止未确认，保留占位与现场 | 清锁、另起执行者并发写入 |
| 到期 | 形成明确业务结果，并独立确认停写 | 因计时结束就声称进程已停止 |

同一实例继续沿用现有单一活动待决约束，不顺手开发多待决并行调度。第二个不同待决发生时必须保留来源证据并明确拒绝覆盖；不得丢失事件、延期或用后者替换前者。是否支持多个同时办理不属于本轮。

裁决对象分两种，不能为了共用代码伪造卡片：有卡的语义验收必须绑定当前card_ref/attempt及实际证据，决定后才能进入该卡完成手续；无卡的节点方案裁定只绑定实例/节点/轮次，决定只改变该节点的合法控制结果，不调用卡交付和Git提交。两者共享身份、权限、截止和重复决定检查，保留必要的执行差异。

旧文件中无法可靠区分“用户暂停”和“恢复待确认”时，保持保守人工恢复，不从自然语言猜分类。当前新调用也不得为追求分类完整，额外维护第二份日志状态；如现有结构化记录确实不能保留必要语义，按S1退出条件报告协议缺口。

### 4.3 一次决定后的程序操作顺序

读取当前身份与策略→校验全部参数和证据→登记办理记录→按现有入口验收→交付→必要时Git交卷→清理该待决→受理一次后续推进。

用户/模型提供判断和依据，程序绑定实例/attempt并完成以上确定步骤。必需字段不完整时不发生业务写入。各步骤无法作为数据库事务整体回滚，沿用`PendingResolutionRecord`和现有交付记录恢复；不再维护另一套阶段账。

业务外部副作用发生后才能记录的窗口（例如Git提交成功但阶段写失败）必须从真实提交/版本事实核对，不能简单重试再提交。关闭后是否自动恢复仍遵守原有人工恢复限制；幂等表示合法重放不重复生效，不表示重启自动获准推进。

相关回归：index-wiring、runtime-wiring、loadout-role、host-lifecycle、session-shutdown-fixture、真实产品入口装配；最终检查不能只用源码字符串匹配。

## 12. S6：地图读取优化

### 12.1 范围与默认方案

只改`dispatch-brief/workspace.ts`、相关precheck/brief/snapshot读取调用点与必要`shared/git.ts`接口。采用Git现成批量对象查询、一次读取索引与路径清单、请求内复用；不增加跨请求缓存，不普遍改成不受控并行，也不修改地图有效期规则。

### 12.2 小任务

| 编号 | 实施步骤 | 必须产物 |
|---|---|---|
| S6-1 基准夹具 | 建10/100/1000个文件的固定临时Git仓，混合已跟踪、修改、暂存、删除、未跟踪、空文件与特殊文件名 | 相同输入可在旧新实现运行；记录机器和Git版本 |
| S6-2 批量读取 | 用现有Git命令能力一次取HEAD/索引对象身份并批量取对象内容；工作区按原规则读取 | 不再每个文件启动两个show和两个cat-file |
| S6-3 操作内复用 | 合并一次prepare内部等价重复采集；跨有副作用边界仍重新核验 | 明确复用生命周期，不能把派发前重验省掉 |

### 12.3 硬验收

- 除时间戳外，固定现场的内容身份、覆盖范围、缺失标记和有效性判定与原契约一致。
- 常规路径的一次采集Git进程数不随文件数逐文件增长；10/100/1000文件均报告实际数量。为受支持特殊路径保留回退时，说明准确触发条件并测试，不能所有情况都回退旧实现。
- 100与1000文件场景Git进程数量至少降低80%；这是本计划对照验收目标，不是已取得结果。
- 同机1000文件采集耗时中位数至少降低30%；10文件无超过10%的可重复退化。若测量噪声影响判断，只能做一次受控复测并保留两组结果；未达标不降低目标来宣布性能完成，应定位或报告未完成。
- 空文件、删除、暂存/工作区不同内容、中文、空格、换行文件名（平台支持时）结果正确；平台不支持的路径场景在相应支持平台验证，不能用跳过声称跨平台通过。
- 不改变地图与当前成果版本绑定、调用边界确认和派发前检查；不提高任务预算与测试超时。

相关回归优先dispatch-brief-artifacts、dispatch-brief-prepare、workflow-node-map-merge、content-tree-metadata及实际引用这些模块的测试。

## 13. S7：最终组合、兼容与发行验收

### 13.1 范围与步骤

1. 停止对本次源码的继续修改，记录最终三仓实际内容身份（含未跟踪源码）。不要求提交他人修改。
2. 检查S1—S6的删改清单：旧实现是否还有运行时调用、动态加载、公开导出和测试依赖；只删已被替代且证实无用途的内部路径，公开兼容接口保留薄适配。
3. 按§13.2—13.4执行组合场景，复用同一产品入口和脚本模型；脚本只模拟模型响应，不直接写卡/控制文件来替程序走流程。
4. 重建当前内核和桌面依赖，运行完整相关检查；产物须与最终源码匹配。
5. 运行Windows真实Electron定向用例及本地目录发行包验证，不发布、不改正式PAO_HOME。
6. 与S0同口径比较，写交付报告并更新长期架构和必要操作说明；只在总册标记阶段状态。

### 13.2 核心组合矩阵：36个场景槽位

三种执行形态：单卡部门直派、工作流直接节点、工作流部长拆解节点。两种运行策略：有人值守、可信无人值守。六种结果：正常完成、fail/not_run、需语义判断、机械验收失败、结果未知、取消。组合为36个明确槽位。

每个槽位在S0表中注明实际入口及预期；现行公开入口不支持某种策略时，必须验证启动/调用拒绝，不能强行新增支持，也不能空着标“不适用”。批量派发另在边界案例B13/B14检查，不强行改成第四种工作流形态。

| 结果 | 必须断言 |
|---|---|
| 正常完成 | 原契约要求的验收/交付实际发生；下一步只受理一次；无虚假待决 |
| fail/not_run | 逐项事实保留；授权主控裁决或合法人工出口；必需机械失败不能被接受 |
| 需语义判断 | 部长/直接执行都能产生真实判断请求；没有部长时不伪造会话 |
| 机械验收失败 | 未交付，保留失败证据；按已有返修资格处理或明确失败 |
| 结果未知 | 不宣布成功、不释放未知执行占位、不自动重复派发 |
| 取消 | 不启动后续任务；等待真实停止并分别记录业务取消与停止状态 |

使用至少两种业务夹具：小型代码修改与中文文稿修订，均使用隔离Git目录。部门名和文件名改变后，通用流程不应增加代码特判。模型为脚本，不证明专业写作/编码质量。

### 13.3 必须独立执行的边界案例

| 编号 | 场景 | 必须看到的结果 |
|---|---|---|
| B01 | 审核pass后成果版本改变 | 原pass不能放行新版本 |
| B02 | 审核change、仍在原范围 | 回到原任务，生成新attempt，旧证据保留 |
| B03 | 审核reject | 明确拒绝，不自动接受 |
| B04 | 新权限/范围变化 | 不被普通质量裁决放行 |
| B05 | 用户主动暂停后到期 | 不自动恢复 |
| B06 | 同一决定重复发送、已受理后改变依据 | 首次生效一次；后者明确冲突 |
| B07 | 旧attempt/旧轮次回执与决定迟到 | 只留证据或拒绝，不改当前任务 |
| B08 | 两个不同待决同时到达 | 第一个不被覆盖，第二个来源和拒绝原因可查 |
| B09 | 控制文件损坏/旧字段冲突/未知版本 | 拒绝推进，错误包含位置，不填默认成功 |
| B10 | 宿主关闭与裁决完成竞争 | 无关闭后的新派发，停止失败保留占位 |
| B11 | Git提交成功但办理落盘失败 | 合法重放不重复提交，证据绑定正确 |
| B12 | 清理工作树与派发竞争 | 同根互斥有效，活写者工作树不被删 |
| B13 | 批量中一项失败、其他项完成 | 逐项报告，不把部分成功写成全成功 |
| B14 | 单卡/批量/工作流相同回执 | 共用完成规则，保留各入口原有提交策略 |
| B15 | 未注册工具/关键模块装配中途失败 | 会话不能派发，资源清理或停止未确认可见 |
| B16 | 工具action与字段混用后纠正 | 第一次无副作用，合法第二次可继续 |
| B17 | 独立审核副本新增检查脚本 | 只提交审核证据，不合并脚本，不误判原成果已被改 |
| B18 | 超过原预算/回边/派卡额度 | 明确停止，重试不重置额度 |
| B19 | 地图采集中现场改变或读取失败 | 不生成可被当作有效的一半旧一半新地图 |
| B20 | CLI/桌面对同一停因查询与处理 | 业务状态及权限一致，界面不自行放行 |

B01—B04至少覆盖有人/无人值守；B10—B12须有真实进程或真实Git证据，不能仅模拟布尔值。中断阶段仍须覆盖§8.3，案例可共用夹具但不能省略断言。

### 13.4 产品装配和运行证据

- 正常四部门链用既有bench正式入口、真实主控/部长/工人子进程、真实Git运行，从受理到审核和完成；每轮不超过现有10分钟彩排上限。
- 各异常不都需要完整四部门链。参数/纯状态可在定向层验证；跨进程、路由、装配和停止必须提升到实际产品入口。
- 正常链至少跑一次最终构建；若其后修改影响装配/交接的源码，重跑受影响检查及正常链，不重复无关测试。
- Windows本地目录包：使用隔离用户数据与PAO_HOME，验证启动、普通任务、待决显示/合法处理、关闭后受控恢复、工作树使用；隐藏真实凭证，不连接付费供应商。实际界面按产品支持的测试方式驱动，不用直接改状态伪造通过。
- Linux离线产品路径按既有WSL/容器方案验证，必须具备相应操作授权及环境。缺前置时列为未验，S7跨平台装配项不能标通过；不自动安装系统依赖。

### 13.5 结构收敛的硬指标

| 指标 | S7必须达到 |
|---|---|
| 停因决策来源 | 内部只消费标准停因；旧字段只在兼容边界编解码 |
| 文案参与决策 | 当前格式正常路径为0；旧未知文本不自动放行 |

## 16. 阶段失败、回退与交接

### 16.1 失败处理

- 正确性失败：保留失败证据，修当前阶段根因；不能以更新预期、跳过用例、放宽超时或降低权限保护消除红灯。
- 性能未达标：单列未完成，不拿正常链通过代替性能验收。
- 发现缺少产品决定：列出具体冲突、受影响行为和一个推荐方案，暂停依赖该决定的写入；可继续独立验证。
- 发现相关源码已由其他工作修改：重新对照当前内容和基线，保留双方修改；不直接checkout/reset。

### 16.2 回退

每阶段保留本阶段差异及必要隔离数据快照。回退仅撤销本阶段自己的修改，不能恢复整仓覆盖其他成果。生产运行数据不在本轮迁移范围；本地验收使用新隔离目录。Git提交、已交付成果和停止未确认的进程不能通过改状态“回滚”，须按真实事实与原保护处理。

### 16.3 最终交付清单

每个小任务开始前，用以下六行写在所属阶段记录中；结束后直接补结果，不新建同义任务系统：

| 项目 | 必填内容 |

| 任务 | 本文小任务编号及当前实际源码版本 |
