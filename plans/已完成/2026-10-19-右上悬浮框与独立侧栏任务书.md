## 1. 目标与决定依据

把现有绑定在一起的右侧状态区和工具区拆成两个独立区域：右上悬浮框负责概况，右侧工具栏负责查看和操作工具。辅助对话采用 Codex 侧边聊天的使用方式，具备主对话上下文，只允许读取、问答和分析。

此前[方案 B 交接](../../.pao/harness完善-20261017/交接-右侧状态区方案B-20261019.md)保留为历史调查入口。其中“状态区与工具一起收起”“打开工具强制展开状态区”“收起后只靠顶栏找回”均被本任务的新决定替代。旧代码路径、行号、测试数量、哈希和安装状态只是历史证据，实施前重新核对。

用户明确的协作要求：**“具体实施派子代理，主对话负责理解需求、派发、验收审核、校准方向。”** 本任务必须按此分工执行，不能以赶进度或子代理不可用为由改成主对话直接实施。

## 2. 已确认的产品要求

### 2.1 布局与开关

| 编号 | 要求 | 可观察结果 |
|---|---|---|
| R01 | 悬浮框锚定主对话区右上方 | 不随聊天正文滚走；侧栏打开后跟随主区右边界向左移动，不盖在侧栏上 |
| R02 | 悬浮框展开时给内容留出宽度 | 正文与输入区域不被悬浮框遮挡；收起后归还这部分宽度，右上仅留短条 |
| R03 | 悬浮框与右侧工具栏分别开关 | 开终端不强制展开悬浮框，收起悬浮框不关终端；侧栏关闭后不留 40px 窄边 |
| R04 | 窄窗优先主区 | 沿用 980px 窄窗阈值；无手动偏好时宽窗默认展开、窄窗默认短条。侧栏打开导致主区不足以展示两者时，悬浮框自动收成短条，仍可手动展开 |
| R05 | 记住用户选择 | 手动展开／收起按现有窗口偏好机制保存；因空间不足自动收起不覆盖手动偏好，空间恢复时按偏好恢复 |
| R06 | 工具栏保留现有能力 | 关闭后完全归还宽度；再次打开保留标签和内容。窗口缩放、拖动宽度、快捷键及焦点行为继续可用 |

“悬浮框”指右上卡片外观及固定位置；展开时必须为正文留出空间。不要把整个聊天容器改成额外一列后，在卡片收起时仍保留空列。短条不能覆盖顶栏、聊天操作按钮或输入控件。

主区不足的判定由实施者依据现有最小宽度和真实界面验证确定，不另造一组无依据断点。用户手动展开后，允许以受限宽度查看内容，但必须无横向溢出、内容可滚动、可再次收起。

### 2.2 悬浮框内容

从上到下固定为文件变更、目标与待办、部门概况，各分区可以折叠。已完成事项默认折叠，完整内容可展开读取。

| 分区 | 显示内容 | 点击后的行为 |
|---|---|---|
| 文件变更 | 当前工作目录全部未提交变更的文件数、增加／删除行数；明确显示统计范围 | 在右侧工具栏打开现有差异查看器 |
| 目标与待办 | 当前会话已经确认的任务／计划目标列表，每个目标可展开已有步骤或待办，明确标出正在执行的目标 | 查看完整要求或对应计划；复杂内容沿现有详情入口展示 |
| 部门概况 | 当前会话所关联工作的部门名称、当前任务、完成进度、等待确认或失败提示 | 打开侧栏并定位对应工作流／部门的执行详情 |

统计与关联要求：

- 文件变更包含用户手动修改和其他代理修改，不能标成“当前助手修改”；工作树存在时使用当前实际工作目录，不混入别的工作树。非 Git 目录、读取失败、无法统计的文件如实显示，不能当成零变更。
- 复用已有计划、待办、卡片、工作流与部门数据；不新增第二套执行状态。单独的会话待办不得凭空绑定到某个目标，无法关联时明确作为会话待办展示。
- 多个目标不能默认以“最近创建”冒充“正在执行”；沿实际运行关联确定执行状态，不新增自动执行或长期目标循环。
- 部门概况只展示当前项目和当前主会话所属工作，多个工作流保留归属标识，不混入其他主控任务。点击哪个部门，就定位哪个工作流下的部门。
- 收起短条优先显示进行中事项；失败或待确认时给出提示。没有目标时显示“当前工作”，仍可展开查看文件变更。加载中、无内容、读取失败分别展示。
- 内容过长可展开阅读全文，不把长路径和完整任务书默认堆在概况里；控制分区高度，避免多层滚动导致下方内容无法到达。

### 2.3 右侧工具栏

侧栏以标签切换辅助对话、终端和当前工作流部门执行详情，保留既有文件浏览、文件查看／编辑与差异查看能力。截图里的浏览器、Git 提交／推送、目标暂停按钮等不因出现在参考图中自动纳入需求。

部门执行详情展示步骤、工人状态、真实执行记录、交付结果及对应会话入口。该详情在本任务中只读；调整任务、重试、取消等意图带回来源主对话处理，不在详情里增加直接控制入口。主页面已有的授权操作不因本任务被删除。

从悬浮框点击部门时自动选择或打开对应详情标签；同一对象复用标签，不无故重复创建。找不到运行会话或记录时解释缺失，不编造“运行中”、实时输出或交付成功。

### 2.4 辅助对话

| 编号 | 要求 | 具体边界 |
|---|---|---|
| A01 | 拥有主对话上下文 | 继承主对话当前完整有效上下文，包括需求、已定决定、工具结果及可用附件；已有压缩记录按主对话同一机制继承，不额外缩成简略摘要 |
| A02 | 问答前同步进展 | 每次发送前获取主对话最新可用记录；主控正在运行也可提问，不要求暂停、取消或转移主控 |
| A03 | 保持自己的连续对话 | 同步主对话时保留辅助对话已有问答，不把同一段主对话反复追加；明确区分主对话资料与用户在辅助对话提出的新问题 |
| A04 | 仅可读取和分析 | 允许读文件、搜索代码、查看差异、任务状态和执行记录；不提供修改、任意终端执行、派发、停止／重试、审批、提交／推送或工作流控制能力 |
| A05 | 单独保存与隔离 | 每个主会话保存自己的辅助对话；切主会话时切换对应记录，不串项目／工作树；关闭侧栏不删除，重开应用后可恢复 |
| A06 | 不自动回传 | 辅助对话问答不自动插入主对话，不自动改变目标、待办或任务状态；可选中结论带入来源主对话输入框，由用户确认发送 |
| A07 | 辅助对话中的明确写请求仍不执行 | 用户在辅助对话要求“修改／运行／派发”时，说明该处只读，并提供带回主对话的入口，不能静默升级权限 |

实施必须满足以下约束：

- **只读在宿主／工具调用入口实际强制执行，不能仅靠提示词或隐藏按钮。** 只暴露核实过的读取工具，禁止借任意 Shell、可写 MCP、扩展动作或子代理间接执行。复用现有权限机制，确有缺口时只补本项所需的小接口。
- 历史中的主对话执行指令只是阅读材料，不能因为继承上下文就继承主控的执行权限；当前辅助对话身份和限制必须优先生效。
- 同步读取一个一致的会话边界；正在输出且尚未完成的记录如实标注。若同步失败、附件无法读取或上下文缺失，显示限制，不能宣称已获得全部上下文。文件实际变化与历史工具结果有差异时说明来源。
- 不为辅助对话另建通用 Agent 平台、第二套记忆库或工作流引擎；优先复用 pi 公开的会话、上下文、压缩和工具配置接口。辅助对话自身问答记录的持久化属于必要应用存储，不授予模型任意文件写权限。
- “带回主对话”复用现有草稿与来源会话校验；不能覆盖非空草稿、发送到另一个主控，或把预填草稿说成已经执行。

## 4. 子代理工作纪律

### 4.1 职责不可混用

| 角色 | 负责 | 不得代替 |
|---|---|---|
| 主对话 | 理解需求、维护任务边界、确定接口与顺序、派发、接收成果、整合、复核与验收、向用户解释取舍和校准方向 | 不直接编写或修改产品实现及配套测试来代替子代理；不能把自己完成的实现冒称子代理成果 |
| 实施子代理 | 在明确分配的文件与模块内调查、编码、编写必要测试、执行检查、修复问题、交付证据 | 不自行改变用户决定，不越界重构，不发布／装机，不替主对话宣布整项验收完成 |
| 独立审查子代理 | 在实现后核查需求、代码和证据，检查越权、串会话和界面回归，报告问题及不确定性 | 不仅凭实施者自报通过就给结论；不得在没有重新分配写权限时顺手修改他人模块 |

主对话可以编写任务书／报告、读取代码、运行必要复核和集成验证、展示原型或截图。产品或测试出现集成问题，回派有明确归属的子代理修复；不得用“整合”作为直接接管实现的理由。

### 4.2 每次派发必须具体

每个子任务必须给出目标、已确认要求、读取入口、允许修改的文件／模块、依赖接口、禁止事项、验收方法，以及交付格式。允许读取相关代码以调查影响面；修改范围之外的必要调整先回报主对话，由主对话重新分配，不能同时修改同一文件。

并行仅用于真实独立工作：先固定共享契约，再让不同模块实施。`App.tsx`、contracts、翻译文件及共享测试助手由主对话指定唯一修改者；依赖该接口的子代理等待接口落定，不能各造一份协议。

### 4.3 失败、偏离与复核

- 子代理启动失败或工具不可用必须如实报告；截至本任务编制时，本会话两次调研子代理均因模型路由不兼容未启动，不能算已完成调查。后续开工先确认能实际派发；若仍不可用，停止依赖子代理的实施并报告阻塞，不由主对话自行接管代码。
- 不擅自修改全局模型路由、账号、工具链或系统配置来恢复子代理；不擅自替换用户已经指定的模型。
- 主对话对所有结论负责：核对实际文件与差异、抽查测试是否覆盖需求，运行关键独立复核。发现误解及时回派修正，不将判断责任推给子代理。
- 发现会改变产品行为、数据归属或权限的缺口，先说明证据和推荐处理，再由主对话判断是否需要用户决定；普通可撤销的实现选择自行解决，不重复询问已定事项。
- 实施和审查结论必须区分已修改、静态检查通过、真实 Electron 运行通过和未验证，不用模拟结果代替真实集成结论，不靠放宽断言或提高超时换通过。
- 不 reset、stash、覆盖、删除或一起提交他轮成果。长脚本先落文件；临时产物放工作区级 `临时文件夹/<任务简称>-YYYYMMDD/`。只清理本轮创建且确认无用的文件与进程。

### 4.4 子代理统一交付格式

每次交付至少包含：完成的需求编号；修改文件和关键入口；复用／接口选择及原因；运行命令、退出结果和日志位置；真实集成与模拟验证的区别；已知问题、未验证项和需要主对话处理的依赖。不输出凭证，不把“已写测试”写成“测试通过”。

## 5. 实施顺序与分配建议

以下是工作包划分，不另建状态表；同一工作包可以由同一子代理分轮执行。

| 工作包 | 负责范围 | 开工依赖 | 交付给主对话的内容 |
