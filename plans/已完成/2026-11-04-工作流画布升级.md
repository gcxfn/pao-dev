## 1. 目标

同一画布提供实例监控与配方编辑两态。监控优先展示节点状态、监督身份、按需读取的结果和会话，支持向 worker、部长、主控注入意见；配方态复用既有编辑器。新增无模型会话的脚本执行方式，生成步骤由脚本及产物声明表达。

监控显示最近一次读取的事实；快照时间与手动刷新可见，不承诺持续实时更新。

| 编号 | 决定 | 实施口径 |
|---|---|---|

## 4. 实施批次与规格

### 4.0 批次依赖与执行约束

推荐执行顺序：**0 → 1 → 4 → 2 → 2p → 3a → 3b-E → 3b-U**。

| 批 | 必需前置 | 独立交付边界 |
|---|---|---|
| 0 最小投影 | 无 | 类型、身份、轮次、回边计数贯通内核至桌面 |
| 1 类型与折叠 | 0 | 正确类型、懒加载详情、实例分组 |
| 4 编辑整合 | 1 | 监控跳编辑与既有编辑能力整合，不依赖脚本 |
| 2 会话与监督 | 0、1 | 会话读取、身份及状态、跳转 |
| 2p 媒体预览 | 1 | 真实资源读取与右侧预览 |
| 3a 注入 | 2、内核能力评审 | 三目标真实投递与审计 |
| 3b-E 脚本执行 | 0、内核执行评审 | schema、执行生命周期、日志与回执 |
| 3b-U 脚本编辑 | 3b-E、4、2p | 编辑、冻结正文、对话回填与产物预览联验 |

批次编号是稳定引用，不代表执行顺序。3a 与 3b-E 的能力评审分别进行；某项技术缺口不阻塞无依赖的批次。

实施者可自主选择组件拆分、内部函数名及测试组织，需保持本节的公开字段、行为和依赖。预计触点是边界提示：调用链中的必要文件可直接补齐，在证据报告中说明职责；不得借此扩展其他模块重构。

内核评审由实施者完成：查明现有调用链、选定一个最小方案、把具体入口与结果契约写入相应小节，然后实施。只有需要改变产品语义、增加依赖或扩大宿主支持范围时才提交用户决定；不得把“待评审”当作重复请示许可的理由。不能实现已定能力时明确登记缺口，不以隐藏入口或仅模拟响应验收。

### 批 0 最小数据投影

字段沿内核 → pi-sdk-driver → main 查询整形 → contracts → renderer 完整贯通：

| 位置 | 字段 | 来源与含义 |
|---|---|---|
| CanvasNodeTemplate、CanvasNodeInstanceRow | `isReview?: boolean`、`readOnly?: boolean`、`executionMode?: "直接" \| "拆解" \| "脚本"` | 配方审核、只读及执行方式；实例只取冻结配方；脚本值在 3b-E 启用 |

| CanvasNodeInstanceRow | `ministerSessionId?: string`、`round?: number` | 当前节点绑定及轮次，round 不表示回退次数 |

### 批 1 类型化、详情折叠与实例分组

**类型**：同一纯函数生成有序徽标：审核、只读、执行方式、人工门、汇合、分支、并行。执行方式为直接显示“直执”，脚本启用后显示“脚本”；拆解保持普通卡体。人工门处于等待确认时激活。全卡展示全部徽标，紧凑档保留一个主类型短标，胶囊档只保留状态、类型经选中详情查看；不以类型覆盖状态色。

源节点至少两条普通出边，且目标存在至少两个不同的非空 branchId 时显示“分支展开”标记。排除审核回边；不表达互斥选择、不添加调度语义。回边显示“退回请求 N 次 / 上限 L · 超限动作”；L=0 显示“不限次数”；N 缺失只显示限额与动作。

**详情**：顺序为基本 → 会话（批 2）→ 输入与输出 → 回执轮次 → 产物 → 用量与错误 → 执行日志 → 监督（批 2）→ 注入（批 3a）。复用同一折叠组件，实例与节点切换后重置。

- 基本区仅使用当前快照。缺少实际 tier 等深读字段时显示“展开详情查看”，不为填满基本区自动深读。
- 首次展开输入与输出、回执、产物、用量或日志时调用一次 getCanvasNodeDetail；同实例、节点、所选卡的其他分区复用该结果。请求在途时不重复发起，失败可手动重试。
- 当前快照状态为 failed 时默认展开回执并读取；历史失败但当前已恢复不触发自动展开。无详情时也保留产物区入口，展开后显示“尚无产物”，避免依赖未加载的数据决定入口是否存在。
- 折叠不重新读取；已发请求可完成并保留在当前选择内。切实例、节点或卡后不接收旧请求结果。手动刷新清除相应详情，只有展开的分区发起重读。
- 会话与媒体独立懒加载，不能由 getCanvasNodeDetail 顺带读取正文或媒体。已有 sessionStats 如会扫描日志，移至执行日志展开时读取；优先复用现有详情 IPC 增加明确的读取选项，不新增泛化查询框架。
- 回执集中到唯一分区；回执中的 attempt 是卡尝试号，节点 round 是流程轮次，分别标注。

**实例分组**：异常优先，其次进行中、已完结。异常包含 anomalies 和 frozenRecipeError；按实例 path 去重，正常组排除已列入异常的实例。组内保持既有顺序，空组隐藏，计数按实际显示行计算。

进行中：运行中、挂起、in_progress、running、paused 及未知值。已完结：已完成、completed、done、失败、failed、已取消、canceled。未知状态原样展示；挂起或单节点失败不自行推断为实例完结。

预计触点：canvas-model、canvas-page、instance-workflow-view、workflow-editor、node-runtime-details、现有样式、i18n、canvas 单测和 d5 spec；按日志统计读取拆分需要扩展既有详情契约及内核读取实现。

### 批 4 配方编辑整合

实例工具条与节点菜单提供“编辑此配方”，按实例 workflow 定位当前配方，同名节点存在则选中。配方存在但节点已改名时打开配方并提示节点不存在；配方已删除或改名时保留实例视图并说明无法定位，不自动新建或模糊匹配。当前配方有解析错误时显示现有配方错误入口。

从冻结实例切入磁盘配方时常显“编辑当前配方，仅影响后续实例”。返回监控保留原实例选择；离开未保存草稿沿用 canSelect/requestAction，取消离开时保持当前草稿与选择不变。

编辑态与监控态共用徽标推导。配方态无 identity 时只读并提示建立主控会话。实例结构、脚本与属性永远只读；运行操作不属于配方编辑。脚本属性的唯一实施归属为 3b-U。

预计触点：canvas-page、recipe-canvas-editor、workflow-editor、i18n、canvas 单测及 d5 spec。

### 批 2 会话与监督

**会话选择**：先按当前卡选择执行锚点，只展示当前节点 round 的会话。worker 使用 `{kind:"worker", executionId, offset}`；默认选择当前卡唯一 current 锚点，多卡或多 current 时保留可见选择器，不从不相关卡中按时间猜“最新”。历史 attempt 可以在当前轮节点详情已有锚点范围内选择；历史流程轮次不纳入本批。

部长使用 `{kind:"minister", instanceId, nodeName, round, offset}`，必须有真实 instanceId、round 和部长绑定。缺字段显示具体原因，不发空参数请求。只有部长缺绑定时，不应隐藏已有 worker 会话。

展开首读 offset=0；续读只使用返回 nextOffset；刷新从 0 替换内容；末行未完显示提示。切会话、卡、节点或实例时清空旧内容和 offset，旧返回不得追加到新目标；同一目标续读在途时禁用重复续读。失败保留已读正文及错误提示，允许重试。会话已结束仍可读历史正文，读取失败不等于会话已结束。

**监督**：主控在实例头部、部长在节点卡与监督区展示。身份来自批 0，状态来自宿主现有会话/监督事实，禁止从“有 sessionId”推导存活或空闲。批 2 实施时把所复用查询入口与已有状态枚举写入此节；若已有查询未覆盖，扩展只读投影，不新增状态存储。

批 2 技术绑定（2026-11-04 侦察后写入）：会话正文入口＝`getWorkboardSession`（contracts/kanban `WorkboardSessionInput` 已双 kind：`{kind:"worker",executionId,offset?}` 与 `{kind:"minister",instanceId,nodeName,round,offset?}`；`expectWorkboardSessionInput` 已严格解码）；底层＝内核 `readDesktopExecution`/`readDesktopWorkflowMinister` 共用 `readDesktopSessionIncrement`（offset/nextOffset/more/incomplete 语义）。worker 锚点＝`CanvasNodeExecutionRef`（execId/attempt/current，按所选卡过滤）。部长绑定＝`ministerSessionId`（有绑定判定）+`instanceId`+`round`（读取必需，缺则不发请求）。部长存活＝宿主 `readDesktopMinisters(owner)` 热会话集合 → main 侧差集出 `deadMinisters` 传 `readDesktopCanvasFresh`/`readDesktopFlowsFresh`（入口已支持，当前未传参），渲染口径复用 `ministerDropped`（绑定无热进程＝已断开）。worker 活性＝`readDesktopWorkerActivity`（`project.liveness`/KanbanCardActivity；canvas 投影现未带，需要则新接只读投影，不得把 `sessionState` 当存活——后者是执行映射登记状态）。owner 状态＝无宿主 busy/存活投影，落「状态未知」；「会话存在」按 `onOpenSessionThread` 线程存在性。状态枚举：部长＝断开(holdKind=minister_disconnected)/未绑定/不适用/未知；owner＝身份未知/状态未知/线程存在可跳。渲染语义复用 `execution-session-view`（requestId 守卫、刷新替换、续读追加、失败保留正文）。

有身份而无状态显示“状态未知”；直接/脚本节点的部长显示“不适用”；拆解节点未绑定显示“尚未绑定”；主控身份缺失显示“身份未知”。点击部长展开对应会话，主控沿 onOpenSessionThread 跳转，找不到线程时留在原处显示原因。每个状态展示读取时间，手动刷新沿已有入口。

预计触点：会话共享加载/行渲染件、canvas-page、node-runtime-details、监督查询适配、必要的只读契约投影、i18n、定向测试。会话正文复用 getWorkboardSession。

### 批 2p 产物媒体预览

产物依据所选卡的回执展示，标注 attempt；相同路径可合并为一项并保留来源尝试号。主进程接受实例、节点、卡、产物路径选择子，核对其来自对应回执后解析；renderer 不自行构造本地资源 URL。

旧回执沿既有产物路径约定解析；若记录无法确定基准，显示原因，不在卡目录与项目根之间试探并打开同名文件。脚本新产物统一按项目根解析。

媒体读取接口至少返回：解析后的展示路径、媒体类型、sizeBytes、可消费资源或明确失败原因。沿现有 Electron 文件访问边界提供资源；二进制不经文本预览解码。读取方式与资源释放入口在本批实现前补入本节。仅对当前展开的产物请求内容，单文件大于 20 MiB 时只给打开入口；切换或关闭预览释放本次资源。

批 2p 技术绑定（2026-11-04 侦察后写入）：资源读取＝主进程按选择子核对回执白名单→execution-context 定基准（相对路径先查该 attempt 绑定 executionRoot，无绑定/损坏→projectRootForCards 或显式报原因不回退）→realpath 边界→stat 分流（>20MiB 返回 too-large 只给打开入口）→读字节 **data: URI 快照**（base64+mime 经 IPC 返回，满足「打开时取得的固定内容」；不用 pao-media:// 自定义协议——URL 指向可变文件违反快照口径）。释放＝预览状态以产物身份+打开时刻为键，切产物/折叠/切详情键丢弃载荷（data: 无句柄无需 revoke；视频若内部用 blob 则 cleanup revokeObjectURL）；不建主进程资源表。MIME 只按扩展名映射（image:png/jpg/jpeg/webp/gif/svg；video:mp4/webm/mov；其余→text 白名单），不做内容嗅探；SVG 经 `<img src=data:...>`（不 innerHTML/object）；视频解码不支持由 `<video onerror>` 回落显示原因+打开入口。「打开」＝shell.openPath / 定位＝showItemInFolder（复用 openCanvasCard 核对链形态）。白名单核对形态抄 temporary-plans-query `readArtifactContent` 三段检查（身份→范围→目标），基准核真值抄 plans.ts `artifactOf` 口径（越界不展示、exists:false 标原因、symlink/junction 逐段拒绝），不直接复用其白名单数据源（它是临时计划投影非卡回执）。

图片 png/jpg/jpeg/webp/gif/svg 用图片元素显示缩略，点击在右侧放大；视频 mp4/webm/mov 用 video controls，不自动播放。扩展名用于选择展示方式，解码不支持时显示原因并提供打开入口。其他文件复用文本/文件打开入口，SVG 不作为 HTML 注入。

预览表示打开时取得的内容；普通刷新不抢换当前预览，用户选择重新打开才取新内容。历史回执路径没有历史文件副本时明确显示“当前路径内容”，不宣称历史版本可还原。媒体承载方式必须支持这一口径，不能拿持续读取可变文件的地址宣称已固定版本。

预计触点：媒体读取契约、main/preload 对应接线、现有文件访问与预览模块、产物分区、i18n、媒体夹具与定向 spec。保持单一媒体入口，不重建文件管理器。

### 批 3a 三目标注入

走 controlWorkflow → runDesktopFlowCommand 链扩展 inject。命令以 action/target 区分字段，不让 confirm/pause/resume 承担新动作的必填字段。

| 目标 | 必填身份 | 接受条件 |
|---|---|---|
| owner | workspaceId、发起 sessionId、instanceId、text | 发起者属于当前 owner；目标 owner 存活且空闲；不要求伪造 nodeName/round |
| minister | 公共身份、nodeName、round、text | 当前轮次绑定部长，实际热会话匹配；复用绑定部长投递 |
| worker | 公共身份、nodeName、round、cardRef、executionId、attempt、text | 卡与执行均属于当前节点当前轮，attempt 当前且执行在途；不向同节点另一 worker 代投 |

输入 text 非空、最多 100000 字符；owner 沿既有斜杠命令拒绝语义，worker/minister 作为普通消息正文。目标变动或过期直接拒绝并提示刷新，不自动重定向或重试。

结果为带目标实际标识的已投递、已排队、拒绝及原因；“已投递”只代表宿主接受，不代表模型已执行意见。“已排队”仅在底层真实排队时返回，不自建持久消息队列。超时或连接中断而无法确认接受结果时显示“结果未知，请查看目标会话”，不自动重发。

内核评审必须写明 worker 的真实入口、可投递时机和队列行为；部长复用 host.inject/followUp；owner 复用 sendDesktopChat。若 worker 需要新增跨进程传输，限于该执行宿主的窄消息入口，不重建 worker 控制协议。排队消息不得跨 execution 或部长绑定迁移。

审计复用 flow.记录，事件 inject，理由包含目标、实际会话/执行标识、结果和最多 200 字符摘要；worker 同时记录卡与 attempt。owner 记录不伪造节点和轮次。身份校验失败不写入无权限目标；已核对身份的投递结果应记录。投递已被接受但审计写入失败时如实返回两项事实，不提示重新发送。

注入动作本身不确认人工门、不写执行回执、不直接改卡或推进流程；接收会话随后通过正常工具产生的动作照常生效。

节点面板默认唯一在途 worker；多个 worker 时明确选择；无 worker 时选可用部长，再无则选 owner。实例入口默认 owner。显示具体目标身份，发送在途禁重复点击；拒绝保留正文，接受后清空。切目标保留正文但更新目标标识，切节点离开有正文时沿已有草稿离开守卫。脚本节点不提供 worker/minister 注入。

预计触点：workflow-control 契约、tools schema、flow-control-payload、control 审计、宿主投递、driver/main 适配、canvas 注入区及定向测试。

### 批 3b-E 脚本 schema 与执行生命周期

**schema**：执行方式增加“脚本”；脚本为必填非空正文，UTF-8 编码最多 64 KiB；超时为可选正整数秒，默认 300；产物为可选非空相对路径列表。正文限额由内核与编辑器采用同一计算口径，不以 JavaScript 字符数代替字节数。脚本节点禁止只读、审核及显式工人数量；解析器不得先补默认工人数量再把所有脚本节点拒绝。模型/思考强度等模型专属字段不参与脚本执行，编辑器不显示相应输入。

首批脚本语言为 PowerShell，复用内核 shell 定位逻辑，记录实际解释器路径与版本；不静默回退到 cmd/bash。无解释器显式失败，不安装全局工具。执行评审需落实无交互启动参数、UTF-8 文件读取及原生命令退出码处理；脚本正文应显式检查原生命令失败并返回退出码，不把 PowerShell 最后一条表达式等同整个脚本成功。

工作目录为项目根，脚本物化到实例运行目录并按节点、round、attempt 区分。只冻结正文，不冻结解释器、项目内容、依赖和环境。现有配方参数替换对脚本正文不做无差别字符串插值；本批脚本正文按原文执行，生成时由主控写定需要的值。产物路径按现有配方参数代入规则处理，内核解析后以项目根为基准，拒绝逃出该基准的声明。工作目录约定不是进程沙箱。

**执行**：一节点单卡，无模型和部长。工作流层只决定就绪与推进；执行层拉起、停止进程并收集结果；卡模块写日志和回执。复用现有认领与 attempt 入口，一次认领只启动一个执行，页面刷新或查询不得触发执行。

| 结果 | 卡回执口径 |
|---|---|
| 退出 0 且声明产物均存在 | 成功，summary 记录退出结果，artifacts 写实际存在的声明产物 |
| 非零退出 | failureType=`script_exit:<code>`，保留退出码和日志摘要 |
| 启动失败 | failureType=`script_start`，保留解释器或创建进程错误 |
| 超时 | 终止本次进程树后 failureType=`script_timeout` |
| 用户停止 | 沿既有卡取消终态；不自动重试，不伪装成功或超时 |
| 退出 0 但声明产物缺失 | failureType=`script_artifact_missing`，列出缺失项；已有产物可作为诊断结果保留 |
| 宿主中断 | 标记执行中断并进入现有恢复流程；不得仅凭旧 PID 存在认定仍在执行，不自动重复运行 |

复用进程树终止能力，停止/超时完成后才结算；终止失败则保持需恢复状态并说明原因，不报告已停止。正常退出与停止收口沿同一完成入口，单次执行只产生一次终态回执。

stdout/stderr 执行期间分别有界保留尾部，各最多 64 KiB，写卡时注明流名及是否截断。完整日志不是本批承诺；不先无限缓冲到退出再截断。临时脚本随对应运行留档，不写开发源码目录或工作区根。

重试复用现有 attempt 及流程轮次机制，不增加独立重试循环；脚本可能重复外部副作用，宿主中断后的重新执行须走已有人工恢复。前置依赖与审核回边兼容；人工确认仍是执行交付后、下游放行前的门。用量显示“脚本节点无模型用量”，不补零 token。

执行评审需在此节补齐所复用的认领、停止、回执与恢复函数，以及新 failureType 与现有回执校验的对应；不得只做退出码包装而跳过卡状态机。CLI 与桌面走同一执行入口。

唯一属性入口为 RecipeCanvasEditor：执行方式切换、脚本文本、超时、产物路径。等宽纯文本，不引入编辑器依赖。切换执行方式会影响字段时在草稿中明确展示并清理不适用字段；取消离开保留原草稿。保存仍走 saveWorkflowRecipe/saveDesktopRecipe 的 revision、确认、备份链。
