## 四、本地修正四则（外部方案不知道的事实）

1. **配方 schema 落在既有 parseRecipe 文本格式上扩展**（nodes/edges/positions 作为扩展字段，如 `recipe.ui.positions`），不另起 JSON 新 schema；卡协议 14 字段中文键冻结不动。

4. **不外发仓库地址**：fork 私有仓不可推；代码对位与改造任务书由主会话基于本地仓自出。

1. 看板积压卡点击无反应 → 点开卡详情（回执轮次视图）
2. 配方库选中无反应 → 选中即加载画布（并入新形态）

4. 「工作流画布」→「工作流」：i18n zh/en 两字典＋入口文案（独立小改）
5. **主控对话切走再切回消失（2026-10-07 诊断）**：主控对话面板挂载条件绑定**全局当前会话**（`desktop/apps/desktop/src/features/canvas/canvas-page.tsx:634-637` 要求 `chatTarget`＝标签主控才渲染），用户切普通对话后全局选择变化，切回画布面板整块不渲染。修法：切回画布视图时若活动标签已绑定主控，自动按标签重新激活（复用 `activateWorkflowController` 语义），**标签绑定是唯一事实源**，不依赖离开前的全局选择；顺带纠正跨项目切换后画布 workspace 跟错的问题。
6. **主控对话不跟随最新消息（2026-10-07 诊断）**：时间线视口 hook 只在 threads 视图视为活跃（`desktop/apps/desktop/src/app/App.tsx:314` `active: activeView === "threads"`），画布内嵌期间新消息不自动滚动、切回时恢复离开时的旧位置而非最新。修法：`active` 条件纳入 canvas 视图；沿用该 hook 既有纪律——仅 following 态自动滚底，用户上翻历史时不打扰。
7. **主进程 EPIPE 崩溃弹窗（2026-10-07 报）**：`Uncaught Exception: Error: EPIPE: broken pipe, write at Socket.write … console.error → electron sendInternal`——主进程向已关闭的管道写日志触发未捕获异常弹窗（典型场景：启动终端／子进程管道先于主进程关闭）。修法方向：主进程对 `process.stdout/stderr` 注册管道 error 兜底（吞 EPIPE 类）＋`uncaughtException` 钩子对 EPIPE 静默记日志不弹窗；实施时复现定位具体是哪条管道（dev 终端／渲染进程／子进程 stdio）。
8. **pao_推流阻塞主控（2026-10-07 报，内核行为）**：自动执行配方的推流在**工具调用内同步跑完整条自动链**——`tickWorkflowCore`（`PAO/packages/coding-agent/src/pao/workflow/tools.ts:130`）`await runAutoChain`，后者 `await Promise.allSettled(各卡 runChainForCard)`（`workflow/auto.ts:124`），卡链内 `executeDispatch` 等 worker 子会话真实执行完产出回执（分钟～小时级）——期间主控回合一直挂着，UI 表现为主控被阻塞。定调（用户）：**推流是一次性动作，触发即返回**。修法方向：
   - 推流只做非阻塞段（tick 落卡＋派发），立即返回当前快照（已落卡／已派发节点清单）；
   - 后续链步（回执→越界核查→验收→交卷→再 tick 解锁下游）由**后台驱动器**异步推进，回执落卡事件触发续跑；既有 dispatch 文件锁天然防双跑（锁被占时推流返回「链进行中」）；
   - owner 校验／暂停／signal 中止／maxCards 语义保持；链停因通过系统提醒注入通知主控（复用 afterToolCall／事件通道），不再靠工具同步返回报告；
   - 后台推进事件同时作为 8.4 运行动画的数据源（一处事件，两处消费）。
9. **残留会话锁挡住主控（2026-10-07 报，列入计划）**：`[builtin:pao] before_provider_request: Error: 残留会话锁须显式接管，原控制标识：<uuid>`——进程异常退出（含 bug 7 的 EPIPE 崩溃）未走 release，`<PAO_HOME>/.pao/运行时锁/` 下 owner json 残留；同会话再驱动时 fail-closed 拒绝自动接管（`PAO/packages/coding-agent/src/pao/runtime/session-lock.ts:48`）。fail-closed 是刻意设计（防双驱动），与 §五「孤儿须显式接管」红线一致，**不放宽自动接管**；缺口＝恢复体验：显式接管目前只有模型侧工具入口（`runtime/index.ts`「查看控制权或显式接管残留会话锁」），用户侧无便捷入口、报错文案也没说怎么接。修法方向：①桌面/TUI 提供一键接管入口，报错文案给出具体操作路径；②与 bug 7 EPIPE 修复联动减少残留源。

## 七、实施路线（画布优先五步，已拍板）

### 实施前补齐（2026-10-05 用户采纳）

1. **节点坐标贯通保存链路**：在既有配方格式保留 `ui.positions`，保存、重开、启动冻结、重新查看实例均使用同一份坐标；无坐标的旧配方才使用默认布局。
2. **旧实例读取启动时的图**：读取实例已有的冻结配方，不再按名字读取最新配方。配方后来增删节点、修改依赖或坐标，都不能改变旧实例的展示。现状定位：`桌面端/apps/desktop/src/features/canvas/canvas-model.ts` 的实例图构造。
3. **启动先保存并检查**：未保存时点击启动，先完成保存与配方检查，再冻结保存成功的本次版本；保存或检查失败不启动、不落执行卡。不能让预览图与实际执行图不一致。
4. **属性对应真实执行能力**：首期节点为部门任务，连线为依赖及审核退回。逐项核实模型、思考、输入输出、审核等执行接口；只显示已经接通的可编辑项。开始、结束、工具节点及 Prompt、重试、超时控件不能因示意图存在便显示为可执行能力，未接通时不提供有效操作。
5. **完整处理未保存内容**：关闭标签、切换配方、退出程序时提供保存／放弃／取消；取消保留当前编辑内容，保存失败不关闭、不切换。不以 `dirty` 标记冒充草稿恢复。首期不恢复未保存草稿；若后续实施恢复，必须持久化完整草稿与来源版本，校验后恢复。
6. **看板状态操作遵守卡规则**：拖动不能直接把卡改成完成，也不能绕过派发和验收。只提供既有接口支持的合法操作，失败显示原因并刷新真实状态；卡仍是唯一真相源。
7. **连线校验三边界（2026-10-07 补，参照 pi-maestro-flow `src/gateway/board-contracts.ts` 三色 DFS 与 `board-store.ts` 转移表）**：① 环检测与悬空依赖（指向不存在节点）在配方**保存、读取、启动**三个边界都跑，非法连线在连线动作当场拒绝并提示，坏文件在读取时明确报错，不进内存；② 状态转移白名单（非法转移抛错，如完成不能改回执行中）；③ 激活/启动节点前依赖必须全部完成；④ 日后卡归档不得回收仍被依赖的卡。
