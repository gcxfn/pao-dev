## 推荐的部门设置第一版

设置增加“部门”，用于配置；原部门页面继续显示任务、进度和异常。界面直接读取当前实际生效的 PAO_HOME，不在 UI 状态中再存一份部门配置。

| 区域 | 用户能做什么 | 边界 |
|---|---|---|
| 部门名单 | 查看、新建部门、查看标签和配置问题 | 首版不做改名或删除，避免破坏历史任务与知识库引用 |
| 部门配方 | 编辑人设、干法和部门标准 | 保留现有未编辑字段，不重建整份模板覆盖用户内容 |
| 默认模型 | 选择已有模型档位，并看到实际供应商、模型和思考程度 | 卡片指定档位仍可覆盖部门默认；不另建一套模型选择规则 |
| 工具权限 | 勾选该部门工人可用的已有工具 | 明确只约束工人；命令执行的进一步保护另行设计 |

可附加展示关联技能与可用性，帮助理解哪些内容只在任务需要时加载。配置保存前校验；文件被别处修改时提示重载，不悄悄覆盖。保存默认作用于新派出的任务，不在执行中突然更换模型或权限。

复用依据：内核 `dept/registry.ts` 的注册表、`dept/catalog.ts` 的配方解析、`dept/scaffold.ts` 的建部入口及 `routing/config.ts` 的档位解析；桌面现有设置分组与部门运行页。编辑配方目前缺少统一受控保存入口，需要补在内核后再接桌面，不能由 renderer 随意写路径。现有工具字段支持 read、grep、find、ls、bash、powershell、write、edit。

## 命令保护：推荐先防误操作，再补恢复和隔离

| 顺序 | 机制 | 解决的问题 |
|---|---|---|
| 1 | 受控删除与编码转换入口 | 在操作发生前限制目标、明确影响，默认使用可恢复删除 |
| 2 | 危险修改前的保存点 | 保留当前改动，出错时能有依据地恢复 |
| 3 | 按需使用 Git worktree | 并行改代码或大范围试验时，使用独立工作目录减少相互干扰 |

删除建议：常规文件默认送系统回收站，显示精确目标与范围；回收失败就明确停止，不悄悄改成永久删除。硬删除保留为明确、单独授权的操作，不默认对所有执行开放。桌面可复用 [Electron shell.trashItem](https://www.electronjs.org/docs/latest/api/shell)，CLI 的同等能力须另行验证。大规模依赖缓存的删除仍需评估体积与可恢复性，不自动兜底硬删。

当前 `pao_preview_cleanup` / `pao_confirm_cleanup` 可复用目标预览与确认设计，但没有通用删除执行器；巡库 shell 护栏目前只在巡库环境启用，并非所有任务的通用隔离。仅拦截 rm/del/Remove-Item 文本仍可被 Python、Node 或其他程序绕过，不能承诺“所有删除必经回收站”。若要强保证，需要进一步限制进程的可写范围，属于另一层工程工作。另有可先收紧的具体路径：内核 `modes/interactive/components/session-selector.ts` 的会话删除在 trash 失败后会回退 unlink 永久删除；后续建议取消这一静默降级，桌面删除路径也须单独盘点，不能只修改一个入口后宣称全覆盖。

编码建议：普通编辑保留已有编码、换行与 BOM；新文件遵循项目默认 UTF-8，PowerShell 5.1 中文脚本按已有规则用 UTF-8 BOM。批量转换必须明确源编码、目标编码和文件清单，先预览、保留可恢复原件，再通过专用入口转换；未知编码不猜。不要依赖 shell 默认编码，也不默认允许 Get-Content | Set-Content 等整文件覆盖命令做转换。

保存点复用桌面已有 `TurnCheckpointStore`，不再新建快照引擎。现有机制保存 before/after tree，主要服务差异查看；当前调查未发现可直接复用的恢复入口，需要补恢复预演与冲突检查。当前默认捕获预算 2 秒、10,000 文件、64 MiB、单文件 16 MiB；忽略文件、嵌套仓库等不在完整保护范围，超限不能冒充备份成功。保存点须覆盖实际操作前的未提交修改和相关未跟踪文件，不能只记录 HEAD；不能把 Git 忽略文件或工作区外数据也说成已保护。恢复先显示差异，不能覆盖保存点之后的其他改动。现有认领基线只记录改动清单，用来核对越界，不是完整备份。

worktree 复用 [Git 原生能力](https://git-scm.com/docs/git-worktree)及桌面已有 `worktree-manager.ts`，只在并行编码、大改或试验时使用，普通小修改不默认创建。它提供独立检出目录，不限制程序访问其他目录；完成后仍需审查和合并，依赖安装及产物占用也要计算。

## token：建议按实际消耗排序推进

日志 gzip 节省磁盘，模型看到的内容和调用次数不变，不能把压缩率当作 token 节省率。

1. **先看现有原生用量**：按任务列输入、输出、缓存命中、模型调用与重试，先处理费用最高的实际来源；未知用量继续标未知。
2. **缩小工具回包**：默认返回命中位置、差异与必要尾部；完整输出留文件并给路径，需要时按段读取。现有 read 已支持分页，但其默认上限仍为 2,000 行或 50 KB，值得针对常用任务评估更小摘要。
3. **技能与工具按任务加载**：先测量每次实际激活的工具及其参数说明体积，再按角色和任务收窄。PAO 工具数量多，但静态定义数不能代表每次请求都发送了全部工具。继续复用部门配方和工作流的按需 skills，不把所有技能、工具说明与知识库内容都塞进每次上下文。
4. **减少重复读取和重复检查**：一次任务内复用已经核对的事实；只有文件变化、测试失败或新疑点时重跑相关检查，不靠跳过必要验收省 token。
5. **保持固定提示词稳定、任务交接简短**：动态状态与固定规则分开；给执行者目标、限制、验收条件和精确文件位置，回传摘要与证据指针，延续现有上下文隔离设计。

部门模型档位可帮助选择合适成本的模型，但不能代替减少无用上下文；调整模型及思考程度需结合任务效果评估，不默认全面降低质量门槛。
