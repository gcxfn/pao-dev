日期：2026-11-12。本文规定已完成阶段的需求、实现、效果与代码质量审核，以及审核后的优化路径；审核执行状态统一维护在 §10。

承接[内置记忆与受控自进化实施计划](2026-11-08-内置记忆与受控自进化实施计划.md)。原计划的阶段状态仍归其 §10，审核发现与处理情况归本计划及审核报告。核实日期：2026-11-12；本轮覆盖 S0—S9 的实现、验收声明及接入边界。

## 1. 目标与交付判断

判断持久记忆是否持续改善后续任务、自进化是否能产生有证据的有效改进，同时核实原计划的全部要求和实现质量。

审核分别给出四项结论：

| 目标 | 需要回答的问题 | 结论依据 |
|---|---|---|
| 需求兑现 | 设计、实施计划及详细路径的要求是否完整落地？ | 逐项要求、当前实现、真实调用链、行为证据 |
| 代码质量 | 规则、状态和职责是否清楚，是否存在值得处理的重复、无效层次或运行开销？ | 源码、调用者、生命周期、实际使用规模 |
| 机制借鉴 | 已决定采用的外部机制是否落实，项目取舍是否成立？ | 固定提交的参考源码、采用结论、PAO 对应实现与行为 |
| 实际效果 | 记忆是否减少重复解释和纠错，进化是否改善原问题且保持正常用法？ | 冻结任务对照、真实模型结果、执行回执、费用与失败样例 |

不使用综合分数抵消某项必要能力的失败。各模块分别说明已实现、已接入和已证明有效的范围；正确的实现直接确认。

## 2. 范围与执行边界

- 深入审核 S0—S9 涉及的 PAO 自有模块、测试、配置、提示词、资源、CLI 装配、桌面桥与界面、构建分发及相关文档。pi 上游沿实际接入边界阅读，必要时追踪调用。
- 需求覆盖包括设计正文、实施总计划、三份详细路径中的行为要求和完成判据，不能只核对阶段表中的文件名或函数名。
- S9 记录实际变更范围，核对发布、绑定、观察、回退与宿主接线；重点复核第三期交付报告中的真实改进、后台取消和双宿主使用证据。第三期交付结论以完整验收为前提。
- 本计划编制阶段只交付审核方案。后续启动审核、代码优化及真实付费验证，按用户执行授权推进；不把原计划首次真实验收不限预算的约定自动扩大为新一轮无限额度。
- 测试和候选运行使用隔离 PAO_HOME；实际项目任务使用明确授权的工作副本。正式现场切换继续沿原计划单独确认。
- 审核结论对应具体代码版本及相关工作区改动。只记录必要路径和版本信息，不复制全仓或新增摘要校验文件。

## 4. 审核方法与问题记录

### 4.1 需求覆盖

逐项登记原计划任务编号及详细路径中的补充要求，关联实现入口、实际调用者、测试和验收证据。共享要求只维护一条正文，通过引用关联多个任务。明确区分：

- 满足：实现与接线成立，证据支持相应完成判据。
- 部分满足或未满足：指出具体缺失行为与影响。
- 待验证：静态实现成立，但真实模型、宿主、发行物或实际效果证据不足。
- 在建：属于 S9 当前施工范围，记录补审入口。

报告写明各区域深入阅读、静态搜索、抽样及未覆盖范围。未读源码或失效证据不能支撑完整通过的结论。

### 4.2 代码质量

沿真实调用链判断业务规则的唯一归属、数据库与宿主状态的一致性、错误传播、取消及恢复、资源释放、公开契约和动态资源引用。调查重复读盘、重复模型调用、无用全量加载及随数据增长的开销；性能结论区分实测与静态推断。

结构优化不以发生故障为前提：能实质降低维护成本、消除重复规则或明确职责的调整也纳入建议。每项说明具体收益和保持的行为；不以文件长、调用者少或代码相似单独证明需要删改。删除前核对导出、动态引用、提示词和测试。

### 4.3 问题与优化建议

每项发现记录位置、需求依据、受支持的触发方式、证据、影响、最小修法及定向验证。区分需求遗漏、行为缺陷、验收缺口、结构优化和效果优化，按实际影响排序。

必要修正和新增改进分别列明。多个方案合理时选定推荐方案，写清收益、代价和适用条件；涉及重大产品选择或难以回退的变化再提交决策。无须阻塞审核的细节记录后继续推进。

## 6. 持久记忆与自进化效果验证

### 6.1 持久记忆

优先复核原计划 I01—I10、S7 冻结任务对照及已有真实模型记录；当前代码变化或存在覆盖缺口时补验。试验通过实际 CLI、桌面或共享会话装配入口触发自动行为，直接数据库调用只验证数据规则。

| 情景 | 观察与判断 |
|---|---|
| 新对话决定→关闭→独立会话改写提问 | 自动保存决定、理由和条件；主动找回并实际用于判断；来源准确，不靠提示答案或手工植入结论 |
| 暂定、未知理由、模型推断与正式决定 | 各类依据保持区分，不擅自确认；条件变化能提示重议 |
| 纠正→旧提炼返回→下一相关动作 | 当前依据使用纠正后的修订，旧任务与归纳不恢复错误认识 |
| 同项目双会话、同名项目和 worktree | 共享正确决定，各自进度和分支条件不串；进入项目不自动执行 |
| 连续使用、压缩与重启 | 不重复注入可见内容，缺失后补回正确修订，来源仍可读取 |
| 成果复用与准确版本 | 能发现并读取对应 Git/未提交/非 Git 成果版本，核对当前使用条件 |
| 停用、彻底删除、整理及备份恢复 | 停用可恢复，删除不重新提炼；恢复保留现行排除记录及原计划明确的恢复限制 |
| 嵌入不可用或禁止外发 | 本地搜索和管理仍可用，语义降级可见，无越权外发或虚构历史 |

效果对照复用同组冻结任务，记录无记忆与有记忆的正确性、重复解释、重复纠错、成果复用、无关注入、延迟和总成本。模型配置、任务条件和初始状态一致；有记忆组只增加情景允许的历史。检查失败样例的提炼、召回、选择和使用环节，不用命中率或相似度代替任务结果。

### 6.2 自进化

从真实任务、用户纠正和执行回执中选择一个可追溯的重复问题，优先 PAO 自有文本技能。保持原问题、关键正常用法和独立保留样例三组验收，按原计划核对最多三个不同候选、相同差异不重复验证、保留组失败不回灌生成器。

验证应覆盖：问题归因与实际反馈、基础版本、资源副本上的真实模型生成、同条件旧版/候选实际执行、独立保留样例、失败/取消/额度不足、来源失效与基础版本过期。环境执行失败记未完成；不能通过排除失败样例或放宽验收发布候选。

候选必须通过实际产品加载与执行路径产生行为差异。单独执行一个不消费候选资源的命令，即使结果通过，也不能证明技能有效。预设模型输出和手写补丁只作为机制测试；手写修复可用于诊断，实际闭环仍需验证真实生成过程。

S9 完成后检查固定版本发布、任务绑定、空闲与安全点切换、后续真实使用、证据化退步判断、自动回退及重启恢复。真实改善与人为注入的退步场景分别留证，回退已发生的业务结果按原计划单独处理。

无法找到合适真实问题时，明确真实闭环尚未证明，并继续完成其他审核；不制造历史或把模拟完成写成真实成功。初审已知核对点为 S8-13：其报告使用 fakeRegistry 机制验证，须追查是否已有后续真实证据，并据此修订完成结论。

### 6.3 效果结论与优化选择

原计划已有判据直接沿用。新增对照在运行前明确样例、预期行为和成功标准，结果出来后不改口径；有争议的产品质量目标先提出具体方案与取舍。

优化依据失败所在环节选择：提炼与证据分类、范围筛选、混合召回、上下文选择、实际采用、经验整理、问题归因、候选反馈或验证设计。已有机制足够时修实现或接线；只有明确能力缺口才增加机制。优化后的效果用同组任务比较，报告保留原始数字和失败样例；成本、延迟与正确性的取舍平实说明。

## 7. 检查与证据

每次检查前说明具体要检测的失败，以及失败后会修改哪处实现或结论。已有证据与当前版本一致且无新疑点时直接复用；改动后重跑受影响检查。

| 触发条件 | 采用入口 | 失败后的动作 |
|---|---|---|
| 数据、提炼、召回、整理或进化规则有疑点 | 对应内核 Vitest 行为测试 | 定位具体规则和调用路径，补有效回归后修正 |
| 内核公开类型、导出、依赖方向或宿主装配变化 | 原计划 §6.3 类型、集成类型及内核边界入口 | 修接口或装配，保持公开契约 |
| 桌面桥或页面链路变化 | 共享包构建、桌面类型检查、定向真实 Electron 用例 | 修 SDK/IPC/preload/renderer 断点和用户交互 |
| 存储依赖、vendor 或发行闭包变化 | 双仓边界检查、Windows 发行物定向用例 | 修分发与运行依赖，验证脱离开发仓路径运行 |
| 提炼质量、改写召回、记忆采用或候选生成未被证明 | 隔离真实模型与任务对照 | 分辨模型质量、提示、机制和接线问题，调整相应方案 |

实际命令沿原计划 §6.3 和当前脚本核实后使用。离线行为验证沿用隔离 PAO_HOME、`PI_OFFLINE=1`、`PI_NO_LOCAL_LLM=1`；真实模型另用隔离目录、明确配置及 token 用量记录。缺失实际用量标未知，不按零 token 统计；缺少单价只影响金额估算。成本及额度统一按[成本计量口径](../../.pao/memory-evolution-audit-20261112/优化任务.md#成本计量口径)。外部数据源或环境不可用时保留具体待验项，不降低完成标准。

## 9. 完成标准与已知限制

### 9.1 完成标准

审核完成须覆盖 S0—S9 全部任务和路径补充要求，对主要参考机制给出可追溯结论，明确实际接线、效果和代码质量，并为所有确认问题提出具体修法或后续归属。证据不足可以形成审核结论，但不能据此认定产品已验收成功。

优化完成须落实本轮选定任务，验证行为与公开契约、更新相关说明并交付可审阅差异。未解决的必要需求和缺陷不得藏入一般建议。代码正确且结构合理的部分保留，不要求每个模块都产生改动。

持久记忆成功以真实任务中的正确保存、主动使用、纠正生效及可追溯复用为依据；自进化成功以真实问题改善、正常用法保持、独立验收及 S9 生效/观察/回退证据为依据。三个层次分别判断：机制跑通、真实闭环成立、持续使用收益。单次闭环只能支持其已验证范围。

### 9.2 已知限制

- S9 的完成登记不自动证明真实问题闭环成立，第三期完整交付结论依赖对其原始证据与实际调用链的审核。
- 真实长期收益需要持续使用记录；独立进程、重启与不同时间戳验证只能证明相应机制。
- 模型质量和端点可用性会影响效果，需记录配置与失败，结论限定在实际覆盖的任务及资源类别。
- 部分执行资源的能力边界可能尚不支持自动发布；沿原计划明确缺口，不能把文本技能的成功扩展为所有资源已成功。
