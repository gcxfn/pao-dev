# 内置记忆与受控自进化设计

日期：2026-11-08。状态：S0 技术落地与契约已完成（2026-11-08），驱动固定 node:sqlite，类型契约与调用点清单已冻结，S1 可启动。

本文是内置记忆与受控自进化的需求和设计依据。实施启动仍由用户另行决定；既有任务的执行状态继续由原执行总册维护。

实施路径、阶段任务与确认结论见[实施计划](2026-11-08-内置记忆与受控自进化实施计划.md)，本项执行状态统一维护在该计划 §10。采用 PAO 自管 SQLite，复用现有嵌入模型端点，数据库与索引保存在本机。全部阶段先在隔离 PAO_HOME 验收，再确认正式现场切换。

## 1. 设计哲学与目标

**让过去的真实经历持续改善当前工作。保留可追溯的历史，提炼并按需使用相关知识，结合当前目标和条件作判断；在明确允许的范围内改进工作方法，验证后自动生效，退步时可以回退。整个过程减少用户重复解释、重复劳动和重复纠错，成本与任务价值相称。**

PAO 的记忆由自身统一管理，内置系统彻底取代 gbrain。核心收益是：跨对话、跨月份理解同一个项目，记得决定及原因，能够复用历史成果，并从真实错误中改进做法。

首要交付目标是决定记忆：上个月因某些条件否决的方案，这个月即使用不同说法再次涉及，PAO 也能主动找到历史结论、核对条件并用于当前分析。条件变化时，可以建议重新讨论，由用户决定是否改变正式选择。

记忆和自进化共用真实经历作为依据：记忆负责保存与使用认识，自进化负责改变允许范围内的工作方法。保存更多内容本身不代表效果更好。

## 2. 记忆内容与可信依据

记忆应覆盖用户偏好、项目事实与决定、执行经验、代码成果和任务连续性。不同内容以适用范围和来源关联，不因进入同一个数据库而失去项目、任务与版本边界。

| 内容 | 保留的关键信息 |
|---|---|
| 决定与理由 | 解决的问题、所选及被否方案、原因、成立条件、原始来源、后续替代关系 |
| 事实与偏好 | 内容、适用对象、来源、有效条件及用户纠正 |
| 执行经验 | 实际行动、结果、问题原因、有效做法及验证依据 |
| 代码与脚本成果 | 用途、输入输出、使用条件、保存位置、对应版本和执行结果 |
| 目标与任务 | 项目目标、当前阶段、验收条件、任务进展、承诺与下一步 |

用户明确表达、执行结果和模型推测应能区分。讨论倾向可以自动保存为未定案，明确选择后成为正式决定；未知理由保持未知。外部材料是参考，采纳后才成为项目决定。

内容更新保留来源和历史关系。明确的新决定替代旧决定；用户纠正优先于旧记录，后续整理不能从历史材料中恢复已纠正的错误认识。有实质歧义且影响下一步时再询问用户。

通用经验可以跨项目使用；项目决定及环境约定按项目解释。其他项目的历史选择可以提供参考，不能直接成为当前项目的约束。代码复用也需重新判断条件。

## 3. 存储与历史管理

### 3.1 数据归属

长期记忆采用数据库存储，Markdown 不作为记忆正本。PAO 统一管理数据、搜索入口和界面；终端与桌面共用业务实现。正式数据归 PAO_HOME，开发验证使用隔离数据目录。

| 数据 | 保存方式 |
|---|---|
| 整理后的事实、决定、经验及其关系 | 数据库，关联来源、范围及变化历史 |
| 代码、脚本及其版本 | 成果文件与版本存储，记忆引用准确版本 |
| 原始对话与关键执行证据 | 可完整回读的无损压缩归档 |
| 大附件 | 单独管理，记忆保存说明和关联 |
| 搜索索引 | 可从原始内容重建的衍生数据 |

项目已有正式文档继续维护项目事实，记忆关联其位置和必要的历史依据，避免另维护一份冲突正文。代码成果复用已有版本记录；没有版本保障但值得保留的成果，需有稳定保存位置，不能只记一个可能失效的路径。

新决定、偏好与执行经验统一以数据库为正本，部门作为归属与检索维度。已有部门 Markdown 保留为历史资料，不批量转存；项目规范、说明书及报告继续在原文件维护。

### 3.2 保存、压缩与规整

从新系统启用当天积累，不批量导入既有对话或 gbrain 数据。以后任务中实际读到旧资料时，可以记录本次发现及其来源。

保留对话、代码和脚本的修改历史、关键执行证据；不归档可重新生成的依赖包和构建缓存。相同内容去重保存，多处引用共享成果及其版本；摘要用于发现和召回，不能覆盖原始材料。

自动整理负责合并重复内容、连接决定变更和成果版本，并降低过期内容在日常召回中的优先级。重要决定不因时间久而自动删除。归档后仍可检索和回查。

“忘掉”默认停止召回并保留可恢复历史；明确要求彻底删除时按指定范围删除，同时避免从残留来源中再次自动提炼该内容。凭证不进入记忆、日志和成果说明。

## 4. 长期项目连续性

项目目标、当前阶段、关键约束和验收条件明确保存，接续任务时读取，不依赖一次搜索恰好命中。历史决定、经验和成果按相关性补充。

进入项目时自动了解必要背景；用户表达“继续”或提出任务后才执行。每个任务都能说明与项目目标的关系，恢复时将记录与实际代码、文件和环境核对。用户调整目标形成有来源的新决定，执行方法的自动改进不能悄悄扩大需求。

同项目的多个对话共享已确认决定和成果，各自保留任务进度；未定案尝试不作为其他对话的正式依据。重要决定变化应在相关操作前被感知。未完成承诺在适当阶段提醒，不自动变成执行授权。

## 5. 召回、注入与成本

相关记忆由 PAO 主动发现并带入当前工作，无需用户先打开记忆页面。先按项目、任务与适用范围筛选，再结合关键词和语义查找；同一方案的不同说法也应能关联到历史讨论。

默认读取简短结论和适用条件，需要重新判断或复用代码时再读取来源与准确版本。已有证据足够支持下一步就停止检索，不固定全库扫描或把所有历史塞进上下文。找不到记忆时正常分析，不伪造曾经讨论过的结论。

固定指令、工具定义和已有消息前缀尽量稳定，动态记忆按需追加到当前上下文；避免每轮改写固定内容或重复注入相同材料。工具版本在任务边界更新，运行任务在适合的边界切换。实际缓存收益由模型供应商与请求结构决定，以缓存命中和费用实测判断。

记忆整理和自进化预算随任务投入分配，简单任务保持轻量，复杂任务允许更多投入。优先使用可直接完成的数据库查询与检索，必要时才调用模型提炼和判断。费用需同时考虑整理、检索、注入、验证与失败尝试，不以耗尽预算为目标。

召回效果通过真实问题观察：相关历史能否找到、条件和版本是否正确、无关内容是否减少，以及用户重复解释和任务成本是否下降。不使用搜索分数冒充事实可信度。

## 6. 独立记忆界面

桌面应用提供独立记忆页面，以记忆内容为主体；自进化记录作为其中一部分。具体布局在界面设计阶段确定。

页面支持搜索、查看、纠正、合并、停止使用与恢复记忆。决定可展开理由、成立条件、来源和变更历史；代码成果可查看说明、预览内容、定位文件及版本。用户既能在页面操作，也能在对话中表达纠正，二者进入同一业务入口。

使用记录能回答本次任务参考了哪些记忆。影响方案选择的历史依据在对话中简短说明，普通偏好不重复打扰。自进化部分展示问题、改动、验证结果、生效范围、版本与回退记录。

## 7. 受控自进化

harness 指围绕模型运行的指令、工具、上下文组织与执行机制。自动进化限定在可单独停用和恢复的区域，与核心实现有清晰边界。

| 对象 | 变更方式 |
|---|---|
| 记忆整理、检索策略、上下文选择 | 在既有接口及数据结构内自动改进 |
| PAO 自有技能、任务模板、自定义命令、扩展工具 | 在明确允许的范围内自动修改、验证、启用与回退 |
| PAO 核心代码、pi 内核、存储结构、更新机制 | 按正常开发流程，经用户明确授权修改 |
| 用户目标、正式决定、权限、费用上限、自进化范围 | 用户决定，自动进化不能自行扩大 |

行为指令的改进随其所属范围处理；不能通过修改技能或扩展工具间接改写上述边界。范围外的问题提出具体开发建议。

自进化按上述允许对象的类别授权，先用一个真实问题验证闭环，再逐类开放；已在授权类别和能力范围内的具体资源不逐项重复确认。

改进由真实问题或有依据的机会触发：定位原因，形成具体改动，在隔离环境验证，通过后自动启用。验证应重现原问题、覆盖受影响的正常用法，并保留不随候选改动一起放宽的验收依据；一次成功不能直接推广成通用结论。改进也包括删除、合并与保留现状。

例如 PowerShell 引号错误重复出现时，应判断原因是未采用已有经验、参数传递方式，还是工具实现。可以改进命令扩展以减少手工拼接；需要修改内核时进入正常开发流程。成功与否以同类错误减少和正常命令仍可使用为依据。

自进化默认在当前任务结束后进行；阻塞当前任务的问题当场处理。普通任务优先，未完成整理可稍后继续。PAO 关闭时保存进度并停止，重启后在空闲时继续。验证失败保留原版本，后续发现退步时自动回退并简短通知；已产生的文件和外部结果另行核对，不随版本回退盲目撤销。

## 8. 实施顺序与首期验收

按可用成果推进，保持同一条记忆与改进链路：

1. 决定及理由的数据库存储、自动提炼、相关召回与独立管理页面。
2. 长期项目接续、成果版本关联及自动复用，完善成本与缓存观察。
3. 基于重复错误的技能、命令与扩展工具改进，验证后自动启用与回退。

首期以跨时间、跨对话的真实任务检验：能够保存决定和来源，通过不同说法找回相关的被否方案，正确解释原因和条件，使用纠正后的结论，并在独立页面回查和管理。另观察无关记忆、缓存命中、延迟及调用费用。模拟测试与真实模型验证分别记录。

这次设计确认不改变其他开发任务，也不授权修改正式 PAO_HOME。未来启用内置记忆时停止依赖 gbrain，既有共享库不因替换而删除。

## 9. 技术调查与参考

Hindsight、Hermes、Reef 作为机制与源码参考：分别借鉴记忆组织及来源回查、经验形成技能及维护、候选评估与版本激活。功能由 PAO 共享内核实现，复用现有数据库、模型路由、执行、账本和 pi 资源加载；参考映射与任务见[实施计划 §2.1](2026-11-08-内置记忆与受控自进化实施计划.md#21-外部方案与取舍)。实际移植代码片段时记录来源和许可。

采用 PAO 自管 SQLite 路线，复用项目现有模型调用、部门知识检索和 pi 公开扩展钩子，按需借鉴现有记忆引擎的局部实现。具体数据库连接库经 CLI 与 Electron 实测确定；压缩、版本保存和搜索路径见实施计划。新经验只写数据库，已有部门库资料按来源引用。
