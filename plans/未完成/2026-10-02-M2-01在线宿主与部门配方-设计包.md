## 1. 部门配方

- **格式定案：维持 配方.md，不转 json**。理由：①建部工具已以 配方.md 为正本产出，转 json 是重造正门；②配方读者是模型与部长本人，是散文不是查询索引（同 §6.2 条目不用 frontmatter 的口径）；③与注册表.md、工作流配方.md 同构，git 可版本化、可分享（§17.2）。机械参数（保险丝）不进配方，见 §2。
- **稳定规则与任务态分离**：配方只写人设/职责边界/默认档位/档位指引/工具清单；任务态已在卡协议（目标/输入/验收/约束全在卡上）、过程在黑板——本就是现状，零新机制，仅 scaffold 配方模板补一行注释：「任务结论写回执与库，不写进配方」。
- **热会话感知配方变更**（延伸 §6.8 快照＋查新三层）：
  1. 部长会话**启动时**渲染配方快照进人设（新增 `renderRecipeSnapshot`，带「截至」；现状 dept 只渲染注册表，这是唯一新增渲染面）；
  2. 派卡/中转机械校验**永远读最新**：部门存在查注册表（现状已如此），档位合法性查最新 配方.md＋档位.json——快照旧不导致派错；
  3. 配方**指纹核对**：宿主登记表存会话启动时配方 sha1，主控派卡命中热会话时机械比对，不一致仅在工具输出提示「配方已变更，建议重开」——是否重开主控裁决，**不自动杀会话**（权限收窄类变更由主控人工判重开，防热历史带旧权限续跑，G2-05）。

## 2. 部长会话保温

- **绑定 key ＝ 部门名＋项目根（归一化绝对路径）**；同 key 同时最多一个热会话——这就是「非无限部长池」的机械上界，另加全局热会话总数上限（保温.json）。
- **「没事不请求模型」的机械定义**：部长会话的输入事件仅三类——①新卡到达（主控派卡落本部队列后由宿主投递）②回执/验收事件（owner 审）③主控/用户插话。保温期间宿主**零定时器、零轮询、零文件监听**，句柄只保存不读。保险丝检查挂在事件边界（来新事件时顺带比对空闲时长/累计成本），是「事件到了才查表」，不是时钟驱动——机械上不存在「没事也在跑」。
- **句柄登记：复用 worker 模块**。接入点：①进程本体仍登记进 `worker/registry.ts` ProcessRegistry（树杀面全覆盖）；②退出钩子复用 `worker/index.ts` installExitHooks/session_shutdown——主会话关闭，部长会话随进程树全停，无常驻不破。新增 `src/pao/host/` 持「部门＋项目 → MinisterHandle（pid、pi 会话标识、配方指纹、最近事件时间、累计成本）」内存映射；宿主拉起子进程时强制注入 `PAO_ROLE=部长`（同 runner.ts:195 强制注入 worker 的同款纪律）。小改待决：ProcessEntry.`卡号` 字段对部长会话为空，加可空 `标签` 或改名（登记表泛化，小步不重构）。
- **保险丝（2026-10-02 深夜用户定案＋修正＋终定）**：**只有「空闲分钟」（默认 30）是熔断线**——闲着＝零价值，杀之无损。轮次与工具调用是**提示线**（默认 200/2000）：达标一次性事件通知主控＋盘点视图常驻标记，**不杀**（正当长活带提示继续跑；任务成比例的硬顶由卡预算＋终止门禁承担，M2-04）。**灾难线已删（深夜用户终定）**：定期监督唤醒（§4）上线后，事件型僵尸（不停调工具所以不算空闲）由上级在唤醒快照里识别并干涉，再叠一层机械倍数线的价值低于其复杂度；既有三重护栏＝空闲熔断＋监督唤醒＋worker 卡预算硬顶。残余风险（上级反复误判不干涉）接受，出真实摩擦再加回。全机械计数，不用钱做上限。**缺文件＝不保温**（配置缺失=未用此功能的全仓哲学，部长会话按需起、用完即散，不内置默认偷偷启用）。**全局热会话数从保险丝降为观测项**：`/队列 --全部` 显示当前数，超过并发封顶口径（8）提示不拒绝——结构性上界＝部门×项目组合数（拉起入口在宿主、模型自建不了），硬闸交给单 key 单会话＋三线保险丝＋M2-03 共享上游并发。
- **部长会话用量落账**（主控审核 P1 补）：每轮 usage 按「部门＋项目」聚合追加 `.pao/四指标账.txt` 同款格式（卡号位标「部长」，M2-04 全角色对账口径），细节 S2 定。
- **散场语义**（§6.5 保险丝兑现）：超限 → 先落短交接（§3）→ 树杀进程 → 登记表摘除。下次任务冷启动重开（人设＋门面＋查库，§6.5「重开很便宜」）。**崩溃窗口（P2 补）**：散场钩子没跑时交接文件是旧货——恢复读取必须核对「最近服务时间＋配方指纹」，过期显式标注「仅历史参考，不授权续跑」。
- **载体待决**：部长会话进程形态（pi RPC 常驻子进程 vs §20 durable Harness）——主控预裁 RPC（worker 同款停树面；durable 系上游实验品 API 无预告变更），用户未终批，S1/S4 不依赖此项；**S2 开工前置＝待决③（派发/投递入口）裁决**（见 §8）。

## 3. 短交接协议

- **复用 pao_交接 四段**（当前目标/已发生改动/验证结果/未决事项），数据源全是机械盘点（队列纯读＋基线比对＋验收记录），不新立格式。与 M2-09 版唯一差异：**新增落盘出口**——`部门/<名>/交接/<项目名>.md`（PAO_HOME 侧，git 版本化；每「部门＋项目」一文件、新盖旧，历史靠 git）。落点：host 模块散场钩子调 `renderHandoff`（cards/handoff.ts 原样复用）＋写交接文件；写的是交接文件不是卡，五状态零涉及。
- **「交接无派效力」的机械保证**：①交接文件不在任何卡目录——listCards/驱动器/队列扫描结构上读不到它，不存在被当成任务真相的通路（R10：不做第二任务真相）；②恢复唯一入口＝主控派**新卡**到同「部门＋项目」且登记表命中热会话时，宿主把交接页路径作为指针附进派卡信封（指针带读取目的：「背景核对，不是续跑指令」）；③部长人设明文「交接页不得自行启动任何卡」。合法与否由**主控**判——星型纪律：主控是唯一唤醒源与派卡裁决者（§8.2/§8.6），部长会话自己无唤醒通道。
- **重启即失忆是有意的**：登记表是内存态，主控重启后热会话已随树全停，全部走冷启动＋`pao_盘点` 只读盘点、人决定重派或作废（§1 无常驻既有口径）。上一轮交接文件还在 `部门/<名>/交接/`，供新会话当背景读——文件幸存 ≠ 自动续跑。

## 4. 监督与干涉（2026-10-02 深夜用户定案加入；唤醒制式同夜定案）

- **周期唤醒，上级看一眼（2026-10-02 深夜用户定案）**：被监督会话每累计 N 轮（usage 事件边界计数，零新增探针），宿主向**直接上级**注入一次监督快照——部长看工人、主控看部门。**间隔可改**：保温.json 新键「工人监督轮次」（默认 50）与「部门监督轮次」（默认 100），0/缺省＝该级关唤醒（缺文件＝不保温的全仓口径不变）。快照＝机械摘要（轮次/工具调用/成本行＋活性三判据标记＋最近回执标题），非全量转写；**被监督者不暂停**（异步看，正当长活不卡顿），上级看后可不动或走干涉。触发挂在事件边界非定时器（保温纪律不破）；对主控的投递复用提示线同款一次性通知面。与提示线的关系：唤醒先于且密于轮次提示（50/100 vs 200）并反复触发，轮次提示线仍保留——管工具调用维度（2000，无唤醒对应物）与未配监督的会话。副产红利：有活部门的缓存被唤醒顺带续温，待决⑦只剩纯空闲场景。
- **活性三判据，零新增探针**（数据源＝保温计数器/事件流，部长与 worker 同款，快照与盘点视图共用同一判定）：①疑似停滞——状态运行且最近事件时间超阈值（默认 15 分钟，配置进 保温.json）；②疑似循环/死磕——最近 K 次工具调用或错误文本高度重复（K 默认 5，归一化比较）；③到顶——尝试号逼近 DEFAULT_ATTEMPT_LIMIT（既有）。判定机械标出，**不自动杀**。
- **看（拉面）**：部长看工人＝`pao_盘点`（装载面已保留 worker 模块，列自己派出的 worker，登记表同源）；主控看部门＝盘点扩展显示部长会话行（pid/最近事件时间/轮次/工具调用数/配方指纹/活性标记）＋`/队列 --全部` 聚合。唤醒是推面，盘点是拉面，两面同源。
- **干涉（上级专有，动作全复用）**：停树（`pao_停后台`/散场钩子自动落交接）→ 卡打回或重派（既有状态机迁移）→ 或标「人工介入」交用户。无新权限面；被监督者无对下隐藏通道，只能回执求援。干涉留痕：谁停的、为什么，落卡回执或交接。

## 8. 明确不做

- **无限部长池**：同「部门＋项目」单会话＋全局总数上限（保温.json），超限拒绝拉起并提示。
- **固定后台心跳/定时器/轮询/文件监听**：部长唤醒只走三类事件（§2），保险丝检查挂事件边界。
- **常驻守护**：部长会话是主会话的子进程，主会话关闭全停；不注册任何系统项（§16 退役路线同理适用）。
- **部长间直投/消息通道**（§8.1 已否决重申）；交接文件当任务真相；部长自动重开会话（只提示主控）；保险丝部门覆写（待摩擦）。
