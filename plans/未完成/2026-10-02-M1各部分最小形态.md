## 目标与受限形态

一次接通四块必须能力：两档路由，skills/MCP/todo，文件知识库，单 worker 派发。不是只做卡片后就宣布 M1 完成。

运行形态保持：**一个部门、同时一个执行 worker、同项目串行写、线性依赖、两档显式选择、一个真实 MCP**。知识审核可以按需启动短会话，但不做 M2 的长期保温或多部门调度。

完成的含义：一件真实日常活可从可判目标进入卡片，经过执行、证据、验收，得到正确交付；应沉淀的候选可经审核入库，并在新会话中被正确使用。失败、中断和知识不足不会导致空跑或误交付。

## 开工条件

M0 有真实装载与 GLM 工具调用证据。现有实现先盘点；相关修订同步到架构，尤其是直通 owner、依赖满足、受限补查、同轮尝试和关闭语义。正式入库前解决上级公约归属，未解决可先用隔离测试库开发验证，不宣称正式记忆能力已完成。

配置与证据必须区分测试库/正式库、模拟接口/真实端点。试跑额度与外发许可明确，未知费用不能当零。

## 复用选择

直接用 pi 的虚拟模型、扩展钩子、skills 和 MCP，装目标 `rpiv-todo` 包；subagent 按官方骨架抄改。实现卡片与知识薄工具，文件写入/锁/YAML 优先复用项目已有组件。来源 [E2—E7](../附件/复用核验与来源.md)。

`pi-goal-x` 在本阶段末评估，不预先引入第二套任务进度和自动续跑。没有现成隔离好的审计接口时，只借审计清单与完成检查思路。

## 任务与顺序

### M1-01｜冻结最小接口、角色装载和用量口径

先画清 owner/worker/候选/正式库责任，冻结 YAML 卡格式、当前尝试标识、可判验收、线性依赖、输出路径与失败分类。仅补实现所需字段，不造独立协议平台。

为主控与 worker 定各自加载的扩展/工具清单，避免子进程继承派发或自动推进插件。用量从运行事件与接口返回取，不让 worker 凭空自报。记录原始 usage、请求标识、尝试和配置快照。

**交付**：规则正本修订、最小接口测试夹具、角色装载清单、度量字段映射。**不做**跨项目聚合、自动档位选择、协作预算分配对象。

### M1-02｜卡片、单写入口和 `/队列`

实现项目内稳定发号、Markdown 信封、单 owner 写入、原子保存、尝试回执追加、五状态、依赖就绪与只读队列。卡号按项目唯一；重复调用不能多建任务或重复推进。

`/队列` 显示状态、优先级/创建顺序、待审、前置失败原因、知识待验证积压。派生状态可显示，但不额外存一套状态机。

项目改动互斥放在派发前；受 PAO 控制的主控直干写操作也应接入同一互斥入口。当前软纪律无法拦住外部编辑器/任意 shell 的部分明确披露，开工/交付时做现场差异核对。

**交付**：卡片工具、队列命令、发号/单写/并发测试。**依赖**：01。

### M1-03｜接一个 headless worker，并先做停止与验收

沿官方示例启动一次性 worker，显式绑定目标目录、模型档、工具、人设与输入指针；worker 无再派发入口。输出落文件，主控只收到摘要和证据定位。

回执带卡号/尝试号，程序判断当前/重复/迟到，owner 最终改状态。直通卡按 R03 完成机械验收；需要判断时交审核，不凭 exit 0 或一句“完成”通过。

实现取消、主会话正常退出与异常后的盘点；追踪本轮启动的进程，而非用进程名字全局清理。写任务停止前不能提前放锁。现有基线与本轮差异均保留，重启不自动续跑。

**交付**：worker 薄包装、结构化回执收集、取消/停止/重启核对证据。**依赖**：02。停止边界必须在开放真实写任务前过关。

### M1-04｜两档路由和生态实挂

按菜单配置两个虚拟档位，派卡选档写回信封，记录实际 provider/model/thinking。工具后续轮次和接口重试保留被选择档位，端点出错不静默变笨。测试恢复会话时虚拟模型丢失、配置失效的行为，不能沿底层默认回退悄悄绕过 PAO 规则。[E2]

只移植确实高频的 skills，数量随当前真实任务而定，不整包灌进每个角色；检查路径、工具名称和权限前提。装 rpiv-todo 仅管单会话步骤。至少一个原有 MCP 真实连接并调用，首选已存在且日常需要的能力；另一候选留“未验证”，不声称两者都通。

工具输出默认给状态、关键失败与完整文件路径；保留按需展开，不因截断丢错误再重跑。工具集合按角色精简；查看所有已启用的直接/间接入口，不仅查看提示词列表。[E4]

**交付**：两档配置、skills 兼容记录、一个 MCP 运行证据、todo 边界和工具输出测试。**依赖**：01；路由可与 02/03 部分交错，综合测试须接入实际卡片。

### M1-05｜一个部门与知识最小闭环

建部工具一次生成配方、四类型知识目录/索引、待验证、归档和注册表行；重复执行不覆盖已有内容。注册表渲染进主控提示，用于能力匹配，不把整库塞进去。

查库按架构已有方案实现词法＋语义合并、JSON 向量缓存、增量更新；云端不可用时词法独跑。新增运行约束为可信项目/版本/外发绑定、有效命中与风险提示分开、待验证不作依据、删除/归档/授权撤销能失效。给 worker 一次受限补查，而不是全库检索。

候选从回执进入待验证，直通卡由主控扩展代投；部长审核后入库。入库移条目、更新子索引和机械巡检可幂等重放。中断后重跑修索引，不重复生成知识。M1 机械巡检只标记，不开巡库后台 worker。

正式条目保留一页、来源/适用范围/状态/最后核验；不强行加入已否决的知识 YAML frontmatter。解析字段不足时标未知或待复核，不猜有效。跨会话查到条目后仍核当前适用性。

**交付**：一个部门、建部/查库/入库薄工具、可重建缓存、候选闭环与检索题集。**依赖**：01/02，真实回执管线依赖 03，实际语义端点另需批准和可用凭证。

### M1-06｜合拢异常、证据与启动恢复

把缺输入、端点故障、能力不足、写入后未知结果、重复通知、旧尝试结果、取消、进程残留纳入同一批测试。接口客户端与 worker/调度层统一重试上限，分别记录内部请求次数。

开工先记用户已有修改，收工比对本轮范围；不能把用户原有脏工作树当成本次 worker 产物。模拟使用测试项目，不在真实重要目录做破坏性故障注入。

**交付**：异常测试集、用量对账、清晰的未验证清单。**依赖**：02—05。

### M1-07｜真实一条龙、跨会话回用与阶段评审

至少完成原需求要求的一件真实日常活；可复用增量经审核入库，关闭相关会话后再用同类任务验证召回。另验证“无可沉淀内容也能正常交付”，不为验收编知识。

技能、MCP、两档各有实际证据；不要求把所有机制硬塞进同一个本来很简单的任务。记录四指标、未知费用与人工介入。评估 goal 审计是否可单独复用，结论“先不引入”也合格。

**交付**：完整验收报告、部门评测记录、M2 摩擦候选、项目 Commands 与当前焦点更新。**依赖**：06。

## 验收清单

| 编号 | 必测场景 | 通过条件 |
|---|---|---|
| G1-01 | 发号、同卡双写与文件保存 | 不重号、不半写、不让旧 owner 覆盖当前状态；失败可诊断 |
| G1-02 | 线性前置成功/失败/取消/不存在 | 只有已交付前置放行；其余可解释地停住，不新增隐形等待状态 |
| G1-03 | 直通任务有回执但未验收；无知识候选 | 前者不误结卡；后者验收通过可以完成，不依赖常驻部长 |
| G1-04 | 重复回执、旧尝试迟到、取消后迟到 | 不重复计费/晋升/交付，不推进新的尝试 |
| G1-05 | 缺输入、瞬时故障、达到尝试上限、现场结果未知 | 分路正确；无空转/无盲目重做；请求重试没有倍增 |
| G1-06 | 取消、Ctrl+C、正常关闭及本地子进程 | 不再派新活，受管执行停止后才放锁；只处理本轮拥有的进程 |
| G1-07 | 强制终止主控/终端、再启动 | 核目标 Windows 场景；无自动续跑，现场可盘点；无法保证停树则不开放该自动模式 |
| G1-08 | 精确词、换说法、没答案、错项目/版本、待验证/过期、归档/删除 | 正确召回或明确无可用依据；风险独列；缓存不会继续送出退役知识 |
| G1-09 | 语义端点断网、禁外发项目、worker 第二次/跨部补查 | 词法降级标志真实；正文和查询均不越权外发；补查额度不可绕过 |
| G1-10 | 重复候选、晋升中断、索引缺失、无价值候选 | 可重放修复、无重复正式条目；拒绝/挂待验证有决定记录 |
| G1-11 | 用量缺失、重复通知、父子汇总夹具、预算耗尽 | 未知不当零，来源可复算，不双计；超限不继续开新请求 |
| G1-12 | 子进程角色装载、递归尝试、隐式扩展、todo/goal | worker 无 PAO 再派发能力；插件不成为第二任务真相；软权限边界说清 |
| G1-13 | 两档实际路由、工具续轮、故障、skill、MCP | 两档各实测；不静默跨档；至少一项高频 skill 和一个 MCP 真正用于任务 |
| G1-14 | 中文空格路径、长错误输出、用户已有修改 | 错误原因可见、原日志可展开；正确工作目录；不覆盖或冒领原改动 |
| G1-15 | 真任务完整链路＋新会话知识回用 | 交付可验、证据可找、成本可解释；正式库正本归属已合法确认 |

G1-01—14 可拆为小测试，但不得用纯 mock 替代 G1-06/07/13/15 的关键目标环境实测。不能因网络断了只跑词法，就宣称“混合检索已全部通过”。

## 完成门槛与回退

四块能力全部有最小真实证据；专属验收通过，无 [严重阻断项](../附件/验收与度量口径.md)。未通过保留“部分完成”和缺项，不能改个状态进入 M2 并行。

某插件冲突可停用该插件并保留原 pi 能力；知识故障优先降级到明确标记的只读/词法模式；卡/回执/停机有严重问题则关闭自动派发，保留 M0 日常使用入口。不得在错误恢复时批量删除知识或强制重置项目。

## 本阶段不做

不做多部门协作、跨项目总看板、部长长期保温、自动巡库、并行代码修改、worktree、大规模扇出、重排/向量数据库、桌面 UI 或强沙箱平台。也不宣称已经证明蜂群比单 worker 更便宜；那是 M2 的对照问题。
