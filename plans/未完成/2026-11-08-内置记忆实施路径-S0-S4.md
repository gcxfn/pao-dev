## 调用链与接口

### 一条决定如何进入、使用和纠正

```text
会话消息落盘
  → captureCommittedEntries：按会话条目 ID 采集新增内容
  → sources + archive_segments：保存来源及可回读事件
  → extraction_jobs：记录待提炼的来源范围
  → agent_settled：调度一批已提交来源
  → extractDecisionCandidates：现有模型运行入口 + 结构化结果
  → validateCandidateSources：检查出处、确认状态和已有修订
  → commitCandidates：一个事务保存记忆、修订和来源关系
  → embedPendingRevisions：增量嵌入，写本地索引

before_agent_start
  → resolveMemoryScope：项目/任务/分支范围
  → searchMemory：词法 + 独立语义候选
  → selectForContext：条件、修订、上下文预算、去重
  → pao-auto-recall 消息：追加结论与来源
  → context：排除已被纠正或停用的旧记忆消息

页面保存 / 对话明确纠正
  → correctMemory(id, expectedRevision, replacement, source)
  → 单事务追加修订、更新当前指向、使旧索引失效、增加范围修订号
  → 当前会话清理旧依据；其他会话在下一相关操作前刷新
```

`agent_settled` 表示自动重试、压缩、排队续跑已结束；不能用 `agent_end` 替代。`turn_end` 用于及时采集已经提交的消息及工具结果，不直接启动一次新的模型整理请求。明确纠正是即时业务写入，不等待后台队列。

### 首期业务接口

在 `K/memory/types.ts` 定义结构，在 `service.ts` 实现；名称是本计划的实现约定。

| 接口 | 输入 | 输出与提交点 |
|---|---|---|
| `openMemoryService` | PAO_HOME、只读/读写用途、显式运行配置 | 服务实例；连接按 PAO_HOME 在进程内共享，由宿主关闭引用，最后一处释放才关库 |
| `createMemory` | 类型、范围、结论、条件、证据类别、确认状态、来源 ID | `id + revision`；正文和来源关系同事务提交 |
| `getMemory` | ID、可选历史修订 | 结构化内容、状态、来源摘要与替代关系；正文按需展开 |
| `searchMemory` | 可信 Scope、query、current/history、limit、AbortSignal | hits、degraded、reason；不调用写入/提炼 |
| `correctMemory` | ID、expectedRevision、替换内容、用户来源 | 新修订；版本不一致返回冲突及最新修订，不重试覆盖 |
| `setMemoryUsage` | ID、expectedRevision、active/stopped、用户来源 | 更新后的修订；恢复只切使用状态，不复活已纠正内容 |
| `mergeMemories` | 保留 ID、被合并 ID、各自修订、明确理由 | 保留项的新修订及旧 ID 的合并指向 |
| `previewMemoryDeletion` | 准确 ID 或用户明确给出的来源范围 | 实际对象、引用关系、受影响会话、未受管外部来源；不删数据 |
| `deleteMemory` | 已展示范围、对应修订、用户删除指令来源 | operationId、complete/pending/failed、未完成对象；不把隐藏当物理删除 |
| `readMemorySource` | sourceId、事件范围 | 原文及来源元数据；读取未封存或 gzip 段 |
| `readScopeRevision` | 项目/通用范围 ID | 单调递增的修订号，用于其他会话更新判断 |

`Scope` 由宿主上下文确定，包括 projectId、taskId、sessionId、branch/执行根与部门。模型参数可表达查询意图，不能自行指定另一个项目为当前身份。

### 表与事务的最小形状

- `projects` 保存稳定 ID，`project_roots` 保存规范根与 worktree 映射；只有实际建立映射时才写记录。
- `memories` 保存 ID、类型、范围、当前修订、使用状态、合并指向；`memory_revisions` 保存结论、条件、决定字段、证据类别、确认状态及时间。
- `sources` 保存 sourceId、sessionId、entryId、原始事件类型、来源位置；以会话和原始条目身份防止重复采集。来源关系精确绑定到修订。
- `archive_segments` 保存段 ID、原始/压缩位置和已发布状态。SQLite 内的来源行可以先指向未封存段；归档发布后只更新位置，不更换来源 ID。
- `extraction_jobs` 保存来源范围、状态、游标和尝试；模型输入在事务外读取，提交时重新判断来源排除与相关记忆修订。
- `memory_vectors` 绑定 memoryId、revision、model、dimension；FTS 记录相同逻辑身份。更新正文与词法索引同事务，向量异步生成，检索只认当前有效修订。
- `memory_usage` 保存任务、记忆修订、检索/注入/引用事件和用量引用；不另存一套费用总额。
- `source_exclusions` 与 `deletion_operations` 只保存阻止重提炼和恢复删除作业所需的 ID、范围和状态；不保存删除对象的正文。

## S2

**具体顺序：** 持久任务→事件触发→模型调用→来源及状态判断→去重/纠正→跨会话感知→失败恢复。后台写入只用服务事务；模型不直接执行 SQL 或改用户正式文档。

| 任务 | 具体实施步骤 | 直接产出与验证位置 |
|---|---|---|
| S2-01 | `extraction-jobs.ts` 用来源范围创建唯一任务；状态分 pending/running/done/failed，处理游标随候选提交推进；记录所属进程和尝试 ID。 | 崩溃后先核原任务持有者，再重取未提交范围；不重复处理已提交事件。 |
| S2-02 | `turn_end` 只采集，`agent_settled` 唤醒一次队列；`agent_start` 取消/让出后台调用；`session_shutdown` 停止领取、取消请求、保存已完成进度。 | 一串工具回合只产生一个合并批次；退出不新开付费请求。 |
| S2-03 | 新增 `model.ts`；在事件入口取得 `ctx.modelRegistry`，用 `tierNameToModel` 解析配置档位，再 `find/streamSimple(...).result()` 发请求，沿现有认证；按来源范围取增量并请求结构化候选。作业开始创建专用记账会话，写 parentTaskId/sourceSessionId/jobId，实际用量经公开 `appendUsage` 写入。 | 不创建第二套模型运行时和凭证加载器；专用会话只承载后台用量/归属事件，使用现有用量聚合，迟到结果仍归同一 jobId，不能写入切换后的用户会话。 |
| S2-04 | 校验候选 sourceIds 均在本次输入；quotedSpan 必须能在已保存文本定位；结论、理由和确认状态分别检查依据；失败候选不提交。 | `memory-extraction.test.ts` 构造虚构 ID、补造理由和外部文章冒充决定。 |
| S2-05 | 使用 `evidenceKind=user_statement/execution/model_inference` 与 `confirmation=tentative/confirmed` 两个字段；正式决定必须关联用户选择，经验必须关联执行回执。 | “可能用 A”和“就用 A”分别落不同状态；执行失败不能自动变用户偏好。 |
| S2-06 | 对涉及已有决定的问题只读取相关决定和条件；输入条件变化时新增“需重议”关联与候选说明，不调用正式决定替代接口。 | 用户明确改选后才新建 confirmed 修订并连 supersedes。 |
| S2-07 | 先按来源 ID 和类型查已处理候选，再检索当前范围相近条目；相同来源重复结果复用已有 ID；相反结论留下独立待定关系。 | 连续重试和分支重复读取不新增同一决定；相似度不自动决定合并。 |
| S2-08 | `registerMemoryCommand` 和写入工具都接受明确 correction 操作；目标唯一时调用 `correctMemory`，多个候选会改变下一步时显示选项；成功后更新 `SessionMemory` 并写持久纠正事件。 | 对话和页面共用同一事务；当前请求后续上下文立即排除旧记忆消息。 |
| S2-09 | 每个提炼候选记录读取时的关联修订；提交前检查 currentRevision、stopped 与 source_exclusions；失效候选丢弃本次提交并按新范围重排。 | 延迟模型响应不能撤销页面纠正、停用或删除。 |
| S2-10 | 每个作用范围维护递增整数；会话记最近读到的值；`before_agent_start` 比较并补拉变化项，不全表扫描；更新已注入 ID 的修订。 | 双会话一写一读看到一致结论；无变化只执行小查询。 |

### 召回实现路线

代码核实日期：2026-11-08。`memory/service.ts` 的 `searchMemory` 当前为 unavailable 占位；`types.ts` 已有 `SearchMemoryInput/Result` 和 `MemorySearchHit`；`resident.ts` 仍使用供应商 top3 和主控 MEMORY.md；`SessionMemory` 已有选择与过滤入口。S3 在这些入口实现新查询，S4 按既定流程完成供应商切换。S2 在建的 `extract-model.ts`、`extract-commit.ts`、`extraction-jobs.ts` 继续负责提炼与提交。

采用 Hindsight `search/fusion.py` 的独立召回后融合机制，以及 Hermes 的有限常驻上下文与按需展开方式。具体来源见[调查文档 §7](2026-11-08-记忆与自进化方案调查.md#7-源码核实与采用结论)。下列新函数为 S3 待实现名称。

1. **查询装配（S3-01/02/08）。** `service.ts::searchMemory` 委托 `search.ts::searchMemories`，传入内部 store、可信 scope 和查询参数。`scope.ts` 先解析项目/任务/分支条件；current 路只读当前修订、active、未合并走且来源未排除的项。history 显式走历史查询。`resident.ts` 只调用服务，不读取数据库或拼 SQL。
2. **索引身份（S3-02/04）。** FTS 行以 memoryId+revision 关联正文；向量记录同一身份、模型和维度。内容由 conclusion/question/options/rationale/conditions 的实际已有字段组成，不把模型推断的理由补成事实。索引结果回表核对当前修订后才能成为命中；修订或删除后旧索引即使尚未清理也不能返回当前结果。
3. **两路独立取候选（S3-03—05）。** 词法按 FTS5 BM25 排序；短词走范围内字面子串。语义路读取同范围、同模型/维度的有效向量，复用 `embedTexts/cosine`；在相似度计算前严格核维度。每路初始候选上限取 `max(20, 4 × limit)`，先各自排序再截取，语义集合不依赖词法命中。该值是首期实现常量，S3-14 只有实际漏召回或耗时超标才调整。
4. **融合及精确命中（S3-05/07）。** `mergeSearchCandidates` 按 memoryId+revision 去重，保留两路名次和原分数用于诊断。其余结果使用倒数排名融合 RRF：每路从 1 开始，贡献 `1/(60+rank)`，求和排序；同分按 memoryId 稳定排序。对查询明确给出的记忆 ID 或完整方案/工具标识的精确命中优先，不将普通短词子串视为强制置顶。RRF 只决定相关结果顺序，不判断事实真伪或当前授权。现有 relevance 的 0—1 契约保留，RRF 值按两路理论最大值 `2/61` 归一；原分数仅放内部诊断，不宣称为置信度。
5. **条件和证据渲染（S3-07/11）。** 命中保留 evidenceKind、confirmation、needsReDiscussion、conditions、revision；sourceIds 由既有修订来源接口批量取得。明确不符的任务/分支不注入；自然语言条件无法确定时显示“需核对条件”，不得自行变成禁止规则。选择器先计完整单项的结论、条件和来源标识预算，装不下则省略整项；不为缩短正文再调模型。
6. **动态上下文与来源展开（S3-09—11）。** `SessionMemory` 用 ID+revision 判断当前投影中是否已可见，再通过 `pao-auto-recall` 追加消息。纠正后的修订替换当前依据，旧修订只保留历史。`readMemorySource` 按选定 sourceId 回读必要事件；搜索不调用总结模型。需要综合多条经验时由当前任务在读到来源后分析，归纳落库仍走 S2 提炼入口。
7. **取消与使用证据（S3-12/13）。** 语义 deadline 到期使用已得词法结果并返回 degraded；用户取消终止整个请求。search、inject、expand、used 记录 requestId/taskId/sessionId、memoryId/revision 和实际发生的动作。只有回答中的明确引用或实际工具选择登记 used；候选排名、列表展示和注入都不能推导“成功使用”。

**定向验收：** 无关键词交集的同义查询能进入语义候选；单路第一名不会因先取另一条路的集合而消失；短中文、完整工具名与引号输入正确；修订发生在取向量和渲染之间时不注入旧依据；很长的否定条件保持完整；语义端点超时仍可本地查询；压缩后重注入、新修订立即替换和无明确采用时 used 为零均有行为断言。继续沿 S3-14 的真实端点与 1千/1万条性能验收，不新增图数据库或独立重排模型。
