## 1. 交付目标与总边界

### 1.1 三次可用交付

| 交付 | 阶段 | 用户能实际得到什么 | 完成条件 |
|---|---|---|---|
| I：决定记忆 | S0—S4 | 自动保存决定及理由，跨会话换一种说法仍能找到；纠正生效；独立页面可管理和回查来源 | 从新系统开始产生的真实对话贯穿保存、关闭、重开、召回、纠正、页面回查；脱离 gbrain 运行 |
| II：项目连续性与成果复用 | S5—S7 | 接续项目时知道目标、进度和承诺；找到并核对可复用成果；费用与记忆使用可解释 | 两个对话共享决定但进度不串，成果版本可读取，整理可中断恢复，费用完整计入 |
| III：受控自进化 | S8—S9 | 从真实问题形成改动，在允许范围内验证、生效、观察、回退 | 至少一条真实问题链路完成闭环，并实际验证正常用法、失败不发布与退步回退 |

首期交付必须同时包含存储、自动提炼、语义召回和独立管理页。只有数据库或搜索工具不算首期完成。各阶段允许交付内部可用成果，但不提前宣称达到所在交付的验收条件。

### 1.2 范围

- 业务在共享内核实现，CLI 与桌面只装配和展示；沿用 pi 的公开会话事件、资源加载和工具注册接口。
- 新长期记忆、来源关系、修订与使用记录归 PAO_HOME 数据库；项目正式文档和任务卡继续是各自事实的正本。
- 新系统从启用点开始积累。旧对话与 gbrain 不批量导入，实际任务读到旧资料时记录本次发现。
- 记忆默认主动参与分析；进入项目只加载背景，不启动任务；历史承诺不授予执行权限。
- 自动进化只处理用户批准的 PAO 自有技能、模板、命令、扩展工具和策略资源。核心、存储结构、权限、预算上限、正式决定及范围变更走正常开发流程。
- 本轮编制计划，只修改工程文档。实现、模型调用、正式数据切换不在本轮执行。

## 3. 技术路线

### 3.1 存储和部署

采用每个 PAO_HOME 一份 SQLite 数据库；进程内复用连接，CLI 与桌面通过同一内核访问。使用短事务和 WAL（预写日志），跨进程写入交给 SQLite；模型、压缩和网络调用不占数据库事务。S0 验证并发写、忙等待及关闭行为，避免首期另建常驻数据库服务。

建议运行目录：

```text
<PAO_HOME>/memory/
  memory.sqlite
  archives/<session-id>/<segment-id>.jsonl.gz
  artifacts/<artifact-id>/<version-id>/...
  attachments/<attachment-id>/...
<PAO_HOME>/evolution/
  candidates/<candidate-id>/...
  versions/<resource-id>/<version-id>/...
```

实际路径集中在内核路径模块。数据库、WAL、归档和附件一起纳入产品已有数据备份范围；一致性备份通过数据库支持的方式建立，不在写入时直接拷一个主库文件。初始结构直接建表；后续确有表结构变化才写对应升级步骤，不预建迁移平台。

### 3.2 检索与模型

**已确认：复用现有嵌入模型端点，数据和索引留本机。** 项目许可沿用现有外发规则。

检索顺序为：确定项目/任务/部门范围 → 排除停用、失效和已替代的当前依据 → 词法和语义两路各自取候选 → 合并去重 → 返回简短结论、条件和来源 → 有必要时展开原文。历史查询可以显式包含被替代及归档内容，并清楚标注状态。

首期向量以数据库 BLOB 保存，复用已有余弦计算，对选定范围的向量执行精确检索；语义路不得先被关键词结果截断，否则同义改写会漏召回。先覆盖本项目实际规模。S0/S3 测定候选规模与前台耗时，只有越过已定目标才替换为成熟向量索引，不预装图数据库或额外搜索服务。

向量绑定记忆修订、模型标识和维度；相同修订不重复嵌入，模型变化只重建衍生索引。不同模型或维度的向量不混算。关键词查询不调模型；语义查询只嵌入查询文本，内容嵌入走增量后台。无可用语义端点时标明降级，仍能查词、回读来源和管理记忆。

提炼复用现有模型路由与用量入口。直接纠正立即提交；新决定在该轮结束后优先提炼，长对话按新增条目分段处理。一般经验归纳在任务结束后进行。不要把所有提炼推迟到会话关闭，也不要每轮重读整个历史。

### 3.3 数据关系与可信状态

| 实体 | 最小字段/关系 | 不变量 |
|---|---|---|
| `projects` | 项目 ID、规范根、关联 worktree、显示名 | 同名不同目录不混用；worktree 共享项目决定，任务和分支上下文独立 |
| `memories` / `memory_revisions` | ID、类型、范围、结论、条件、证据类别、确认状态、使用状态、修订号 | 用户表达、执行证据、模型推断分开；确认状态与停用状态不混成一个枚举 |
| 决定内容 | 问题、选中/被否方案、理由、条件、来源、替代关系 | 理由未知写未知；“曾否决”与“当前禁止”不同；模型不能自行改变正式选择 |
| `sources` / 来源关联 | 会话及条目 ID、分支/任务、事件范围、时间、归档定位或文档版本 | 每条正式依据可回读；引用的文件版本不能用当前文件冒充 |
| 修订关系 | 替代、纠正、合并、源自、成果版本关联 | 用户纠正优先；旧提炼任务不得把旧认识写回当前版本 |
| `extraction_jobs` | 来源范围、处理游标、任务状态、尝试和费用引用 | 同一来源范围不重复入库；重启后继续已提交游标之后的内容 |
| 使用记录 | 任务/会话、记忆 ID 与修订、检索/注入/展开阶段、用量引用 | 区分检索候选、实际注入、实际引用，不把命中当成已采用 |
| 来源排除记录 | 来源 ID 与范围、删除操作 ID | 只保留阻止重新提炼所需的定位，不留被删正文或其摘要 |
| `project_context` / 任务接续 | 目标及决定引用、正式文档定位、阶段、验收、承诺、各任务下一步 | 卡状态从现有正本读取，记忆只保存接续线索和来源 |
| 成果 | 成果 ID、用途、输入输出、条件、版本定位、验证回执 | Git 已跟踪版本优先引用；临时文件和未提交内容须稳定保存才可长期引用 |
| 进化记录 | 问题来源、资源与基础版本、候选、冻结验收、验证结果、生效/回退范围 | 验收依据与授权边界不由候选修改；运行任务绑定确定版本 |

这些是关系与职责清单，按阶段建立实际需要的表；S1 不提前实现成果、自进化的空表和空接口。

### 3.4 与部门知识库、文档和旧记忆的衔接

启用内置记忆后，新决定、偏好和执行经验只写数据库。部门作为记忆的归属和检索维度；原有查库/入库工具仍是业务入口，内部改为路由数据库经验与文件资料。此正本归属已于 2026-11-08 确认。

已有部门 Markdown 保留为历史资料，实际读到时可形成有来源的新记忆；不主动全库转存。仍在维护的项目规范、说明书、报告和任务卡继续在文件中维护，数据库只引用它们及所需历史证据。对旧经验形成纠正时，新记忆关联旧来源，默认召回使用纠正后的结论，不要求再维护一份旧文修订正文。

启用切换完成后 PAO 不调用 gbrain，也不把缺配置解释成“继续使用旧供应商”。旧共享服务及其他使用者的数据保留；本计划不停止共享容器或删除共享库。现有公开工具名和中文配置键有真实调用时保留入口语义，内部统一到新业务服务；明确弃用项在 S4 一次说明和处理。

### 3.5 归档、纠正和删除

原始对话按新增事件段归档，来源引用段 ID 和事件位置；已封存段用 gzip 无损压缩。凭证在进入这条归档链前按已知字段及现有脱敏规则剔除。归档保留其余对话与关键证据，不以摘要替代。完整性按解压后的允许保存内容比较。

普通“忘掉”是停用，历史可恢复。明确“彻底删除”先确定范围，在同一业务操作中清除记忆修订、FTS/向量、使用记录中的正文、PAO 管理的来源片段与相关附件引用；共享片段按范围重写归档，只删除无其他引用的成果。排除规则阻止旧任务和旧来源再次提炼。

删除流程也覆盖 PAO 管理的原会话文本、压缩摘要和派生证据里的目标内容，不能只删除数据库行。操作前展示实际涉及的对象和保留的共享对象；失败保留未完成状态，不能先报完成。用户项目源文件、Git 历史及用户自管备份不因删除记忆被自动改写，其控制边界见 §8。

### 3.6 自进化运行方式

S8 在冻结真实问题与独立验收后，将 Reef 的候选副本、反馈评估和激活分离机制，以及 Hermes 的技能维护机制，映射到 PAO 自有模块。首个闭环选择 PAO 自有文本技能。生成、验证、版本保存、effectiveVersion、授权、费用和回退均由共享内核实现。

单次改进的输入输出、模块职责及执行路径已写入 [S8 实现路线](2026-11-08-受控自进化实施路径-S8-S9.md#pao-具体实现路线)，由 S8-01/07—11 实现。首期每个问题最多自动生成 3 个不同候选；开发样例的失败可驱动后续局部修改，独立保留样例只用于最终验收，保留组失败结束本轮改进。按旧版与候选的实际行为判断收益，关键正常用法失败不发布，环境执行失败记未完成。

候选生成与验证使用现有受控执行入口、隔离 PAO_HOME 和临时工作目录。可写资源由用户批准的类别/资源 ID、路径和能力范围确定；验收文件、预算及权限配置由核心控制。现有子进程执行器提供超时、取消和进程树停止，不提供通用操作系统沙箱；具体工具调用及资源加载路径见 [S8—S9 实施路径](2026-11-08-受控自进化实施路径-S8-S9.md)。

自进化按 PAO 自有资源类别授权，先用一个真实问题验证闭环，再逐类开放。已经在授权类别和能力范围内的资源，不逐个重复请求授权。验证包括原问题复现、正常用法和独立保留样例；只对有证据的适用范围启用。发布创建新版本并更新当前指向，任务在开始时绑定版本，运行中只在安全边界换版。退步有可定位证据时回退版本；已经生成的文件和外部动作单独核对。

## 8. 限制与实施风险

1. **数据库宿主兼容尚未实测。** Node 和 Electron 版本约束已从仓库读取，但 `node:sqlite` 在实际桌面进程及打包后的可用性必须由 S0 证明；不能仅凭 Node 官方接口存在就宣布选型完成。
2. **语义质量取决于现有端点。** 已决定复用端点，不在计划阶段读取凭证或发起真实请求。S0/S3 验证中文和改写召回，端点不适合时保留本地数据契约，另讨论模型选择。
3. **精确向量检索有规模上限。** 初期减少依赖，代价是范围内线性计算。S0 定验收规模，S3 记录耗时；超过目标才引入成熟索引，不降低召回完整性掩盖瓶颈。
4. **凭证排除优先于原文完整保留。** 无损指压缩不丢失允许保存的文本；凭证、已明确删除内容不进入归档。现有脱敏不能保证识别所有自然语言中的任意秘密，支持用户明确排除来源和删除内容。
5. **彻底删除有管理范围。** PAO 管理的数据库、归档、会话派生记录和索引应完整处理；用户项目文件、Git 历史、已发出的外部请求和用户自行保存的副本不能由记忆删除自动撤销。恢复受管备份前保留当前最新删除排除记录，恢复后重新应用；只有旧备份且后续删除记录已丢失时，不能推断后来删除过什么。
6. **自动合并与重议不是自动定案。** 缺理由、互相矛盾或条件不明的内容保留状态；只有影响当前下一步时才提问。召回相关度不提升来源权威。
7. **自进化执行边界需要真实验证。** 技能/命令文件可间接触发其他工具，不能仅用目录白名单宣称已经受控。S8 验证实际动作边界；某资源类型无法约束时保持建议态，先交付已能约束的类型。
8. **缓存和长期收益不能预先承诺。** 记录供应商真实缓存字段、额外费用与任务效果；长期真实使用另积累证据。验证失败不把模拟结果或搜索分数当成功。
