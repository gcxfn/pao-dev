## 1. 技术路线

Hindsight、Hermes、Reef 是设计机制与源码参考。记忆与自进化由 PAO 共享内核实现，数据正本采用本机 SQLite，模型调用、执行、费用、取消和资源加载复用 PAO 及 pi 的现有能力。研究结果以“参考机制→PAO 模块→行为验收”落实，具体代码移植记录来源提交、文件及许可。

Hindsight 重点解决认识如何组织与回查，Hermes 重点解决经验如何形成可维护技能，Reef 重点解决候选如何经过评估并形成可恢复版本。S2 沿既定提炼、来源和纠正契约实施，后续模块通过公开接口消费结果。

## 3. Hindsight 的记忆机制

[官方说明](https://github.com/vectorize-io/hindsight)将保留、召回和归纳分为不同操作，组织事实、经历和归纳观察。PAO 的实现映射：

- 提炼时保留证据类别，区分用户表达、实际执行与模型推断；归纳结论关联来源及修订。
- 检索时先按项目、有效状态及替代关系筛选，再复用词法与向量两路召回。
- 注入时给简短结论与来源；需要解释原因和条件时再展开原始证据。
- 用户纠正直接改变当前依据；模型生成的归纳不能自行升级为正式决定。

这些机制落在 S2 现有提炼/修订契约和 S3 召回任务中。S2 正在实施，按现有接口与验收推进；S3 验证同义召回、来源展开及过时决定排除。

## 4. Hermes 的技能维护机制

[记忆文档](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md)区分有限常驻事实和 SQLite 会话检索；[技能管理](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md)支持创建和局部修订；[Curator](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/curator.md)跟踪技能使用并整理或归档。

PAO 在 S3 按上下文预算注入重要记忆，在 S7 区分检索命中、实际注入、实际使用和修改，在 S8 从真实失败、成功经验及用户纠正形成技能候选。维护动作针对有依据的重复、过时和冲突；仅因长时间未使用不删除资源。新技能沿现有资源加载入口生效。

独立 Self-Evolution 项目只将技能优化列为已实现。[执行入口](https://github.com/NousResearch/hermes-agent-self-evolution/blob/main/evolution/skills/evolve_skill.py)的 `run_tests` 默认 false。PAO 以自己的实际执行和独立验收作为发布依据。

## 5. Reef 机制参考

源码核实提交：`281c730a0f7a5a3eadb475003c043907351c4f3b`。参考 [README](https://github.com/Human-Agent-Society/reef/blob/281c730a0f7a5a3eadb475003c043907351c4f3b/README.md)、[方法契约](https://github.com/Human-Agent-Society/reef/blob/281c730a0f7a5a3eadb475003c043907351c4f3b/reef/train/harness_backend/contract.py)、[操作与评估文档](https://github.com/Human-Agent-Society/reef/blob/281c730a0f7a5a3eadb475003c043907351c4f3b/docs/user-guide/evolve-your-harness.rst)。

| 参考机制 | PAO 实现落点 | 行为要求 |
|---|---|---|
| 反馈准确关联一次执行 | `problems.ts`，读取 taskId、sourceIds、resourceVersion 和回执 | 失败归因可回查，不凭模型推测产生历史事实 |
| 在资源副本上产生候选 | `candidates.ts`，复用模型路由及限定文件操作 | 固定基础版本和允许范围，保留实际差异，可返回 no_change |
| 方法取得开发反馈再改进 | `types.ts` 单次改进契约；候选循环沿任务限制执行 | 反馈包含实际错误及条件；费用完整归因；取消及额度停止生效 |
| 原版和候选运行相同任务 | `validation.ts`、`runner.ts`，复用受控执行器 | 分别保留原问题、关键正常用法和独立保留样例结果 |
| 验证通过与激活分开 | `versions.ts`、`activation.ts` | passed 后仍须检查范围和基础版本，文件完整后才更新有效指向 |
| 版本历史与重新选择 | `observe.ts`、`rollbackResource`、taskBinding | 实际退步有证据，回退可恢复，新旧任务绑定明确 |

实现顺序、数据契约和行为验收见[PAO 具体实现路线](2026-11-08-受控自进化实施路径-S8-S9.md#pao-具体实现路线)；S8-01/07—11 实现生成与验证，S9 实现版本生效与回退。

## 6. 已知限制与采用条件

- Reef 核实提交的 README 明示正在迁往 control plane + workers，部分 main 配方可能失败。参考代码按同一提交阅读，机制实现以 PAO 当前需求和运行环境为准。
- Reef 支持 `policy: none`，ACE、ReasoningBank 配方列用此策略；compare 的总体胜出也可能包含部分任务退步。PAO 的关键正常用法和独立保留样例必须逐项通过，开发样例评分不替代最终验收。
- Hindsight 的[存储](https://hindsight.vectorize.io/developer/storage)主要基于 PostgreSQL，[Node 封装](https://hindsight.vectorize.io/sdks/hindsight-all-npm)管理独立进程；Hermes 和 Reef 也有各自宿主、存储或生命周期。这些工程形态属于参考项目自身，PAO 的实现使用既有共享内核和本机 SQLite。
- [MemOS 技能说明](https://github.com/MemTensor/MemOS/blob/main/apps/memos-local-plugin/core/skill/README.md)中的文本覆盖和相关性验证，不能证明工具执行行为正确。技能与命令必须验证实际动作。
- 普通子进程与资源副本不构成操作系统沙箱。可执行资源仍按项目已定可信本机协作范围验证能力边界；文本技能的通过结果不自动扩展到任意代码资源。
- 局部代码移植需记录许可证和必要声明；参考项目的宣传指标及示例结果不作为 PAO 验收证据。

## 7. 源码核实与采用结论

核实日期：2026-11-08。读取官方仓库固定提交与本地 PAO 源码；本轮完成机制调查和实施路线编制，未运行第三方引擎或真实模型评测。

### Hindsight

提交：`0bd55015393d224deec1073d63b24bcc0faad164`。

- [`engine/search/fusion.py`](https://github.com/vectorize-io/hindsight/blob/0bd55015393d224deec1073d63b24bcc0faad164/hindsight-api-slim/hindsight_api/engine/search/fusion.py)：`cap_per_source` 先限制各路候选；`reciprocal_rank_fusion` 使用倒数排名相加；`interleave_fusion` 针对去重召回保留各路前项。PAO 的普通召回采用词法+语义两路 RRF；整理查重采用两路交替取项，实际合并另经业务判断。
- [`engine/consolidation/consolidator.py`](https://github.com/vectorize-io/hindsight/blob/0bd55015393d224deec1073d63b24bcc0faad164/hindsight-api-slim/hindsight_api/engine/consolidation/consolidator.py)：归纳记录来源记忆，提交前过滤已消失来源并检测读后变化。PAO 使用现有 sourceIds、revision、usageState、source_exclusions 和短事务实现同类约束；模型归纳保持 tentative，不把来源数量当作正式确认。

落实位置：[S3 召回实现路线](2026-11-08-内置记忆实施路径-S0-S4.md#召回实现路线)、[S7 经验整理与维护](2026-11-08-内置记忆实施路径-S5-S7.md#经验整理与维护的实施路线)。

### Hermes

提交：`8422e54df36f42371f31b8fbee653e7c801edcbd`。

- [`tools/memory_tool.py`](https://github.com/NousResearch/hermes-agent/blob/8422e54df36f42371f31b8fbee653e7c801edcbd/tools/memory_tool.py)：会话开始冻结记忆快照以保持提示前缀稳定。PAO 保留固定工具与系统规则，动态依据追加消息；本项目要求纠正立即生效，故通过 ID+revision 过滤旧上下文，不把整个会话冻结为旧认识。
- [`tools/skill_usage.py`](https://github.com/NousResearch/hermes-agent/blob/8422e54df36f42371f31b8fbee653e7c801edcbd/tools/skill_usage.py)：`latest_activity_at` 分别读取最后查看、使用和修改时间，`activity_count` 汇总各类事件。PAO 保留事件类别，使用日志聚合统计；loaded、viewed 和 used 各自表达真实动作。
- [`agent/curator.py`](https://github.com/NousResearch/hermes-agent/blob/8422e54df36f42371f31b8fbee653e7c801edcbd/agent/curator.py)：维护前检查启用、暂停和运行时机，选择受管技能；`apply_automatic_transitions` 包含按时间归档。PAO 采用空闲调度和受管资源范围，维护变更必须有重复、冲突、失效或实际退步证据；长期少用本身不触发删除。

落实位置：S3-09—13、S7-01—08、S8-03/04、S9-06—10。各模块继续使用共享内核和现有加载入口。

### Reef

提交：`3a6db13b657b9e93be9f89fbf401c31303a3ef3a`。

- [`train/harness_backend/backend.py`](https://github.com/Human-Agent-Society/reef/blob/3a6db13b657b9e93be9f89fbf401c31303a3ef3a/reef/train/harness_backend/backend.py)：`prepare/propose` 准备副本、生成候选并跳过未变内容；`settle_step` 保存选择结果，拒绝候选不产出发布物。PAO 实现对应的 candidates/validation/versions 职责，正文直接比较，基础身份使用已有 versionId。

### PAO 现有实现的承接点

- `memory/types.ts` 已定义 SearchMemoryInput/Result、MemorySearchHit、MemoryRevisionContent 和来源/修订服务接口；`service.ts::searchMemory` 尚为 unavailable 占位，S3 直接实现此入口。
- S2 在建的 `extract-model.ts::requestExtraction` 已使用现有模型注册表、请求 ID 及专用账本；`extract-commit.ts` 处理候选来源和提交；`extraction-jobs.ts` 已有领取、游标、完成、失败及恢复函数。S7 扩展这些职责，避免出现第二套队列和提炼规则。
- `core/sdk.ts::createAgentSession` 支持显式 agentDir、modelRuntime、tools、resourceLoader 和 sessionManager；`core/resource-loader.ts` 支持附加技能/扩展路径；`cards/process.ts::runCardProcess` 提供超时、取消及进程树结束。S8 通过这些入口执行隔离用例，停止未确认仍是未完成状态。

详细任务文档中的新增函数是实施契约；上述已有函数是本次源码核实结果。实施阶段以当时 S2 验收后的公开契约承接，既有任务状态仍只维护在总计划。
